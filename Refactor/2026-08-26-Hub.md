# 2026-08-26 Hub 씬 점검

대상: `HubUIController`/`IHubUIController`/`HubUIElementIds`/`HubUIWiring`, 상행 준비(Trip) UI
(`UI/Trip/`), 지도 디버그 도구(`Debug/Trip/`), 에디터 인스톨러(`TripUIInstaller`, `FormationUIInstaller`).
공통/Formation 추가분으로 이미 리뷰한 코드(`ICaravanRosterProvider`, `FormationPanel` 등)는 제외.

## 1. 최적화 점검

**`TripMapInteractionCoordinator.RefreshLinesForCity()` — 드래그 중 매 프레임 전체 선형 스캔 + 문자열
할당.** 도시 마커를 드래그하는 동안 매 프레임 `linesByRouteKey` 전체를 순회하며 각 키를
`Split('|')`로 분해했다. 같은 파일 그룹의 `InMemoryTripRouteRepository`가 `RemoveAllRoutesFor`용으로
이미 유지하던 `adjacency` 인접 정보를 활용하지 않고 있었다.

## 2. SOLID 점검

문제점 없음. OCP(`ICityDragBehavior` 전략), ISP(`ITripCityReader`/`ITripRouteReader` 등 읽기 전용 분리),
DIP(`TripOriginDestinationAssigner`가 `ITripRouteReader`에만 의존), SRP(`TripMapInteractionCoordinator`가
`TripPanel`에서 이미 분리됨)가 코드 곳곳에 이미 적용/문서화돼 있었다.

## 3. 확장성/하드코딩 점검

**미사용 인터페이스 멤버 4개.** `ITripInfoProvider.GetOrigin()`/`GetDestination()`,
`ITripCityReader.GetAll()`/`TryGet()`, `ITripRouteRepository.GetAll()` — 전체 코드베이스에서 호출부가
전혀 없음을 grep으로 확인. 출발/도착 표시는 디버그 도시 마커 시스템(`BuildLocationInfo`)이 대신하게
되면서 남은 흔적으로 보인다.

## 4. 수정안 및 통합 점검

- `ITripRouteReader`에 `GetConnectedCityIds(string cityId)` 추가, `InMemoryTripRouteRepository`가 기존
  `adjacency` 딕셔너리를 그대로 반환하도록 구현(새 컬렉션 복사 없음). `RefreshLinesForCity`는 이제
  연결된 도시만 순회 + `RouteKey`로 직접 조회 — O(전체 노선) → O(연결된 노선), 문자열 분해 제거.
  `linesByRouteKey`와 `adjacency`는 항상 같은 `TryAddRoute`/`RemoveRoute` 호출로 함께 갱신되므로
  결과는 기존과 동일하다(순수 최적화).
- `ITripInfoProvider.GetOrigin()`/`GetDestination()` 제거, `PlaceholderTripInfoProvider`의 관련
  필드/생성 코드도 함께 제거(`GetTripSummary()`만 남음).
- `ITripCityReader.cs` 삭제(멤버 전부 미사용, 별도 참조 없음). `ITripCityRepository`는 더 이상
  상속하지 않고 자신의 쓰기 멤버만 유지.
- `ITripRouteRepository.GetAll()`과 `InMemoryTripRouteRepository`의 구현 제거.

통합 점검: 확장성 정리로 지운 메서드들은 애초에 안 쓰이던 코드라 최적화에 영향 없음. 새로 추가한
`GetConnectedCityIds`는 기존 자료구조를 그대로 노출해 추가 비용이 없다. `ITripRouteReader`에 조회
메서드가 하나 늘지만 읽기 전용이라 ISP 위치가 적절하고, `ITripCityReader` 제거는 오히려 안 쓰이는
추상화를 걷어내는 방향이라 SOLID를 해치지 않는다.
