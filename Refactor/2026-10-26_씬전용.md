## 2-1. 최적화 측면 점검 (문제점 식별만)

### Hub

확인 범위: 매 프레임 경로(`Update`·코루틴), 트리 탐색(`Find`·`GetComponentInChildren`), 매번 파괴·생성, 이벤트 처리기의 갱신 범위·빈도, 할당.

확인 결과 정상:
- 매 프레임 경로는 휴식 진행 코루틴 하나뿐이다. 게이지는 앵커만 바꾸고 문구는 하루가 지날 때만 만든다.
- 시설 화면 6종·골드 변환은 Bootstrap 상주 저장소 이벤트를 받아도 열려 있을 때만 다시 그린다.
- 목록·지도 마커·도로선·미리보기 칸은 모두 풀 재사용(파괴·생성 없음). 지도 마커 드래그(디버그)는 끝점 선만 고친다.
- Hub가 언로드된 뒤 오는 이벤트는 파괴된 요소를 확인해 바로 빠져나온다(상행 준비·재화 HUD).
- 트리 탐색은 씬 로드 시 배선 단계에서만 한다.

### 4.3 적용 조건 (제작 시 지킬 것)

① 풀 반환 시 뷰 상태를 전부 되돌린다 — 유닛 이벤트 해제, 실행 중 코루틴 정지(피격 깜빡임·찌르기·투사체·페이드), 색·크기·투명도·정렬 순서, 게이지 투명도, 투사체 비활성. 비활성 상태에서 코루틴을 시작하지 않는다(반환 뒤 늦게 오는 이벤트 무시).
② 투사체는 뷰 소유로 두고(뷰 반환 시 함께 숨김), 이미 컨테이너에 남은 옛 투사체 정리는 런타임 생성물이라 씬 정리가 필요 없다 — 풀 도입 뒤 전투 2회 연속 Play로 컨테이너 자식 수가 늘지 않는지 확인.
③ 배틀 테스트: 클릭 대상 컴포넌트는 반환 시 제거(또는 비활성)하고, 배치 취소·적 구성 적용·초기화는 컨트롤러의 반환 경로로만 — 정보 패널은 "배치 취소 요청" 콜백만 낸다.
④ 상행 생명주기 객체는 Field 로드마다 새로 만들고 Bootstrap 상주 의존성(상태 저장소·신호)을 구독하지 않는다(호출만) — 구독이 필요해지면 해제 대칭을 둔다. 결과 정리 흐름(Bind 1회/RebindViews 매 로드)에는 RebindViews로 넘긴다.
⑤ 숨김 게이트: 같은 레이어에 "숨김"과 "입력 차단"이 동시에 걸리면 숨김이 우선. "휴식 중" 조건은 휴식 진행 화면이 Hub 로드마다 새로 만들어지므로 그 로드의 규칙표로 등록된다(이전 규칙은 교체).
⑥ 시설 바인딩: 기존 등록 순서·조건(의존성 없으면 경고 후 미등록)·Dispose 시점을 그대로 유지. 숨김 규칙 기여는 선택 계약으로(숙소만 구현), Hub 배선이 모아서 한 번에 등록.
⑦ 대화 계약 분리: 상행 대화(선택지 있음) 동작 불변. 선택지 계약 없이 선택지가 오면 경고 로그 — 동작(멈춤)은 바꾸지 않고 드러내기만 한다. 이벤트 대본에 선택지가 실제로 들어갈 수 있는지(콘텐츠 검증)는 제작 착수 시 확인해 보고.
⑧ 인스톨러: Hub 분리(H-3)·행 레이블 통합(H-4)·표 배선 공유(H-1)는 재실행 후 씬 해시 동일(Hub·Bootstrap·BattleTest). 지도 디버그 UI 분리(H-2)는 Hub 재빌드가 기존 디버그 오브젝트를 지우지 않는다(디버그 인스톨러 소유) — 제거는 Remove 메뉴만. BattleTest 재실행 2회 연속 diff 없음(H-5).
