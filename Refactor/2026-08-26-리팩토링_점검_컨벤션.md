# 리팩토링 점검 컨벤션

프로젝트 전체 코드를 씬 기준으로 점검/리팩토링하기 위한 절차 정의 문서.

## 기록 방식(파일명 = 날짜_대상)

점검 결과는 이 폴더(`Docs/Refactor/`) 하위에 `{YYYY-MM-DD}_{대상}.md` 파일로 기록한다. `{대상}`은
씬 이름(`Hub`, `Field` 등) 또는 `공통`이다 — 예: `2026-08-26_공통.md`, `2026-08-27_Hub.md`.
같은 대상을 다른 날 다시 점검·수정하게 되면 기존 파일을 고쳐 쓰지 않고 그날 날짜로 새 파일을
만든다 — 언제 무엇을 왜 바꿨는지 파일명만으로 시간순으로 남기기 위함이다.

## 진행 순서

### 0. 공통 코드 선점검
여러 씬에서 공유되는 코드(전역 매니저, `UI/Common`, 인스톨러 유틸리티 등)를 별도 "공통" 카테고리로 묶어 가장 먼저 점검한다.
이후 각 씬 점검에서는 공통 코드를 다시 점검하지 않고, 이미 확정된 공통 코드 결과를 전제로 진행한다.

### 1. 씬별 코드 분류
씬에서 실제로 사용되는 코드를 나열한다.
- 대상: 순수 C# 스크립트 로직뿐 아니라 `Assets/Scripts/Editor/`의 씬 인스톨러, DI 등록(`RegisterSelf`/`ResolveDependencies`), 프리팹 구조까지 포함한다.
- 이미 공통 카테고리로 분류된 코드는 제외한다.
- 분류 결과 자체에 대한 별도 확인 절차는 두지 않는다. 분류가 잘못된 경우 다음 점검 단계에서 드러나면 그때 바로잡는다.
- 분류 도중 이미 "씬 전용"으로 분류해뒀던 코드가 실제로는 다른 씬에서도 재사용되고 있음을 발견하면(예: Hub 분류 중 `FormationPanel`이 Field에서도 쓰이는 것을 뒤늦게 확인), 그 부분만 "공통 추가분"으로 떼어 0번과 같은 방식(최적화→SOLID→확장성 점검 후 수정)으로 먼저 마무리하고, 그 결과는 원래 공통 점검 파일(`{같은 날짜}_공통.md`가 이미 있다면 그 파일에 절 추가, 없다면 새로 생성)에 기록한 뒤 원래 씬 분류로 돌아온다.

### 2. 점검 기준별 순차 점검 (문제점 식별만)
아래 세 기준을 한 번에 묶어 점검하지 않고, 대화를 끊어 순서대로 점검한다. 이 단계에서는 **수정안을 마련하지 않고 문제점 식별 및 정리만** 한다. 각 기준을 점검할 때는 앞서 정리된 상위 기준의 문제점 목록과 충돌하는 새 문제가 없는지도 함께 확인한다(교차 확인만 하고, 수정책 작성은 하지 않는다).

기준 순서는 중요도 순이다:

1. **최적화 측면 용이성**
2. **SOLID 원칙 준수 여부**
3. **확장성 측면 및 하드코딩 여부**

기준 간 상충 시 우선순위(= 위 순서와 동일): **최적화 > SOLID > 확장성**.
(즉 최적화 문제와 SOLID 문제가 서로 얽혀 있으면 최적화를 우선 해결하는 방향으로, SOLID와 확장성이 얽혀 있으면 SOLID를 우선하는 방향으로 문제를 정리한다.)

### 3. 수정안 도출
세 기준 점검이 모두 끝난 뒤, 정리된 문제점 전체를 종합해 수정안을 도출한다. 개별 기준을 점검하던 중간에는 수정안을 만들지 않는다.

### 4. 통합 점검
3번에서 도출한 수정안이 세 기준(최적화/SOLID/확장성·하드코딩)을 모두 만족하는지 최종 확인한다.

### 5. 수정 착수
통합 점검을 통과한 수정안을 실제 코드에 반영한다.
- 씬 편집이 필요한 경우 `.unity`/`.prefab`을 직접 편집하지 않고 `Assets/Scripts/Editor/`의 get-or-create 인스톨러를 통해 반영한다(CLAUDE.md 씬 편집 규칙 준수).
- 수정 후 컴파일 확인만 수행한다. 플레이 테스트를 통한 별도 회귀 확인 단계는 두지 않는다.
- **MonoBehaviour 파생 클래스 파일을 삭제하는 수정은 예외적으로 주의한다.** 그 컴포넌트가 이미 씬에 저장(부착)돼 있었을 수 있어, 컴파일은 통과해도 씬을 열면 "Missing Script" 경고가 뜰 수 있다(실제 사례: `BattleResultEvaluator` 삭제 후 Bootstrap 씬에서 발생). 이런 삭제가 있었다면 `ManagerHierarchyInstaller` 같은 관련 인스톨러에 `GameObjectUtility.RemoveMonoBehavioursWithMissingScript` 기반 정리 로직이 있는지 확인하고, 없으면 추가한다.

### 6. 다음 씬으로 반복
해당 씬 작업이 끝나면 2~5번을 다음 씬에 대해 반복한다.
씬별 작업 완료 시 커밋 여부/단위는 고정 규칙 없이 그때그때 사용자 지시에 따른다.

## 비고
- 이 문서 자체를 포함한 `Docs/` 전체는 `.gitignore` 대상이며, 이는 의도된 설정이다.
- 하나의 대화 요청에서는 기획/설계/제작 중 한 단계만 수행한다는 전역 규칙을 이 리팩토링 작업에도 동일하게 적용한다. 즉 점검(기획/설계에 해당)과 수정 착수(제작)는 요청을 분리해 진행한다.
