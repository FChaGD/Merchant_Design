# 2026-08-26 Field 씬 점검

대상: AI(`AIManager` 등), 전투 핵심(`BattleManager` 등), 전투 하위 도메인(`Battle/Combat`,
`Battle/Consequence`, `Battle/Enemy`, `Battle/Field`, `Battle/Morale`, `Battle/Simulation`),
인카운터(`EncounterManager` 등), Field 화면 조율(`FieldUIController` 등), 전투 뷰(`BattleCharacterUnitView` 등),
`Editor/FieldUIInstaller.cs`. 공통/Formation 추가분(`Battle/Stats/` 등)은 제외.

## 1. 최적화 점검

**`BattleCharacterUnitView.FireProjectile()` — 원거리 공격마다 투사체 GameObject를 새로 생성/파괴.**
공격 주기마다 반복되는 이벤트라 전투가 길어지고 궁수 수가 늘수록 생성/파괴가 누적된다. 다만 발생
빈도가 낮고(공격 주기 단위) 오브젝트도 가벼워 심각도는 낮다고 판단했다.

그 외 `BattleSimulationLoop.Tick()`의 매 틱 리스트 할당, `LiveBattleSimulationRule.FindRosterUnit()`의
O(n) 탐색, `LinearScanUnitSpatialQuery`의 O(n) 탐색은 이미 팀이 주석으로 "현재 규모에선 무시할 만하다"
/ "교체 지점"이라고 명시해둔 의도된 트레이드오프라 재지적하지 않았다.

## 2. SOLID 점검

**`IBattleResultEvaluator`/`BattleResultEvaluator` — `IBattleResultRule`과 시그니처가 동일한 불필요한
중간 계층.** `BattleManager`가 마커 인터페이스 주입을 위해 이미 `GetComponent<IBattleResultRule>()`로
규칙 인스턴스를 직접 갖고 있는데, `StartBattle()`은 그 대신 `IBattleResultEvaluator`(내부적으로 같은
`IBattleResultRule`을 다시 `GetComponent`로 조회해 그대로 위임만 하는 컴포넌트)를 거쳐 호출하고 있었다.

## 3. 확장성/하드코딩 점검

**`LiveBattleSimulationRule.DefaultColumnCount`가 `FormationGridView.columnCount`의 인스펙터 기본값(8)과
중복.** 두 값이 독립적으로 하드코딩돼 있어 `BattleFieldGeometry.cs`가 이미 경계하는 것과 같은
"조용히 어긋남" 위험이 있었다.

AI 서브시스템(`IAIControllable`/`AIManager.Register`)의 미사용 여부도 확인했으나, `Docs/설계/
01-2026-08-25-매니징오브젝트_컴포넌트구조.md`에 명시된 정식 설계(`UnitAIBehavior`/`AIProfileComponent` 도입 예정)의
일부로, Hub에서 지운 죽은 코드(대체되고 남은 흔적)와 성격이 달라 수정 대상에서 제외했다 — 사용자 확인.

## 4. 수정안 및 통합 점검

- `BattleCharacterUnitView`에 `projectileView` 필드를 추가해 원거리 공격마다 재사용(파괴 대신
  `SetActive(false)`). 발사 후 공격자가 죽어도 투사체는 그대로 유지되는 기존 동작과 동일하다
  (투사체가 유닛 자신이 아니라 `rectTransform.parent`의 자식이라 소유자 파괴와 무관하게 존재).
- `IBattleResultEvaluator.cs`/`BattleResultEvaluator.cs` 삭제. `BattleManager`는 마커 인터페이스
  주입용으로 이미 조회하던 `IBattleResultRule` 참조를 필드(`resultRule`)로 승격해 `StartBattle()`에서
  직접 호출. `ManagerHierarchyInstaller`에서 `BattleResultEvaluator` 형제 컴포넌트 부착 코드 제거.
- `FormationLayout`(Hub/Field 공통 그룹)에 `public const int DefaultColumnCount = 8;` 추가.
  `FormationGridView.columnCount` 인스펙터 기본값과 `LiveBattleSimulationRule`의 배치 없음 폴백이
  이 상수를 참조하도록 변경.

통합 점검: SOLID/확장성 변경은 런타임 경로에 새 비용을 추가하지 않는다(둘 다 초기화/등록 시점
변경). `DefaultColumnCount`를 이미 Hub/Field 공통 타입인 `FormationLayout`에 둔 것이라 씬 간 부적절한
결합을 새로 만들지 않는다. `IBattleResultEvaluator` 제거는 불필요한 계층을 줄여 SOLID를 개선하며,
투사체 재사용은 유닛 수/전투 길이가 늘어나도 그대로 동작해 확장성을 해치지 않는다.

### 후속 조치: Missing Script 경고

플레이 테스트 중 Hub/Bootstrap 시작 시 `The referenced script (Unknown) on this Behaviour is missing!`
경고가 발생했다. 원인: 이전 세션에서 `Tools/Game/Build Manager Hierarchy`를 실행·저장했을 때
`BattleManager` GameObject에 `BattleResultEvaluator` 컴포넌트가 이미 붙어 Bootstrap.unity에 저장돼
있었는데, 이번 SOLID 수정으로 그 스크립트 파일을 삭제하면서 씬에 남은 참조가 깨졌다. 인스톨러
재실행만으로는 지워지지 않는다(삭제된 타입은 `GetComponent<T>()`로 찾을 수 없어서다).

조치: `ManagerHierarchyInstaller.BuildManagerHierarchy()`에 `RemoveMissingScriptsRecursively` 헬퍼를
추가해, 재실행할 때마다 매니저 하이어라키 전체에서 `GameObjectUtility
.RemoveMonoBehavioursWithMissingScript`로 없어진 스크립트 참조를 자동 제거하도록 했다(기존
EventSystem 잔재 정리와 같은 "재실행 안전성" 패턴).

Hub.unity/Field.unity도 전체 GUID를 대조해 확인했다 — 실제 결측은 없었고, 처음에 의심됐던 항목은
전부 `Library/PackageCache/`(UGUI/TextMeshPro/InputSystem/URP)에 있는 정상 패키지 스크립트였다.

사용자 확인: 경고 해결됨.
