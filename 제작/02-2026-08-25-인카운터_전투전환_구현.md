## 1. 개요

[[01-2026-08-25-Field씬_이동뷰_구현]]에서 미구현으로 남겼던 "인카운터 발생 → 경고 → 전투 전환 → 결과 팝업" 전체 흐름을 구현했다. 세 단계로 나눠 진행했다 - ① 인카운터 판정(5초/30%)과 경고창 점멸, ② 전투 뷰 전환과 승패 결과 팝업(1차), ③ 실제 플레이 확인 후 발견된 문제 2건 수정(2차 - §1.1 참고).

**설계 대비 조정 사항**: [[04-2026-08-25-Field씬_아키텍처]] §7은 "카메라가 두 앵커 사이를 이동"하는 실제 카메라 전환을 상정했으나, 실제 Field 씬은 Camera가 고정된 채 전부 Canvas UI로 구성돼 있어(월드 오브젝트 없음) `FieldCameraController`를 "MovementView/BattleView 두 RectTransform(둘 다 화면 전체를 채우는 stretch 앵커)의 `anchoredPosition.x`를 함께 슬라이드"하는 방식으로 구현했다. API 시그니처(`TransitionToBattle`/`TransitionToMovement`)는 설계 문서와 동일하게 유지해 소비 측(`FieldEncounterFlowCoordinator`) 코드는 그대로 따른다.

### 1.1 1차 구현 후 발견된 문제 2건과 수정 (같은 세션, 실플레이 확인 후)

1. **전투 뷰 전환이 즉시 스왑이었다**: 1차 구현은 `FieldCameraController`가 `SetActive`만으로 두 뷰를 즉시 교체했다 - "카메라가 오른쪽으로 이동하며 이동 뷰가 왼쪽으로 밀려나고 검은 전투 뷰가 오른쪽에서 들어오는" 슬라이드 연출이 빠져 있었다. `SlideToBattleRoutine` 코루틴으로 두 RectTransform의 `anchoredPosition.x`를 0.6초에 걸쳐 함께 이동시키도록 수정했다(§2 `FieldCameraController.cs` 참고).
2. **전투 결과가 전투 뷰 진입과 동시에 나왔다**: `EncounterManager.TriggerEncounter()`가 인카운터 발생과 동시에 `battleController.StartBattle()`을 호출하고 있었는데, `PlaceholderBattleResultRule`의 1초 판정이 2초짜리 경고창 표시 중에 이미 끝나버려 전투 뷰에 들어가자마자 결과 팝업이 뜨는 문제였다. `StartBattle()` 호출을 `EncounterManager`에서 제거하고, `FieldEncounterFlowCoordinator.TransitionAfterWarning()`의 `TransitionToBattle` 완료 콜백(=전투 뷰 슬라이드가 끝난 시점) 안으로 옮겼다 - 이제 "전투 뷰 진입 → 1초 뒤 결과"라는 순서가 실제로 보장된다([[01-2026-08-25-매니징오브젝트_컴포넌트구조]] §4.4, [[04-2026-08-25-Field씬_아키텍처]] §4 "갱신 2" 문서도 함께 갱신).
3. **경고창 점멸이 즉시 on/off 토글이었다**: `FieldEncounterWarningView`가 `CanvasGroup.alpha`를 0.4초마다 1↔0으로 즉시 전환하고 있었다 - 사인파 기반 보간(`(Mathf.Sin(...) + 1) * 0.5f`, 0.8초 주기)으로 교체해 0~1 사이를 매끄럽게 오가도록 수정했다.
4. **승리 확인 후 이동 뷰 복귀가 비대칭(즉시 전환)이었다**: [[06-2026-08-25-Field씬_기획]] §4.1이 "복귀는 로딩화면 없이 즉시 재표시"로 확정했던 사항을 실플레이 피드백에 따라 폐기했다 - `TransitionToMovement`도 `TransitionToBattle`과 대칭인 슬라이드 애니메이션을 쓰도록 변경했다(카메라가 왼쪽으로 이동하며 전투 뷰가 오른쪽으로 밀려나고 이동 뷰가 왼쪽에서 들어옴). `FieldCameraController`는 방향(`toBattle` bool)만 다르고 로직은 동일한 `SlideRoutine` 하나로 양방향을 처리하도록 리팩터링했다.

## 2. 신규 파일

```
Core/Encounter/
  IEncounterRule.cs / RandomEncounterRule.cs
    - 5초마다 30% 확률로 판정하는 전략 객체. EncounterManager가 순수 C# 객체로 직접 소유.

Core/Battle/
  IBattleResultRule.cs / IBattleResultEvaluator.cs / BattleResultEvaluator.cs / PlaceholderBattleResultRule.cs
    - 승패 판정 위임 체계(OCP). PlaceholderBattleResultRule은 1초 후 70%/30%로 판정.
    - BattleResultEvaluator/PlaceholderBattleResultRule 모두 BattleManager와 같은 GameObject에 부착,
      각자 자신의 Awake()에서 GetComponent로 다음 단계 인터페이스를 조회한다.

Core/UI/Field/
  FieldEncounterWarningView.cs
    - 인카운터 발생 시 화면 중앙에 점멸하는 경고창(CanvasGroup 알파를 사인파로 보간, §1.1-3).
  FieldEncounterFlowCoordinator.cs
    - 인카운터 발생→경고→전투 전환→결과 처리 상태 흐름 전담(순수 C# 합성 객체).
  FieldCameraController.cs
    - 이동 뷰 ↔ 전투 뷰 슬라이드 전환(§1 조정 사항 참고).
  FieldResultPopupView.cs
    - 승리/패배(추후 도착까지) 공용 결과 팝업 - "메시지 + 버튼 1개" 구조.
```

## 3. 주요 변경

- **`EncounterManager`**: `ISessionPauseControl` 단독 의존을 `ISessionState`로 확장, `OnProgressChanged`
  구독을 판정 타이머의 틱 소스로 재사용([[05-2026-08-25-인카운터_판정_아키텍처]] §3) - `SessionStateTracker`가
  전투 중/도착 후 이 이벤트를 멈추므로 판정 타이머도 별도 코드 없이 함께 멈춘다. `TriggerEncounter()`는
  `sessionState.Pause()` + `OnEncounterTriggered` 발행만 하고, `battleController.StartBattle()` 호출은
  갖지 않는다(§1.1-2 참고 - `FieldEncounterFlowCoordinator`로 이동).
- **`BattleManager`**: `IBattleResultEvaluator`를 GetComponent로 조회해 `StartBattle()`에서 위임하도록 변경
  (기존에는 TODO 스텁이었음).
- **`FieldCameraController`**: 이동 뷰/전투 뷰 RectTransform의 `anchoredPosition.x`를 0.6초 동안 함께
  이동시켜 슬라이드 전환을 구현(`SlideRoutine(toBattle, onComplete)`). `TransitionToBattle`/
  `TransitionToMovement` 양방향 모두 동일한 코루틴을 방향만 바꿔 재사용한다(§1.1-4).
- **`FieldUIController`**: `MovementViewRoot`/`BattleViewRoot`/`ResultPopup` 요소를 추가로 바인딩하고,
  `FieldEncounterFlowCoordinator.Bind(...)`에 `IBattleController`/`IBattleResultSource`까지 전달.
  `RebindViews(...)`에 `FieldCameraController`(씬 로드마다 새로 생성, `this`를 코루틴 실행 주체로 전달)와
  `FieldResultPopupView`를 추가.
- **`FieldEncounterFlowCoordinator`**: 인카운터 발생 시 정비창을 강제로 닫고(`uiManager.Close`), 경고창을
  2초간 표시한 뒤 전투 뷰로 슬라이드 전환, 전환이 끝난 시점에 `battleController.StartBattle()`을 호출한다
  (§1.1-2). 전투 결과(`OnBattleEnded`)를 승리/패배로 분기해 팝업 표시 - 승리 시 이동 뷰로 복귀 후
  `sessionState.Resume()`, 패배 시 `Application.Quit()`.
  - **큐잉 안전장치**: `StartBattle()` 호출을 전환 완료 시점으로 옮겨 "결과가 경고창 표시 중에 먼저
    도착"하는 실제 문제 자체는 사라졌지만, 미래에 결과가 동기적으로(즉시) 나오는 전투 로직이 들어올
    가능성에 대비해 `isTransitioning`/`pendingResult` 큐잉은 그대로 남겨뒀다 - `StartBattle()` 호출이
    그 안에서 곧바로 `OnBattleEnded`를 발생시켜도 순서가 보장된다.

## 4. 적용에 필요한 에디터 작업 (순서)

1. `Bootstrap.unity` → `Tools > Game > Build Manager Hierarchy` → Ctrl+S
   (BattleManager 산하에 `PlaceholderBattleResultRule`/`BattleResultEvaluator` 추가됨)
2. `Field.unity` → `Tools > Game > Build Field UI` → Ctrl+S
   (BattleView/ResultPopup UI 하이어라키 추가됨)

두 인스톨러 모두 get-or-create라 재실행해도 안전하다.

## 5. 남은 이슈 (후속 세션 대상)

- 궤주/포로/사망/도주 판정은 미구현 - 현재는 승리/패배 2종만 존재.
- 도착 성공 팝업("도시 입장")은 미구현 - `FieldResultPopupView`는 재사용 가능하나 `FieldUIController`가
  `sessionState.OnArrived`를 아직 구독하지 않는다([[04-2026-08-25-Field씬_아키텍처]] §5.3).
  - **참고: [[01-2026-08-25-Field씬_이동뷰_구현]] §6에 있던 "인카운터 발생 → 전투 전환 → 결과 팝업" 미구현 항목은
  이번 세션으로 해소됐다.**
- 실제 전투 로직이 생기면 `PlaceholderBattleResultRule`을 통째로 교체.
- 블랙아웃 페이드/전투 세팅 연출(슬라이드 도중 화면이 검게 페이드되는 연출 등)은 아직 없다 - 필요해지면
  `FieldCameraController.TransitionToBattle` 시그니처에 콜백을 추가하는 정도로 확장 가능.
