# Hub↔Field 씬 전환 연출 구현 기록

작성일: 2026-08-26
상태: 구현 완료 (슬라이드+커튼 페이드아웃, 상호작용 게이팅, 전투 시뮬레이션 일시정지까지 전부 반영, 실플레이 확인 완료). `Tools/Game` 인스톨러 정리도 같은 세션에 함께 진행.

## 0. 이 작업 직전에 별도로 수정한 버그 2건

기획/설계 문서 없이 바로 고친 단발성 버그라 별도 문서는 두지 않고 기록만 남긴다.

1. **상행 준비 UI 지도 강조 스타일이 배치 UI를 갔다 와도 안 사라짐**: `TripOriginDestinationAssigner`에 `Reset()`을 추가하고, 상행 준비 UI "종료" 버튼에서만 호출하도록 배선(`TripMapInteractionCoordinator.ResetOriginDestination()`). 배치 UI 왕복 중에는 배정이 유지되고, `TripPanel.Open()`이 정보 패널을 무조건 비우던 것도 제거해 지도 강조와 정보 패널이 항상 같은 상태를 보이게 했다.
2. **배치 UI를 Hub에서 직접 열고 종료하면 상행 준비 UI가 열림**: `PanelNavigationStack`의 열림/복귀 기록이 씬 전환을 넘어 남아있던 게 원인 - `PanelNavigationStack.Reset()`을 추가하고 `UIManager.HandleSceneLoaded`가 콘텐츠 씬이 로드될 때마다 호출하도록 함.

## 1. 개요

[[10-2026-08-26-씬전환_연출_기획]]/[[10-2026-08-26-씬전환_연출_아키텍처]]대로 슬라이드+커튼 페이드아웃 연출을 구현했다. 설계 문서 자체는 구현 전 초안이라, 실플레이로 이어지는 과정에서 여러 문제가 드러나 그때그때 수정했고 최종 동작은 설계 초안과 몇 군데 달라졌다.

### 1.1 설계 대비 조정 사항

1. **ContentRoot "사후 재배치" 폐기 → 처음부터 최종 위치에 생성**: 설계 §9는 배치/상행 준비 UI를 만든 뒤 `ContentRoot` 밑으로 옮기는 방식이었다. 이 방식은 `EditorUIBuilder.GetOrCreateUIObject`의 get-or-create 조회(`Transform.Find`, 직계 자식만 검색)와 충돌해, 재실행할 때마다 이미 옮겨진 패널을 못 찾고 새로 하나씩 더 만드는 버그로 이어졌다(마커 ID 중복 등록 경고 57건 발생). `HubSceneInstaller`가 `ContentRoot`를 먼저 만들고 배치/상행 준비 UI를 그 "안"에 직접 생성하도록 구조를 바꿨다 - `FormationUIBuilder.Build`도 `SceneUIRoot` 대신 `Transform`을 받도록 시그니처를 넓혔다.
2. **Field 내부 전환 커튼도 페이드 아웃으로 통일**: 원래 `FieldTransitionCurtainView`는 즉시 `SetActive(false)`였는데, Hub↔Field 커튼과 동일한 EaseInCubic 페이드로 통일했다(사용자 확정, `SlideTransitionTimeline` 그대로 재사용). 그 결과 **전투 시뮬레이션이 커튼이 반투명해지는 동안에도 계속 틱을 돌려 캐릭터가 비쳐 보이는** 새 문제가 생겼다 - `LiveBattleSimulationRule`에 일시정지 개념(`IPausableBattleSimulation`)을 추가해, 유닛 배치는 즉시 하되 실제 틱(`Update()`)은 화면이 완전히 드러난 뒤(`ResumeSimulation()`)에만 재개하도록 고쳤다.
3. **상호작용 게이팅 추가**: 설계 문서 §12가 "필요하면"으로 남겨뒀던 항목이 실제로 필요해졌다 - 상행 준비/배치 버튼, 상행 시작 버튼, "전투 시작"(=상행 진행 시작, `sessionState.Begin()`)을 화면이 완전히 드러나기 전까지 막는 `ISceneRevealSignal`(신규)을 추가했다.
4. **Hub EventSystem 보장 주체 부재**: Hub 전용 설치기가 없던 시절엔 `Tools/Game/Build Formation UI`가 우연히 Hub의 EventSystem을 만들어주고 있었다 - 전용 설치기(`HubSceneInstaller`)가 `EditorUIBuilder.EnsureSceneEventSystem`을 직접 호출하도록 명시적으로 보장했다.
5. **지속시간/곡선**: 슬라이드 0.9초(재사용, 기존값)는 그대로. 커튼 페이드는 0.4초(최초 제안값) → 3초(1차 확정) → **2초(최종 확정)**로 조정됐고, 곡선은 슬라이드와 동일한 EaseInCubic으로 통일했다(Field 내부 전환 포함).

## 3. 주요 변경

- **`FieldCameraController`**: 내부 슬라이드 루프를 `SlideTransitionTimeline.Run(...)` 호출로 교체(동작은 동일, 로직만 공용화).
- **`FieldTransitionCurtainView`**: `Hide()`(즉시) → `FadeOut(coroutineRunner, duration, onComplete)`(페이드).
- **`FieldEncounterFlowCoordinator`**: `battleController.StartBattle()`(유닛 배치, 커튼 페이드 시작 전) →
  `transitionCurtain.FadeOut(...)` → `onComplete` 안에서 `battleController.ResumeSimulation()`(실제 틱 재개).
- **`LiveBattleSimulationRule`**: `paused` 필드 추가, `Evaluate()`가 매 전투 시작 시 `true`로 세팅,
  `ResumeSimulation()`이 해제. `BattleManager`가 `resultRule as IPausableBattleSimulation`로 선택적 캐스팅해
  `IBattleController.ResumeSimulation()`으로 노출(Placeholder 규칙은 자동으로 no-op).
- **`GameManager`**: `RequestSceneTransition`이 `ISceneLoader` 직접 호출 대신 `ISceneTransitionEffectPlayer`에
  위임 - 기존 3개 호출부(TripPanel/FieldUIController/FieldEncounterFlowCoordinator)는 무변경.
- **`HubUIController`/`FieldUIController`/`TripPanel`**: `ISceneRevealSignal.SceneRevealed`를 구독해 각자의
  버튼(`상행 준비`/`배치`/`상행 시작`)을 화면이 드러나기 전까지 `interactable = false`로 막는다.
  `FieldUIController`는 추가로 `sessionState.Begin()` 호출 자체를 반영(reveal) 시점으로 미룬다.
- **`HubUIController.ContentRoot` / `FieldUIController.MovementViewRoot`**: 씬 전환 연출이 슬라이드시킬
  대상으로 노출(Hub는 신규 ContentRoot, Field는 기존 이동 뷰 루트 재사용).
- **`HubUIWiring`/`FieldUIWiring`**: `ISceneTransitionContentRootRegistry.RegisterContentRoot(...)`,
  `ISceneRevealSignal` 조회·전달 추가. Hub 쪽은 예외가 나도 핵심 패널 등록이 깨지지 않도록 관련 호출을
  `Wire()` 맨 마지막에 둔다.

## 4. `Tools/Game` 인스톨러 정리 (부수 작업)

Hub 관련 인스톨러가 Formation/Trip/Hub 3개로 쪼개져 있었고, 이 셋이 실행 순서(배치→상행 준비→ContentRoot 재배치)에 의존하면서 §1.1-1의 중복 생성 버그로 직접 이어졌다. 이 기회에 전체 메뉴 구조를 씬 단위로 정리했다.

**삭제**: `FormationUIInstaller.cs`, `TripUIInstaller.cs`, `HubUIInstaller.cs`(`HubSceneInstaller.cs`로 통합) / `BootstrapSceneInstaller.cs`(Setup/1~3, 이미 완료된 최초 1회성 작업이라 통째로 삭제)

**최종 메뉴 구성**:

| 메뉴 | 대상 씬 | 비고 |
|---|---|---|
| `Tools/Game/Build Bootstrap Scene` | Bootstrap | 구 `Build Manager Hierarchy`, 클래스명(`ManagerHierarchyInstaller`)은 유지 |
| `Tools/Game/Build Hub Scene` | Hub | 배치 UI → 상행 준비 UI → ContentRoot를 한 메뉴로 순서대로 실행 |
| `Tools/Game/Build Field Scene` | Field | 구 `Build Field UI`, 이름만 변경 |
| `Tools/Game/Debug/Install\|Remove Bootstrap Reentry Guards` | 전체 콘텐츠 씬 | 변경 없음(별개 디버그 기능) |

`CLAUDE.md`/`DEBUG_FEATURES.md`의 관련 예시/절차도 새 이름에 맞춰 갱신했다.

## 5. 적용에 필요한 에디터 작업 (순서)

1. `Bootstrap.unity` → `Tools > Game > Build Bootstrap Scene` → Ctrl+S
   (`SceneTransitionEffectController` + 전용 커튼 Canvas 추가됨)
2. `Hub.unity` → `Tools > Game > Build Hub Scene` → Ctrl+S
   (`ContentRoot`, EventSystem, 배치/상행 준비 UI 전부 이 안에 생성됨)
3. `Field.unity` → `Tools > Game > Build Field Scene` → Ctrl+S
   (전환용 커튼에 `CanvasGroup` 추가·연결됨)

세 인스톨러 모두 get-or-create라 재실행해도 안전하다.

## 6. 남은 이슈

- **CanvasScaler 정합성**: 씬 전환용 커튼 Canvas와 Hub/Field 콘텐츠 씬 Canvas의 스케일러 설정이 다르면
  슬라이드 거리·커튼 커버리지가 화면상 어긋날 수 있다(설계 문서 §12) - 실플레이에서 어긋남은 확인되지
  않았으나, 두 Canvas 설정을 명시적으로 대조해본 적은 없다.
- **콘텐츠 씬 3개 이상으로 확장 시**: `SceneTransitionEffectController`가 "현재 씬 = 대상 씬의 반대"로
  추론하는 부분(§4 설계 문서)이 깨진다 - 그때는 `ISceneLoader`가 현재 씬 id를 명시적으로 노출해야 한다.
- **지속시간 수치**: 슬라이드 0.9초, 페이드 2초 모두 실플레이 조정 대상으로 남겨둔다.
- **연출 중 입력 차단 범위**: 커튼이 슬라이드~페이드 구간 대부분을 raycastTarget으로 막지만, 슬라이드
  시작 직후~완전히 덮이기 전 아주 짧은 구간은 이론상 클릭 가능하다 - 지금까지 실플레이에서 문제로
  드러난 적은 없어 별도 조치는 하지 않았다.
