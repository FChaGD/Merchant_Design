## 1. 개요

Field 씬의 이동 뷰(진행 게이지, 배경, 정비창 재호출 버튼)를 구현했다. 구현 도중 "정비창 재호출"이 실제로 동작하려면 배치(Formation) UI가 Hub뿐 아니라 Field에도 필요하다는 게 드러나 배치 UI 조립 로직을 공용화하고, 씬마다 따로 존재하던 그리드 열/행 수가 어긋나는 문제, EventSystem 중복 문제 등을 함께 해결했다. 인카운터 발생 → 전투 전환(카메라 이동, 검은 로딩화면) → 결과 팝업은 이번 범위에 포함하지 않았다(설계 문서의 `FieldEncounterFlowCoordinator` 등은 후속 세션 대상).

## 2. 신규 파일

```
Core/Game/
  ISessionPauseControl.cs / ISessionState.cs / SessionStateTracker.cs
    - 상행 진행 상태(0~1). 테스트 단계는 시간 기반. GameManager 산하 컴포넌트.

Core/UI/Field/
  IFieldUIController.cs / FieldUIController.cs
    - Field 씬 UI 등록(진행 게이지 구독, 배경, 정비창 버튼 배선). UIManager 산하 컴포넌트.
  FieldUIElementIds.cs
    - Field 씬 UIElementMarker id 상수.
  FieldProgressGaugeView.cs
    - 진행 게이지 표시 전담 뷰.

Editor/
  FieldUIInstaller.cs
    - Field 씬에 이동 뷰(배경/게이지/정비창 버튼) + Formation UI 하이어라키를 생성/동기화.
  FormationUIBuilder.cs
    - 배치 UI 하이어라키 조립 로직(팔레트/그리드/정보패널/디버그패널 + 프리팹 생성). 원래
      FormationUIInstaller에만 있던 로직을 Hub/Field 공용으로 추출.
```

## 3. 주요 변경

- **`GameManager`**: `SessionStateTracker`를 산하 컴포넌트로 조회해 `ISessionState`/`ISessionPauseControl`로 등록.
- **`UIManager`**: `FieldUIController` 결선, `HandleSceneLoaded`에 `SceneNames.Field` 분기 추가. 이 분기에서
  `FormationPanel.RegisterFormationUI(..., SceneNames.Field)`도 함께 호출(정비창 재호출용).
- **`FormationPanel` / `IFormationPanel`**: `RegisterFormationUI`가 씬 이름을 매개변수로 받는다 —
  Hub/Field 어느 콘텐츠 씬이 로드되든 그 씬의 배치 UI 화면 요소로 다시 바인딩된다(화면 요소 자체는
  콘텐츠 씬에 속해 있어 씬이 바뀌면 파괴되기 때문).
- **`FormationLayout`**: `ColumnCount`/`RowCount`를 데이터에 포함시켜, 저장된 배치를 불러올 때 그
  모양대로 그리드를 다시 맞춘다(Hub에서 8×4로 배치·적용하면 Field도 8×4로 동기화됨 — 이전엔 씬마다
  `FormationGridView`의 Inspector 값이 따로 있어 어긋났음).
- **`FormationGridView`**: 그리드가 열릴 때(또는 열/행/타일크기 변경 시) 실제 타일 영역이 뷰포트
  중앙에 오도록 초기 스크롤 위치(`CenterContentOnTiles`)를 계산해 맞춘다 — 기존엔 항상 좌상단
  여백부터 시작해 타일까지 드래그해야 했음.
- **`SceneLoader`**: 콘텐츠 씬 전환 시 새 씬을 로드한 직후(언로드를 기다리지 않고) 이전 씬의
  EventSystem을 즉시 파괴 — "There can be only one active Event System" 경고와 함께 입력이
  먹통이 되는 문제 방지. 콘텐츠 씬마다 자체 EventSystem을 갖는 구조는 유지(영속 EventSystem 하나로
  통합했다가 그리드 드래그가 깨지는 회귀가 있어 되돌림).
- **`Game.Core.Editor.asmdef`**: `Unity.InputSystem` 참조 추가(`InputSystemUIInputModule` 생성 코드용).
- **`FormationSlot.prefab`**: 타일 배경색을 그리드 배경(연한 민트)과 뚜렷이 대비되는 주황색으로 변경.

## 4. 디버깅 기록 (원인이 헷갈렸던 것들)

- **정비창 버튼이 Field에서 안 눌림**: Hub 씬이 언로드되며 `FormationPanel`이 바인딩하고 있던 화면
  요소가 파괴됐는데도 `Open()`이 `panelRoot == null` 체크에서 조용히 리턴해 예외/경고 없이 아무
  일도 안 일어났다. → Formation UI를 Field에도 만들고 씬별 재바인딩 구조로 해결(3절 참고).
- **그리드 드래그(빈 배경 팡판)가 안 됨**: 실제로는 코드 문제가 아니라 **Unity 에디터의 스크립트
  재컴파일이 멈춰 있어서** 여러 라운드의 수정이 전혀 반영되지 않은 채 테스트를 반복하고 있었다.
  진단용 임시 컴포넌트(`FormationGridDragDiagnostics`, 확인 후 삭제)로 이벤트 자체는 정상 도달하는
  걸 확인했고, 에디터 재시작 후 컴파일이 정상화되며 해결됐다. **교훈: 코드 수정 후 테스트 전에
  `Library/ScriptAssemblies`의 .dll 타임스탬프가 최신 소스보다 최신인지 확인하는 습관이 필요.**
  이 세션에서 최소 3번 같은 패턴(컴파일 안 됨 → 원인 오판)이 반복됐다.
- **그리드가 안 보임(대비 문제)**: 실제로는 드래그가 정상 동작하고 있었는데, 타일 배경색과 그리드
  배경색이 너무 비슷해 스크롤이 되는지 육안으로 구분이 안 됐다. 타일 색을 뚜렷한 대비색으로 교체.
- **초기 스크롤이 중앙이 아니라 타일 왼쪽 절반만 보임**: `CenterContentOnTiles()`의 X축 계산식에서
  부호를 한 번 더 뒤집는 실수가 있었다(Y축은 처음부터 맞았음).

## 5. 적용에 필요한 에디터 작업 (순서)

1. `Bootstrap.unity` → `Tools > Game > Build Manager Hierarchy` → Ctrl+S
2. `Hub.unity` → `Tools > Game > Build Formation UI` → Ctrl+S
3. `Field.unity` → `Tools > Game > Build Field UI` → Ctrl+S

세 인스톨러 모두 get-or-create라 재실행해도 안전하다. `FieldUIController.backgroundSprite`는
Bootstrap 씬의 `UIManager` GameObject에서 수동으로 연결해야 한다(HubUIController와 동일 패턴).
