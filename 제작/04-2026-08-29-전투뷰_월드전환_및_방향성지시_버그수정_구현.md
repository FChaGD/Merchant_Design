## 0. 이 세션의 출발점

전투 뷰가 UGUI(Screen Space Overlay, `CoordinateToPixelScale=40` 픽셀 배율)로 렌더링되던 중, 시뮬레이션 좌표(1유닛=1m)를 그대로 월드 좌표로 그리는 디버그 기즈모(`BattleDebugGizmoView`)가 두 좌표계 스케일 차이 때문에 화면 구석에 조그맣게 그려지는 문제를 발견 → 근본 원인이 "전투 렌더링이 UI 좌표계"라는 점 자체라고 판단해 **전투 뷰 전체를 월드 오브젝트(SpriteRenderer+Camera)로 전환**했다. 이후 그 김에 방향성 지시(포위/방진) 로직을 실전투로 재점검하며 발견된 버그들도 같은 세션에서 함께 고쳤다.

## 1. 전투 뷰 UGUI → 월드 오브젝트 전환

설계는 [[13-2026-08-29-전투뷰_월드오브젝트_전환_아키텍처]] 참고. 핵심 결정: 새 카메라를 만들지 않고 Field 씬의 기존 Main Camera를 재사용(이미 Orthographic + AudioListener 보유), 레이어는 사용자가 Project Settings에서 직접 추가한 `Battle`(User Layer 6), 정렬은 Y좌표 기반(`sortingOrder = -Y×100`).

### 1.1 신규 파일

```

  OrthographicCameraZoomController.cs
    - ScrollRectZoomController(UGUI)와 같은 규칙(커서 고정 줌/드래그팬/경계 클램프)을 Orthographic
      카메라 좌표계로 재유도. UGUI의 "scale↑=확대"와 반대(orthographicSize↓=확대)라 공식을 그대로
      옮기지 못하고 다시 유도했다 - min/maxOrthographicSize, 드래그팬(신규, ScrollRect가 없어 새로
      구현), 커서 고정 줌(eventData.pressEventCamera가 Screen Space Overlay라 항상 null이라 카메라를

  BattleFieldWorldCameraView.cs - Main Camera에 부착, 실제 카메라 조작(줌 컨트롤러 위임)
```

### 1.2 재작성/삭제

- **삭제**: `BattleFieldCameraView.cs`(구버전, ScrollRect 기반)
- **재작성**: `BattleCharacterUnitView.cs`/`BattleProtectedUnitView.cs` — `RectTransform`+`Image` → `Transform`+`SpriteRenderer`. 피격/사망/도주/러지/투사체 연출 로직은 좌표 프로퍼티만 교체해 그대로 이식. 크기는 기존 체감(24px/28px = 0.6/0.7 월드유닛, `CoordinateToPixelScale=40` 기준)을 유지.
- **`BattleFieldGeometry.cs`**: `CoordinateToPixelScale` 제거, `BattleLayerName`(`"Battle"`, Editor/런타임 공유 상수) 추가.
- **`BattleViewPresenter.cs`/`FieldUIController.cs`**: 컨테이너 타입 `RectTransform`→`Transform`, 카메라 타입 `BattleFieldCameraView`→`BattleFieldWorldCameraView`, `BattleWorldRoot`/`BattleBackgroundGridView` 조회 추가.
- **`FieldCameraController.cs`**: 생성자에 `battleWorldRoot`(GameObject) 인자 추가 — 전투 유닛 스프라이트가 이제 Canvas 밖 별도 하이어라키에 있어, 기존 `battleViewRoot.SetActive`만으로는 자동으로 안 꺼짐(구현 중 발견, §1.3-1). `battleViewRoot`와 정확히 같은 시점에 `battleWorldRoot`도 SetActive해 해결.
- **`Editor/FieldUIInstaller.cs`**: `BuildBattleView`를 배경/라벨/입력 캡처만 남기도록 단순화(ScrollRect/Viewport/Content 제거), `BuildBattleWorldRoot()`/`ConfigureBattleCamera()`(Main Camera cullingMask=Battle 레이어) 신설, 프리팹 생성 로직을 SpriteRenderer 기반으로 재작성(기존 프리팹은 `SpriteRenderer` 보유 여부로 옛 버전 판정 후 자동 재생성).

### 1.3 구현 중 발견해 함께 고친 버그

1. **전투 유닛이 배경에 가려 안 보임**: `BattleView`의 UI 배경 Image가 불투명한 채 전체 화면을 덮고 있었는데, Screen Space Overlay 캔버스는 항상 모든 카메라 렌더링 "위"에 그려지므로 월드 카메라가 그리는 스프라이트를 통째로 가렸다. 배경 Image를 투명(alpha=0.001, `EditorUIBuilder.CreateViewportAndContent`의 Viewport와 같은 "투명하지만 raycastTarget 유지" 패턴)으로 바꾸고, 어두운 배경색은 Main Camera의 `clearFlags=SolidColor`/`backgroundColor`로 옮겼다(스프라이트 "뒤"에 그려지므로 안 가림).
2. **그리드 배경 타일이 유닛을 가림**: `SpriteRenderer.sortingOrder`는 public API가 `int`지만 실제로는 `short`(-32768~32767) 범위만 유효 — 타일에 `-100000`을 넣었더니 16비트로 잘리며 부호가 뒤집혀(+31072대) 타일이 유닛보다 앞에 그려졌다. 유효 범위 안의 `-30000`으로 교체.

### 1.4 그리드 배경 타일 (사용자 요청 - 카메라 단색 배경을 실제 오브젝트로 교체)

`BattleBackgroundGridView`가 2m×2m 타일(`SpriteRenderer`, 사용자 확정값)을 재사용 풀로 관리하며, **적 스폰 링을 전부 감싸는 정사각형**에 배치한다. 스폰 링 반지름(`FieldRadius`보다 항상 `FieldBoundaryGap`(2m) 더 바깥)이 기존엔 `BattleFieldLayout`의 `private` 헬퍼였는데, `IBattleFieldGeometry.ComputeSpawnRadius`로 공개 승격하고 `BattleSimulationLoop.SpawnRadius`(신규 프로퍼티, `FieldRadius`와 같은 자리)까지 꿰었다. 개별 타일은 평범한 `SpriteRenderer`라 나중에 아무 코드나 `renderer.sprite = X`로 개별 교체 가능(확장 용이성, 사용자 요구사항). 타일 정렬은 고정 `sortingOrder=-30000`(유닛보다 항상 아래).

## 2. 디버그 기즈모 정리

**기능별 분리**: 포위망 원/방진선+슬롯/보호대상 연결선/이동목적지 선을 그리던 기즈모 뷰를 `BattleSurroundGizmoView`/`BattleFrontlineGizmoView`/`BattleMoveTargetGizmoView` 3개로 완전히 독립 분리(각자 스스로 `IBattleSimulationEvents` 구독, 코드 공유 없음) — 하나만 빼고 싶을 때 그 파일만 지우면 되게 함.

**설치 위치 분리**: 처음엔 `ManagerHierarchyInstaller`(Bootstrap 전체 빌드)에 형제 컴포넌트로 얹었으나, "이미 `Tools/Game/Debug/`에 관련 빌드(`DebugBootstrapReentryGuardInstaller`)가 있는데 왜 따로 뒀냐"는 지적에 따라 `Editor/Debug/BattleGizmoInstaller.cs`(신규, `Tools/Game/Debug/Install|Remove Battle Gizmos` 메뉴)로 옮겼다 — "게임 빌드"와 "디버그 도구 켜고 끄기"는 다른 관심사라는 기존 확립된 패턴과 일관성을 맞춤. **교훈**: 새 디버그 컴포넌트는 게임 빌드 인스톨러가 아니라 전용 Install/Remove 인스톨러로 만들 것(메모리 `feedback_debug_tool_installer_placement` 참고).

`BattleFrontlineGizmoView`는 §3.2에서 추가된 `FrontlineFormationLine.AnchorCandidates`를 이용해 "이 라인이 누구를 보호하는지" 초록 선으로 표시하는 기능도 갖고 있다.

## 3. 방향성 지시 실전투 재점검 — 발견 버그 수정

### 3.1 포위(Surround) — 같은 사거리인데 링이 여러 개로 쪼개짐

**증상**: 같은 사거리 궁수를 여러 명 배치했는데 시스템 포위망이 여러 개로 보임.

**원인**: `RangedSurroundCoordinator.FindMatchingRing`이 "내 타겟이 기존 링의 `RecognizedUnion`(그 링 소속 유닛들만의 인식 목록)에 이미 있는지"로 매칭했다. 같은 군집·같은 사거리인 궁수 A/B가 서로 다른 개체를 타겟팅하면, B의 타겟이 A의 인식 목록에 없을 수 있어(B는 아직 그 링 소속이 아니므로) 매칭이 실패하고 별도 링이 생겼다.

**수정**: 매칭 기준을 "링 자기 멤버의 좁은 인식 목록"에서 "이번 틱 전역 클러스터링 결과"로 교체 — 후보의 타겟이 속한 전역 군집을 먼저 찾고, 그 군집의 아무 적이나 기존 링의 `RecognizedUnion`과 겹치면 매칭. 신생 링은 생성 시점에 `RecognizedUnion`을 군집 스냅샷으로 미리 채워둬(다음 틱엔 실제 멤버 기준으로 좁혀짐) 같은 틱 안에서도 후속 후보가 올바르게 매칭되게 했다.

### 3.2 방진(Frontline) — 교전 시작되면 라인이 영구 고정

**증상**: 최초 방진선이 확정된 이후, 전투가 진행돼도 방진선이 이동하지 않고 최초 발생 지점에 고정됨.

**원인**: `ReconcileExistingLines`의 정지/전진/당겨오기 3분기 중 "정지"(그 외 전부)는 `linePoint`/`lineDir`를 아예 갱신 안 했다(원 설계 그대로). "전진"은 `!hasEngagedMember`(교전 가능 상태 없음)를 요구하는데, 근접 교전+스티키 타겟팅 특성상 한 번 붙으면 `hasEngagedMember`가 전투 내내 거의 계속 true라 이 조건이 사실상 안 풀렸다. "당겨오기"(`OffensiveJudgmentPursuitPolicy.ShouldDisengage`)도 `isOutsideRadius`가 먼저 false면 즉시 false를 반환하는데, 방진선은 보통 활동 반경 안에서 형성되므로 이 탈출구도 정상 상황에선 거의 안 열렸다. 결과: 교전 시작 즉시 "정지"에 갇혀 전투 내내 안 풀림.

**재설계(사용자 제안)**: "당기기/전진"과 "방진의 각도 조절"을 분리한다.
- **각도(`lineDir`)·위치(`linePoint`)**: 상태 무관, 매 틱 `anchorCenter`(보호대상 중심, 실시간)+`axisDir`(실시간)로 재조립. `anchorCenter`는 마차/시설뿐 아니라 원거리딜러/서포터 아군도 포함하므로(§12.3), 이들이 포위/산개로 전투 중 움직이면 라인도 자동으로 따라간다(단, 적 군집이 움직이는 경우엔 방향만 즉시 따라돌고 "거리"는 여전히 상태 게이트됨 — 비대칭).
- **`DistanceFromAnchor`(신규 스칼라, `FrontlineFormationLine`에 저장)**: 당기기/전진/정지는 이제 "그 축 위에서 앵커로부터 얼마나 나가 있는가" 이 값 하나만 조절 — 순수하게 "보호대상↔적 군집 중심 거리 비율" 문제로 좁혀졌다.

`FrontlineFormationLine.AnchorCandidates`(신규, 디버깅용 - §2 기즈모가 사용)도 함께 추가 — 이 라인의 앵커 계산에 실제로 기여한 보호대상 후보 목록을 코디네이터가 매 틱 채워둔다.

## 4. 적용에 필요한 에디터 작업 (순서, 전부 완료 확인됨)

1. Project Settings > Tags and Layers에서 `Battle` 레이어 추가(User Layer 6) — 사용자 완료.
2. `Field.unity` → `Tools > Game > Build Field Scene` → Ctrl+S (BattleView 재구성, BattleWorldRoot/배경 그리드 생성, Main Camera 설정, 프리팹 SpriteRenderer로 재생성).
3. `Bootstrap.unity` → `Tools > Game > Build Bootstrap Scene` → Ctrl+S (옛 `BattleDebugGizmoView` 잔재 정리).
4. `Bootstrap.unity`에서 `Tools > Game > Debug > Install Battle Gizmos` → Ctrl+S (기즈모 3종 부착 - Build Bootstrap Scene과 별개로 반드시 필요).
5. 방진/포위 관련 변경은 로직/필드 변경만이라 씬 재빌드 불필요, 컴파일만 되면 반영.

## 5. 남은 이슈 / 확인 필요 사항

- **포위 링 재타겟 시 소속 불일치 가능성**: 궁수가 활동 반경 밖에서 5초 이상 명중 실패해 `Disengage`가 발동하면, 반경 내 다른 적으로 즉시 재타겟할 수 있는데 이때 포위 링에서 자동으로 빠지지 않는다(링은 `CurrentTarget==null`일 때만 멤버 제거) — 새 타겟이 원래 링의 군집과 무관해도 그 유닛은 옛 링에 "합류됨" 상태로 남을 수 있다. 실전투 미확인, 문제로 드러나면 후속 세션에서 다룰 것.
- **포위 궤도 원 겹침 / 인원 상한 없음**: §13.3′ 설계 시점부터 알려진 한계, 아직 해결 대상 아님.
- **방진 §12.10 갱신의 실전투 재검증**: 사용자가 "결과물을 확인했고 만족스럽다"고 확인함(2026-08-29) — 이 문서 작성 시점 기준 재검증 완료로 간주.
