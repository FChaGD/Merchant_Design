## 1. 배경

시장 지구의 무역품 구매 버튼은 있지만 시설 화면이 없다. 이번 문서는 이 화면의 구성과 구매 흐름을 정한다.

## 2. 범위

- 포함: 무역품 구매 화면의 배치, 좌측 상단 물류품 고정 패널, 우측 상점 패널(판매 목록과 상품 정보), 구매 흐름, 진입과 퇴장.
- 제외: 교역품 판매(되팔기), 평판에 따른 가격 증감, 재고와 시세 변동, 실제 품목과 가격 밸런싱, 특산물 구매·전당포 등 다른 시설.

## 3. 확정 사항 (사용자 스펙, 2026-09-27)

### 3.1 화면 가시성
- 무역품 구매 화면이 열려 있는 동안 **재화 패널을 제외한 모든 UI를 숨긴다.**

### 3.2 배치
| 위치 | 요소 |
|---|---|
| 좌측 | 상단 물류품 패널 |
| 우측 | 상점 패널 |
| 우상단 | 재화 패널(기존 위치를 유지하며 계속 표시) |

### 3.3 좌측 상단 물류품 패널
- 지금은 팝업으로 띄우는 상단 물류품 UI를 **고정형 패널**로 배치한다.

### 3.4 우측 상점 패널
- 판매품을 **리스트 형태**로 보여준다.
- 상품 정보를 보여주는 패널을 함께 둔다.

### 3.5 상품 데이터 (2026-09-27 추가)
- 가격, 이름, 설명 같은 상품 정보는 데이터 테이블(수치)과 스트링 테이블(문자열)에 속성(열)을 만들어 관리한다.
- 테이블 구조는 [49번](49-2026-09-27-아이템_공용_테이블_기획.md)에서 확정: 판매가는 공용 데이터 테이블, 이름·설명은 공용 스트링 테이블, 일반/특산 구분은 교역품 데이터 테이블.
- 33번 §3.5가 "거래 시스템 기획에서 다룬다"며 미뤄 둔 가격 필드를 이 문서와 49번에서 해소한다.

### 3.6 배치 공간이 없을 때 (2026-09-27 추가)
- 상단 물류품 그리드에 상품을 놓을 공간이 없으면 **구매할 수 없다.** 임시 보관 영역은 구매한 상품을 받아 두는 공간으로 쓰지 않는다(§4.1의 C안 제외).

### 3.7 판매 목록 (2026-09-27 추가)
- **모든 마을에서 테이블에 등록된 판매 대상 아이템을 판다.** 무역품 구매의 판매 대상은 교역품 가운데 일반 품목(49번 §3.3)이다.
- 판매가는 공용 데이터 테이블의 판매가다. 마을별 판매 품목·판매가 차별화는 아직 구현하지 않는다(49번 §3.2).

## 4. 채택된 추천안 (2026-09-27 사용자 채택)

### 4.1 구매 흐름 — A안 채택

| 안 | 흐름 | 장점 | 단점 |
|---|---|---|---|
| **A (채택)** | 리스트에서 상품 선택 → 구매 버튼 → 교역품 그리드의 빈 자리에 자동 배치. 자리가 없으면 구매 불가와 안내 문구 | 조작이 단순하고 실수가 없음. 배치 규칙은 자동 정렬(39번 §3.6)의 "좌상단부터, 안 들어가면 회전" 규칙을 재사용 | 구매 순간에는 끼워 맞추는 재미가 없음(구매 후 드래그로 재배치는 가능) |
| B | 리스트 항목을 그리드의 원하는 칸으로 끌어다 놓으면 구매 | 테트리스식 배치의 재미가 구매 순간부터 이어짐 | 패널 경계를 넘는 드래그와 구매 확정이 섞여 구조가 복잡해짐. 잘못 놓았을 때의 처리 규칙이 추가로 필요 |
| C | 구매 → 임시 보관 영역에 넣음 → 플레이어가 직접 배치 | 배치를 플레이어가 결정 | 나갈 때 자리가 부족하면 퇴장이 막혀(39번 §3.5), 사실상 "샀는데 못 나가는" 상황이 생김 |

세부 규칙:
| 항목 | 확정 | 근거 |
|---|---|---|
| 1회 구매 수량 | 1개 | 스택이 없는 그리드 구조(31번)라 수량 선택의 의미가 약함 |
| 재화 차감 대상 | 기본 소지 재화만 | 골드 상자를 헐어 쓰는 규칙은 정해진 적이 없음. 골드 상자 사용은 후속 과제로 남김 |
| 재화 부족 / 배치 공간 없음(§3.6) | 구매 버튼 비활성 + 사유 문구. 선택한 상품이 바뀌거나 재화·그리드가 바뀔 때마다 다시 판정 | "상행 시작" 비활성 사유 미표시가 UI/UX 과제로 남은 선례를 반복하지 않음 |
| 구매 확인 창 | 없음 | 되팔기가 없어 취소 수단이 없다는 위험은 있으나, 1개 단위 구매라 피해가 작음 |

### 4.2 판매 목록과 가격
| 항목 | 확정 | 근거 |
|---|---|---|
| 판매 품목 | §3.7 | 사용자 확정 |
| 가격 데이터 | §3.5. Placeholder 4종은 1칸당 100, 설명은 "아이템 설명 텍스트"(49번 §5) | 사용자 확정 |
| 재고 | 무제한 | 재고 시스템은 정의된 적이 없음 |
| 리스트 한 줄 표시 | 색 사각형(그리드와 같은 품목별 색) + 이름 + 크기(가로×세로) + 가격 | 아이콘이 테이블에 없음. 그리드 표시와 색을 맞추면 구매 후 식별이 쉬움 |
| 정렬 | 테이블 행 순서 | 정렬 기준은 정해진 적이 없음 |

### 4.3 상품 정보 패널
| 항목 | 확정 |
|---|---|
| 위치 | 우측 상점 패널 안, 리스트 아래 |
| 표시 시점 | 리스트에서 항목을 선택했을 때. 선택하지 않았으면 비워 둠 |
| 표시 내용 | 이름, 차지하는 칸 모양 미리보기, 가격, 설명 |
| 설명 | 공용 스트링 테이블의 설명을 표시 |
| 구매 버튼 위치 | 상품 정보 패널 안(선택한 상품과 구매 대상을 한곳에서 확인) |

### 4.4 좌측 고정 패널 — 팝업과 다른 점
| 기능 | 확정 | 근거 |
|---|---|---|
| 드래그 이동·교환·Q 회전·임시 보관·자동 정렬·클릭 시 이름 표시 | 팝업과 동일하게 유지 | 구매 뒤 바로 정리할 수 있어야 함 |
| 창 드래그 | 제거 | 고정형 패널 |
| 닫기 버튼 | 제거. 화면 전체의 "나가기"로 대체 | 패널만 따로 닫을 이유가 없음 |
| 저장소 | 팝업과 같은 교역품 저장소를 그대로 표시 | 같은 소지품이므로 |

### 4.5 진입과 퇴장
| 항목 | 확정 | 근거 |
|---|---|---|
| 진입 | 시장 지구 depth에서 무역품 구매 버튼 | 기존 카테고리 depth 구조 |
| 진입 시 열려 있던 인벤토리 팝업 | 모두 닫음. 인벤토리 버튼도 숨겨지므로 화면 안에서는 다시 열 수 없음 | 교역품이 팝업과 고정 패널에 동시에 나타나는 중복을 막음 |
| 진입 시 팝업의 임시 보관 아이템 | 고정 패널의 임시 보관 영역으로 그대로 이어짐 | 진입이 막히는 상황을 만들지 않음. 가능 여부는 설계 단계에서 확인 |
| 퇴장 | 화면 안의 "나가기" 버튼 → 시장 지구 depth로 복귀 | 기존 카테고리 depth 복귀 구조 |
| 퇴장 시 임시 보관 아이템 | 39번 §3.5와 같은 규칙: 빈 자리에 자동 배치하고, 전부 넣지 못하면 퇴장을 막고 안내 문구 표시 | 기존 규칙과 통일 |

## 5. 설계 단계로 넘길 기술 과제

- "재화 패널을 뺀 모든 UI 숨김"을 무엇으로 구현할지. 기존 모달 팝업 축(설계 38번 — `DepthLayer`와 `PersistentLayer`를 숨기고 `PopupExemptLayer`의 재화 패널만 유지)과 동작이 같으므로 재사용 여부를 검토. 관리 축 정리는 보류 방침(`ui.md` §1-9)이라 하드코딩으로 구현하되, 리팩토링될 것을 염두에 둔다.
- 상단 물류품 팝업의 그리드·임시 보관·정렬 UI를 팝업과 고정 패널이 공유하는 구조. 두 곳이 같은 저장소를 표시할 때 임시 보관 상태를 어디에 둘지(설계 40번에서 임시 보관 상태를 둔 위치 확인 필요).
- 구매 처리: 재화 차감과 그리드 배치를 하나의 원자적 연산으로 묶기. 한쪽만 성공하는 경우를 막아야 함.
- 테이블 재구성과 임포터 변경은 49번 §8.
- 판매 목록 조회 계약은 마을 Id + 시설 Id를 받되, 지금 구현은 마을 Id를 무시하고 전 마을 동일 목록(일반 교역품 전부, 공용 판매가)을 돌려준다. 마을별 차별화 구현 시 이 구현만 교체한다.

## 6. 남은 미정 사항 (후속)

- 교역품 판매(되팔기)를 어느 시설에서 할지(전당포는 전리품 매각 전용 — 24번).
- 골드 상자로 결제하는 규칙.
- 마을별 판매 품목·판매가 차별화.
- 평판에 따른 가격 증감, 시세 변동.
- 실제 품목과 가격 밸런싱.
