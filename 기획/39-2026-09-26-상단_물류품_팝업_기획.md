## 1. 배경

Hub 우상단 "상단 물류품" 버튼은 존재하지만 팝업 화면이 없어 눌러도 동작하지 않는다. 기획 31번은 팝업의 호출 방식까지만 정했고, 그리드 내 조작 규칙(회전, 드래그 등)은 미정으로 남겼다. 이번 문서는 교역품/전리품 팝업 하나의 화면 구성과 조작 규칙을 정한다.

## 2. 범위

- 교역품/전리품 팝업의 표시 요소, 아이템 드래그 이동·교환·회전, 임시 보관 영역, 자동 정렬, 아이템 정보 표시, 팝업 창 드래그.
- 검증용 Placeholder 초기 아이템.
- 범위 밖: 장비/전투 소모품/개인 물품 팝업(같은 구조를 후속 적용할 수 있으나 이번엔 제작하지 않음), 팝업 간 아이템 이동(카테고리가 다르므로 대상 아님), 버리기, 아이템 획득·매각 트리거, 스택·조합(RE4의 탄약 스택/허브 조합 — 아이템 데이터 미정), 팝업 내부 탭, 시설 연계 진입점, 아이템 설명 문구(테이블에 없음), New Input System 키 바인딩(상시 호출 키).

## 3. 확정 사항 (사용자 스펙, 2026-09-26)

### 3.1 조작 방식
누른 채 끌어서 놓는 드래그. RE4의 클릭-클릭(집기/놓기) 방식은 채택하지 않았다.

### 3.2 드롭 위치별 처리

| 드롭 위치 | 처리 |
|---|---|
| 그리드 빈 칸(점유 범위 전체가 그리드 안이고 겹침 없음) | 그 위치로 이동 |
| 그리드의 다른 아이템과 겹침 | 교환 시도(§3.3). 교환 불가면 원위치 복귀 |
| 그리드 범위를 넘음 | 원위치 복귀 |
| 임시 보관 영역 | 임시 보관 영역으로 이동(§3.5) |
| 그 밖의 팝업 바깥 | 원위치 복귀(버리기 없음) |

### 3.3 교환
- 겹친 아이템과 자리를 바꾼다.
- 두 아이템의 크기가 다르면, 교환 후 두 아이템이 모두 그리드 안에 겹침 없이 들어가는 경우에만 교환한다. 들어가지 않으면 원위치 복귀.

### 3.4 회전
- 드래그 중 **Q 키**를 누르면 드래그 중인 아이템이 **시계방향으로 90°** 회전한다.
- 회전해도 처음 잡은 칸이 포인터 아래를 벗어나지 않는다(잡은 칸이 회전 축). (2026-09-26 추가)
- 회전 상태는 드롭 후에도 유지된다.

### 3.4-1 드래그 기준점 (2026-09-26 추가)
- 아이템을 끄는 동안 **처음 잡은 칸의 중심**이 포인터 위치에 오도록 따라온다. 놓일 위치도 이 기준으로 정해진다.

### 3.5 임시 보관 영역 (RE4 채택)
- 그리드 옆에 아이템을 잠시 꺼내 두는 영역. 정리 중 자리를 비우는 용도다.
- 임시 보관 영역의 아이템도 드래그해 그리드로 되돌릴 수 있다.
- **팝업을 닫을 때 임시 보관 영역에 아이템이 남아 있으면 그리드 빈자리에 자동 배치한다. 전부 넣지 못하면 닫지 않고 안내 문구를 표시한다.** 임시 보관 영역이 추가 수납 공간이 되지 않고(마차 용량 규칙, 31번 §3.3), 버리기 없음 원칙도 지켜진다.

### 3.6 자동 정렬 (RE4 채택)
- 버튼 한 번으로 그리드를 재배치한다.
- 기준: 점유 칸이 큰 아이템부터 좌상단부터 채운다. 들어가지 않으면 회전해서 시도한다.
- 임시 보관 영역의 아이템도 정렬 대상에 포함한다.
- 정렬 결과 모든 아이템이 들어가지 않으면 정렬을 취소하고 원래 상태를 유지한다.

### 3.7 아이템 정보 표시 (RE4 채택)
- 아이템을 **클릭했을 때만** 선택된 아이템의 이름을 팝업 하단에 표시한다.
- 설명 문구는 테이블에 없어 이름만 표시한다. 이름이 없으면 "값 없음".

### 3.8 팝업 창 드래그 이동
| 항목 | 확정 |
|---|---|
| 잡는 영역 | 제목 줄만(그리드 안 아이템 드래그와 입력 영역을 분리) |
| 화면 경계 | 창 전체가 화면 안에 머물도록 이동 범위 제한 |
| 재오픈 위치 | 게임 실행 중에는 마지막으로 옮긴 위치 유지. 게임 재시작 시 기본 위치(저장 시스템 미구현) |

### 3.9 검증용 아이템 (제작 완료)
- 실제 아이템 테이블(`Assets/Table/Item/TradeGoods.xlsx`)에 `placeholder-1x1`/`2x1`/`1x2`/`2x2` 4행 추가(표시명 "Placeholder WxH"). 실제 아이템 획득 시스템이 생기면 이 행들과 초기 배치 목록을 함께 제거한다.
- `PlaceholderTradeGoodsInventoryRepository`가 시작 시 테이블에서 이 Id를 조회해 초기 배치: 1×1 (0,0)·(0,1), 2×1 (1,0), 1×2 (3,0), 2×2 (4,0). 테이블에 행이 없으면 건너뛴다.
- 골드 상자는 초기 배치하지 않는다 — 배치 시 재화 지갑에서 500이 차감되는 연동이 있어 재화 HUD 수치가 바뀐다.

## 4. 사용자 확인 필요 (추천안)

### 4.1 교환 규칙 세부
| 항목 | 추천안 | 근거 |
|---|---|---|
| 밀려난 아이템이 갈 자리 | 드래그한 아이템의 **원래 자리**로 이동(원래 자리가 임시 보관 영역이면 임시 보관 영역으로). 회전 상태는 유지 | 가장 단순하고 예측 가능. RE4의 교환 방식은 자료로 확인하지 못함(미확인) |
| 두 개 이상의 아이템과 겹칠 때 | 교환하지 않고 원위치 복귀 | 3개 이상 아이템 재배치는 결과가 불명확 |
| 원위치 복귀 시 회전 | 드래그 전 회전 상태로 되돌림 | "복귀 = 드래그 전 상태 그대로" |

### 4.2 드래그 중 미리보기
- 추천: 드래그 중 놓일 칸을 **이동 가능 / 교환 가능 / 불가** 3색으로 표시한다(색상은 설계 재량). 교환·원위치 규칙이 있어 결과를 드롭 전에 보여줘야 오조작이 줄어든다.

### 4.3 임시 보관 영역 형태
| 항목 | 추천안 | 근거 |
|---|---|---|
| 형태 | 칸 구분 없는 목록형 — 아이템을 크기와 무관하게 세로로 나열 | 닫을 때 반드시 비워야 하므로(§3.5) 용량 제한이 필요 없고, 그리드형이면 임시 영역에서도 끼워 맞추기가 필요해짐 |
| 위치 | 그리드 오른쪽 | — |
| 개수 제한 | 없음(넘치면 스크롤) | 같은 이유 |

### 4.4 화면 구성
| 항목 | 추천안 |
|---|---|
| 표시 요소 | 제목 줄("상단 물류품", 창 드래그 영역) + 닫기 버튼 + 그리드 + 임시 보관 영역 + 자동 정렬 버튼 + 하단 정보 줄(선택한 아이템 이름 / 닫기 차단 안내) |
| 아이템 표시 | 아이콘이 테이블에 없으므로(Icon 비어 있음) 단색 사각형 + 이름 |
| 기본 위치 | 화면 좌측(처음 열 때 / 게임 재시작 후). 이후 위치는 §3.8을 따름 |
| 용량 표시 | 제외(마차 스탯 기획 전이라 의미가 확정되지 않음) |
| 선택 해제 | 빈 칸 또는 다른 아이템 클릭 시 해제·전환. 드래그를 시작하면 드래그한 아이템이 선택됨 |

## 5. 설계 단계로 넘길 기술 과제

- 회전 상태를 아이템 배치 데이터에 추가(현재 배치 인스턴스에 회전 정보 없음).
- 이동·교환을 원자적으로 처리하는 저장소 조작 추가(현재 배치/제거만 있음). 특히 골드 상자는 제거 시 재화 환급·배치 시 차감이 걸려 있어, 이동이나 임시 보관 영역으로 빼는 동작을 "제거 후 배치"로 구현하면 지갑 연동이 오작동한다.
- 임시 보관 영역의 상태를 어디에 둘지(저장소의 일부 vs 팝업 UI 상태) — 팝업을 닫을 때 반드시 비워지므로 UI 상태로 둘 수 있으나, 골드 상자가 임시 영역에 있을 때의 재화 처리와 함께 판단.
- 자동 정렬 알고리즘(큰 순서 + 회전 시도의 탐욕 배치)과 실패 시 롤백.
- Q 키 입력 처리 방식 — New Input System이 미연동 상태(설계 32번 §6). 드래그 중 한정 입력을 어떻게 받을지.
- 드래그 처리 구조 — 정비창 드래그(`FormationGridEditor`/`FormationUnitIconView`) 재사용 가능 여부. 클릭(선택)과 드래그 시작의 구분.
- 팝업 패널을 `InventoryPopupCoordinator`에 등록하는 방식과 Hub 인스톨러의 `ModelessPopups` 하위 생성. 닫기 차단(§3.5)이 코디네이터의 토글 흐름과 어떻게 맞물리는지.
- 창 드래그 컴포넌트를 나머지 인벤토리 팝업 3종에도 재사용할 수 있는 공용 구조로 둘지. 창 위치를 어디에 보관할지(씬 전환 후에도 유지되는지 확인 필요).
- 비모달 팝업이 여러 개 겹칠 때 클릭한 창을 맨 앞으로 올릴지(현재는 팝업 1종만 제작하므로 미정으로 둠).

## 6. 남은 미정 사항 (후속)

- 나머지 인벤토리 팝업 3종에 같은 구조 적용 여부.
- 버리기 규칙, 팝업 간 이동, 스택·조합, 아이템 설명 문구.
- 상시 호출 키 바인딩.
- (UI/UX 개선) "상행 시작" 버튼 비활성 사유 표시 — 임시 보관 아이템이 남아 있으면 상행 시작이 비활성화된다(설계 40번 §5.5). 사유 표시 방안은 향후 확장·개선 과제.
