# 상행 날짜 흐름 개정 기획

작성일: 2026-10-18
상태: 확정(2026-10-18 — §3 항목 전부 사용자 결정). 작업 브랜치 `system`.
개정 대상: [84 게임 시간 시스템](84-2026-10-11-게임_시간_시스템_기획.md) §4.1-3(나머지 처리)·§4.2(가산 시점)·§4.3-9(예상 일수)·§4.4-11(Field 시간 디버그 표시).
관련: [89 이벤트 인카운터 설계](../설계/89-2026-10-12-이벤트_인카운터_아키텍처.md) §5.2(도로 난이도 기간 변경 만료).

---

## 1. 배경 (2026-10-18 Play 확인·코드 확인)

| 항목 | 현재 동작(기획 84) |
|---|---|
| 날짜 진행 | 구간 도착 시 그 구간 이동 초 ÷ 30을 버림해 한꺼번에 가산. 구간 이동 중에는 날짜 고정 |
| 나머지 | 구간마다 버림(87초 구간 2개 = 2일 + 2일 = 4일, 이어서 세면 5일) |
| 궤주 | 직전 도시부터 이동 초 × 1.5 ÷ 30, 버림 |

문제(이벤트 인카운터 Play 확인 N2에서 발견): 도로 난이도 **기간 변경**(설계 89 §5.2)의 만료일 = 건 날짜 + N일. 구간 이동 중엔 날짜가 고정이라, 건 시점이 구간의 어디든 같은 만료일이 되고 도착 시 일괄 가산으로 한꺼번에 지나간다 → 긴 구간 끝에 건 기간 변경이 몇 초 만에 도착과 함께 만료된다. 이벤트 지연·난이도 변경으로 소요 시간이 바뀌면 도착 가산 일수도 바뀌어 경계(예: 87초 → 90.6초 = 2일 → 3일)를 넘기도 한다.

## 2. 범위

- 포함: 상행 중 날짜 진행 방식, 궤주 가산, 상행 끝 나머지 처리, 상행정보 패널 예상 일수, Field 시간 디버그 표시.
- 제외: Field 현재 날짜 표시(§4), 마을 행동 시간 소모(기획 84 §5 그대로), 기간 변경 길이 규칙 변경(날짜 기준 유지, §3-5).

## 3. 확정 사항 (2026-10-18 사용자 결정)

| # | 항목 | 결정 |
|---|---|---|
| 1 | 날짜 진행 | **구간 도착 가산 삭제**. 상행 이동 초를 누적해 **30초마다 1일**을 그 자리에서 진행. 누적은 구간이 바뀌어도(중간 도시 도착) 이어진다 |
| 2 | 이동 초 | 기획 84 §4.1-2 그대로 — 구간 진행 시간. 전투·이벤트·정지 중엔 흐르지 않는다. 지연·단축은 실제 이동한 시간에만 반영된다(단축하면 그만큼 날짜가 덜 흐름) |
| 3 | 상행 끝 나머지 | 상행이 끝나면(최종 도착·궤주) 30초 미만 나머지는 **버림**. 다음 상행은 0초부터 센다 |
| 4 | 궤주 | 이미 흐른 이동 초는 §3-1로 진행된 그대로 두고, **직전 도시부터 이동 초 × 0.5**를 추가분으로 더한다. 추가분은 **남은 나머지 초에 더해** 30초 단위로 진행하고 그 나머지는 §3-3대로 버림. 총량은 기획 84와 같은 1.5배 |
| 5 | 도로 난이도 기간 변경 | **날짜 기준 유지**(설계 89 §5.2 그대로 — 건 날짜 + N일이 되면 만료). 날짜가 이동 중에 흐르므로 실제 지속은 이동 (N−1)×30초 초과 ~ N×30초 |
| 6 | 도주 | 기획 84 §4.2-5와 같은 결과 — 별도 가산 없이 같은 구간을 이어 가고 날짜도 이동 초대로 계속 흐른다 |
| 7 | 상행정보 패널 예상 일수 | 합계: 구간별 버림 합 → **전체 구간 소요 초 합 ÷ 30 버림**(이월 없음 — §3-3으로 상행은 항상 0초에서 시작). 구간별 "약 n일": **현행 유지**(구간 소요 초 ÷ 30 버림). 구간 일수의 합이 합계보다 작을 수 있다(예: 87초 + 87초 → 구간 2일·2일, 합계 5일) |
| 7-1 | 0일 표기 | 구간별·합계 일수가 0이면 "약 0일" 대신 **"당일 도착"**(2026-10-18 — 짧음 최소 20초로 30초 미만 구간이 생김, 기획 75 개정) |
| 8 | Field 시간 디버그 표시 | 기획 84 §4.4-11의 "도착 시 가산 일수"는 없어진다. 새 규칙에 맞는 값(상행 누적 이동 초·다음 날까지 남은 초·궤주 시 추가 일수 등)으로 바꾼다 — 세부 항목은 설계 |

예시(기획 84 §4.2 예시 재계산): 구간 1:30 / 2:00 / 4:00, 두 번째 구간 1:40에 궤주
→ 이동 190초 = 이동 중 6일 진행, 나머지 10초 → 궤주 추가 100초 × 0.5 = 50초, 10 + 50 = 60초 = 2일 → **합계 8일**(기획 84와 같음).

예시(§3-3): 87초 구간 2개 상행 → 174초 = 5일(기획 84에선 4일), 나머지 24초 버림.

## 4. 향후 결정 (기록만)

- **Field 현재 날짜 표시**: 이동 중에도 날짜가 바뀌지만 이번엔 Hub HUD만(기획 84 §4.3-8 유지). 표시하게 되면 위치·이벤트 중 가림(설계 89 §13) 대상 여부를 함께 정한다.

## 5. 검증 방법

- 전투 없이 30초 이동마다 날짜 +1(Field 디버그 표시로 확인), Hub 복귀 후 날짜 = 상행 총 이동 초 ÷ 30 버림.
- 다구간 경로: 중간 도시 도착 때 날짜가 한꺼번에 뛰지 않고, 구간을 넘어 나머지 초가 이어진다.
- 전투·이벤트 중 날짜 정지, 재개 후 이어서 진행.
- 도주 후 같은 구간 계속, 날짜도 계속.
- 궤주: §3 예시와 같은 계산(나머지 + 추가분 × 0.5).
- 상행 끝 나머지 버림: 다음 상행 첫 1일은 출발 후 30초.
- 도로 난이도 기간 3일 변경을 구간 중간에 걸면 이동 약 60~90초 뒤 만료(도착과 무관).
- 상행정보 패널 합계 = 전투·지연 없이 도착했을 때의 실제 진행 일수.

## 6. 설계 단계로 넘길 기술 과제

- 상행 누적 이동 초의 소유 위치 — 구간 시계(구간 시작 때 경과 0으로 초기화)와 별개로 상행 단위 누적이 필요. 상행 시작·끝(최종 도착·궤주·포로)에서 초기화.
- 진행 시점: 매 프레임 이동 초 증가에서 30초 경계를 넘을 때 날짜 진행 신호 — 기존 날짜 변경 구독자(Hub HUD·도로 난이도 만료·조건 문맥)가 이동 중에도 호출되는지 확인(만료 시 현재 구간 재계산은 설계 89 §4.3에 이미 있음).
- 기존 구간 도착 가산·궤주 × 1.5 가산 제거와 궤주 추가분 연결(전투 결과 정리 흐름).
- 예상 합계 일수 계산 위치(상행 계획) 변경. 구간별 일수는 그대로.
- Field 시간 디버그 표시 항목.
