# 게임 시간 시스템 기획

작성일: 2026-10-11
상태: 확정(2026-10-11 — §4 항목 전부 사용자 결정). 작업 브랜치 `system`. 2026-10-18 §4.1-3·§4.2·§4.3-9·§4.4-11은 [92 상행 날짜 흐름 개정](92-2026-10-18-상행_날짜_흐름_개정_기획.md)으로 개정(30초마다 진행·궤주 추가분 ×0.5).
선행: [75 상행 소요시간·난이도 리뉴얼](75-2026-10-01-상행_소요시간_난이도_리뉴얼_기획.md)(구간 단위 상행, 소요시간 공식, 이동 중에만 시간 진행)·[77 마차 피격 화물 손실·잔해](77-2026-10-02-마차_피격_화물손실_잔해_기획.md) §4-20(파괴 마차당 구간 +20초)·[78 전투 결과 정리 플로우](78-2026-10-02-전투_결과_정리_플로우_기획.md)(도주·궤주·포로·사망 분기). 대체 대상: 75 §4.3-11 예상 소요 표기("약 N분 M초" → "약 n일").

---

## 1. 배경 (코드 확인)

| 항목 | 현재 동작 |
|---|---|
| 게임 내 날짜 | 없음 |
| 상행 이동 | 구간(다음 도시까지) 단위. 구간 소요시간 = 기획 75 공식(실제 초). 전투 중엔 멈추고 이동 중에만 흐름 |
| 마을 행동 | 무역품 구매·용병 고용·마차 구매·인벤토리 정리·골드 변환·정비창 등 전부 즉시 처리, 시간 소모 없음 |
| 상행정보 패널 | 구간마다 "약 N분 M초 · 짧은/중간/긴" + 합계 |
| 저장/불러오기 | 없음(런타임 메모리만) |

## 2. 범위

- 포함: 일 단위 게임 날짜, 상행 이동 시간 → 일수 환산·가산 시점, 궤주 시 가산 규칙, Hub 날짜 표시, 상행정보 패널 예상 소요의 일수 대체, 디버그 기능.
- 제외: 마을 행동의 시간 소모(이번엔 없음, §5), 시간 경과가 일으키는 결과(재입고·급여·이벤트 등, §5), Field 날짜 표시, 저장/불러오기.

## 3. 시간 단위

| 항목 | 값 |
|---|---|
| 진행 방식 | 실시간이 아닌 트리거 기반, 일 단위 |
| 1개월 | 30일 |
| 1년 | 6개월(180일) |
| 연도 | 절대 연도 없음. 경과 해 수는 내부에서만 세고 표시하지 않음 |
| 시작 날짜 | 1월 1일 |
| 해 넘김 | 6월 30일 다음 = 1월 1일(순환) |
| 표시 형식 | "n월 n일" |

## 4. 확정 사항 (2026-10-11 사용자 결정)

### 4.1 시간 소모 대상

| # | 항목 | 결정 |
|---|---|---|
| 1 | 시간을 흐르게 하는 요소 | **상행 이동만**. 마을 행동은 시간 소모 없음(현행 즉시 처리 유지). **2026-10-27 추가(사용자 결정): 숙소 휴식은 하루 경과마다 날짜 +1**(기획 94 §4.2 4-10 개정, 설계 105) — 당시 "시간 소모 없음"은 기획 범위 밖이라 제외한 것이지 금지 규칙이 아니다 |
| 2 | 환산 비율 | **이동 30초 = 1일**. "이동 초"는 기획 75의 구간 진행 시간 그대로(전투 중 정지, 기획 77 파괴 마차 지연 +20초도 구간 진행 시간에 포함됨) |
| 3 | 나머지 처리 | 가산 시점마다 30초 미만 나머지는 **버림**(이월하지 않음) |

### 4.2 가산 시점

| # | 상황 | 가산량 |
|---|---|---|
| 4 | 구간 도착(중간 도시 도착 포함, 최종 도착지 포함) | 그 구간 이동 초 ÷ 30, 버림 |
| 5 | 패배-도주(상행 속행) | **가산 없음**. 구간 이동 초는 계속 누적되어 다음 도착(또는 궤주) 때 함께 계산 |
| 6 | 패배-궤주(마을 귀환) | **직전 도시부터 궤주 시점까지의 이동 초 × 1.5** ÷ 30, 버림. 이미 지난 구간의 가산분은 그대로 둔다 |
| 7 | 패배-포로·사망 | 해당 없음(플레이 종료) |

예시(사용자 제시): 구간 1:30 / 2:00 / 4:00 경로에서 두 번째 구간 1:40에 궤주
→ 1구간 도착 90초 = 3일 + 궤주 100초 × 1.5 = 150초 = 5일 → **합계 8일**.

### 4.3 표시

| # | 항목 | 결정 |
|---|---|---|
| 8 | 현재 날짜 표시 위치 | **Hub HUD만**(Field 미표시). 화면 위치는 설계에서 겹침 점검 후 결정 |
| 9 | 상행정보 패널 예상 소요 | "약 N분 M초"를 **일수로 대체**. 구간마다 "약 n일 · 짧은/중간/긴"(구간 초 ÷ 30 버림), 합계 = 구간 일수의 합 |

- 9의 산출은 도착 시 실제 가산(§4.2-4)과 같은 방식이다. 전투·도주가 없고 마차 파괴 지연이 없으면 예상과 실제가 일치한다. 파괴 지연(+20초/대)·궤주(×1.5)는 예상에 반영되지 않는다.

### 4.4 디버그

| # | 항목 | 결정 |
|---|---|---|
| 10 | 날짜 진행 버튼 | Hub에서 +1일 / +N일 수동 진행 |
| 11 | Field 시간 표시 | 상행 중 현재 구간 누적 이동 초와 예정 가산 일수(도착 시 / 궤주 시) 표시 |

- 디버그 기능은 전용 인스톨러로 분리(기존 디버그 도구 규칙). 배치는 설계에서 겹침 점검 후 결정.

## 5. 향후 결정 (기록만)

- **마을 행동의 시간 소모**: 이번엔 없음. 후보(2026-10-11 조사) — 무역품 구매, 용병 고용, 마차 구매, 인벤토리 정리, 골드 변환, 정비창, 시설 이동/체류, 미구현 시설(숙소·대장간·잡화상점·은행). 반복 조작은 산정 기준(행동 1회/물량/화면 진입)도 정해야 함.
- **시간 경과의 결과**: 재입고(기획 80 §5)·급여·이벤트 등. 이번엔 날짜만 흐르고 아무 효과도 없음.
- **시간을 흐르게 하는 다른 요소**: 상행 외 요소 추가 가능(사용자 언급).
- **저장/불러오기**: 날짜도 저장 대상이 되어야 함.

## 6. 검증 방법

- 시작 시 Hub HUD "1월 1일".
- 짧은/중간/긴 구간 각각 전투 없이 도착 → 가산 일수 = 패널 "약 n일".
- 다구간 경로에서 중간 도시 도착마다 가산되는지(Field 디버그 표시로 확인, Hub 복귀 후 날짜 합계).
- 도주 후 도착 → 도주 시 가산 없음, 도착 시 구간 전체 초로 가산.
- 궤주 → 직전 도시부터의 초 × 1.5 버림 가산.
- 디버그 +N일로 월 넘김(1월 30일 → 2월 1일)·해 넘김(6월 30일 → 1월 1일) 확인.
- 마을 행동(구매·고용·정리 등) 후 날짜 불변.

## 7. 설계 단계로 넘길 기술 과제

- 날짜 상태의 소유 위치(Bootstrap 전역 서비스 여부, DI 계약 분리 — 조회/진행).
- 구간 이동 초 누적 위치 — 기존 상행 진행도 계산과의 관계, 도주 후 누적 유지.
- 가산 트리거 연결 지점: 구간 도착, 궤주 결과 처리.
- 상행정보 패널 일수 표기 전환(기획 75 패널 코드 재사용).
- Hub HUD 날짜 표시 위치·디버그 버튼 배치(겹침 점검).
