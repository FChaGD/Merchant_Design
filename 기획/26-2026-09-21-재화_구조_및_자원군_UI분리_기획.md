# 재화 구조 정교화 및 자원군 UI 분리 기획

## 1. 배경

23번 문서는 재화 상한을 "기본 소지량 + 소유한 모든 마차의 보관 가능량 합계"로 정의했고, 25번 문서는 이 마차 보관량이 재화와 교역품/전리품이 공유하는 하나의 자원 풀이라고 정의했다. 다만 재화가 구체적으로 어떤 형태로 그 풀 안에 들어가는지(숫자로 누적되는지, 아이템처럼 슬롯을 차지하는지)는 정의된 적이 없었다. 이번 세션은 이 지점을 해소하고, 추가로 재화 계열 자원과 행정력 계열 자원의 UI 표시 분리 원칙을 정의한다.

## 2. 범위

- 재화의 저장 구조를 "기본 소지 재화"와 "적재 재화(아이템형)" 두 층으로 세분화한다.
- 마차 능력치가 결정하는 것이 정확히 무엇인지(적재 슬롯 칸 수) 확정한다.
- 재화 계열(아이템 확보 관련)과 행정력 계열(유닛 배치 관련) 두 자원군의 UI 표시 공간 분리 원칙을 수립한다.
- 인터페이스 분리는 방향성만 기록한다 — 구체 설계는 범위 밖.
- 지략의 용도 배정은 범위 밖(미확정 유지).

## 3. 확정 사항 (사용자 스펙, 2026-09-21)

### 3.1 재화의 이원 구조

재화는 시스템적으로 두 형태로 나뉜다.

| 구분 | 정의 |
|---|---|
| 기본 소지 재화 | 플레이어가 항상 휴대하는 재화. 마차 보유 여부와 무관하게 존재한다. 23번 문서의 "기본 소지량" 상한이 여기 해당한다. |
| 적재 재화(아이템형) | 마차에 실어야 보관되는 재화. "골드 상자"류 아이템 형태로 존재하며, 교역품/전리품과 동일한 마차 적재 슬롯 풀을 공유해 슬롯을 소비한다. |

23번 문서의 공식 "재화 상한 = 기본 소지량 + 마차 보관 가능량 합계"는 이 이원 구조로 구체화된다: 총 보유 가능 재화 = 기본 소지 재화 상한 + 적재된 골드 상자류가 나타내는 재화 총량. 후자는 마차 적재 슬롯 수의 제약을 받는다.

### 3.2 마차 능력치와 슬롯

- 마차는 "적재 슬롯 칸 수"를 결정하는 능력치를 보유한다.
- 이 슬롯 칸 수가 25번 문서에서 정의한 "재화와 교역품/전리품이 공유하는 자원 풀"의 실체다 — 교역품/전리품 아이템과 적재 재화(골드 상자류) 아이템이 이 슬롯 칸 수 안에서 함께 자리를 차지한다.
- 마차 종류별 슬롯 칸 수 차등 여부와 구체 수치는 밸런싱 영역으로 범위 밖.

### 3.3 자원군 UI 표시 공간 분리

- **재화 계열**: 캐릭터/마차/시설/아이템 등 "확보"와 관련된 자원(기본 소지 재화 + 적재 재화 포함)을 하나의 UI 표시 영역으로 묶는다.
- **행정력 계열**: 유닛 배치(정비창)와 관련된 자원(행정력)을 별도의 UI 표시 영역으로 분리한다. 지략을 이 영역에 포함할지는 지략 용도 확정 후 결정한다.
- 두 영역은 화면상 서로 다른 표시 공간을 가져야 한다 — 사용 맥락(아이템 확보 vs 유닛 배치)이 다르기 때문.

### 3.4 인터페이스 분리 방향 (설계 단계 참고용, 이번 문서에서 확정하는 것은 아님)

- 재화 계열과 행정력 계열은 인터페이스 수준에서도 분리하는 방향으로 간다.
- 구체적인 인터페이스 명칭/구조/책임 분리는 설계 단계에서 확정한다.

## 4. 이 기획이 건드리지 않는 것

- 지략의 용도 배정(방향성 지시 자원 여부) — 사용자가 아직 확정하지 않음, 미정 유지.
- 기본 소지 재화 ↔ 적재 재화(골드 상자) 간 정확한 환산 비율(예: 골드 상자 1개 = 재화 몇 단위).
- 마차 종류별 적재 슬롯 칸 수 구체 수치.
- 적재 재화(골드 상자)가 25번 문서의 "교역품/전리품" 카테고리에 그대로 속하는지, 별도 하위 구분이 필요한지.
- 자원군 UI 표시 공간의 구체 화면 배치/레이아웃.

## 5. 설계 단계로 넘길 기술 과제

- 재화 계열 자원(기본 소지 재화 + 적재 재화)과 행정력 계열 자원(행정력, 그리고 지략 배정 확정 시 지략)을 별도 인터페이스로 노출할지, 각각의 책임을 어떻게 나눌지 — ISP 관점 판단 필요.
- 적재 재화(골드 상자)를 교역품/전리품과 동일한 인벤토리 저장 구현체로 다룰지, 별도 아이템 타입으로 특별 취급할지.
- 마차의 "적재 슬롯 칸 수" 능력치를 노출하는 인터페이스(마차 스탯 조회)와 재화/교역품 상한 재계산 훅의 연계.
