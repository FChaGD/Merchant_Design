## 1. 배경

기존 "본부(허브)" 명칭은 부정확하다 — Hub 씬은 상단의 본부라기보다 상행의 출발/도착 지점인 **마을**에 가깝다(사용자 정정, 2026-09-08). 이 문서를 포함해 앞으로의 기획 문서는 "마을"로 표기를 통일한다. 단, `SceneNames.Hub`/`HubUIController` 등 기존 코드·씬 명칭은 변경하지 않는다 — 이번 정정은 기획 용어에 한정된다.

01번 §7이 남겨둔 미정 사항 "본부 시설(용병 육성/자원/교역 등) 목록"을 이번 문서에서 해소한다.

## 2. 범위

- 마을(Hub) 씬 루트 UI에 노출되는 시설 카테고리와 각 카테고리 하위 시설 목록, 각 시설의 역할(용도)만 정의한다.
- 각 시설의 UI 화면 구성, 재화 가격 체계, 구매/판매 세부 수치, 인터페이스 설계(`IXxxProvider` 등)는 범위 밖 — 후속 세션(시설별 개별 기획)에서 다룬다.
- 카테고리 버튼 클릭 시 하위 시설이 어떻게 열리는지(리스트 팝업/서브 화면 전환 등) 같은 네비게이션 UI 흐름은 범위 밖 — 설계 단계 혹은 후속 기획에서 정의한다.

## 3. 확정 사항 (사용자 스펙, 2026-09-08)

### 3.1 카테고리 구조

마을 씬 루트 UI depth에 시설 카테고리 버튼 4개를 노출해, 유저가 원하는 시설을 카테고리를 거쳐 찾아가도록 한다(계층형 네비게이션). 카테고리 버튼 자체는 하위 시설로 가는 진입점 역할만 한다.

| 카테고리 | 성격 |
|---|---|
| 시장 지구 | 재화를 사용(소비/판매)하는 시설이 모여있는 구역 |
| 주점 지구 | 용병 캐릭터를 고용하고 관리하는 구역 |
| 공업 지구 | 장비·마차·전투 소모품 등 물자 관련 시설이 모여있는 구역 |
| 시청 방면 | 퀘스트, 은행, 행정적 처리를 담당하는 구역 |

### 3.2 하위 시설 목록 및 역할

**시장 지구**

| 시설 | 역할 |
|---|---|
| 무역품 구매 | 어디서나 구할 수 있는 물건, 또는 대량의 물건을 판매 |
| 특산물 구매 | 사치품, 장인 제작품, 토산품을 판매 |
| 전당포 | 상행에서 얻은 전리품을 매각(재화로 환전) |

**주점 지구**

| 시설 | 역할 |
|---|---|
| 숙소 | 시간을 소모하는 대신 추가로 자원을 회복 |
| 용병단 접촉 | 캐릭터(용병) 고용 |
| 주점 | 정보 획득 |

**공업 지구**

| 시설 | 역할 |
|---|---|
| 대장간 | 장비 구매 |
| 마구간 | 마차·시설의 매매 및 보관 |
| 잡화 상점 | 전투에 도움이 되는 소모품 구매 |

**시청 방면**

| 시설 | 역할 |
|---|---|
| 시청 | 퀘스트 전용 창구. 은행 기능(사용자 확정, 2026-09-08 — 별도 시설로 분리하지 않고 시청에 포함)도 이곳에서 처리 |
| 상인조합 | 상단(플레이어 조직) 운영 관련 처리 |

## 4. 이 기획이 건드리지 않는 것

- 각 시설의 상세 UI 화면 구성, 진입 흐름(카테고리 → 하위 시설 네비게이션 depth).
- 각 시설에서 실제로 거래되는 품목 목록, 가격 책정 방식(22/23번 재화·평판 정의와 연계된 가격 공식은 여전히 후속 과제).
- 숙소의 회복 수치와 회복 대상 자원(지략/행정력인지, 22번 문서 범위 밖의 별도 자원인지).
- 주점 "정보 획득"의 정보 종류(상행 경로 정보/인카운터 정보 등)와 획득 방식·비용.
- 시청의 퀘스트 시스템 자체 설계, 상인조합 "상단 운영"의 구체적 조작 범위, 은행 기능의 구체 규칙(23번 문서 "향후 확장 지점"과 동일하게 미정).
- 시설 잠금/해금 조건(초반부터 전부 개방인지, 진행에 따라 순차 해금되는지).

## 5. 설계 단계로 넘길 기술 과제

- 마을 씬 루트 UI에 카테고리 버튼 4개를 추가하는 인스톨러 작업 — 기존 `HubUIController`/`HubUIElementIds`/`SceneUIRoot` 패턴을 그대로 재사용한다(`CLAUDE.md` UI 패널 패턴 참고).
- 카테고리 → 하위 시설 진입 흐름을 `PanelNavigationStack`으로 처리할지, 별도 구조가 필요한지 결정.
- 시설 11개를 각각 개별 `IUIPanel`로 만들지, 카테고리 패널이 하위 시설 목록을 보여주는 2단 구조로 만들지 결정 필요.
- 각 시설의 실제 거래 데이터 시스템(품목/가격 테이블)이 아직 없으므로, `CLAUDE.md` Placeholder 패턴에 따라 `PlaceholderXxxProvider` 계열이 다수 필요할 가능성이 있다.

## 6. 남은 미정 사항 (후속 기획 세션 대상)

- 카테고리/시설별 상세 기획(거래 품목, 가격, 퀘스트 시스템, 정보 획득 방식 등) — 시설 단위로 개별 기획 세션 필요. 단, 거래 품목이 상단 쪽에서 어떻게 보관되는지(인벤토리 카테고리 구성, 마차 보관량 연동 범위)는 [[25-2026-09-09-인벤토리_시스템_기획]]에서 확정 (2026-09-09). 개별 품목 목록·가격·슬롯 수치는 여전히 미정.
- 시설 잠금/해금 조건.
- 숙소의 회복 메커니즘과 22번 문서(지략/행정력)의 관계.
