## 1. 배경

`system.md` "ui 브랜치에서 이관된 과제" 중 숙소 휴식의 남은 두 항목을 다룬다.

| 과제 | 현재 |
|---|---|
| 휴식 회복 | 보류(설계 105). 회복 대상이 없음 — 지략·행정력은 기획 22만 있고 코드 없음, 캐릭터 HP는 상행 시작·종료에 전원 회복 |
| 휴식 중 이벤트 | 미기획. 휴식 진행 화면에 이벤트 알림 자리(빈 영역)만 있음(기획 94 4-7) |

이미 구현된 것: 1일 경과마다 날짜 +1, 개인 골드 10 차감(설계 105).

## 2. 범위

- 포함: 휴식 1일당 지략·행정력 회복 **규칙**, 휴식 중 이벤트(발생·표시·효과·예외), 1일 처리 순서와 비용 결제 규칙 개정.
- 제외:
  - 지략·행정력 자원 자체의 구현(저장·표시·소모처 배정·허브 복귀 회복) — 별도 기획. 이 문서의 회복 규칙과 "지략·행정력 증감" 효과는 **자원 구현 때 함께 제작**한다.
  - 휴식 중 전투, 휴식 중 일반 대화(이동 중 말풍선 대화).
  - 예시 이벤트 콘텐츠 — 제작 때 테스트 데이터로 넣는다(퀘스트 시스템과 같은 방식).

## 3. 확정 사항 (사용자 결정, 2026-10-28)

### 3.1 휴식 회복

| 항목 | 결정 |
|---|---|
| 회복 대상 | 지략·행정력 |
| 회복 단위 | **1일마다 고정량** — 그날 휴식이 성립할 때마다(§3.3) |
| 회복량 | 지략·행정력 **각 3**(인스펙터 값). 상한(기획 22: 20) 초과분은 자른다 |
| 중단 시 | 성립한 일수만큼만 회복 |
| 제작 시점 | 지략·행정력 자원 구현 때 함께 |

### 3.2 휴식 중 이벤트 — 발생

| 항목 | 결정 |
|---|---|
| 시스템 | 기존 상행 이벤트 시스템(Yarn 대화 + 효과 명령, 기획 86·설계 89) 재사용 |
| 후보 목록 | **휴식 전용 목록**. 상행 이벤트 후보와 섞지 않는다 |
| 발생 방식 | **확정 → 랜덤** 순서로 매일 점검. 확정 이벤트가 휴식을 강제 종료하지 않았으면 이어서 랜덤 이벤트를 점검 |
| 랜덤 확률 | **1일 35%**(테스트 추정치, 인스펙터 값) |
| 랜덤 후보 추첨 | 상행과 같은 **가중치 추첨**(정수, 기본 100). 조건 충족 후보 중에서(2026-10-29) |
| 확정 동시 충족 | 하루 **1개만** 발생. 상행 확정 이벤트와 같은 **중요도**(Scenario > Core > Side > Normal)가 높은 것부터, 같으면 데이터 순서. 나머지는 다음 날 다시 점검(2026-10-29, 설계 109에서 정수 칸 대신 기존 중요도 칸 재사용으로 확정) |
| 발생 횟수 | 한 휴식에서 **제한 없음**(매일 독립 점검, 하루 최대 확정 1 + 랜덤 1) |
| 같은 이벤트 반복 | 상행 규칙과 같은 구조: 1회성 = 게임 전체 1회, 반복 = **휴식 1회당** 1번까지 |
| 장소 조건 | **현재 마을**, **지역** |
| 시간 조건 | 상행과 같은 날짜·월 범위만. 휴식 일차(n일째) 조건은 두지 않음(2026-10-29) |
| 이력 | 상행 이벤트·대화와 **공유**(같은 플래그·발생 기록) |

### 3.3 1일 처리 순서

휴식 진행 화면의 하루 단위(게이지 1칸)마다 아래 순서로 처리한다(2026-10-29 개정 — 결제를 하루 끝으로 이동).

1. **시간 대기** — 게이지 1칸 진행. **"휴식 중단" 버튼은 이 구간에만 표시**한다. 중단하면 그날은 시작하지 않은 것으로 보고(결제·점검·성립 없음) 전날까지로 종료.
2. **확정 이벤트 점검** — 조건 충족 시 발생(§3.2 동시 충족 규칙).
3. **랜덤 이벤트 점검** — 2에서 휴식이 강제 종료되지 않았을 때만.
4. **하루 처리** — ① 당일 결제: 1일 비용 10골드, 지출 순서는 기획 82 규칙(개인 골드 → 골드 상자 인출). 합계로도 부족하면 **결제하지 않고 그날 미성립으로 휴식 종료**, 결과에 사유 표시. ② 결제 성공 시 휴식 성립: 날짜 +1, 지략·행정력 회복(§3.1).
5. 다음 날 1단계로.

중단 버튼이 대기 구간에만 있으므로, 이벤트 진행 중·이벤트 직후·하루 처리 중에는 사용자 중단이 일어나지 않는다.

그날이 미성립으로 끝나는 경우(강제 종료, 결제 부족):

| 항목 | 처리 |
|---|---|
| 그날 휴식 | **미성립** — 결제·날짜 +1·회복 없음. 전날까지만 휴식한 것으로 처리 |
| 그날 발생한 이벤트 효과 | 유지(이미 적용된 골드·화물·내구도·합류 등은 되돌리지 않음) |
| 이후 점검 | 하지 않음(확정에서 강제 종료되면 랜덤 점검·하루 처리 생략) |

### 3.4 표시

| 항목 | 결정 |
|---|---|
| 발생 시 | 게이지 정지 → 발생 알림 없이 **곧바로 전체화면 이벤트 화면**으로 전환(2026-10-29) |
| 진행 | 상황 대사·선택·결과 대사는 기존 전체화면 이벤트 화면·전용 선택 UI(기획 86 §3.4) 그대로 |
| 종료 후 | 진행 화면으로 복귀. 강제 종료가 아니면 같은 날 남은 단계(랜덤 점검 → 하루 처리)부터 이어감 |
| 이벤트 영역 | **이번 휴식의 이벤트 기록 목록** — 발생한 이벤트마다 한 줄(n일차 + 이벤트 제목 + 결과 요약) 누적. 결과 상태(기획 94 4-13)에서도 유지 |
| 예상값 표시 | 예상 날짜·누적 비용·예상 남은 골드를 **하루마다 실제 개인 골드·골드 상자 잔액 기준으로 다시 계산**. "예상 남은 개인 골드"와 "골드 상자"를 나눠 표시(2026-10-29) |

### 3.5 휴식 중 이벤트 — 효과

| 효과 | 허용 | 비고 |
|---|---|---|
| 골드 증감 | O | 기획 82·86 규칙 그대로 |
| 무역품 증감 | O | 공간 부족은 상행 규칙 그대로(기획 86 §3.6 — 상단 물류품 팝업 정리 → 포기 확인) |
| 마차·시설 내구도 증감 | O | 기획 90 규칙 그대로. 마지막 마차 예외는 §3.6 |
| 상단원 합류·이탈 | O | 기획 86 §3.5 그대로 |
| 지략·행정력 증감 | O | 자원 구현 때 함께 제작(§2) |
| **휴식 강제 종료** | O(신규) | 휴식 이벤트 전용. 처리는 §3.3 |
| 플래그 기록 | O | 이력 공유(§3.2) |
| 도로 난이도·이동 지연/단축·전투 | X | 상행 전용 |

### 3.6 마을에서의 예외 처리

| 경우 | 처리 |
|---|---|
| 마차 파괴(남은 마차 있음) | 상행 규칙 그대로(기획 86 §3.9 — 파괴 마차 화물을 임시 보관으로 → 남은 마차로 정리 → 못 넣으면 포기 확인) |
| **마지막 마차 파괴** | 남은 화물은 **임시 보관 영역으로 이동**(포기하지 않음), **휴식은 그대로 진행**. 상행의 궤주 처리는 적용하지 않음 |
| 이벤트 골드 손실로 비용 부족 | §3.3 4단계에서 처리(상자 인출 → 그래도 부족하면 그날 미성립으로 종료) |

### 3.7 기존 규칙 개정

| 문서 | 기존 | 개정 |
|---|---|---|
| 기획 94 4-11 | 총 비용 > **개인 골드**면 "휴식" 버튼 비활성 | 총 비용 > **개인 골드 + 골드 상자**면 비활성 |
| 기획 94 4-11 | 진행 중 부족은 발생하지 않음 | 이벤트 골드 손실로 발생 가능 — §3.3 4단계 |
| 설계 105 | 1일 경과마다 개인 골드 10 차감 | 하루 끝(이벤트 점검 후)에 결제(개인 → 상자), 결제 성공 시 날짜 +1. 미성립일은 결제 없음 |
| 기획 94 4-7 | 진행 화면의 예상 날짜·누적 비용·예상 남은 개인 골드는 시작 시점 고정 계산 | 하루마다 실제 잔액 기준 재계산, 골드 상자 별도 표시 — §3.4. "이벤트 알림 자리"는 이벤트 기록 목록 |
| 기획 94 4-12 | "휴식 중단" 즉시 멈춤 | 버튼은 시간 대기 구간에만 표시 — §3.3 1단계 |

## 5. 이 기획이 건드리지 않는 것

- 지략·행정력의 구현·소모처·허브 복귀 회복(기획 22 후속).
- 휴식 중 전투·일반 대화.
- 상행 이벤트의 발생·효과 규칙(변경 없음).

## 6. 설계 단계로 넘길 과제

- 이벤트 진행자(설계 89)는 Field 상행 생명주기(이동 정지·판정 시계)에 묶여 있다. Hub 숙소 휴식에서 쓰려면 "이벤트 진행 맥락(상행/휴식)"을 분리하고, 휴식 진행 화면이 정지·재개를 제어하는 구조가 필요.
- 이벤트 데이터에 발생 장소(상행/휴식) 구분, 장소 조건에 "현재 마을" 추가.
- 전체화면 이벤트 화면·선택 UI가 Hub 씬에서도 뜨도록 배치·레이어 정리(현재 Field UI 기준).
- 상단 물류품 팝업 정리 흐름(무역품 수령·마차 파괴)을 Hub에서 실행.
- 마지막 마차 파괴 시 화물 → 임시 보관 이동: 마차 0대 상태에서 임시 보관 유지와 상단 물류품 팝업 닫기 규칙(임시 보관이 남으면 닫기 차단, 기획 39 §3.5)의 충돌 처리.
- 확정 이벤트 우선순위 값의 데이터 위치·기본값(상행 확정 이벤트와 공용 칸으로 둘지 포함).
- 휴식 진행 화면의 단계별 상태(대기/이벤트/하루 처리)와 "휴식 중단" 버튼 표시 제어.

| 2 | 확정 이벤트 동시 충족 | 하루 1개, 우선순위 값 순, 나머지는 다음 날 — §3.2 |
