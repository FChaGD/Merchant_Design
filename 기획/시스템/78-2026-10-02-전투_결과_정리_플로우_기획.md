## 1. 배경 (코드 확인)

| 항목 | 지금 |
|---|---|
| 전투 뒤 흐름 | 결과 팝업 1장 → [확인] → 이동 뷰 전환 → 배치·이동 활동 재개 + 상행 재개 |
| 결과별 분기 | 승리 / 패배-도주: 상행 속행. 패배-궤주: 마을 귀환. 패배-포로·사망: 플레이 종료 |
| 상단 물류품 팝업 | 마을(Hub)에만 조립. Field에는 없음 |
| 마을 상행 출발 조건 | 도착지 지정 + 임시보관 비어 있음일 때만 출발 버튼 활성. **마차 수·대열 연결 검사 없음**(기획 77 §4-30 확인 결과) |
| 상행 중 정비창 | 배치·이동에 소요시간(기획 20). 마차는 새로 배치·제거 불가, **현재 대열 안 이동만**. 모든 이동은 **최종 상태에서 마차가 모두 이어져야** 허용(기획 59 §3.3) |

기획 77로 전투 뒤 처리할 일이 늘었다: 화물 요약, 회수 물품 적재, 파괴 마차 제거에 따른 대열 재배치·끊어진 영역 수정.

## 2. 범위

- 포함: 전투 종료 ~ 이동 뷰 복귀 사이의 단계·순서·화면·조작, 결과별 적용 범위.
- 제외: 화물 손실 판정 자체(기획 77), 전투 중 연출.

## 4. 세부 결정 (2026-10-05 확정 — §4-29만 추천안에서 수정)

### 4.1 단계 순서

```
전투 종료
 └ ① 결과 팝업 (항상)
    └ ② 회수 물품 적재 (승리 + 회수 물품 있을 때)
       └ ③ 대열 정리 (대열이 끊어졌을 때)
          └ ④ 결과별 마무리 (이동 뷰 복귀·상행 재개 / 마을 귀환 / 플레이 종료)
```

| # | 항목 | 추천 | 근거 / 대안 |
|---|---|---|---|
| 1 | 순서 | 결과 팝업 → 적재 → 대열 정리 → 마무리 | 적재 대상 마차는 대열과 무관하게 이미 정해져 있다(파괴 안 된 마차). 대안: 대열 정리 먼저 |
| 2 | 단계 건너뜀 | 해당 없는 단계는 띄우지 않는다(회수 물품 0개면 ②, 대열이 이어져 있으면 ③ 생략) | — |
| 3 | 뒤로 가기 | 없음 — 한 방향으로만 진행 | ②에서 버린 물품을 ③에서 되돌리는 경우가 없도록 |
| 4 | 시간 | 정리 단계 동안 **상행 시간·배치 활동 모두 멈춤**(지금 전투 뒤 팝업과 같음). ④에서 재개 | — |
| 5 | 자동 재배치 시점(기획 77 §4-26) | 전투 종료 직후 ① 전에 계산·반영. ③은 그 결과 위에서 진행 | 결과 팝업에 재배치 결과를 보여 주기 위해 |

## 5. 설계 단계로 넘길 기술 과제

- 지금 결과 처리(`FieldEncounterFlowCoordinator`)가 팝업 1장 + 결과별 분기로 되어 있다 — 단계 목록(①~④)을 순서대로 진행하는 구조로 분리(결과별 적용표 §4.2).
- 상단 물류품 팝업을 Field에 조립·배선(현재 Hub 전용). 이 단계 전용 차이: 파괴 마차 제외, 닫기 없음·[완료], 남은 물품 경고 후 버림, 기존 적재물 조작 허용.
- 정비창 화면의 "정리 모드": 즉시 완료, 마차 판 어디든 이동, 덩어리 수 기준 이동 허용, 덩어리 표시, [완료] 활성 조건, 안내 문구.
- 연결 판정이 "이어짐 여부"만 반환하는지 확인 — 덩어리 수·덩어리별 칸을 얻을 수 있어야 한다.
- 패배 원인(마차 전멸 / 유닛 전멸) 구분이 결과까지 전달되는지 확인 — 지금 결과는 승리/패배만 담는다.
- 유닛 전멸 패배의 도주·궤주 화물 판정(§4.7) — 전투 화물 처리와 같은 "환급 없는 제거" 경로 사용.
- 마을 상행 준비 UI 출발 조건에 대열 연결 검사 + 안내 문구(§4.8). 마을 정비창의 끊어진 상태 완화 기준(§4-34).
