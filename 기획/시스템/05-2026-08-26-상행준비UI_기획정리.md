## A. 디버깅/테스트 전용 기능 (정식 게임 콘텐츠 아님)

실제 지역/경로 시스템이 설계되면 대체·제거 대상. `Placeholder`/`Debug` 성격 명명 컨벤션 적용 대상.

### A-1. 도시 배치 ([[03-2026-08-23-상행준비UI_디버그도시배치]])
- 팔레트의 도시 아이콘을 지도로 드래그 → 배치(무제한, 여러 개 가능). 팔레트 원본은 소모되지 않음.
- 지도 밖 드롭 = 배치 취소.
- 지도 콘텐츠 좌표계에 부착(팬/줌 연동).
- 삭제: 배치된 도시를 지도 밖으로 드래그 = 삭제. "전체 삭제" 버튼도 제공.
- 표시 정보: 이름 "디버그 도시 N", 설명 "값 없음", 플레이스홀더 아이콘.
- 지속성: 세션(앱 실행) 동안 유지, 재시작 시 소멸. 상시 노출(별도 온/오프 없음).

### A-2. 경로 연결 ([[04-2026-08-23-상행준비UI_디버그경로연결]])
- on/off 토글 UI 추가(상시 노출).
- **off**: A-1과 동일(드래그=이동, 팔레트 드래그=배치).
- **on**: 지도 위 기존 도시 아이콘을 드래그하면 이동 대신 커서를 따라가는 선이 그려짐 → 다른 도시 위에서 드롭하면 연결선 생성. 빈 곳 드롭 = 취소. 팔레트 배치는 on 상태에서도 계속 가능.
- 두 도시 사이 연결선은 테스트 단계에서 단일 개만 허용(중복 시도 무시). 정식 게임에서는 다중 경로 가능 예정이라는 점만 참고로 남김.
- 삭제: 연결선 더블클릭 = 삭제, "전체 삭제" 버튼(도시 전체삭제와 별개), 도시 삭제 시 연결된 선도 함께 삭제.
- 지속성: A-1과 동일.

## B. 정식 게임 로직 ([[02-2026-08-23-상행준비UI]])

디버그 기능이 사라지고 실제 지역/경로 시스템이 생겨도 유지되는 로직. 단, 현재는 경로 데이터 소스로 A-2의 디버그 연결선을 그대로 빌려 쓴다.

### B-1. 지도 클릭 기반 출발/도착 지정 (3.1절)
상태 기반 규칙 (출발=X, 도착=Y라 표기):
| 현재 상태 | 클릭 대상 | 결과 |
|---|---|---|
| 미배정 | 도시 Z | Z가 출발지로 지정 |
| 출발지만(X) | X 자신 | 출발지 지정 취소 → 미배정 |
| 출발지만(X) | X 아닌 Z | X↔Z 경로 있으면 Z가 도착지로 지정, 없으면 무시 |
| 출발/도착 모두(X,Y) | 아무 도시 Z | 기존 배정 전부 취소 후 Z가 새 출발지로 지정(→ "출발지만" 상태). 게이팅 없음 |

- 도시 삭제 시 그 역할만 미배정, 반대편은 유지.

### B-2. 정보 패널을 통한 재지정 (3.1.1절)
- 출발/도착 정보 패널 클릭 = 해당 역할 "변경 모드" on (상호 배타, 켜진 채 같은 패널 재클릭 = off).
- 모드 on 중 도시 클릭(대상 역할 R, 반대 역할 R'):
  | 클릭한 도시 | 결과 |
  |---|---|
  | R 자신 | R 지정 취소, 모드 off |
  | R'(반대편) | 역할 교환(swap), 게이팅 없이 무조건 성공, 모드 off |
  | R'이 있고 제3의 도시 Z | Z-R' 경로 있으면 성공(모드 off), 없으면 거부(모드 유지, 재시도 가능) |
  | R'이 미배정 | Z가 먼저 R로 지정(게이팅 없음) → "R' 지정 대기"로 전환 → 다음 클릭에서 R' 게이팅 검사(실패해도 R은 유지) |

### B-3. 경로 데이터 출처
- 당분간 A-2(디버그 경로 연결)의 연결선을 "두 도시 사이 경로 존재 여부"의 데이터 소스로 그대로 사용. 실제 경로 시스템 도입 시 데이터 소스만 교체.

## C. 예외처리 / 누락 정보 점검 결과

문서 3개를 교차 검토하면서 발견한, 규칙이 없던 경우의 수. C-1~C-4는 게임 규칙에 직접 영향을 줘 사용자 확인을 거쳐 확정했다. C-5~C-8은 제안한 기본값 그대로 확정한다.

### 확정된 규칙 (사용자 확인 완료)
- **C-1. 경로 삭제 시 기존 배정의 운명 → 배정 그대로 유지**: 디버그 연결선을 삭제해도 이미 그 경로로 성립된 출발/도착 배정은 소급 해제되지 않는다. 경로 존재 확인은 배정 "시점"에만 하는 1회성 검사다. → [[02-2026-08-23-상행준비UI]] 3.1절 반영 완료.
- **C-2. road-mode 중 도시 클릭 → 출발/도착 지정 그대로 동작**: road-mode는 오직 "드래그" 제스처의 의미만 바꾼다. 클릭은 영향받지 않고 B-1/B-2가 평소처럼 동작한다. → [[04-2026-08-23-상행준비UI_디버그경로연결]] 4.2절 반영 완료.
- **C-3. road-mode 중 도시 삭제 → 완전히 불가능**: 개별 드래그 삭제, 전체 삭제 버튼 모두 road-mode가 꺼져 있을 때만 쓸 수 있다. 삭제하려면 먼저 toggle을 off해야 한다. → [[04-2026-08-23-상행준비UI_디버그경로연결]] 4.2절, [[03-2026-08-23-상행준비UI_디버그도시배치]] 4.3절 반영 완료.
- **C-4. "상행 시작" 게이팅 → 출발/도착 모두 배정돼야 활성화**: 편성 인원 무관 규칙과는 별개로, 출발지·도착지 중 하나라도 미배정이면 `상행 시작` 버튼이 비활성화된다. → [[02-2026-08-23-상행준비UI]] 5절 반영 완료.

### 기본값 제안 (별다른 지시 없으면 이대로 확정)
- **C-5. 패널 모드 활성 중 지도 클릭 처리**: 출발/도착 변경 모드(B-2)가 켜져 있는 동안에는 도시 클릭이 B-1의 기본 상태 머신이 아니라 B-2 규칙으로만 처리된다(B-1은 일시 정지). 문서에 암묵적으로만 있던 내용이라 명시 확정 제안.
- **C-6. "R' 지정 대기" 중 취소 시도**: B-2 케이스 4에서 "R' 지정 대기" 상태일 때 패널을 다시 클릭하면, 대기만 취소되고 이미 성공한 R 지정은 유지된다(부분 성공 유지, 전체 롤백 아님) — 실패 시 유지 규칙과 일관성 유지.
- **C-7. Open() 시 유지되는 것과 초기화되는 것 구분**: 배치된 도시 목록, 출발/도착 배정 상태, 지도 위 아이콘의 시각적 강조색(3.1 "시각적 구분")은 패널을 닫았다 열어도 유지된다. `TripLocationInfoView`의 텍스트 표시만 `Open()` 시 초기화되어 재클릭해야 다시 채워진다(기존 03번 문서 5절 서술을 좀 더 명확히 구분).
- **C-8. 화면 전환/패널 Close 시 모드 초기화**: 배치 UI로 전환하거나 상행 준비 UI를 닫으면, 켜져 있던 B-2 변경 모드와 A-2 road-mode 토글은 자동으로 off된다(다시 열었을 때 항상 꺼진 상태로 시작).

### 설계 단계 참고용 세부사항 (지금 결정 불필요)
- 경로는 무방향(양방향)으로 취급한다는 점을 설계 문서에 명시할 것(B-2 swap 규칙이 이를 전제함).
- 도시 아이콘이 겹쳐 배치될 때 클릭 판정 우선순위(예: 나중에 배치된 것이 위).
- 드래그가 시작 도시로 되돌아오는 자기 자신 연결(self-loop) 방지.
- Unity 이벤트 시스템에서 "클릭"과 "드래그 시작"을 구분하는 임계값(OnPointerClick vs OnBeginDrag).

```
 └─ 경로 존재 확인 시 04를 데이터 소스로 참조 (임시)

03 (디버그: 도시 배치/삭제)
 └─ 02가 배치된 도시 목록을 대상으로 클릭 판정

04 (디버그: 경로 연결, on/off 토글)
 ├─ 03이 배치한 도시 사이에서만 동작
 └─ 02의 경로 게이팅 규칙에 데이터 제공
```

## E. 지도 카메라(드래그팬+휠줌) 조작 규칙

2026-08-26부터 [Docs/기획/시스템/09-2026-08-26-전투뷰_카메라_기획.md](09-2026-08-26-전투뷰_카메라_기획.md)가 정의한 규칙(최소 줌=지도 전체가 보이는 지점, 최대 줌=최소 줌×2.5, 마우스 커서 위치 기준 줌, 드래그 관성 없음, 하드 클램핑)을 그대로 따른다 — 원래는 화면 중앙 기준 줌·관성 있는 드래그였으나 전투 뷰 카메라와 조작 스타일을 통일하기 위해 변경했다(구현: `TripMapView.cs`, 상세: [Docs/설계/카메라_아키텍처.md](../../설계/2026-09-01-카메라_아키텍처.md)). 지도는 콘텐츠 크기가 고정이라(A-1 "지도 콘텐츠 좌표계에 부착") 전투 뷰와 달리 전투마다 재계산하지 않는다.
