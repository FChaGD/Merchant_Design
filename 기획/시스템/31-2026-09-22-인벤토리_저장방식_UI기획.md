## 1. 배경

25번 문서가 인벤토리 카테고리 4종(교역품/전리품, 장비, 전투 소모품, 상단주 개인 물품)과 마차 연동 범위를 확정했으나, 각 인벤토리의 저장 방식/구체 용량, 마차 보관량 내 재화-교역품 배분 규칙, UI 진입 경로는 §4/§6에서 범위 밖으로 남겨뒀다. 이번 문서는 이 세 가지를 확정한다.

## 2. 범위

- 인벤토리의 저장 방식(그리드 슬롯 구조)과 카테고리별 그리드 크기를 정의한다.
- 마차 보관량 안에서 재화와 교역품/전리품이 용량을 나눠 쓰는 환산 비율을 정의한다.
- 각 인벤토리 팝업의 호출 방식과 시설 연계 진입 경로를 정의한다.
- 개별 아이템 데이터(품목 목록, 스탯, 아이콘), 마차 자체의 스탯(칸수·모양, 마차 종류별 차등)은 범위 밖.
- 그리드 내 아이템 회전/자동 정렬 등 조작 규칙, New Input System 구체 키 바인딩, 팝업 UI의 정확한 좌표/레이아웃은 범위 밖 — 설계·제작 단계 재량.

## 3. 확정 사항 (사용자 스펙, 2026-09-22)

### 3.1 저장 방식 — 그리드형 슬롯

4개 인벤토리 모두 가로×세로 좌표 그리드 구조를 쓴다. 아이템은 크기(예: 1×1, 2×1)만큼 그리드 칸을 점유한다 — 슬롯 하나에 아이템 하나가 아니라, 아이템의 가로×세로 크기에 따라 여러 칸을 차지할 수 있는 공간 배치형 인벤토리다.

### 3.2 카테고리별 그리드 크기

| 카테고리 | 그리드 크기 | 비고 |
|---|---|---|
| 교역품/전리품 | 고정 크기 없음 | §3.3 참고 — 보유 마차 스탯에 따라 총 크기가 결정됨 |
| 장비 | 6×4 (24칸) | 잠정치, 밸런싱 재검토 대상 |
| 전투 소모품 | 5×4 (20칸) | 잠정치, 밸런싱 재검토 대상 |
| 상단주 개인 물품 | 3×3 (9칸) | 잠정치, 밸런싱 재검토 대상 |

장비/전투 소모품/개인 물품 3종의 수치는 이번 세션에서 기준점 없이 정한 잠정값이다(23번 문서의 재화 초기 수치와 같은 성격) — 가격/밸런싱 체계를 정의하는 후속 세션에서 재검토한다.

### 3.3 교역품/전리품 그리드 — 마차 스탯 연동

23번 문서의 "재화 상한 = 기본 소지량 + 소유한 모든 마차의 보관 가능량 합계" 구조와 동일한 원칙을 적용한다.

- 마차 1대당 정해진 그리드 칸수(모양 포함)를 제공하고, **보유한 모든 마차**(현재 상행에 배치된 마차뿐 아니라 허브 창고에 대기 중인 마차 포함)의 칸수를 합산해 교역품/전리품 그리드의 총 크기를 결정한다.
- 각 마차가 정확히 몇 칸을, 어떤 모양(가로×세로)으로 제공하는지, 마차 종류별 차등이 있는지는 마차 자체의 스탯 기획(23번 문서와 동일하게 범위 밖) — 후속 세션 대상.

### 3.4 마차 보관량 내 재화-교역품 환산 — 골드 상자 아이템화

25번 문서의 "재화와 교역품/전리품이 공유하는 마차 자원 풀"은 26번 문서(2026-09-21)가 이미 이원 구조로 구체화해뒀다 — 재화는 **기본 소지 재화**(마차 무관, `IPlayerCurrencyWallet` 관리 대상)와 **적재 재화**(골드 상자류 아이템형, 마차 적재 슬롯 소비) 두 층으로 나뉜다(26번 §3.1~3.2). 이번 절은 26번 §4가 미정으로 남긴 환산 비율만 확정한다.

- **기본 소지 재화**(상한 1,000, 23번 §3.1)는 마차 보유 여부와 무관하게 존재한다 — 교역품/전리품 그리드와 전혀 관계없다.
- **적재 재화는 그리드에 수치로 반영되지 않고, "골드 상자" 아이템으로 존재한다.** 골드 상자는 교역품/전리품 그리드 안에서 다른 아이템과 동일하게 1×1칸을 점유하는 아이템 한 종류다.
- **환산 비율(잠정치, 2026-09-22): 골드 상자 1개(1×1칸) = 재화 500단위.** 재화를 골드 상자로 변환하면(전당포/마구간 등에서 이뤄질 것으로 예상 — 구체 변환 트리거·UI는 범위 밖) 500단위마다 골드 상자 아이템 1개가 생성되어 교역품/전리품 그리드에 놓인다.
- 이 수치는 가격 체계가 아직 정의되지 않은 상태에서 정한 잠정값이다 — **가격 체계/밸런싱을 정의하는 후속 세션에서 반드시 재검토해야 한다.**

### 3.5 UI 진입 경로 — 상시 호출 + 시설 연계 병행

두 진입 경로를 함께 지원한다(양자택일이 아님).

**상시 호출**
- New Input System 키 바인딩과 화면 버튼으로, 시설 방문 여부와 무관하게 언제든 인벤토리 팝업을 호출할 수 있다.
- 팝업은 카테고리 4종(교역품/전리품, 장비, 전투 소모품, 개인 물품)마다 **별개의 팝업**으로 뜬다 — 하나의 팝업 안에서 탭으로 전환하는 구조가 아니다.
- 여러 카테고리의 팝업을 **동시에 중첩해서 열어둘 수 있다**(하나를 열면 다른 게 닫히는 방식이 아님).

**시설 연계 진입점** (24번 문서 시설 목록 기준)

| 시설 | 지구 | 여는 인벤토리 |
|---|---|---|
| 무역품 구매 | 시장 지구 | 교역품/전리품 |
| 특산물 구매 | 시장 지구 | 교역품/전리품 |
| 전당포 | 시장 지구 | 교역품/전리품 |
| 마구간 | 공업 지구 | 교역품/전리품 (추가 진입점 — 마차 관리와 연계) |
| 대장간 | 공업 지구 | 장비 |
| 잡화 상점 | 공업 지구 | 전투 소모품 |
| 숙소 | 주점 지구 | 상단주 개인 물품 |

## 4. 이 기획이 건드리지 않는 것

- 개별 아이템 데이터(품목 목록, 장비 스탯, 소모품 효과, 개인 물품 종류, 아이콘).
- 마차 자체의 스탯(칸수·모양, 마차 종류별 차등, 획득/손실 방식) — 23번 문서와 동일하게 범위 밖.
- §3.4 환산 비율(골드 상자 1개=재화 500)의 최종 확정치 — 잠정값이며 가격 체계 정의 후 재검토 필수.
- 재화 ↔ 골드 상자 간 변환을 일으키는 구체 행위(전당포에서 자동 변환인지, 별도 조작이 필요한지)와 그 UI.
- 골드 상자의 역변환(그리드에서 재화로 되돌리는 절차) 필요 여부.
- 그리드 내 아이템 배치 조작 규칙(회전 가능 여부, 자동 정렬/스택 규칙, 드래그앤드롭 동작).
- New Input System의 구체 키 바인딩 값, 팝업 UI의 정확한 좌표/크기/스타일.
- 아이템 획득/소모 트리거의 구체 규칙(전당포 매각, 대장간 구매 등 각 행위의 그리드 반영 로직).

## 5. 설계 단계로 넘길 기술 과제

→ [32-2026-09-22-인벤토리_시스템_아키텍처.md](../../설계/32-2026-09-22-인벤토리_시스템_아키텍처.md)에서 아래 과제 전부 설계 완료(2026-09-22).


- 26번 §5가 남긴 "적재 재화(골드 상자)를 교역품/전리품과 동일한 인벤토리 저장 구현체로 다룰지, 별도 아이템 타입으로 특별 취급할지"는 §3.4로 해소 — 골드 상자는 교역품/전리품 그리드 안의 아이템 종류 하나(1×1)로 취급한다. 다만 아직 아이템 데이터 시스템이 없으므로 `PlaceholderXxxInventoryProvider` 계열에서 골드 상자를 어떻게 특수 취급할지(재화 지갑과의 연동 지점)는 설계 단계 판단.
- 그리드 좌표/점유 칸 계산을 담당할 자료구조 — 정비창(Formation) 그리드 배치 로직 기존 구현 재사용 가능 여부 확인 필요.
- 카테고리 4종을 어떤 인터페이스로 노출할지(25번 §5 기존 과제 유지) — 그리드 크기가 카테고리마다 계산 방식이 다르므로(고정치 vs 마차 스탯 합산) 인터페이스 분리 시 이 차이를 어떻게 반영할지.
- 여러 팝업 동시 중첩을 `UIManager`/`PanelNavigationStack`에서 어떻게 처리할지 — 기존 `IUIPanel` 패턴은 대체로 단일 패널 전환을 전제하므로, 동시 다중 오픈을 지원하는 별도 처리 필요.
- New Input System 액션 맵에 인벤토리 호출 액션을 추가하는 방식(기존 입력 처리 구조 조사 필요 — 미확인).
- 마구간(마차 관리 시설)에서 교역품/전리품 인벤토리를 여는 진입점을, 마구간의 마차 매매 기능과 같은 화면/패널에 둘지 별도 팝업 호출로 둘지.

## 6. 남은 미정 사항 (후속 기획 세션 대상)

- 개별 아이템 목록 및 데이터(카테고리별 개별 기획 세션 필요, 25번 문서 §6과 동일).
- 마차 스탯 기획(칸수·모양, 마차 종류별 차등) — 후속 세션 대상.
- 골드 상자 환산 비율(현재 1개=재화 500)의 최종 확정 — 가격 체계 정의 세션에서 재검토.
- 재화 ↔ 골드 상자 변환 트리거·UI, 역변환 필요 여부.
- 장비/전투 소모품/개인 물품 그리드 크기(현재 6×4/5×4/3×3)의 밸런싱 최종 확정.
- 그리드 내 아이템 조작 규칙(회전, 자동 정렬 등).
