## 1. 목적

전투 바닥이 그림 1장(BattleFloorTile)의 반복이라 무늬가 눈에 띈다(기획 118 §8). 바닥 타일을 여러 종 만들고, 비율과 펄린 노이즈로 배치 맵을 정해 자연스러운 바닥을 만든다. 배치 맵은 씬 로딩 단계에서 미리 계산해 전투 시작 시 바로 깐다.

## 2. 현행 (코드 확인, 2026-11-24)

| 항목 | 현행 |
|---|---|
| 타일 크기 | 2m × 2m(전장 1단위 = 1m = 정비창 배치 칸 1칸 간격). 그림 256px → 1m당 128px |
| 깔리는 범위 | 적 스폰 반경을 감싸는 정사각형. 스폰 반경 = 대열 반경 + 10m라 전투마다 크기가 다름 |
| 대열 최대 크기 | 정비창 50 × 50칸 → 스폰 반경 약 45m, 한 변 약 46타일 |
| 카메라 | 가장 넓게 보는 줌 = 전장 전체가 보이는 기준 크기, 이동은 전장 경계 안으로 제한 |

## 3. 에셋 (확정)

| 분류 | 개수 | 형태 | 출처 |
|---|---|---|---|
| 잔디 | 5종 | 잔디로 가득 찬 타일 | Western Cartoon 생성본 wgrass 3·1·5·8·10 |
| 잡초 | 3종 | 잔디 + 잡초 | wweed 1·3·4 |
| 꽃 | 5종 | 잔디 + 꽃 | wflower 1·3·4의 꽃잎만 빨강·파랑·노랑·빨강+노랑·파랑+흰으로 재채색(2장은 좌우 반전) |
| 마른 흙 | 3종 | 마른 흙 | B-1(cdirt_1) 형태 + A-2(wdirt_2) 채색, 한 원본에 노이즈 색 얼룩 3종 |

- 합계 30종(16 + 흙 경계 14). 0000(전부 잔디)은 덮개 없음, 1111(전부 흙)은 흙 3종으로 대신한다.
- 크기·저장 규격은 기존 BattleFloorTile과 같다(256px, 2m 타일). 저장 위치 `Resources/UI/Textures/BattleFloor/`(2026-11-25 저장 완료, 임포트 설정은 Textures 폴더 규칙 그대로 적용).

- 기존 BattleFloorTile은 재사용하지 않는다(화풍·결 크기가 새 세트와 다름).
- 원본·도구: `ArtSource/BattleFloor/2026-11-24/`(final_256/ 최종본, tools/build_final.py로 재생성).

## 4. 배치 규칙 (확정)

### 4.1 비율·구조
- 펄린 노이즈는 **분류**만 정한다. 노이즈 값을 비율 누적 구간으로 나눠 분류를 정한다(같은 분류가 군집으로 뭉침).
- 흙은 **격자 꼭짓점 단위**로 판정한다: 꼭짓점마다 노이즈 값이 흙 구간이면 흙 꼭짓점. 흙 비율 15%는 꼭짓점 기준 비율이다(경계 타일이 절반쯤 흙이라 실제 흙 면적은 비슷, 인게임 판단 후 조정).
- (2026-11-25 개정: 잡초·꽃도 꼭짓점 판정, §11.3) 잔디 계열(잔디·잡초·꽃)은 타일 단위 노이즈로 분류하고, 비율은 흙을 뺀 나머지 안에서 나눈다(잠정: 잔디 65%·잡초 23%·꽃 12%).
- 같은 분류 안의 변형(잔디 5종 등)은 타일마다 균등 랜덤으로 고른다 - 같은 그림이 덩어리로 뭉치지 않게.
- 군집 크기 = 같은 분류 덩어리 하나가 걸치는 타일 칸 수(노이즈 주파수로 정함). 맵 크기와 무관한 독립 값이다 - 맵 크기는 계산할 칸 수, 군집 크기는 덩어리 하나의 칸 수다. 잠정값: 덩어리 지름 약 6타일(12m).
- 노이즈는 2겹을 섞는다: 군집 크기의 큰 노이즈 + 경계를 들쭉날쭉하게 하는 작은 노이즈(옥타브). 작은 노이즈의 크기·섞는 세기도 조정 값으로 둔다.

### 4.2 노이즈 맵 개수
- 개수 = ⌊상행 전체 시간(초) / 30⌋ + 3.
  - 상행 전체 시간 = 출발 시 확정되는 구간 계획의 총 소요시간.
  - 예: 90초 → 3 + 3 = 6장, 100초 → 3 + 3 = 6장.

### 4.3 노이즈 맵 크기
- 항상 최대 크기로 만든다 - 대열은 정비 중 뭉쳤다가 상행 중 넓게 퍼질 수 있다.
- 최대 크기 = 상단 대열이 가질 수 있는 최대 크기(50 × 50칸)일 때 카메라가 보여줄 수 있는 최대 범위를 덮는 크기. 정확한 값은 카메라 줌·이동 제한 규칙으로 설계 단계에서 산출한다.

### 4.4 전투에서 쓰는 방법
- 전투마다 아직 쓰지 않은 맵을 하나 쓴다. 전부 썼으면 그중에서 랜덤으로 다시 쓴다.
- 이번 전투에 필요한 범위(이번 대열 크기 기준 카메라가 보여줄 수 있는 범위)를 맵에서 잘라 쓴다. 잘라낼 중심은 그 범위가 맵 안에 들어가는 위치 중에서 랜덤으로 고른다.
  - 대열이 최대 크기면 필요한 범위 = 맵 전체라 맵을 그대로 쓴다.

### 4.5 계산 시점
- Field 씬 로딩 작업(설계 67 로딩바 작업 단위)에 "전투 바닥 배치 맵 계산"을 추가한다. 노이즈·분류·변형 선택까지 로딩에서 끝내고, 전투 시작 시에는 잘라낸 범위의 타일에 그림만 바꿔 낀다.

### 4.6 레이어 (2026-11-24 확정, 레이어 미리보기 확인 2026-11-25) - **2026-11-25 §11.6·§11.7로 대체**: 칸 단위 Tilemap 대신 스플랫 셰이더, 잔디 계열도 꼭짓점 판정, 순서 잔디 → 잡초 → 꽃 → 흙
- 잔디 계열(잔디·잡초·꽃)은 흙 여부와 무관하게 모든 칸에 밑층으로 깐다. 흙·흙 경계는 그 위층 덮개다 - 흙과 맞닿은 칸에도 잡초·꽃이 나온다.
- 덮개 타일 선택: 네 꼭짓점이 모두 흙 → 흙 3종 중 랜덤 / 일부만 흙 → 꼭짓점 조합에 맞는 흙 경계 타일 / 모두 잔디 → 덮개 없음.
- 쌓는 순서는 생성 비율이 아니라 재질별 고정 순서표로 정한다: 잔디 계열 → 흙. 비율을 조정해도 그리는 순서는 바뀌지 않는다.
- 덮개(투명 경계)는 흙만 둔다. 잔디·잡초·꽃은 바탕이 같은 잔디라 칸 단위로 바꿔 깔아도 이음매가 없다.
- 새 재질(물·돌길 등)이 생기거나 잡초·꽃이 칸 모양으로 드러나면 순서표에 덮개 재질로 추가한다.
- 기각안: 생성 비율이 낮은 집합을 위로 올리는 규칙(전 집합 꼭짓점 판정·덮개 135장 또는 마스크 셰이더, 비율 변경 시 순서 뒤집힘).
- 미리보기 재생성: `ArtSource/BattleFloor/2026-11-24/tools/layout_layer.py final_256 out.png 96 22`.

## 5. 확장성 (확정 방향)

- 바닥 세트(분류 목록·분류별 그림·비율)를 하나의 데이터로 묶는다. 이후 지역(지역 시스템, 기획 68)마다 다른 바닥 세트를 연결할 수 있게 둔다.
- 이번 범위는 세트 1개(§3)만 만들고 지역 연결은 하지 않는다.

## 11. 잡초·꽃 사각형 문제 대응 (2026-11-25, 확정)

### 11.1 배경
설계 120 인게임 테스트 A4: 잡초·꽃 지대가 지나치게 바둑판처럼 사각형으로 보인다. 원인 - 잡초·꽃은 칸 단위로 그림을 통째로 바꿔 깔고 그림이 타일 끝까지 같은 밀도라 잔디 칸과 맞닿는 곳이 직선으로 끊긴다. §4.6 "잡초·꽃이 칸 모양으로 드러나면 덮개 재질로 추가한다"에 해당.

### 11.2 해결 방식 (사용자 결정, 2026-11-25)
- **2안 경계 덮개** 채택: 잡초·꽃도 흙처럼 꼭짓점 판정 + 경계 덮개로 그린다.
- 비교한 안(로컬 미리보기, 크레딧 0): 1안 칸 세분화(1m)+회전·뒤집기 - 사각 윤곽이 작아질 뿐 남음 / 3안 개별 장식 흩뿌리기 - 칸 흔적 없음, 렌더링 구조 신규·장식 분리 필요. 비교 이미지는 결정 후 삭제, 생성 스크립트는 스크래치패드 임시본.

### 11.3 결정 사항 (사용자, 2026-11-25)
| 항목 | 결정 |
|---|---|
| 쌓는 순서 | 잔디 → 잡초 → 꽃 → 흙 (§4.6 고정 순서표 갱신). 잔디는 모든 칸 밑층 |
| 경계 덮개 수 | 분류당 대표 1종으로 잡초 14 + 꽃 14 = 28장. 꼭짓점 전부 해당이면 기존 꽉 찬 타일(잡초 3·꽃 5종) 랜덤 |
| 비율 기준 | 같은 수치(잡초 23%·꽃 12%)를 꼭짓점 기준으로 적용, 인게임 판단 후 인스펙터로 조정 |
| 경계 모양 | 가장자리 쪽으로 서서히 옅어지는 부드러운 경계(흙의 또렷한 곡선과 다름) |
| 대표 변형 | 잡초 경계 = Weed_1, 꽃 경계 = Flower_5(파랑+흰, 흰 꽃이 섞여 어느 색 지대에 붙어도 이질감이 적음) |

### 11.5 영향
- 에셋: 잡초 경계 14 + 꽃 경계 14 = 28장 추가(로컬 합성, 크레딧 0), 합계 58장. 기존 30장은 그대로.
- 배치: 잡초·꽃 판정이 타일 단위에서 꼭짓점 단위로 바뀐다(§4.1 개정 대상). 밑층은 잔디 5종만.
- 설계 120(Tilemap 2층) 개정 필요 - 층 수·판정 단위.

### 11.6 재검토 → 스플랫 셰이더 채택 (사용자 결정, 2026-11-25)
- 경계 덮개 4층 미리보기 확대에서도 사각형이 보였다(사용자). 원인: 같은 분류 안에서도 칸마다 그림을 통째로 교체해 잎 크기·밀도·배열 차이가 칸 경계에서 직선으로 끊김(잔디 5종만 깐 확대로 확인, 밝기는 112~116으로 같음). 경계 덮개는 분류 사이 경계만 해결한다.
- 비교: A안 경계 덮개 4층(Tilemap) vs B안 스플랫 셰이더(같은 꼭짓점 판정 데이터, Python 근사 미리보기). A안은 꽃 지대 가장자리 세로 직선·잔디 바둑판 잔존, B안은 칸 흔적 없음. B안 흙은 무작위 샘플링으로 균열이 조각남 → 흙은 일반 반복으로 대응 예정.
- **B안 채택**: 칸 단위 타일 교체를 버리고 전장 바닥을 메시 1장 + 셰이더로 그린다.
  - 스플랫 맵: 로딩 때 계산한 꼭짓점 판정을 작은 텍스처로 올려 픽셀마다 재질 비중을 쌍선형 보간으로 얻는다.
  - 재질 섞기 순서는 §11.3 고정 순서(잔디 → 잡초 → 꽃 → 흙) 유지. 경계 모양: 흙 = 또렷한 곡선 + 어두운 테두리, 잡초·꽃 = 부드럽게 옅어짐(§11.3).
  - 반복 무늬: 육각(삼각 격자) 무작위 샘플링 - 꼭짓점마다 무작위 오프셋·변형, 회전 없음(잎 방향 유지).
- 비용 판단(코드 확인 + 추정, 실측 없음): 배치 계산·로딩·잘라 쓰기(§4.2~4.5) 유지, 드로우 수는 Tilemap 다수 → 1회로 감소, 픽셀당 텍스처 읽기는 1~2회 → 최대 약 13회로 증가(비중 0 재질 생략으로 감소 가능).
- 영향: 흙 경계 14장·잡초/꽃 경계 28장 불필요. 꽉 찬 그림 16장(잔디5·잡초3·꽃5·흙3)만 쓴다. 설계 120의 Tilemap 렌더링을 교체(프로젝트 첫 커스텀 셰이더, URP 17.3).
