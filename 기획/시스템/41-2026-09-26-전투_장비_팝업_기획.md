## 1. 배경

Hub 우상단 인벤토리 버튼 4개 중 "상단 물류품"만 팝업이 있고 "전투 장비"는 눌러도 동작하지 않는다. 장비 인벤토리의 데이터 계층(6×4 그리드 저장소)은 이미 있다. 이번 문서는 장비 보관 팝업의 화면과 조작을 정한다.

## 2. 범위

- 장비 인벤토리 보관 팝업(보관함 화면)의 표시 요소와 조작.
- 검증용 Placeholder 장비.
- 범위 밖: **용병 장착 화면**(착용 부위·장착 규칙·스탯 체계가 미정 — 선행 기획 필요), 대장간 연계 진입점, 장비 스탯/설명, 버리기, 팝업 간 이동, 상시 호출 키.

## 3. 확정 사항 (사용자 스펙, 2026-09-26)

### 3.1 범위
보관 팝업만. 상단 물류품 팝업과 같은 구조로 만든다.

### 3.2 가져오는 기능 (상단 물류품 팝업 기준)

| 기능 | 채택 | 장비 팝업에서의 차이 |
|---|---|---|
| 드래그 이동 | O | — |
| 교환 | O(드래그 이동에 포함) | 장비는 전부 1×1이라 겹친 아이템은 항상 1개, 교환은 항상 성공한다 |
| 회전(Q) | X | 1×1이라 의미 없음 |
| 임시 보관 영역 | X | 교환이 항상 가능해 자리를 비울 필요가 없다 |
| 자동 정렬 | O | 1×1이라 회전 시도 없이 좌상단부터 채운다 |
| 아이템 정보 표시 | O | 클릭 시 이름만(스탯·설명 미정) |
| 창 드래그 | O | 제목 줄만, 화면 경계 제한, 실행 중 위치 유지 |
| 품목별 색 | O | 상단 물류품과 같은 규칙 |

### 3.3 임시 보관이 없어서 달라지는 것
- 닫기 차단 없음 — 닫기 버튼/상시 호출 버튼으로 언제든 닫힌다.
- "상행 시작" 비활성 조건에 장비는 포함되지 않는다.
- 그리드/팝업 바깥 드롭은 원위치 복귀(상단 물류품과 동일).

## 4. 추천안 → 확정 (사용자, 2026-09-26)

### 4.1 창 제목과 기본 위치
| 항목 | 추천안 | 근거 |
|---|---|---|
| 제목 | "전투 장비" | 호출 버튼 라벨과 일치(상단 물류품과 같은 원칙) |
| 기본 위치 | 화면 좌측, 상단 물류품 팝업보다 약간 오른쪽·아래로 어긋나게 | 두 팝업을 동시에 열었을 때(동시 중첩, 기획 31번 §3.5) 완전히 겹쳐 아래 창이 가려지지 않도록 |
| 창 크기 | 6×4 그리드에 맞춰 상단 물류품(10×4 + 임시 보관)보다 작게 | 임시 보관 영역이 없어 그리드가 창 폭 대부분을 차지 |

### 4.2 Placeholder 장비
- 상단 물류품과 같은 방식(사용자 확정 선례): 실제 테이블 `Equipment.xlsx`에 Placeholder 행을 추가하고 저장소가 시작 시 초기 배치.
- 추천: `placeholder-equipment-1` ~ `placeholder-equipment-4` 4행, 표시명 "Placeholder 장비 1"~"4". 4종이면 품목별 색 구분과 교환·정렬을 검증하기에 충분하다.
- 초기 배치 위치는 설계 단계 재량(정렬 검증을 위해 일부러 흩어 둠).

## 5. 설계 단계로 넘길 기술 과제

- 상단 물류품 팝업 구조(`InventoryPopupPanel`/뷰/드래그 컨트롤러/인스톨러 빌더)를 기능 선택형으로 일반화하는 방식 — 회전·임시 보관을 끄는 옵션 vs 별도 구성. 특히 임시 보관 영역이 없는 화면 요소 구성, 닫기 가드가 필요 없는 경우의 처리.
- `IEquipmentInventoryRepository`에 정리 조작 계약(`IInventoryArrangement`) 추가 — 설계 40번 §10에 예고된 확장.
- 장비 테이블 임포트 경로(1×1 고정, 설계 35번)가 Placeholder 행을 그대로 받는지 확인.

## 6. 남은 미정 사항 (후속)

- 용병 장착 화면 — 착용 부위, 장착 규칙, 장비 스탯 체계 기획이 선행돼야 한다.
- 대장간 연계 진입점(기획 31번 §3.5).
- 장비 정보 표시 확장(스탯·설명) — 장비 데이터 필드 기획 후.
