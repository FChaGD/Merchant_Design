## 1. 배경 — 현재 입력 처리 (코드 조사, 2026-10-20)

| 구분 | 현황 |
|---|---|
| 프로젝트 설정 | 입력 처리 = Input System 전용(구식 `Input.GetKey` 사용 불가) |
| InputManager | Bootstrap 상주 매니저로 등록돼 있으나 **내부가 비어 있음**(컨텍스트 전환 메서드 TODO) |
| 입력 액션 자산 | Unity 기본 템플릿(`InputSystem_Actions`, 이동·점프 등)이 그대로 있고 **어디에서도 쓰지 않음** |
| 키보드 입력 | `Q`(들고 있는 인벤토리 아이템 회전) 1개 — 해당 컴포넌트가 직접 입력 액션을 만들어 처리 |
| 포인터 전역 입력 | 누른 인벤토리 팝업을 맨 위로(포인터 누르기) — 해당 컴포넌트가 직접 처리 |
| UI 포인터 입력 | 클릭·드래그·휠·호버는 UGUI 이벤트 시스템으로 처리(버튼, 그리드 드래그, 창 드래그, 지도, 전투 카메라 팬·줌 등 20여 곳) |
| 인벤토리 상시 호출 | Hub 우상단 버튼 4개만 있음. 키는 미구현 |

키 입력이 컴포넌트마다 흩어져 있어, 키가 늘면 "지금 이 키가 먹혀야 하는 상황인가"를 각자 판단하게 된다. 이 문서는 키 입력을 InputManager 한곳에서 관리하는 체계와 이번에 넣을 키를 정한다.

## 2. 범위

- 포함: InputManager가 관리하는 입력의 범위, 입력 상황(컨텍스트) 구분, 인벤토리 상시 호출 키, Q 회전 이관, 키 표시, 입력 액션 자산 정리.
- 제외: 키 재설정(리바인딩) 화면, 게임패드·터치, UI 포인터 입력(UGUI 이벤트 시스템 유지).

## 3. 확정 사항 (사용자 결정, 2026-10-20)

| 항목 | 결정 |
|---|---|
| 관리 주체 | New Input System 입력을 **InputManager**를 통해 관리하는 체계를 확립한다 |
| 상단 물류품 | `I` |
| 전투 장비 | `B` |
| 전투 소모품 | `C` |
| 상단주 개인 물품 | `P` |
| 토글 | 같은 키를 다시 누르면 닫힘(상시 호출 버튼과 같은 동작) |
| Q 회전 | InputManager 체계로 이관 |

## 4. 확정 사항 — 범위·상황·표시 (추천안 그대로 확정, 2026-10-20)

### 4.1 관리 범위

| # | 항목 | 추천 | 근거 |
|---|---|---|---|
| 4-1 | InputManager가 맡는 입력 | **키보드 단축키 전부**(인벤토리 호출, Q 회전, 이후 추가 키) | 상황 판단이 필요한 입력을 한곳에 모음 |
| 4-2 | UI 포인터 입력 | 지금처럼 UGUI 이벤트 시스템 유지(이관 안 함) | 버튼·드래그는 대상 UI가 정해져 있어 라우팅이 필요 없음. 20여 곳 재작성 비용 대비 이점 없음 |
| 4-3 | 팝업 맨 위로(포인터 누르기) | InputManager로 이관 | UGUI 이벤트로 받을 수 없어 전역 입력으로 처리하는 유일한 포인터 입력(설계 46) — 전역 입력은 한곳에 |
| 4-4 | 입력 액션 자산 | 기본 템플릿 자산을 삭제하고 프로젝트 전용 자산 1개로 키를 정의 | 키 값이 코드에 흩어지지 않음, 이후 리바인딩 화면의 기반 |

### 4.2 입력 상황(컨텍스트)과 키 동작

| # | 항목 | 추천 | 근거 |
|---|---|---|---|
| 4-5 | 인벤토리 키가 동작하는 곳 | **상시 호출 버튼이 보이고 누를 수 있을 때만** — Hub 루트·카테고리 depth. 모달 팝업(상행 준비 등)·시설 화면·숙소 휴식 진행 중·Field에서는 무시 | 버튼과 키가 같은 조건을 따라야 "버튼은 없는데 키로 열리는" 상태가 없음 |
| 4-6 | Q 회전이 동작하는 때 | 인벤토리 아이템을 들고 있을 때만(현행 유지). 버리기 선택 상태(95번)에서는 무시 | 현행 동작 유지 + 95번 4-9 "선택 상태 중 회전 막음" |
| 4-7 | 키 입력이 겹칠 때 | 한 번 누름에 동작 하나만. 텍스트 입력 칸에 커서가 있으면 단축키 무시 | 지금 텍스트 입력 칸은 디버그 도구·배틀 테스트 씬에만 있음(예: 숫자 입력 중 `C`가 소모품 팝업을 여는 것을 막음) |
| 4-8 | 디버그 도구 키 | 이번 범위 밖. 추가 시 같은 자산의 별도 묶음으로 | 디버그 분리 원칙 |

### 4.3 표시

| # | 항목 | 추천 | 근거 |
|---|---|---|---|
| 4-9 | 키 표시 | 상시 호출 버튼 4개 모서리에 작은 키 글자(`I`·`B`·`C`·`P`) | 키를 알 수 있는 유일한 수단 |
| 4-10 | 회전 키 안내 | 이번엔 표시 안 함(현행 유지) | 범위 최소화. 필요 시 후속 |

### 4.4 후보 — 추가 여부 결정 필요

| # | 키 | 추천 | 근거 |
|---|---|---|---|
| 4-11 | `Esc` | 이번엔 넣지 않음. 넣는다면 "열린 인벤토리 팝업 중 맨 위 하나 닫기 → 없으면 현재 화면의 뒤로 가기/나가기" | 장르 관례상 기대되는 키지만 닫기 차단(임시 보관) 등 화면별 규칙과 얽혀 별도 결정 필요 |

## 5. 남은 미정 사항 (후속)

- 키 재설정(리바인딩) 화면.
- Field(상행 중) 인벤토리 상시 호출 — Field에는 상시 호출 버튼 자체가 없음.
- 게임패드·터치 지원.
