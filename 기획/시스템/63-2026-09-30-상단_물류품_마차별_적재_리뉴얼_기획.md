## 1. 배경

지금 상단 물류품(교역품/전리품) 그리드는 마차와 무관하게 40칸(10 × 4) 하나로 고정되어 있다. 마구간(기획 55번)에서 마차 구매와 그리드를 잠정적으로 분리했기 때문이다. 이번 문서는 기획 31번 §3.3 원칙(보유 마차가 적재 공간을 제공)을 실제로 적용한다. **마차마다 적재 공간을 테이블로 정의하고, 마차별로 따로 된 인벤토리 슬롯**을 만든다. 팝업 화면 구조도 함께 바꾼다.

## 2. 범위

- 포함: 마차별 적재 공간 데이터, 마차별 인벤토리 슬롯, 마차 전환(스테퍼), 마차 간 아이템 이동, 팝업 영역 배치 변경(아이템 정보 ↔ 임시보관), 자동 정렬·닫기·구매 배치 규칙의 마차 단위 조정, 무역품 구매 화면의 물류품 패널.
- 제외: 마차 판매·손실(파괴) 시 적재물 처리, 재화 상한과 적재 공간 연동(기획 23번), 아이템 설명 문구, 나머지 인벤토리 팝업 3종(장비·소모품·개인 물품).

## 3. 확정 사항 (사용자 결정, 2026-09-30)

### 3.1 마차별 적재 공간 데이터

| 항목 | 결정 |
|---|---|
| 위치 | `Wagon.xlsx` 데이터 시트(마차 개체 단위, 기획 55번) |
| 저장 방식 | **모양 마스크 문자열 1열**(`CargoShape`). `/`는 줄 구분, `1`은 적재 가능 칸, `0`은 막힌 칸 |
| 결과 모양 | 마스크 그대로의 모양. 외곽 크기 = 줄 길이 × 줄 수 |
| 초기값 | 전 행 **5 × 4 전부 적재 가능** — `11111/11111/11111/11111`(20칸) |
| 입력 규칙 | 모든 줄 길이가 같을 것, `1`/`0` 이외 문자 없음, 적재 가능 칸 1개 이상. 어기면 임포트 오류 |

예시: `11110/11111/11111/01110` → 외곽 5 × 4, 막힌 칸 3개, 적재 가능 17칸.

### 3.2 마차별 인벤토리 슬롯

| 항목 | 결정 |
|---|---|
| 대상 마차 | **보유한 모든 마차**(정비창 배치 여부 무관, 기획 31번 §3.3) |
| 슬롯 구성 | 마차 1대 = 인벤토리 슬롯 1개(그 마차의 모양 그대로). 마차끼리 합치지 않는다 |
| 마차 구매 | 마구간에서 사면 빈 슬롯이 하나 늘어난다(기획 55번 "그리드 무관" 결정 대체) |
| 마차 순서 | 보유 순서(시작 마차 → 구매 순) |
| 막힌 칸 표시 | **칸을 그리지 않는다**(빈 공간) — 마차 모양이 그대로 보인다 |

### 3.3 마차 전환 — 스테퍼

| 항목 | 결정 |
|---|---|
| 배치 | 인벤토리 슬롯 **좌우에 스테퍼 버튼**(◀ / ▶) |
| 동작 | 누르면 이전/다음 마차의 슬롯으로 바뀐다 |
| 끝 처리 | **순환** — 마지막 마차에서 ▶를 누르면 첫 마차 |
| 마차 표기 | 슬롯 **상단에 텍스트** — 마차 이름 + 순번(예: `마차이름1 (1/3)`). 이름은 `WagonStrings` 테이블에서 가져온다 |

### 3.4 마차 간 아이템 이동

| 항목 | 결정 |
|---|---|
| 방식 | 아이템을 **끄는 중에 스테퍼 버튼 위에 머물면 마차가 바뀐다**. 바뀐 마차의 슬롯에 그대로 놓는다 |
| 전환 조건 | **0.5초** 머물면 전환, 계속 머물면 0.5초마다 반복 |
| 놓기 규칙 | 기획 39번 §3.2~3.4(이동·교환·원위치·Q 회전) 그대로 — 놓는 곳이 다른 마차 슬롯이라는 점만 다르다 |
| 원위치 복귀 | 놓기에 실패하면 **원래 마차의 원래 자리**로 돌아간다 |
| 임시보관 | 모든 마차가 **하나의 임시보관을 함께 쓴다** — 임시보관을 거쳐 옮기는 방법도 쓸 수 있다 |

### 3.5 자동 정렬·닫기·구매 배치

| 동작 | 결정 |
|---|---|
| 자동 정렬 | **현재 마차 + 임시보관** 아이템을 현재 마차 안에서 정렬(큰 것부터 좌상단, 회전 시도 — 기획 39번 §3.6). 다 들어가지 않으면 정렬 취소. 다른 마차는 그대로 |
| 팝업 닫기 | 임시보관에 아이템이 남아 있으면 **모든 마차의 빈자리**에 현재 마차부터 순서대로 자동 배치. 전부 넣지 못하면 닫지 않고 안내 문구(기획 39번 §3.5) |
| 무역품 구매 | **현재 마차 우선**, 자리가 없으면 다음 마차 순서로 빈자리를 찾는다. 다른 마차에 들어가면 그 마차 슬롯으로 화면이 바뀐다. 모든 마차에 자리가 없을 때만 구매 불가(기획 48번 §3.6) |
| 상행 시작 비활성 | 변경 없음 — 임시보관에 아이템이 있으면 비활성(설계 40번 §5.5) |

### 3.6 화면 구성 변경

| 영역 | 지금 | 변경 |
|---|---|---|
| 아이템 정보 | 팝업 하단 가로 줄 | **팝업 우측, 세로로 긴 영역** |
| 임시보관 | 그리드 오른쪽, 세로 목록 | **팝업 하단, 가로로 긴 영역** — 아이템을 가로로 나열(넘치면 가로 스크롤) |
| 인벤토리 슬롯 | 좌측 넓은 영역 | 좌측 중앙. **좌우에 스테퍼, 상단에 마차 표기 텍스트** |
| 아이템 정보 내용 | 선택한 아이템 이름 / 닫기 차단 안내 | 같음(설명 문구는 여전히 없음) |

```
┌──────────────────────────────────────────┬───────────┐
│ 상단 물류품 (제목 줄 · 창 드래그)          │     [X]   │
├──────────────────────────────────────────┼───────────┤
│            마차이름1 (1/3)                │ 아이템    │
│   ◀   ┌───────────────────────┐   ▶      │ 정보      │
│       │  인벤토리 슬롯(마차 모양) │          │ (세로)    │
│       └───────────────────────┘          │           │

```

### 3.7 적용 화면

- 상단 물류품 팝업과 **무역품 구매 화면의 좌측 상단 물류품 패널** 모두 같은 구조로 바꾼다. 두 화면은 같은 본문 조립 코드와 같은 저장소를 쓴다.

## 4. 설계 단계로 넘길 기술 과제

- 저장소를 그리드 1개에서 **마차별 그리드 여러 개 + 공용 임시보관 1개** 구조로 바꾸기. 아이템 위치에 "어느 마차인지"를 추가해야 한다.
- 그리드 판정에 막힌 칸 조건 추가(판정이 한 곳에 모여 있음 — 확인). 자동 정렬·빈자리 찾기 입력에 모양 정보 추가.
- 마차 보유 목록의 출처 — 지금 로스터(`PlaceholderCaravanRosterProvider`)가 보유 마차를 관리한다. 마차 구매 시 슬롯이 늘어나도록 두 저장소를 잇는 방법.
- 마차 간 이동의 원자적 처리 — 골드 상자는 제거 시 재화 환급·배치 시 차감이 걸려 있어, 마차 간 이동을 "제거 후 배치"로 만들면 지갑 연동이 오작동한다(기획 39번 §5와 같은 문제).
- 드래그 중 스테퍼 호버 감지와 0.5초 반복 타이머, 슬롯 전환 후 드래그 상태 유지.
- 막힌 칸을 그리지 않는 그리드 화면(칸 좌표는 외곽 크기 기준 유지).
- 임시보관 목록을 가로 방향으로 바꾸기(현재 세로 목록 + 세로 크기 자동 계산).
- 검증용 초기 배치(`PlaceholderInitialItems`)가 5 × 4에 맞는지 — 2 × 2 아이템을 (4,0)에 두는 항목은 가로 5칸에서 넘친다(확인). 초기 배치 좌표 조정 필요.
- 상행 중(Field)에서도 이 팝업을 여는지 **미확인** — 여는 경우 같은 규칙이 적용된다.

## 5. 남은 미정 사항 (후속)

- 마차 판매·손실 시 적재물 처리.
- 재화 상한(기본 소지량 + 마차 보관량)과 적재 공간의 관계(기획 23번).
- 마차 종류별 적재 모양 차등(지금은 전 행 5 × 4).
- 나머지 인벤토리 팝업 3종의 영역 배치 통일 여부.
