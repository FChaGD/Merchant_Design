## 1. 배경

지금 정비창 대열은 고정 격자(8열 × 2행 = 16칸)이고, 모든 칸에 모든 유닛을 놓을 수 있다. 마차는 여러 유닛 종류 중 하나일 뿐 대열 구조에 영향을 주지 않는다. 이번 문서는 **대열이 마차와 시설을 중심으로 확장**되도록 배치 규칙을 다시 정한다. 마차 시스템 리뉴얼의 첫 단계다.

## 2. 범위

- 포함: 대열 영역 결정 규칙, 배치 가능 조건, 마차 제거 조건, 영역 축소 시 처리, 마차·시설 영역 데이터, 적용 범위(마을 + 상행 중).
- 제외: 마차 스탯(체력·적재), 교역품 그리드 연동, 전투 규칙 변경, 마구간 판매·보관.

## 3. 확정 사항 (사용자 결정, 2026-09-28)

### 3.1 대열 영역

| 항목 | 결정 |
|---|---|
| 영역 결정 | 대열 영역은 배치된 **마차와 시설**을 중심으로 확장된다 |
| 마차가 없을 때 | 대열은 **1칸으로 축소**되고, 그 칸에는 **마차만** 놓을 수 있다 |
| 마차가 배치되면 | 배치된 위치를 중심으로 영역이 정해지고, 영역 안에 캐릭터를 놓을 수 있다 |
| 영역 모양 | **정사각형** — 마차(시설) 칸을 중심으로 한 변이 2 × 반경 + 1(반경 4 = 9 × 9). 테이블의 반경 값은 **중심에서 상하좌우(십자 방향) 각 방향으로의 거리**다(2026-09-28 사용자 정정 — 초안의 "십자 반경"은 반경을 십자 방향 거리로 저장한다는 뜻이었고 대열을 십자 모양으로 짜라는 뜻이 아니었는데, 십자 모양 대열로 잘못 기록·제작했다) |
| 영역 크기 | **마차·시설별 데이터**(개체 단위 테이블의 반경 열). **기본값 4** |
| 시설 | 영역만 넓힌다 — **마차 영역 안에만** 놓을 수 있고(§3.2 시설 자리), 놓으면 자기 반경만큼 영역을 넓힌다. ~~제거 연결 조건에는 포함되지 않는다(마차만 따진다)~~ → **2026-09-29 개정: 시설 영역도 마차 연결에 포함**(§3.3) |

### 3.2 배치·제거 규칙

| 항목 | 결정 |
|---|---|
| 두 번째 이후 마차·시설 배치 | **현재 영역 안의 빈 칸에만** 놓을 수 있다 — 배치 단계에서부터 마차들이 항상 하나로 이어진다 |
| 시설 자리 (2026-09-29 추가) | 시설은 **마차 영역(디버그 핀 영역 포함) 안에만** 배치·이동할 수 있다. 시설이 넓힌 칸에는 시설을 놓을 수 없다(캐릭터·마차는 가능) — 시설을 자기 영역 끝으로 반복해 옮기면 대열에서 끝없이 떨어져 나가던 문제(실전 확인)를 막는다. 캐릭터와 교환해 시설이 마차 영역 밖으로 밀려나는 이동도 거부. ~~**마차 이동**으로 시설이 마차 영역 밖이 되면 **이동 거부**~~ → 2026-09-29 개정: 마차 이동·제거 모두 **시설 자동 해제 후 연결 판정**(§3.3) |
| 마차 제거 조건 | 제거한 뒤 **남은 마차들의 영역이 모두 하나로 이어져 있어야** 제거할 수 있다. 예: 마차 - 마차 - 마차가 일렬로 있고 중간 마차를 빼면 양 끝 영역이 끊어지는 경우 제거 불가 |
| 연결 판정 기준 | **영역이 이어져 있는지**로 판정한다 — 마차끼리 칸이 직접 맞닿지 않아도 영역이 맞닿으면 연결 |
| 제거로 영역 밖에 남은 유닛 | **자동 해제** — 배치에서 빠져 팔레트로 돌아간다 |
| 적용 범위 | **마을 정비창(상단 배치) + 상행 중 정비창 배치 모두** |

### 3.3 개정 — 시설 영역의 연결 포함 (2026-09-29 사용자 결정)

§3.1 시설 행의 "제거 연결 조건 제외"와 §3.2 시설 자리 행의 "마차 이동 시 거부"를 아래로 대체한다.

| 항목 | 결정 |
|---|---|
| 시설 자리 | 변경 없음 — 시설은 **마차 영역 안에만** 놓을 수 있다(시설이 넓힌 칸에는 불가). 시설에 대해서는 "마차 영역 안인지"만 따진다 |
| 연결 판정 | **시설 영역도 마차를 잇는 영역으로 친다** — 마차 영역끼리 직접 맞닿지 않아도, 사이를 시설 영역이 이어 주면 연결 |
| 마차 이동·제거 시 시설 | 마차가 옮겨지거나 빠진 뒤 **마차 영역 밖이 된 시설은 팔레트로 돌려보낸다**(자동 해제) |
| 연결 확인 시점 | 시설 해제와 마차 재배치를 모두 반영한 **최종 상태**에서 모든 마차가 이어져 있어야 한다. 이어지지 않으면 그 마차 이동·제거를 **금지**(해제도 일어나지 않음) |
| 시설 이동·제거 | 시설이 연결을 잇고 있을 수 있으므로, 시설을 옮기거나 빼서 마차 연결이 끊기면 **금지** |
| 캐릭터 | 변경 없음 — 최종 대열 밖이 된 캐릭터는 자동 해제 |

### 3.4 개정 — 마을 정비창의 마차 자유 배치 (2026-09-29 사용자 결정)

§3.1 "마차가 없을 때 그 칸에는 마차만"과 §3.2 "두 번째 이후 마차 배치는 현재 영역 안에만" 중 **마차** 부분을 마을 정비창에 한해 아래로 대체한다.

| 항목 | 결정 |
|---|---|
| 적용 동작 | 마차의 **팔레트 배치 + 격자 이동** |
| 배치 가능 칸 | 마차는 **대열과 상관없이 판 어디든** 놓을 수 있다 |
| 첫 마차 | 배치된 마차가 없으면 판 어디든(비교할 마차가 없어 연결 판정 없음). 기준 칸은 "마차가 없을 때 보이는 1칸" 역할만 남는다 |
| 이미 마차가 있을 때 | 놓은 뒤(시설 해제 반영 후, §3.3) **모든 마차가 이어지는지** 확인하고, 안 되면 배치·이동 거부 |
| 적용 범위 | **마을 정비창만**. 상행 중 정비창은 기존 규칙(현재 대열 안에만) 유지 |
| 화면 (2026-09-29 사용자 결정) | 마을 정비창은 연결 가능한 칸(대열 경계 + 가장 큰 마차 반경 + 1)까지 칸을 깐다. **최대 축소 범위는 대열 + 2칸 유지** — 그 바깥 칸은 확대 후 스크롤로 접근 |
| 상행 중 마차 (2026-09-29 사용자 결정) | 상행 중 정비창에서는 마차를 **새로 배치·제거할 수 없다**(팔레트에 마차를 보이지 않음). **이동만 허용**(현재 대열 안). 기존 "상행 중 마차 최소 1대 유지"(기획 20번 §3.4)는 제거 금지에 포함된다 |
| 휠 줌 (2026-09-29 사용자 결정) | 휠 한 칸당 배율 변화는 20%로 하되, 즉시 바꾸지 않고 목표 배율까지 부드럽게 이어지게 한다(마을·상행 공통) |
| 캐릭터·시설 | 변경 없음 — 캐릭터는 대열 안, 시설은 마차 영역 안에만 |

## 4. 외곽 판 크기

### 4.1 외곽 판과 대열의 차이

| 개념 | 의미 | 지금 |
|---|---|---|
| **외곽 판** | 좌표가 존재하는 전체 격자. 칸마다 고정된 좌표(열·행)가 있고, 화면의 칸 크기와 전투 배치 위치가 이 좌표에서 계산된다. 대열이 아무리 넓어져도 이 판 밖으로는 나갈 수 없다 | 8열 × 2행 고정. 모든 칸이 곧 대열 |
| **대열(영역)** | 외곽 판 중 지금 유닛을 놓을 수 있는 칸들. 마차·시설 위치로 계산되며 배치할 때마다 바뀐다 | 개념 없음(= 외곽 판 전체) |

- 마차 반경이 판 가장자리를 넘으면 넘는 부분은 잘린다.
- 예시(반경 4): 판 중앙의 마차 한 대가 여는 영역은 9 × 9 정사각형(81칸)이다. (결정 당시 문서는 십자 17칸으로 잘못 계산했었다 — 위 §3.1 정정 참고)
  - 지금 판(8 × 2)이면 세로는 2행뿐이라 정사각형의 세로 7행이 잘리고, 가로 9칸도 8열에 잘린다.
- 최대 5대를 영역 안에 이어 놓으면(각 마차가 앞 마차 영역 안, 최대 4칸 간격), 일렬로 늘어놨을 때 대열 폭은 최대 4 × 4 + 4 × 2 + 1 = 25칸까지 가능하다.

### 4.2 선택지 (A 채택)

| 안 | 내용 | 장점 | 단점 |
|---|---|---|---|
| A. 고정 판 확대 | 외곽 판 크기를 정해 두고(예: 17 × 9 — 중앙 마차 한 대의 십자가 잘리지 않는 크기) 그 안에서 영역이 펼쳐짐 | 좌표·전투 위치 계산이 지금 구조 그대로. UI 칸 크기 고정 | 판 크기를 넘는 확장은 잘림. 판이 크면 화면에 칸이 많아져 칸이 작아짐 |
| B. 지금 판(8 × 2) 유지 | 판은 그대로, 안에서만 영역 결정 | 변경 최소 | 반경 4 십자의 세로 방향이 사실상 의미 없음 — 이번 규칙의 효과가 가로로만 나타남 |
| C. 무제한(동적 확장) | 판이 영역만큼 자동으로 커짐 | 확장 제한 없음 | 화면 스크롤·확대 축소, 전투 좌표 기준(원점) 정책 등 추가 기획 필요 |

### 4.3 확정 (사용자 결정, 2026-09-28)

| 항목 | 결정 |
|---|---|
| 외곽 판 | **A안 — 고정 판, 50 × 50** |
| 첫 칸 위치 | 판 중앙(추천안). 50은 짝수라 정중앙 칸이 없으므로 (열 25, 행 25)(0부터 셀 때 24, 24)로 둔다 |

- 50 × 50이면 마차 5대를 어떤 방향으로 이어 놓아도(최대 25칸) 판에 잘리지 않는다.

### 4.4 판 표시 방식 (확정 — 사용자 결정, 2026-09-28: A안 범위 + B안 기능, 해석 확인 완료)

| 항목 | 결정 |
|---|---|
| 기본 화면(기본 카메라) | A안 범위 — 현재 대열 영역을 감싸는 사각형 + 여백. 정비창을 열면 이 범위 전체가 보인다 |
| 최대 범위 | A안 범위가 볼 수 있는 최대 범위(가장 축소된 상태) — 이보다 넓게 축소하거나 밖으로 스크롤하지 않는다 |
| 추가 기능(B안) | 확대/축소와 스크롤 — 최대 범위 안에서 확대해 칸을 크게 보고 스크롤로 이동 |
| 대열 표시(사용자 결정) | **주황색 사각 타일 = 대열 영역**의 칸. 대열에 속한 칸에만 주황 타일을 그린다 |
| 외곽 표시(사용자 결정) | **민트색 그리드 = 외곽 판**. 표시 범위 안에서 대열이 아닌 칸은 민트색 판 바탕으로 보인다(배치 불가) |
| 화면 여백·판 밖 (2026-09-29 사용자 결정) | 화면에 칸 없는 빈 여백이 생기지 않도록 표시 범위를 뷰포트에 맞춰 판 칸으로 채운다(최대 축소 배율은 대열 + 여백 기준 그대로). 50 × 50 판 경계 밖은 **어두운 회색**으로 표시해 판 칸(민트)과 구분한다 — 판 밖에는 칸이 없어 배치 불가 |
| 화면 위치 유지·원점 포커스 (2026-09-29 사용자 결정) | 배치·이동·제거로 대열이 바뀌어도 보던 위치와 배율을 유지한다. 단 **배치된 마차가 없으면**(정비창을 열 때, 마지막 마차를 뺀 순간) 화면을 **기준 칸(원점)** 중앙으로 옮긴다 |

- 지금 정비창 화면의 민트색 배경은 판 패널 배경이고, 주황 타일은 판의 모든 칸(8 × 2)이다 — 판 = 대열이라 모든 칸이 주황이었다. 새 규칙에서는 주황 타일이 대열 칸에만 남는다.

### 4.5 디버그 도구 (사용자 결정, 2026-09-28)

- 지금 디버그 도구(열·행·칸 크기 입력)는 외곽 판 크기를 바꾼다. **대열을 임의로 배치하는 도구로 고친다.** 외곽 판은 50 × 50 고정이라 디버그로 바꾸지 않는다.

| 항목 | 결정 |
|---|---|
| 디버그 핀 | 디버그용 **핀 아이콘**을 추가한다. 핀을 판에 놓으면 핀을 중심으로 입력한 크기만큼 대열을 임의로 생성한다 |
| 핀 대열 모양 | 마차와 같은 규칙 — 핀 칸 중심 **정사각형**, 반경(상하좌우 거리) 입력칸 1개 |
| 배치 위치·개수 | **외곽 판 어디든, 여러 개** — 마차 연결 규칙의 예외(임의 배치가 목적) |
| 디버그 제거 | 핀 대열을 제거할 수 있다. 단 **마차(시설) 영역과 겹치는 칸은 남고** 나머지 칸만 사라진다 |
| 디버그 제거 연결 조건 | 핀 제거도 마차 제거와 같이 **제거 후 마차들이 여전히 하나로 이어져 있는지 확인**하고, 연결을 끊는 제거면 **제거를 취소**한다(사용자 결정, 2026-09-28) |
| 마차 제거 연결 판정 | 핀 대열 칸도 **포함**한다 — 핀 대열이 마차 영역 사이를 이으면 연결된 것으로 본다 |
| 기존 입력 | 열·행 입력은 제거(판 고정). 칸 크기 입력은 확대/축소 기능과 겹쳐 제거 후보(설계에서 결정) |
| 빌드 포함 | 기존 디버그 도구와 같이 에디터 전용 |

## 5. 설계 단계로 넘길 기술 과제

- 대열 코드(정비창 격자·배치 판정·상행 중 이동 경로·전투 위치 변환)가 어느 브랜치에 있는지 확인하고 작업 브랜치 결정.
- 영역 계산(마차·시설 정사각형 영역의 합집합)과 연결 판정(남은 마차 영역의 연결성) — 배치·제거·이동(상행 중 이동 경로 포함)마다 판정.
- 상행 중 배치 소요시간·이동 중 유닛 처리와 "영역 밖 자동 해제"의 관계(진행 중 활동이 있는 유닛).
- 기존 "상행 중 마차 최소 1대 유지"(기획 20번 §3.4)와 새 제거 조건의 관계 — 마차 0대 = 1칸 축소 상태가 상행 중에도 허용되는지.
- 마차·시설 테이블(`Wagon.xlsx`·`Facility.xlsx`)에 반경 열 추가(기본 4).
- 카테고리당 배치 상한 5(기획 11번)는 유지.
- **전투 위치 계산의 "행 2개" 가정 제거** — 지금 전투 시작 위치는 `(행 − 0.5)` 고정식이라 행이 3 이상이면 대형이 한쪽으로 치우치고 전장·출현·활동 반경에 행 방향 폭이 빠진다(2026-09-28 조사). 50 × 50 판에서는 대열 영역의 중심을 기준으로 행·열 양방향을 계산해야 한다.
- 외곽 판 크기 50 × 50 적용 — 기본 판 크기 상수(`FormationLayout` 기본 8 × 2) 교체.
- 정비창 격자 표시 재구성: 주황 타일은 대열 칸에만, 민트 판 바탕 위에 표시 범위(대열 영역 사각형 + 여백) 렌더링, 확대/축소·스크롤. 지금은 판 전체를 `GridLayoutGroup`으로 한 번에 그리는 구조라 2,500칸을 전부 만들지 않는 방식 필요.
- 디버그 도구를 핀 기반 임의 대열 배치로 변경(§4.5) — 대열 영역 = 마차·시설·디버그 핀 영역의 합집합, 연결 판정에도 핀 포함. 핀 제거는 마차·시설 영역 겹침 칸 유지. 디버그 도구 설치 규칙(`Tools/Game/Debug/Install|Remove`) 편입 여부 검토.
- 핀 제거로 영역 밖이 된 유닛의 처리 — 마차 제거와 같이 자동 해제로 둘지.
