## 1. 배경

공업 지구의 마구간 버튼은 있지만 시설 화면이 없다. 보유 마차·시설은 Placeholder 로스터가 각 5개를 고정 제공하며, 데이터(이름·가격)와 구매 경로가 없다. 이번 문서는 마구간의 구매 화면과, 이를 위한 마차·시설의 개체 단위 데이터를 정한다.

## 2. 범위

- 포함: 마차·시설 개체 단위 데이터 테이블, 시작 보유 수, 구매 화면 배치, 구매 흐름, 보유 현황 표시, 진입·퇴장.
- 제외: 마차·시설 판매, 보관(마구간에 맡기기), 마차 적재 칸수와 교역품 그리드 연동(31번 §3.3), 시설 유닛의 역할·효과, 마차·시설 스탯, 마구간에서 교역품 인벤토리 열기(31번 §3.5 진입점), 보유 로스터의 실제 시스템 전환.

## 3. 확정 사항 (사용자 결정, 2026-09-28)

| 항목 | 결정 |
|---|---|
| 거래 범위 | **마차·시설 구매만.** 판매·보관은 후속 |
| 데이터 단위 | **개체 단위 행**(용병과 같은 구조). 한 행 = 마차 한 대 / 시설 하나 |
| 마차 데이터 | 이름·가격. **교역품 그리드와 무관** — 이번엔 구매해도 교역품 그리드 크기가 바뀌지 않는다 |
| 시설 데이터 | 이름·가격만. 스탯·효과는 시설 역할 기획 때 열 추가 |
| 등록 수 | 마차 5대, 시설 5개 |
| 시작 보유 | **마차 1대, 시설 1개**(각 테이블 첫 행) |
| 보유 상한 | 각 5(정비창 카테고리당 배치 상한과 일치) — 등록 수가 5라 후보 소진으로 자연히 도달 |
| 고용 후보에 해당하는 구매 후보 | 아직 보유하지 않은 개체 |
| Placeholder 값 | 이름 `마차이름1`~`마차이름5`, `시설이름1`~`시설이름5`. 가격 전부 1,000 |
| 보유 현황 표시 | 마차는 교역품이 아니므로 인벤토리 그리드형으로 관리하지 않는다. **목록 형태로 소유 현황을 보여 준다** |
| 화면 틀 | 용병 고용 화면 틀을 쓰고, 좌측 보유 현황 패널을 마차·시설 목록으로 바꾼다 |

## 4. 확정 사항 — 화면·흐름·테이블 (추천안 그대로 확정, 2026-09-28)

### 4.1 화면 구성

| 항목 | 결정 | 근거 |
|---|---|---|
| 가시성 | 재화 패널을 제외한 모든 UI 숨김 | 다른 시설 화면과 통일 |
| 좌측 | 보유 현황 패널 — "마차 1/5" 제목 아래 보유 마차 이름 목록, "시설 1/5" 제목 아래 보유 시설 이름 목록 | §3 "목록 형태 소유 현황". 용병 고용 좌측 패널과 같은 표시 방식 |
| 우측 위 | 구매 후보 목록 — 미보유 마차·시설을 한 목록에: 아이콘 + 이름 + 종류(마차/시설) + 가격. 마차 먼저, 시설 다음(각 테이블 행 순서) | 목록 하나로 두 종류를 같이 보여 주면 화면 구성이 고용 화면과 같아짐. 아이콘은 정비창 아이콘(마차 삼각형·시설 원) 재사용 |
| 우측 아래 | 정보 패널 — 이름, 종류, 가격, 구매 버튼, 사유 문구. 선택 전에는 비워 둠 | 스탯이 없어 표시할 항목은 이름·종류·가격뿐 |
| 후보가 없을 때 | 목록 자리에 "구매 가능한 마차·시설 없음" | 고용 화면과 같은 처리 |

### 4.2 구매 흐름

| 항목 | 결정 | 근거 |
|---|---|---|
| 흐름 | 후보 선택 → 구매 버튼 → 재화 차감 + 보유 목록에 추가 → 후보 목록에서 제거 | 용병 고용과 같은 흐름 |
| 1회 구매 수량 | 1개 | 다른 시설과 통일 |
| 재화 차감 대상 | 기본 소지 재화만 | 골드 상자 결제 규칙 미정 |
| 구매 불가 조건 | 재화 부족 / 해당 종류 보유 5개 → 구매 버튼 비활성 + 사유 문구 | 다른 시설과 같은 표시 규칙 |
| 확인 창 | 없음 | 다른 시설과 통일 |
| 정비창 반영 | 구매한 마차·시설은 정비창 팔레트 보유 수에 바로 반영(예: "마차 1/1" → "2/2") | 구매의 결과가 배치로 이어져야 의미가 있음 |

### 4.3 진입과 퇴장

| 항목 | 결정 | 근거 |
|---|---|---|
| 진입 | 공업 지구 depth에서 마구간 버튼 | 기존 카테고리 depth 구조 |
| 진입 시 열린 인벤토리 팝업 | 모두 닫음 | 시설 진입 공통 규칙 |
| 퇴장 | "나가기" 버튼 → 공업 지구 depth로 복귀. 퇴장을 막는 조건 없음 | 미정리 상태가 없음 |

### 4.4 데이터 테이블

| 항목 | 결정 | 근거 |
|---|---|---|
| 워크북 | 마차·시설 각각 워크북 하나(데이터 시트: Id·가격 / 스트링 시트: Id·이름) | 도메인별 워크북 분리 원칙(14번 §6.3). 용병 테이블과 같은 데이터/스트링 분리 |
| Id 형식 | `Wagon01`~`05`, `Facility01`~`05` | 용병(`Warrior01`)과 같은 형식 |

## 5. 기존 동작 변화 — 설계 단계에서 처리할 것

- **교역품 그리드 크기**: 지금은 보유 마차 수 × 8칸이다. 시작 마차가 5대 → 1대로 줄면 그리드가 40칸 → 8칸으로 줄고, 구매할 때마다 늘어난다. §3 "이번엔 무관" 결정에 따라 **그리드 크기를 로스터의 마차 수와 분리해 지금 크기(40칸)로 고정**해야 한다.
- **정비창 배치**: 시작 마차·시설이 각 5 → 1로 줄어 정비창에 놓을 수 있는 마차·시설이 줄어든다. 구매로 다시 늘어난다.
- **판매 목록 조회 계약**: 용병 후보와 같이 "마을 + 시설"을 받는 형태로 열어 둔다(마을별 판매 차별화 대비).

## 6. 남은 미정 사항 (후속)

- 마차·시설 판매, 보관(마구간에 맡긴 마차의 의미 — 적재량 합산 포함 여부 등).
- 마차 적재 칸수·모양과 교역품 그리드 연동(31번 §3.3), 재화 상한 연동(23번).
- 시설 유닛의 역할·효과·스탯.
- 마구간에서 교역품 인벤토리를 여는 진입점(31번 §3.5, 47번 §2).
- 실제 이름·가격, 마을별 판매 차별화.
