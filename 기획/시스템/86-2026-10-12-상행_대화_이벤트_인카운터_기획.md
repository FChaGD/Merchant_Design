## 2. 범위

- 포함: 이벤트 인카운터(발생·표시·선택·결과), 상행 중 대화(발생·표시·선택·이력), 이력(플래그), 발생 조건 구조, 검증용 예시 콘텐츠, 디버그 강제 발생.
- 제외: 퀘스트·메인 스토리 시스템(조건 종류를 늘릴 확장 자리만, §5.3), 상단원 관계·호감도, 마을(Hub)에서의 대화, 스탠딩 일러스트 리소스(Placeholder), 저장/불러오기, 합류 캐릭터의 이탈·사망 후 처리(캐릭터 재고용·디폴트 용병 생성 기획과 함께 — 기획 80 §4-10).

### 2.1 스크립트 형식 — Yarn Spinner (2026-10-12 결정)

대사·분기·선택지는 **Yarn Spinner 3.x**(`.yarn` 파일)로 작성한다. Ink와 비교한 판단 근거:

| 기준 | Yarn Spinner | Ink | 판정 |
|---|---|---|---|
| 잠긴 선택지(§3.1: 흐림+조건 문구) | 조건이 거짓인 선택지도 **'선택 불가' 표시로 게임에 전달** — 그대로 흐림 표시 가능 | 조건이 거짓인 선택지는 **목록에서 빠짐** — 흐림 표시엔 우회 작성 필요 | Yarn |
| 화자 지정(§4.1) | `이름: 대사` 문법이 화자를 분리해 전달 | 태그·문자열 규약을 직접 정해야 함 | Yarn |
| 게임 효과 호출(골드·전투·합류 등, §3.5) | `<<명령>>` → C# 메서드 연결 | 외부 함수·태그 | 동등 |
| 이력(플래그, §5.2) | 변수 저장소를 게임 쪽 구현으로 교체 가능 — 이력 시스템과 직접 연결 | 이야기 상태 안의 변수, 게임과 동기화 필요 | Yarn |
| 조건부 후보 선택 | 노드 그룹 `when:` 조건(`once` 포함) | 직접 구현 | Yarn(참고 — 상행당 1회 등은 어차피 게임 쪽 규칙) |
| 진행 제어(타자기·일시정지·무응답, §4.5) | 표시 담당 컴포넌트 교체 구조 | UI 없음, 전부 직접 구현 | 둘 다 직접 구현 범위 큼 |
| Unity 6 호환 | 3.x가 Unity 2022.3 이상 지원 — 프로젝트(6000.3) 포함 | 지원 | 동등 |
| 라이선스 | MIT, 무료 배포(스토어 구매는 후원 성격) | MIT | 동등 |

- 결정 요인: **잠긴 선택지 표시**와 **화자 지정**이 Yarn에는 기본 기능이고 Ink에서는 우회가 필요하다.
- 발생 메타데이터(발생 방식·가중치·1회 제한·계기·조건)를 `.yarn` 노드 헤더에 둘지, 기존 엑셀 테이블에 두고 노드 이름으로 참조할지는 **설계에서** 정한다.
- 미확인(제작 시 확인): 패키지 도입 시 기존 DLL과의 충돌 여부(NuGet 폴리필 충돌 이력 있음).

## 3. 이벤트 인카운터

### 3.1 형태

| 형태 | 내용 |
|---|---|
| 선택지형 | 상황 묘사 → 플레이어 선택 → 결과 |
| 자동 결과형 | 선택 없이 상황 묘사 → 결과 |

- 선택 하나에 결과 하나(확정). 확률 분기 없음. 결과 하나에 **효과를 여러 개 묶을 수 있다**(예: 무역품 +1과 도로 난이도 +10).
- 선택지에 조건을 붙일 수 있다. **조건 미충족이면 잠김 표시**(흐리게 + 미충족 조건 문구, 선택 불가 — §3.4).
- 한 번 발생한 이벤트의 재발생 여부(1회성/반복)는 **이벤트별 지정**.
- 확정·랜덤 이벤트 모두 **같은 이벤트는 상행당 1회**. 반복 이벤트도 같은 상행 안에서는 다시 나오지 않는다(1회성 = 게임 전체 1회, 반복 = 상행마다 1회까지).

### 3.2 발생

| 방식 | 내용 |
|---|---|
| 랜덤 | 전투와 독립된 이벤트 전용 판정. 5초 주기, 회당 약 3.3%(5분 평균 2회), **도로 난이도 무관**. 판정 성공 시 발생 조건을 만족하는 후보 중 **가중치 추첨** |
| 확정 | 조건(시간·장소·이력·선행 조건, §5)을 만족하면 반드시 발생. 이벤트 판정 시점에 점검 |

- **판정 시점이 겹치지 않게** 둔다: 전투 0초, 대화 +1.25초, 이벤트 +2.5초 기준으로 어긋나게(같은 5초 축). 대화는 주기가 20초라 +1.25초 위치 중 4번에 1번.
- 향후 방향이 바뀌어 같은 시점에 겹치게 되면 우선순위는 **확정 이벤트 > 전투 > 랜덤 이벤트**(나머지는 버림).
- 수치는 테스트 추정치. 플레이테스트 후 조정.

### 3.3 진행 중 상태

- 이벤트 진행 중에는 **상행 이동 정지**(진행 시간·게임 날짜·모든 판정도 정지).
- 허용 UI: 인벤토리 팝업 확인, 상행 정보 확인, 정비창 **열람**(편집 불가). 그 외(정비창 편집·방향성 지시·대화 걸기)는 불가.
- 진행 중인 대화가 있으면 이벤트 발생 시 대화는 **중단**된다(즉시 종료 — 무응답 분기 미적용, 발생 기록 없음, §4.3).
- **정비창이 열려 있을 때** 이벤트가 발생하면: 상행 타이머(이동·판정)를 멈추고 정비창이 닫히기를 기다린다. 닫히면 이벤트를 바로 시작한다. 이벤트 중 정비창을 다시 열면 열람 모드.
- 이벤트 진행 중 정비창 배치·이동 활동의 타이머도 멈춘다(전투 때와 같음).
- **전투 중**에는 이벤트 판정·대화 점검을 하지 않는다(이동 정지).

### 3.4 표시

흐름: **이벤트 대화 화면(상황 대사) → 전용 선택 UI(선택) → 이벤트 대화 화면(결과 대사)**. 이벤트 대화 화면은 **화면 전체를 차지하는 이벤트 전용 화면**으로, 이동 중 말풍선 대화(§4.4)와 다른 화면이다(2026-10-12 정정 — 대사 진행 규칙 §4.5는 공용).

| 단계 | 표시 |
|---|---|
| 상황 대사 | **이벤트 대화 화면**(전체화면). **타자기 출력**(§4.5), **자동 넘김 없음 — 클릭으로만** 넘김(이동 정지 상태라 플레이어 속도로 진행). 클릭은 2단계(출력 중 = 전체 표시, 출력 완료 후 = 다음 대사) |
| 선택 | 상황 대사가 끝나면 **전용 선택 UI(전체화면)**. 제한시간 없음 |
| 결과 | 선택 UI를 닫고 **이벤트 대화 화면으로 복귀**해 결과 대사 진행. 수치 변화(골드·무역품 등) 표기 방식은 설계에서 |

전용 선택 UI 구성:

| 요소 | 내용 |
|---|---|
| 상황 설명문 | 선택 전 상황을 요약한 글(이벤트 데이터) |
| 캐릭터 스프라이트 | **이벤트가 지정**(상단원·외부 인물, 0~여러 명). 이번엔 Placeholder(색 사각형+이름) |
| 선택지 | 조건 미충족은 **흐림 + 미충족 조건 문구**(예: "골드 300 필요"), 선택 불가 |

- **자동형 이벤트**(선택지 없음)는 선택 UI 없이 **이벤트 대화 화면만** 쓴다.
- 기존 "전체화면 표시는 염두만"은 이 선택 UI로 대체한다(이벤트별 표시 방식 지정 자리는 두지 않음).

### 3.5 결과 종류

| 분류 | 결과 | 세부 |
|---|---|---|
| 전투 | 전투 발생 | 적 구성은 이벤트가 지정할 수 있는 구조. **현재 데이터는 랜덤 전투와 같은 구성 규칙**(도로 난이도 기반). 흐름은 §3.8 |
| 상행 상태 | 도로 난이도 변경 | 유지 방식은 **이벤트별 지정**, 세 종류 — ① 이번 구간만 ② **게임 날짜 기간**(지정 일수 후 기본값 복귀) ③ **영구 변경**(도로 현재값을 바꾸고 복귀 없음, 다른 요인으로는 다시 바뀔 수 있음). 세 방식은 로직을 나눈다 |
| 상행 상태 | 이동 지연·단축 | 현재 구간 소요시간 증감 |
| 자원 | 골드 증감 | 기획 82 지출·수입 규칙 그대로(지출 = 개인 → 적재 상자 인출, 수입 = 개인 골드·상한 초과 처리 포함) |
| 자원 | 무역품 증감 | 받을 때 공간 부족이면 §3.6 |
| 자원 | 마차·시설 내구도 증감 | **보류 해제(2026-10-13) — [기획 90](90-2026-10-13-마차_시설_내구도_지속_기획.md)**. 최대치 대비 %, 효과마다 종류(마차/시설/둘 다) 지정, 감소는 보유 중 무작위 1개·회복은 가장 손상된 1개. 0이 되면 아래 §3.9(시설은 화물 없이 제거만) |
| 상단원 | 합류 | 대상은 기존 캐릭터 풀(미고용) 또는 이벤트 전용 캐릭터(§3.7) — 이벤트가 지정. 합류한 캐릭터는 **정비창 팔레트**에 둔다(자동 배치 없음). 직업당 보유 상한은 없다(기획 80 §3-10에서 폐기) |
| 상단원 | 이탈 | 고용 해제 → 마을 고용 후보로 복귀 |
| 이력 | 플래그 기록 | 후속 이벤트·대화의 조건(§5) |

- 상단원 HP 증감은 이번 범위에서 제외(사용자 선택에 없음).

### 3.6 무역품 수령 — 공간 부족

1. 받을 무역품이 마차 적재 공간에 다 들어가지 않으면 **상단 물류품 팝업을 열어 정리**하게 한다. 받을 무역품은 임시 보관 영역에 놓인다.
2. 정리해도 다 들어가지 않으면, 플레이어가 **포기할 적재물을 임시 보관 영역에 둔다**. 이때 **기존 적재물도 포기 대상**이 될 수 있다.
3. 닫을 때 "임시 보관 영역의 물품을 포기하겠습니까?" 확인 → 확인하면 포기(삭제)하고 수령 완료.
- 기획 39 §3.5 "버리기 없음"(닫을 때 임시 보관이 남으면 닫지 않음)의 **예외**다. 예외는 이벤트 수령 흐름에 한한다.

### 3.7 이벤트 전용 캐릭터

- 기존 캐릭터 테이블에 **표시 열**(고용 후보 제외)을 추가해 구분한다. 스탯 등 나머지는 공용.
- 이탈·사망 후 처리는 이번 범위 밖(§2).

### 3.8 이벤트 전투 흐름

| 단계 | 내용 |
|---|---|
| 선택 후 | 결과 대사를 **보고 전투**하는 경우와 **바로 전투**하는 경우 둘 다 가능(이벤트별) |
| 전투 | 기존 전투와 같음 |
| 전투 후 대화 | **승리 시에만**, 상행 정지 상태로 **이벤트 대화 화면**(이벤트 대사와 같은 규칙 — 클릭 넘김)를 띄울 수 있다. 이벤트마다 있을 수도, 없을 수도 있다 |
| 패배 시 | 전투 후 대화 없음. 기존 패배 처리만 |
| 종료 | 전투 후 대화(있으면)가 끝나면 이벤트 종료, 상행 재개 |

- 이 "전투 후 대화"는 이벤트 데이터의 일부다. 상행 중 이동하며 뜨는 확정 대화의 계기 '전투 직후'·'이벤트 직후'(§4.3)와는 **별개**다.

### 3.9 효과를 그대로 적용할 수 없을 때

| 경우 | 처리 |
|---|---|
| 골드 부족(자동형 등) | 있는 만큼만 잃는다 — **0까지**. 지출 순서는 기획 82 규칙(개인 → 적재 상자) |
| 무역품 손실 대상 | 무역품 종류를 지정하지 않은 손실은 **무작위** |
| 무역품 부족 | **있는 만큼만** 잃는다 |
| 마차 내구도 0 | **마차 파괴**. 화물 손실은 처리하지 않고, 파괴된 마차의 화물을 남은 마차로 **옮기는 흐름** — §3.6 수령 흐름 재사용(상단 물류품 팝업, 파괴 마차의 화물을 임시 보관 영역에 둠 → 남은 마차로 옮김 → 다 못 넣으면 포기 확인 후 삭제). 이벤트 진행 중(상행 정지) 처리 |
| 마지막 마차 파괴 | 파괴하고 그 마차의 **화물은 포기**, **궤주 처리**(기존 패배 처리) |
| 내구도 회복 초과 | **최대치에서 자른다** |

## 4. 대화

### 4.1 참여자

- 상단원끼리, 플레이어(상단주)와 상단원, 외부 인물. 이후 다른 주체가 추가될 수 있다.
- 화자는 **특정 캐릭터 지정**. 지정된 상단원이 **고용 상태**이기만 하면 발생한다(정비창 배치 여부 무관).
- 대화 도중 화자가 이탈하는 흐름은 의도에 없다(이탈은 이벤트 결과뿐이고, 이벤트 발생 시 대화는 중단된다).
- 외부 인물은 이벤트와 대화 모두에 등장할 수 있다. 외부 인물은 새 인물 테이블(이름·일러스트 참조)로 정의한다.

### 4.2 종류

| 유형 | 내용 | 게임 영향 |
|---|---|---|
| 읽기 | 대사만 | 없음 |
| 선택지 | 응답 선택, 분기 대사만 다름 | 없음 |
| 선택지+결과 | 선택이 **이력(플래그)**을 기록하고 **후속 대화**로 이어짐 | 이력만(자원·수치 변화 없음) |

### 4.3 발생

| 방식 | 내용 |
|---|---|
| 주기 점검 | **20초마다**(1분 3회) 대화 시작 판정. 이때 확정 대화 조건과 랜덤 대화를 함께 점검 |
| 랜덤 | 회당 30%. 성공 시 조건 만족 후보 중 가중치 추첨 |
| 확정(계기) | 계기: **상행 출발 직후, 전투 직후, 이벤트 직후, 중간 도시 도착**. 계기가 생긴 뒤 다음 점검에서 판정 |
| 플레이어가 걸기(수동) | Field 화면의 **버튼 → 상단원 목록**(고용 상단원, 플레이어 자신 제외) → 선택한 상단원의 대화 시작. **언제나** 걸 수 있다. 그 상단원의 **이번 상행에서 아직 하지 않은 수동 대화**가 있으면 그것, 없으면 **반복 대화** |

- 이미 진행 중인 대화가 있으면 그 점검의 발생 판정은 무시한다. 그 점검에서 못 띄운 **계기 대화는 소멸**.
- 다른 대화가 진행 중이면 **걸기 불가**(버튼 비활성).
- 이벤트 진행 중에는 걸기 불가(§3.3). 이동 정지 중이라 주기 점검도 멈춘다.
- **전투가 발생하면 진행 중 대화는 중단**된다. 즉시 종료한다 — 선택지 대기 중이어도 무응답 분기를 적용하지 않고, 끝까지 진행하지 않았으므로 발생 기록도 남기지 않는다(같은 대화가 다시 뜰 수 있음, 2026-10-12 설계 87 결정).
- 확정과 랜덤이 같은 점검에서 함께 성립하면 **확정 우선**(한 번에 대화 하나).
- 횟수 제한: **랜덤 대화·수동 대화는 같은 대화가 상행당 1회**. 수동의 **반복 대화는 제한 없음**. 확정(계기) 대화는 당분간 제한 없음(§8-9).
- 계기 '전투 직후'·'이벤트 직후'는 유지한다. 이벤트 전투 후 상행 정지 상태로 뜨는 이벤트 대화 화면의 대화(§3.8)와는 별개다. 이벤트 전투의 '전투 직후'·'이벤트 직후'는 이벤트가 끝나고 상행이 재개된 뒤 생긴다.
- 두 20초 판정 사이에 계기가 여러 개 생기면 **'이벤트 직후'를 우선**하고, 그 밖에는 먼저 생긴 계기 순서로 대화가 있는 첫 계기를 띄운다. 나머지 계기는 소멸(2026-10-12).

### 4.4 표시·진행

- 이동 뷰에 **캐릭터 스탠딩 일러스트 스프라이트 + 말풍선**. 일러스트는 이번엔 Placeholder(색 사각형 + 이름).
- 대화 중에도 **이동은 계속**된다.
- 대사 출력·넘김은 §4.5.
- 선택지는 이동을 멈추지 않고 **제한시간 10초**. 시간이 지나면 선택지와 별개인 **'무응답' 분기**(대사·이력)가 적용된다.

### 4.5 대사 출력 (타자기)

| 항목 | 규칙 |
|---|---|
| 출력 | 말풍선에 대사가 **타자기처럼 한 글자씩** 쳐진다. **초당 12자** |
| 글자 수 기준 | **공백 제외, 문장부호 포함**. 공백은 출력 시간을 쓰지 않고 바로 찍힌다. 출력 속도·대기 시간 모두 이 기준 |
| 자동 넘김 | 대사가 **전부 출력된 뒤 대기 시간**이 지나면 다음 대사로 넘어간다 |
| 대기 시간 | **1초 + 글자당 0.05초**, 최소 **2.5초**·최대 **5초** |
| 클릭 | 2단계 — 출력 중 클릭: 대사 전체 즉시 표시(그때부터 대기 시작). 출력 완료 후 클릭: 대기 생략하고 다음 대사 |
| 선택지 대사 | 질문 대사가 다 쳐지면 **대기 없이 바로 선택지 표시**, 그때부터 **10초** 제한시간 |
| 이벤트 | 타자기 출력·2단계 클릭은 같고, 자동 넘김 없음. 선택은 전용 선택 UI(§3.4) |
| 다른 화면 열림 | 인벤토리 팝업·정비창·상행 정보를 열면 **타자기 출력·대기(자동 넘김)·선택지 10초 제한시간 모두 일시정지**. 닫으면 이어서 진행 |

- 예: 20자 대사 → 출력 약 1.7초 + 대기 2.5초(1+1.0 → 최소값). 60자 대사 → 출력 5초 + 대기 4초.

## 5. 조건과 이력

### 5.1 발생 조건 (확정·랜덤 후보 공통)

| 종류 | 예 |
|---|---|
| 시간 | 날짜·월 범위, 구간 진행도 |
| 장소 | 지역, 도로, 출발/도착 도시 |
| 이력 | 플래그 존재·부재, 특정 이벤트·대화 발생 여부 |
| 선행 조건 | 퀘스트·메인 스토리 진행 — **확장 자리만**(§5.3) |
| 화자 | 지정 상단원이 상단에 있음(대화) |

- 상태(골드·화물·상단 구성 등) 조건은 발생 조건 종류에 넣지 않는다(사용자 선택에 없음). 단 이벤트 **선택지 잠김 조건**(§3.1)은 골드 등 상태를 쓸 수 있어야 한다 — 선택지 조건 종류의 세부는 설계에서 정리.

### 5.2 이력(플래그)

- 이벤트 선택·대화 선택이 기록하고, 조건이 읽는다. 이벤트·대화의 발생 여부(1회성 판정)도 이력으로 본다.

### 5.3 확장 자리

- 조건 종류를 데이터로 늘릴 수 있는 구조로 둔다. 퀘스트·메인 스토리가 기획되면 그 시스템이 조건 종류를 추가한다.
