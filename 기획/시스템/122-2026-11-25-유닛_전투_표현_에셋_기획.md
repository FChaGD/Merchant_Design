## 1. 목적

전투 유닛(아군 3종·적 3종)·마차·시설·투사체·HP바·잔해의 자리표시자 도형을 실제 아트로 바꾼다.

## 2. 현행 (코드 확인, 2026-11-25)

| 대상 | 현재 표현 | 쓰이는 곳 |
|---|---|---|
| 아군 3종(전사·궁수·방패병) | 파란 도형 아이콘 × 아군 틴트 | 전투 몸체, 정비창 팔레트, Hub 고용 목록 |
| 적 3종(약탈자·괴수·적대자) | 흰 사각·삼각·원 × 적 틴트 | 전투 몸체 |
| 마차·시설 | 파란 오각형·육각형 아이콘 | 전투, 정비창, Hub 마구간 목록 |
| 투사체 | 흰 사각 0.15m, 쏜 유닛 색 틴트 | 원거리 공격 |
| HP바 | 코드 생성 둥근 사각형 | 유닛 머리 위 |
| 잔해 | 마차 아이콘 + 연두 틴트 | 파괴된 마차 |
| 피격·사망 | 흰 번쩍임 / 짙은 빨강 + 1.1배 후 사라짐 | 공통 |

- 유닛 몸체 0.6m(최대 체력에 따라 0.7~1.5배), 기본 줌 약 33px. 회전·애니메이션 없음.

## 3. 유닛 스타일 (사용자 지정, 2026-11-25)

- 전신 SD 1.5등신, 전형적인 사이드뷰 기준 캐릭터.
- 모습 2가지: **뒷모습** = 화면 위쪽(상·좌상·우상)으로 향할 때, **앞모습** = 화면 아래쪽(하·좌하·우하)으로 향할 때. 위쪽 세 방향은 같은 애니메이션, 아래쪽 세 방향도 같은 애니메이션을 공유 → 캐릭터마다 정면샷·후면샷 두 벌.
- 예시(사용자 제작, GPT 생성): `ArtSource/예시/`(2026-11-27 이동, 비공개 저장소 Merchant_Asset) - 도적 1~4(약탈자용), 검사·창병(전사용). 빈 얼굴(그늘), 굵은 외곽선, 흙·가죽 계열 카툰 채색.

## 4. 예시 실사용 판단 (2026-11-25)

- 실사용 가능: 스타일이 전투 바닥과 맞고, 해상도(약 1200px)·투명 배경·앞뒤 짝 양호.
- 로컬 보정 필요(크레딧 0): 불투명부 알파 251~253 → 255, 발바닥 기준 정렬·키 통일(아래 여백 66~158px 편차), 투명부 검정 → 임포트 투명 가장자리 보정.
- 가독성: 현재 크기(약 33px)에서는 도적끼리·도적과 검사 구분 불가, 1m(약 55px)에서는 머리 장비·무기로 구분됨 → 표시 크기 결정 필요(§6).
- 진영 틴트(곱하기)를 그대로 쓰면 그림이 뭉개짐 → §5 결정.
- 부족분: 도적 3 후면, 궁수·방패병·괴수·적대자 전부, 마차·시설 미정.

## 4.1 예시 생성 방식 (프롬프트 기록 확인, 2026-11-25)

출처: `2026-11-25-도적검사창병-에셋생성프롬프트.txt`(프로젝트 루트, 원문 영어 보존).

| 항목 | 내용 |
|---|---|
| 도구 | GPT 이미지 생성·편집(입력 이미지 + 지시문) |
| 절차 | 사용자 선택 러프(구도·비율 기준, "Image 1") + 원본 디자인 참고(재질·의상만, 키 큰 원본 비율은 금지, "Image 2") → sketch-to-render 완성 → 편집으로 수정(v2·v3) |
| 비율 표기 | 프롬프트상 "extreme one-head-tall SD"(머리가 실루엣 대부분, 턱 아래 몸·발이 짧게 붙음) |
| 얼굴 | 눈·눈썹 없음, 위는 거의 검은 그늘 → 아래 복숭아색 턱 |
| 공통 금지 | 지면 그림자·배경·글자·여러 뷰·스프라이트 시트, 사실적 질감 |
| 후면 | 후면 러프 + 완성 정면을 색·재질 참고로 사용(검사·창병 기록). 도적 후면 프롬프트는 파일에 없음 |
| 측면 | 검사·창병 측면(오른쪽 향함)도 제작 기록 있음 - `ArtSource/예시/`에는 없음 |
| 스타일 차이 | 도적 = 거친 손그림 질감(마른 붓 질감·해진 천). 검사·창병 = v2부터 깔끔한 카툰 셀 채색(두꺼운 외곽선, 2~3톤, 사실 질감 금지)으로 전환 |

- 재현 조건: 프롬프트만으로는 재현되지 않는다 - 매 장마다 사용자 러프(구도 기준)와 원본 디자인 참고 이미지가 입력으로 들어갔다.

### 7.1 시험 판단 (2026-11-26, Unity 미리보기 창)

- 미리보기: `Tools/Game/Art/Unit Anim Preview`(에디터 전용, `ArtSource/UnitAnim/<날짜>/`에서 직접 읽음). GIF는 뷰어가 20ms 미만 지연을 100ms로 바꿔 타이밍이 깨지므로 판단에 쓰지 않는다.
- A(Ignis 대기) 폐기. C(Hydra 대기) 양호.
- 걷기: B의 위아래 들썩임 + D의 명확한 다리 걸음 동작을 합친 형태를 목표로 한다.
- 카툰 타이밍 기준 개정: 앞·뒤 프레임 고정 절삭은 예시일 뿐이다. 동작 중 적절한 핵심 포즈 몇 곳을 지정해 머무르게 하고, 그 사이를 건너뛰어 끊기게 연출한다.
- E 걷기 재생성(Hydra 3초, 9크레딧): 지시문 `exaggerated bouncy walk in place toward the camera, body bobbing up and down with each step`. 결과 25장/2.13초, 420×398, loop_score 0.92. 다리 걸음이 뚜렷하고 몸이 위아래로 약 5% 들썩이며, 발은 바닥에 고정. 25장에 걸음 약 4회(6장 주기).
- E 카툰 타이밍 v1: 두 걸음(1~13번)만 사용 - 디딤(1·8) 머무름 → 정점(4·11)으로 끊어 넘어감 → 내려오며 부드럽게(6·7, 12·13).
- E 카툰 v1도 너무 부드럽다는 판단(2026-11-26) → 연출 기법 허용 범위 확대: **핵심 포즈 선정·중간 프레임 제거·같은 프레임 재사용**. 타이밍 v2(`cartoon_timing_v2.txt`): C·E에 머무름 + 생략 + 재사용 반동(착지 후 튕김) 적용. 미리보기 창은 타이밍 파일마다 한 줄씩 비교하도록 확장, 폐기 시안 A는 숨김.
- v2도 부드럽고 버벅인다는 판단(2026-11-26). 원인 추정: 40~50ms 사이 프레임·작은 반동이 박자를 불규칙하게 만들어 끊김이 의도가 아닌 버벅임으로 보임. → v3(핵심 포즈만, 83ms 박자 배수)·v4(v3 + 강약: 디딤 짧게·정점 체공 길게) 시안. v1은 `timing_archive/`로 옮김, 미리보기 창은 C·E만 표시.
- 2026-11-26 사용자 선택: 대기 C = 카툰 v2, 이동 E = 카툰 v4 → 설계 123으로 배틀 테스트 씬 아군 전사에 시험 적용(제작 완료, 인게임 판단 대기).
- 2026-11-26 대기를 카툰 v1(`timing_archive/cartoon_timing_v1.txt`: 1:220 6:60 8:60 10:60 13:300 18:60 21:70 23:80)로 교체해 다시 가져옴(Idle 고유 8장). 이동은 v4 유지.
- 2026-11-26 연출 방향 확정(사용자): **대기는 부드럽게, 이동은 카툰식으로 딱딱하고 과장되게**. 산적(약탈자, 예시 도적 1~4)도 같은 방식으로 제작 예정.
