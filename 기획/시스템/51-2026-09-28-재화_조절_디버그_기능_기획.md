## 1. 배경

무역품 구매 검증 중 재화가 부족하거나 남는 상황을 만들기 어려웠다. 재화 지갑 기본 상한을 1,000 → 10,000으로 올려 검증했지만, 재화 부족·그리드 가득 참 같은 경계 상황을 반복해서 만들려면 실행 중에 재화를 바로 바꿀 수 있어야 한다.

## 2. 범위

- 포함: 플레이 중 현재 재화를 늘리고 줄이는 디버그 버튼, 설치·제거 방법.
- 제외: 상한 조절, 적재 재화(골드 상자) 조절, 다른 자원(지략·행정력·평판) 조절, 정식 게임 기능.

## 3. 확정 사항 (사용자 결정, 2026-09-28)

| 항목 | 결정 |
|---|---|
| 조절 대상 | 현재 금액만. 상한(인스펙터 값) 안에서만 증감 |
| 증감 단위 | 두 단계: ±100(Placeholder 가격 1칸 단위), ±1000 |
| 지갑 기본 상한 | 10,000 유지(설계 50번 검증 때 올린 값) |

## 4. 확정 사항 — 표시·설치 (추천안 그대로 확정, 2026-09-28)

| 항목 | 결정 | 근거 |
|---|---|---|
| 표시 방식 | 화면에 직접 그리는 디버그 버튼(`BattleDebugResultView`와 같은 방식). 에디터 실행에서만 동작하고 빌드에는 포함되지 않음 | 게임 UI 구조(레이어·인스톨러)를 건드리지 않음. 켜고 끄기가 쉬움 |
| 버튼 배치 | 한 줄: `[-1000] [-100] 현재 금액 [+100] [+1000]` | 스핀 버튼 형태. 현재 금액을 버튼 사이에 보여 줌 |
| 위치 | 화면 우상단, 재화 패널 바로 아래 | 재화 패널을 보면서 조작. 무역품 구매 화면(재화 패널만 남는 화면)에서도 보임 |
| 표시 씬 | 마을(Hub)에서만. 상행(Field)·전투 뷰에서는 보이지 않음(2026-09-28 제작 후 사용자 정정 — 초안 "마을·상행 모두"에서 변경) | 무역품 구매 등 재화 소비 검증이 마을에서만 일어남 |
| 경계 처리 | 늘리면 상한에서 멈추고, 줄이면 0에서 멈춤 | 지갑의 기존 규칙(상한 초과분 손실, 부족하면 차감 불가)을 그대로 따르되, 디버그 조작이 "아무 일도 안 일어남"으로 끝나지 않게 가능한 만큼만 증감 |
| 반영 경로 | 지갑의 증감 기능을 그대로 사용 | 재화 패널·무역품 구매 화면의 구매 가능 판정이 기존 변경 이벤트로 자동 갱신됨 |
| 설치 | `Tools/Game/Debug/Install/Currency Spin Buttons`, `Remove/…` 메뉴 + `Install All`/`Remove All`에 등록. Bootstrap 씬의 재화 지갑 오브젝트에 부착 | 디버그 도구 설치 규칙. 게임 빌드 인스톨러와 분리 |

## 5. 설계 단계로 넘길 기술 과제

- 디버그 컴포넌트 위치(`Core/Debug/Player/` 등)와 지갑 조회 방식(같은 오브젝트의 지갑 컴포넌트를 직접 조회).
- 화면 좌표: 재화 패널이 화면 비율(우측 30%) + 고정 픽셀 오프셋으로 배치되어 있어, 디버그 버튼 위치를 어떻게 맞출지.
- 버튼 크기·글자 크기(고해상도에서 너무 작지 않게).

## 6. 남은 미정 사항 (후속)

- 상한·골드 상자·다른 자원 조절 필요 여부.
- 지갑 기본 상한 10,000을 정식 수치로 되돌리는 시점(가격 체계 기획 때 재검토).
