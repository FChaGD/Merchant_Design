## 1. 배경

주점 지구의 용병단 접촉 버튼은 있지만 시설 화면이 없다. 보유 용병은 Placeholder 로스터가 직업(전사·궁수·방패병)당 5명을 고정 제공하고, 같은 직업은 스탯 데이터를 공유한다(캐릭터 테이블의 행 = 직업). 이번 문서는 고용 화면과 고용 흐름, 그리고 이를 위한 **캐릭터 단위 데이터**를 정한다.

## 2. 범위

- 포함: 캐릭터 단위 스탯·스트링 테이블 전환, 전투의 캐릭터별 스탯 적용, 고용 화면 배치, 고용 후보 목록, 고용 흐름(재화 차감·보유 인원 증가), 보유 용병 목록 표시, 진입·퇴장, 시작 보유 인원.
- 제외: 보유 로스터의 실제 데이터 시스템 전환(이번엔 기존 Placeholder 로스터에 인스턴스를 덧붙이는 임시 처리), 해고, 영구 사망, 성장·경험치, 마을별 후보 차별화, 정비창 팔레트·전투 화면의 이름 표시, 마차·시설 획득(마구간 등 다른 시설), 적 테이블.

## 3. 확정 사항 (사용자 결정, 2026-09-28)

### 3.1 캐릭터 데이터

| 항목 | 결정 |
|---|---|
| 데이터 단위 | **캐릭터(개체) 단위.** 캐릭터 한 명마다 스탯 행 1개와 스트링 행 1개를 가진다. 서로 다른 캐릭터가 스탯 행을 공유하지 않는다(예: 전사이름1 ≠ 전사이름2) |
| 테이블 구조 | 기존 캐릭터 스탯·스트링 테이블의 행을 캐릭터 단위로 바꾼다. 스탯 테이블에 직업 열과 고용비 열을 추가한다. 직업명(전사/궁수/방패병) 스트링은 직업 전용 테이블로 분리한다 |
| 등록 인원 | **직업당 5명, 총 15명**(보유 상한 5와 일치) |
| 이름 | Placeholder — `전사이름1`~`전사이름5`, `궁수이름1`~`궁수이름5`, `방패병이름1`~`방패병이름5` |
| 초기 스탯 | 현재 직업 스탯 값을 같은 직업 캐릭터 5명에게 그대로 복사(값은 이후 캐릭터별로 따로 조정 가능) |
| 고용비 | 스탯 테이블의 고용비 열, **잠정 전원 1,000** |
| 전투 적용 | **전투까지 적용.** 전투는 직업이 아니라 캐릭터 Id로 스탯을 조회한다. 직업은 역할군·방향성 지시 분류 용도로만 남는다 |

### 3.2 고용

| 항목 | 결정 |
|---|---|
| 로스터 반영 범위 | **화면 우선.** 고용 결과는 기존 Placeholder 로스터에 인스턴스를 덧붙이는 임시 처리. 보유 로스터의 실제 시스템 전환은 후속 기획 |
| 고용 후보 | **테이블에 등록된 캐릭터 중 아직 고용하지 않은 캐릭터**. 모든 마을 동일. 향후 수정 대상으로 기록(§6) |
| 보유 상한 | 직업당 5명 — 테이블 등록 인원이 직업당 5명이라 후보가 소진되면 자연히 상한에 도달 |
| 시작 보유 인원 | **직업당 2명**(각 직업 1·2번, 총 6명). 후보는 직업당 3명(3·4·5번) |
| 이름 표시 범위 | **고용 화면만.** 정비창 팔레트(직업당 1줄+잔여 수)·전투 표시는 변경 없음 |

## 4. 확정 사항 — 화면·흐름 (추천안 그대로 확정, 2026-09-28)

### 4.1 화면 구성

| 항목 | 결정 | 근거 |
|---|---|---|
| 가시성 | 재화 패널을 제외한 모든 UI 숨김 | 무역품 구매 화면(48번 §3.1)과 통일. 같은 모달 팝업 채널을 쓰면 추가 구조 불필요 |
| 좌측 | 보유 용병 패널 — 직업별로 묶어 이름 목록 표시, 직업 제목 옆에 보유 수(예: "궁수 2/5") | 무역품 구매의 "좌측 = 내 소지품" 배치와 대응 |
| 우측 위 | 고용 후보 목록 — 미고용 캐릭터를 한 줄씩: 직업 아이콘 + 이름 + 직업명 + 고용비 | 무역품 구매 리스트 한 줄 구성(48번 §4.2)과 대응. 직업 아이콘은 기존 로스터 아이콘 재사용 |
| 우측 아래 | 후보 정보 패널 — 이름, 직업명, 주요 스탯(최대 HP·공격력·방어력·사거리), 고용비, 고용 버튼. 선택 전에는 비워 둠 | 캐릭터별 스탯이 달라질 수 있으므로 고용 전에 비교할 수 있어야 함. 설명 문구는 테이블에 없어 표시하지 않음 |
| 후보 정렬 | 테이블 행 순서(전사 → 궁수 → 방패병, 번호순) | 정렬 기준이 정해진 적 없음 |
| 후보가 없을 때 | 목록 자리에 "고용 가능한 용병 없음" 문구 | 빈 목록만 보이면 오류와 구분이 안 됨 |

### 4.2 고용 흐름

| 항목 | 결정 | 근거 |
|---|---|---|
| 흐름 | 후보 선택 → 고용 버튼 → 재화 차감 + 해당 캐릭터를 보유 목록에 추가 → 후보 목록에서 제거, 좌측 목록에 즉시 추가 | 무역품 구매 A안과 같은 단순 흐름 |
| 1회 고용 인원 | 1명 | 무역품 구매와 통일 |
| 재화 차감 대상 | 기본 소지 재화만 | 골드 상자 결제 규칙 미정(48번과 동일) |
| 고용 불가 조건 | 재화 부족 → 고용 버튼 비활성 + 사유 문구. 선택·재화가 바뀔 때마다 다시 판정 | 무역품 구매와 같은 표시 규칙. 보유 상한은 후보 소진으로 자연 처리되지만, 방어적으로 "보유 상한" 사유도 둠 |
| 확인 창 | 없음 | 무역품 구매와 통일. 해고가 없어 취소 수단은 없음 |
| 정비창 반영 | 고용한 인원은 정비창 팔레트 보유 수에 바로 반영(예: "궁수 2/2" → "3/3") | 고용의 결과가 배치로 이어져야 의미가 있음 |
| 고용 직후 상태 | 최대 HP(자기 스탯 행의 최대 HP), 배치 가능 | 마을에서는 항상 만피(13번 §4) |

### 4.3 진입과 퇴장

| 항목 | 결정 | 근거 |
|---|---|---|
| 진입 | 주점 지구 depth에서 용병단 접촉 버튼 | 기존 카테고리 depth 구조 |
| 진입 시 열린 인벤토리 팝업 | 모두 닫음 | 시설 진입 공통 규칙(설계 50번 §6.1) |
| 퇴장 | 화면 안 "나가기" 버튼 → 주점 지구 depth로 복귀. 퇴장을 막는 조건 없음 | 임시 보관 같은 미정리 상태가 이 화면엔 없음 |

## 5. 캐릭터 테이블 (Placeholder 값)

- 행 Id는 `직업Id + 두 자리 번호`(예: `Warrior01`). 스트링 테이블의 같은 Id 행이 이름을 가진다.
- 직업 열 값은 기존 직업 Id(`Warrior`/`Archer`/`ShieldBearer`)를 그대로 쓴다 — 역할군 매핑·방향성 지시가 이미 이 값을 기준으로 한다.
- 스탯 값은 현재 직업 스탯 복사(§3.1). 고용비 전원 1,000.

| Id | 직업 | 이름(스트링) | 시작 보유 |
|---|---|---|---|
| Warrior01~05 | Warrior | 전사이름1~전사이름5 | 01·02 |
| Archer01~05 | Archer | 궁수이름1~궁수이름5 | 01·02 |
| ShieldBearer01~05 | ShieldBearer | 방패병이름1~방패병이름5 | 01·02 |

- 직업명 스트링(전사/궁수/방패병)은 직업 전용 테이블로 옮긴다(§3.1). 고용 화면·정비창 팔레트의 직업 표시는 이 테이블을 쓴다.
- 시작 보유 캐릭터를 테이블 열로 둘지 코드 상수로 둘지는 설계 단계 과제(§7).

## 6. 향후 수정 대상 기록 (사용자 지시)

- **고용 후보 방식**: 지금은 "테이블의 미고용 캐릭터 전부, 전 마을 동일". 마을별 후보 차별화, 후보 일부만 노출, 후보 갱신 주기 등으로 바꿀 수 있어야 한다. 후보 조회는 무역품 구매 판매 목록과 같이 "마을 + 시설"을 받는 형태로 열어 두고, 지금 구현만 전 마을 동일 목록을 돌려주게 한다(설계 단계 과제).
- **로스터 실체화**: 이번 고용은 Placeholder 로스터에 덧붙이는 임시 처리다. 보유 로스터 실제 시스템 전환 시 이 고용 흐름의 반영 대상만 교체한다.
- **이름**: `전사이름1` 등은 Placeholder. 실제 이름은 스트링 테이블 값만 교체한다.

## 7. 설계 단계로 넘길 기술 과제

- 캐릭터 테이블 전환: 행 단위 변경(직업 → 캐릭터), 직업 열·고용비 열 추가, 직업명 스트링 분리, 임포터·런타임 자산 변경. 새 테이블 자산은 "Play(자동 임포트) → Build Bootstrap Scene" 순서 필요.
- 전투 스탯 조회 경로 변경: 지금 직업으로 스탯을 찾는 지점(유닛 생성, 개체별 HP 저장소의 최대 HP 등)을 캐릭터 Id 기준으로 바꾸기. 직업이 계속 필요한 지점(역할군 매핑·방향성 지시)은 캐릭터 → 직업 조회로 유지. 이 변경은 battle 영역 코드에 걸치므로 브랜치 반영 순서 확인 필요(CLAUDE.md 머징 규칙).
- 배틀 테스트 씬: 자체 임시 로스터가 직업 단위로 유닛을 만든다(13번 §2). 캐릭터 단위 조회로 바뀔 때 영향 범위 확인.
- Placeholder 로스터가 "직업당 5명 고정 생성"에서 "시작 캐릭터 + 고용으로 증가"로 바뀔 때, 로스터를 읽는 소비자(정비창 팔레트 보유 수·배치 상한, 개체별 HP 저장소, 전투 편성)가 목록 변경을 어떻게 알게 할지.
- 로스터 인스턴스 Id를 캐릭터 Id와 같게 할지(현재 `character-warrior-1` 형식).
- 고용 처리: 재화 차감과 로스터 추가를 하나의 원자적 연산으로 묶기(무역품 구매 서비스 선례).
- 화면 UI는 "하드코딩으로 구현하되 리팩토링될 것을 염두"(`ui.md` §1-9). 무역품 구매 화면의 목록·정보 패널 구성 재사용 여부.
