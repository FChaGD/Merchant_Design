## 1. 배경

Hub의 `상행` 버튼이 기존에는 UI 없이 즉시 Field 씬으로 전환됐다. 상행을 시작하기 전에 출발지/도착지, 예상 소요·위험도, 현재 편성을 확인하고 배치를 마무리할 수 있는 중간 화면(상행 준비 UI)을 추가한다.

이번 라운드는 **UI 구성과 화면 전환 흐름만** 다룬다. 지역/경로/보상을 실제로 계산하는 데이터·로직 시스템은 범위 밖이며 후속 기획이 필요하다 ([[01-2026-08-25-게임개요_핵심루프]]의 "남은 미정 사항"과 동일한 성격).

## 2. 진입 흐름

```
Hub 씬
 ├─ [상행] 버튼 → 상행 준비 UI 오픈
 │     ├─ [배치] 버튼 → 화면 전체가 배치(Formation) UI로 전환
 │     │      └─ 배치 UI의 종료 버튼 → 상행 준비 UI로 되돌아감
 │     ├─ [상행 시작] 버튼 → Field 씬 전환 (편성 인원 제약 없음, 항상 활성화)
 │     └─ [닫기] → Hub로 복귀
 └─ [배치] 버튼(Hub 레벨, 기존) → FormationPanel 오픈 (상행 준비 UI를 거치지 않는 경로도 계속 유효)
```

Hub 레벨의 기존 `배치` 버튼은 그대로 유지한다 — 두 진입 경로(Hub 직접 / 상행 준비 UI 경유) 모두 유효하다.

### 3.1 지도 UI 및 출발/도착 결정 로직

> **2026-08-23 개정**: 출발/도착 핀은 더 이상 지도에 고정 배치되지 않는다. [[03-2026-08-23-상행준비UI_디버그도시배치]](디버그 전용 기능)로 지도 위에 임의 배치한 도시 아이콘이 그 역할을 대체하며, 아래 역할 지정 로직은 **정식 게임 기능**이다(디버그 기능이 사라지고 실제 지역 시스템이 들어와도 이 로직은 유지된다).

- 정적 배경 위에 (디버그 기능으로) 배치된 도시 아이콘들이 표시된다. 다중 경로 선택 등은 범위 밖.
- 드래그로 상하좌우 이동, 마우스 휠로 확대/축소.
- 도시 아이콘 클릭은 정보 패널을 채우는 유일한 트리거다 — UI가 열리자마자 자동으로 채워지지 않는다.

**출발/도착 역할 지정 규칙** (상태 기반):
- **미배정 상태** (출발지·도착지 모두 없음): 도시를 클릭하면 그 도시가 **출발지**로 지정된다.
- **출발지만 배정된 상태** (출발지=X):
  - 클릭한 도시가 X와 같으면: 출발지 지정이 취소되어 미배정 상태로 돌아간다.
  - 클릭한 도시가 X와 다르면(Z): Z가 **도착지**로 지정된다(→ 출발/도착 모두 배정 상태).
- **출발/도착 모두 배정된 상태** (출발지=X, 도착지=Y): 어떤 도시(Z)를 클릭하든 — X, Y, 제3의 도시 어느 쪽이든 — 기존 출발/도착 지정이 모두 취소되고, 그 클릭이 "미배정 상태에서의 첫 클릭"으로 취급되어 Z가 새 출발지로 지정된다(→ 출발지만 배정된 상태로 전이). 따라서 이 상태에서 같은 도시를 연속 두 번 클릭하면 결과적으로 완전 미배정 상태로 돌아간다.
- 도시가 삭제되면([[03-2026-08-23-상행준비UI_디버그도시배치]] 4.3) 그 도시가 맡고 있던 역할(출발 또는 도착)만 미배정으로 바뀌고, **반대편 지정은 그대로 유지**된다.

**경로 존재 게이팅 규칙** (정식 기능):
- 출발지가 지정된 상태에서 도착지를 선택하려 할 때(위 "출발지만 배정된 상태"에서 X와 다른 도시 Z를 클릭하는 경우), **두 도시(X, Z) 사이에 경로가 존재하지 않으면 도착지로 지정되지 않는다** — 클릭은 아무 효과 없이 무시되고 "출발지만 배정된 상태"가 그대로 유지된다.
- 이 규칙은 "출발/도착 모두 배정된 상태"에서 새 출발지를 다시 고르는 클릭(전체 리셋 후 Z가 새 출발지가 되는 전이)에는 적용되지 않는다 — 그 전이는 항상 성공한다. 경로 존재 여부는 오직 **도착지 지정** 시점에만 확인한다.
- **경로 데이터 출처**: 실제 경로 시스템이 아직 없으므로, 현재는 [[04-2026-08-23-상행준비UI_디버그경로연결]]에서 디버그로 그린 연결선을 "두 도시 사이 경로 존재 여부"의 데이터 소스로 그대로 사용한다 — 즉 이 정식 로직을 테스트하려면 먼저 디버그 경로 연결 기능으로 두 도시를 이어놔야 한다. 실제 지역/경로 시스템이 설계되면 데이터 소스만 교체되고(예: 읽기 전용 인터페이스의 구현체 교체), 이 게이팅 규칙 자체는 유지된다.
- **경로 삭제의 소급 효과 없음**: 디버그 경로 연결(04번 문서)에서 이미 게이팅에 쓰인 연결선을 나중에 삭제하더라도, 그 경로로 이미 성립된 출발/도착 배정은 **그대로 유지**된다(자동 해제하지 않음). 경로 존재 확인은 배정 "시점"에만 이뤄지는 1회성 검사이며, 배정된 이후에는 지속적으로 재검증하지 않는다.

**남은 미정 사항**: 경로가 없어 선택이 거부될 때 사용자에게 별도 피드백(예: 안내 메시지)을 줄지 여부는 설계 단계에서 결정.

### 3.1.1 정보 패널을 통한 출발/도착 재지정 (정식 기능)

지도 위 도시를 순서대로 클릭해 배정하는 3.1절의 기본 흐름과 별개로, 출발지·도착지 정보 패널(`TripLocationInfoView`) 각각에 **변경 모드 on/off**를 추가해 이미 지정된 출발지 또는 도착지 하나만 골라 다시 지정할 수 있게 한다.

**모드 켜기/끄기**
- 출발지 패널을 클릭하면 "출발지 변경 모드"가 켜진다. 도착지 패널을 클릭하면 "도착지 변경 모드"가 켜진다.
- 두 모드는 상호 배타적이다 — 하나를 켜면 다른 하나는 자동으로 꺼진다.
- 도시를 아직 선택하지 않은 상태에서 켜져 있는 패널을 다시 클릭하면 모드가 취소(off)된다.
- 모드가 켜진 상태에서 도시 지정에 **성공**하면 모드는 자동으로 꺼진다(1회성). 경로가 없어 지정이 **거부**된 경우는 모드가 꺼지지 않고 유지되어 바로 다른 도시로 재시도할 수 있다.

**도시 클릭 시 동작** (모드가 켜진 동안 대상 역할을 R, 반대 역할을 R'이라 함)
1. 클릭한 도시가 이미 R로 지정된 도시(자기 자신)면: R 지정이 취소되어 미배정 상태가 된다. 모드는 꺼진다.
2. 클릭한 도시가 이미 R'(반대 역할)로 지정된 도시면: **역할을 서로 교환(swap)**한다 — 경로 게이팅 없이 무조건 성공한다(두 도시가 이미 출발/도착으로 지정돼 있었다는 것 자체가 둘 사이에 경로가 있다는 뜻이므로, 교환해도 게이팅 규칙이 깨지지 않는다). 모드는 꺼진다.
3. R'이 이미 지정돼 있고, 클릭한 도시가 그 자신도 R'도 아닌 제3의 도시 Z인 경우: Z와 R' 사이에 경로가 있으면 R := Z로 지정(성공, 모드 off). 경로가 없으면 지정이 거부되고 모드는 켜진 채로 유지된다.
4. R'이 아직 미배정인 경우: 클릭한 도시 Z가 먼저 R로 지정된다(비교할 반대편이 없으므로 게이팅 없이 무조건 성공). 모드는 즉시 "R' 지정 대기"로 전환되어, 다음 도시 클릭이 R'을 지정하는 시도가 된다.
   - 이 다음 클릭에서 경로가 있으면 R' 지정도 성공하고 모드가 꺼진다.
   - 경로가 없으면 R' 지정만 거부되고, 방금 성공한 R 지정은 그대로 유지된다(부분 성공) — "R' 지정 대기" 상태가 유지되어 다른 도시로 바로 재시도할 수 있다.

이 흐름도 경로 데이터 출처는 3.1절과 동일하게 당분간 [[04-2026-08-23-상행준비UI_디버그경로연결]]의 디버그 연결선을 사용한다.

### 3.2 상행정보 패널
- 4개 항목 모두 실제 데이터 시스템이 없어 값은 placeholder. 항목 자리만 확정한다.
- "현재 편성 요약"은 별도 데이터 소스를 새로 만들지 않고 배치(Formation) UI가 이미 갖고 있는 편성 데이터를 그대로 읽어 표시한다.

## 4. 화면 전환 규칙

- 상행 준비 UI → 배치 UI: **화면 전체가 전환**된다(오버레이 아님). 상행 준비 UI는 가려지고, 배치 UI의 기존 종료 버튼이 "되돌아가기"를 겸해 상행 준비 UI로 복귀시킨다.
- 이 왕복은 배치 UI를 프리팹으로 복제하지 않고, 기존처럼 하나의 `FormationPanel` 인스턴스를 그대로 재사용한다 — 어느 경로로 들어왔는지는 UI 매니저가 화면 전환 스택으로 기억한다 (구현 세부는 설계 문서 참고).

## 5. 게이팅 규칙

- `상행 시작` 버튼은 편성 인원 수와는 **무관하게** 활성화한다(0명이어도 상행 가능 — 편성 최소 조건 검증은 이번 범위 밖).
- 다만 **출발지와 도착지가 모두 배정돼 있어야** `상행 시작` 버튼이 활성화된다(3.1절/3.1.1절). 둘 중 하나라도 미배정이면 비활성화 상태를 유지한다. (2026-08-23 개정: 출발/도착이 고정 핀이 아니라 동적 배정으로 바뀌면서 추가된 조건.)

## 8. 2026-09-03 개정 — 출발/도착 지정 로직 전면 재설계 (3.1/3.1.1/5절 대체)

3.1절/3.1.1절/5절의 출발/도착 지정 로직은 [[16-2026-09-03-상행_출발도착_지정_로직_재설계_기획]](설계 [21번](../설계/21-2026-09-03-상행_출발도착_지정_로직_재설계_아키텍처.md))으로 전면 재설계되어 **제작까지 완료**됐다. 핵심 변경:

- **출발지**: 더 이상 사용자가 지정하지 않는다. "플레이어가 현재 체류 중인 지역"(신규 상태, `ITripCurrentLocationReader`)으로 자동 고정 — 3.1절 "출발/도착 역할 지정 규칙"과 3.1.1절 "정보 패널을 통한 재지정" 전체가 폐기됐다.
- **도착지**: 지도 클릭으로만 지정(정보 패널을 통한 재지정도 폐기, 지도 클릭으로 통일) — 현재 위치에서 경로를 거쳐 도달 가능한 도시만 선택 가능(직접 인접이 아니어도 됨 — 경로 탐색 도입, 기획 16번 §6.1).
- **게이팅**(5절): "출발지와 도착지가 모두 배정돼야" → "도착지만 배정되면" 활성화로 단순화.
- 상행 도착 판정이 성립하면(6번 기획, Field 씬) "현재 위치"가 그 상행의 도착지로 갱신된다 — 다음 상행 준비 UI의 출발지가 자동으로 바뀐다.

이 문서의 위 3.1/3.1.1/5절 본문은 v1(2026-08-23) 설계의 기록으로만 남겨둔다 — 실제 동작은 기획 16번/설계 21번을 따른다.
