## 1. 배경

26번 문서 §3.3이 재화 계열/행정력 계열의 UI 표시 공간을 분리해야 한다고 정했으나 구체적인 화면 구성은 범위 밖으로 남겼다. 이번 기획은 재화 계열 쪽의 화면 구성을 Hub 씬 기준으로 확정한다.

## 2. 범위

- Hub 씬 우상단에 재화 계열 자원을 표시하는 패널의 구성 원칙을 정의한다.
- 행정력 계열 패널(26번 §3.3, 별도 위치)은 범위 밖.
- Field 씬 적용 여부는 범위 밖 — 사용자가 이번 요청에서 Hub만 명시했다.
- 패널의 정확한 좌표/크기, 아이콘 그래픽 자체, 값 변경 시 연출(애니메이션 등)은 설계/제작 단계 재량.

## 3. 확정 사항 (사용자 스펙, 2026-09-21)

### 3.1 위치/스타일

Hub 씬 화면 우상단에 배치한다(2026-09-21 변경 — 최초에는 좌상단으로 정했으나 우상단으로 이동). 스타크래프트류 RTS 자원 바와 동일한 형태 — 패널 안에 "아이콘 + 수치" 조합을 가로로 나열한다.

### 3.2 수치값 표시 형식

UI에는 현재값만 상시 표기한다(예: "820"). 상한은 항상 함께 노출하지 않고, 수치값에 마우스를 호버했을 때 툴팁으로 보여준다(예: "상한 1,000"). 재화 상한 초과 시 초과분이 손실되는 규칙(23번 §3.1)은 여전히 유효한 제약이지만, 상시 노출보다는 필요할 때 확인하는 보조 정보로 다룬다(2026-09-21 변경 — 최초에는 "현재/상한" 상시 병기로 정했으나 취소).

### 3.3 패널 구조 — 목록형(확장 가능)

패널은 자원 종류별 행(아이콘+수치)을 나열할 수 있는 목록형 구조로 설계한다. 재화 계열에 향후 자원(적재 재화 등)이 추가되면 같은 목록에 행을 추가하는 방식으로 확장한다.

지금은 재화(기본 소지 재화, `IPlayerCurrencyReader`) 하나만 실데이터로 채운다. 적재 재화는 마차/인벤토리 시스템 자체가 없어 아직 표시할 대상이 없다(26번 §4) — 이번 기획에서 빈 슬롯을 미리 만들어두지는 않는다. 목록형으로 설계하는 것은 "구조가 확장에 열려 있어야 한다"는 뜻이고, 존재하지 않는 자원의 자리를 미리 예약해두는 것은 아니다.

### 3.4 갱신 방식

`IPlayerCurrencyReader.OnAmountChanged` 이벤트를 구독해 값이 바뀔 때만 갱신한다 — `Update()` 폴링 금지(CLAUDE.md 최적화 컨벤션).

### 3.5 다른 패널과의 중첩 동작

정비창/상행 준비/방향성 지시 패널(Formation/Trip/Tactics)은 화면 전체를 덮는 구조라 열리면 우상단도 함께 가려질 수 있다. 재화 패널은 `HubUIController`의 상단 버튼(다른 패널이 열리면 숨김)과 다르게, **다른 패널이 열려도 가려지지 않고 항상 최상단에 표시**한다(2026-09-21 확정) — 상시 상태 노출이 우선이라는 RTS 자원 바 컨벤션에 맞춘 것이다.

## 4. 이 기획이 건드리지 않는 것

- 행정력 계열 패널의 위치/구성.
- Field 씬 적용 여부.
- 아이콘 그래픽 에셋, 패널의 정확한 좌표/크기.
- 값 변경 시 시각 효과(반짝임 등).
- 적재 재화가 실제로 추가될 때 행이 몇 개/어떤 이름으로 표시될지 — 마차/인벤토리 시스템 설계 후 결정.

## 5. 설계 단계로 넘길 기술 과제

- 패널/행 컴포넌트 명명 및 배치 — 기존 UI 패널 패턴(`XxxPanel`/`XxxView`/`UIElementMarker`+`XxxUIElementIds`) 재사용 여부.
- 목록형 구조를 코드로 어떻게 구성할지 — get-or-create 재사용 원칙에 따라 자원 종류가 늘어날 때 행을 늘리는 방식(정비창 팔레트의 카테고리 행 생성 패턴, 설계 16번 참고 가능).
- `IPlayerCurrencyReader`를 이 패널이 어느 계층에서 조회해 전달받을지(Hub UI Wiring에서 TryResolve 후 전달하는 기존 패턴 재사용 여부).
- 상한 툴팁 구현 방식 — 기존 툴팁 컴포넌트가 있는지 조사 후 재사용, 없으면 신규 최소 구현(호버 시 표시/해제만, 애니메이션 등은 범위 밖).
- §3.5 "항상 최상단 표시"를 정렬 순서(Canvas sortingOrder)로 처리할지, 다른 패널과 별개의 Canvas/계층으로 분리할지 — 기존 씬 전환 커튼(`SceneTransitionCanvas`, sortingOrder 100)과의 순서 관계도 함께 확인 필요.
