# 공격 중 이동 정지·도주 모션 캔슬·달리기 아키텍처

작성일: 2026-11-27
상태: 확정(2026-11-27 섹션 승인), 제작 완료(2026-11-27, EditMode 1090/1090, CLI 가져오기·씬 빌드·Play 확인) - 사용자 인게임 판단 대기, 메인 미커밋
근거: [기획 122 유닛·전투 표현 에셋](../기획/시스템/122-2026-11-25-유닛_전투_표현_에셋_기획.md) §8.6·§8.7, [설계 124 유닛 공격 애니메이션·타격 판정](124-2026-11-27-유닛_공격_애니메이션_타격_판정_아키텍처.md)
범위: 배틀 테스트 씬(설계 124와 같음) - 시뮬레이션 변경은 애니메이션 세트가 있는 유닛에만 효과

---

## 1. 목적

공격 동작 도중 캐릭터가 미끄러지듯 움직여 어색한 문제를 없앤다(사용자 인게임 판단, 기획 122 §8.6). 공격 애니메이션이 끝날 때까지 AI 이동을 멈추고, 공격 중 도주가 결정되면 짧은 딜레이 뒤 자연스럽게 동작을 끊는다. 이동 애니메이션은 달리기로 바꾼다.

## 2. 범위

| 구분 | 내용 |
|---|---|
| 목표 | 공격 중 AI 이동 정지, 공격 중 도주 모션 캔슬 딜레이, 이동 = 달리기 |
| 비목표 | 밀어내기·장애물 빼내기 정지, 애니메이션 없는 유닛의 동작 변경, Field 실전투 적용, 걷기/달리기 속도 구분 |
| 실패 조건 | 애니메이션 없는 유닛의 이동·도주 시점이 바뀜(회귀) / 공격 중 유닛이 AI 이동으로 움직임 / 도주 결정 뒤 영원히 도주하지 않음 / 취소된 공격 그림이 계속 재생됨 |

## 3. 기획 확정 사항 (기획 122 §8.7, 사용자 2026-11-27)

| 항목 | 내용 |
|---|---|
| 멈추는 범위 | AI 이동(접근·포지셔닝·복귀)만. 같은 편 밀어내기·장애물 빼내기 유지 |
| 멈추는 시간 | 공격 애니메이션 끝까지(검사 0.83초, 약탈자 0.67초). 애니메이션 없는 유닛은 멈추지 않음 |
| 공격 중 도주 | 모션 캔슬 딜레이 0.25초(83ms × 3), 딜레이 동안 제자리 |
| 도주 시작 시점 | ① 타격이 이미 났거나 딜레이 안에 나면 → 피해 발생, 애니메이션 끝까지 재생 후 도주 ② 딜레이 안에 타격 프레임 미도달 → 0.25초 뒤 공격 취소(피해 없음) 후 도주 ③ 딜레이 전에 애니메이션이 끝나면 그때 도주 |
| 이동 애니메이션 | 항상 달리기(검사 `run_hydra`, 도적1 `bandit1_run_hydra`), 걷기 클립은 게임 데이터에서 제외 |

## 4. 접근

설계 124 A안을 확장한다 - 시뮬레이션이 공격 클립 데이터에서 타격 전 시간과 함께 **클립 전체 길이**를 읽어 "공격 중" 상태를 직접 관리한다. 다른 안은 남지 않는다: 화면이 애니메이션 종료를 알리는 방식은 설계 124 B안과 같은 문제(판정이 화면에 묶임), 테이블 값은 타이밍 파일과 이중 관리.

## 5. 설계

### 5.1 시뮬레이션 (`BattleCharacterUnit`)

| 항목 | 내용 |
|---|---|
| 공격 길이 | 생성자에서 한 번: `Attack` 클립 `TotalSeconds`(없으면 0). 설계 124의 타격 지연과 같은 데이터 경로 |
| 공격 중 상태 | 공격 시작 시 남은 공격 시간 = 공격 길이. 매 틱(생존 확인 직후, 대기 중 타격 진행과 같은 위치) 감소. 0보다 크면 "공격 중" |
| 이동 정지 | `MoveToward`(교전·포지셔닝·복귀 이동이 모두 지나는 한 곳) 맨 앞에서 공격 중이면 반환. 디버그 목적지 표시도 이동 의도 없음과 같게 둔다(제작자 판단). `ResolveOverlaps`(밀어내기·장애물 빼내기)는 별도 경로라 영향 없음. 대상 선택·쿨타임 감소는 계속 |
| 다음 공격 | 공격 시작 조건에 "공격 중 아님" 추가(설계 124의 "대기 중 타격 없음" 조건을 대체·포함). 현재 데이터(0.83초 < 간격 1초)에서는 영향 없음 |
| 도주 결정 | `TryRollFleeCheck`가 도주를 결정한 순간(`isFleeing = true`) 공격 중이면 **도주 보류** 시작: 남은 딜레이 = 0.25초. 도주 판정·사기 파동 등 도주 결정 자체의 효과는 그대로 |
| 보류 중 틱 | 도주 분기 안에서 `TickFlee` 대신 보류 처리: 대기 중 타격은 계속 진행(설계 124의 "도주 시 즉시 취소" 규칙 폐기)해 시점이 되면 피해. 딜레이 감소. 위치 고정(이동 없음, 밀어내기·장애물 빼내기는 유지) |
| 보류 해제 | 공격 중이 끝나면 → 도주 이동 시작(①·③). 딜레이가 0 이하이고 대기 중 타격이 남아 있으면 → 타격 취소, 남은 공격 시간 0, 새 이벤트 `OnAttackCanceled` 발행, 도주 이동 시작(②). 타격이 이미 났으면 딜레이가 끝나도 공격 중이 끝날 때까지 보류 유지(①) |
| 애니메이션 없는 유닛 | 공격 길이 0 → 공격 중 상태가 생기지 않아 이동 정지·도주 보류 없음, 도주 즉시 시작(현행) |
| 인터페이스 | `IBattleCombatant`에 `event Action OnAttackCanceled` 추가. 구현체: `BattleCharacterUnit`, 테스트 가짜 2개 |
| 상수 | 모션 캔슬 딜레이 0.25초 - 유닛 내부 상수(튜닝 값, 기획 122 §8.7 근거 주석) |

도주 보류 상태 흐름:

```
도주 결정 ─ 공격 중 아님 ──────────────────────────→ 즉시 도주 이동
          └ 공격 중 → 보류(딜레이 0.25초, 제자리)
                 ├ 타격 났음(전/중) ─ 공격 끝날 때까지 대기 → 도주 이동
                 ├ 딜레이 끝, 타격 전 ─ 타격 취소 + OnAttackCanceled → 도주 이동
                 └ 딜레이 전 공격 끝 ─────────────────→ 도주 이동
```

### 5.2 화면 (`BattleCharacterUnitView`)

| 항목 | 내용 |
|---|---|
| 공격 취소 | `OnAttackCanceled` 구독·해제. 받으면 공격 재생 상태 해제 후 이동 여부에 따라 이동/대기 클립 재생 |
| 그 외 | 변경 없음 - 클립 종료 시 복귀(설계 124), 보류 중엔 공격 클립이 그대로 재생됨 |

### 5.3 데이터 (달리기)

- `ArtSource/UnitAnim/import.txt`: `Warrior Front Walk` 원본 `2026-11-26/walk_bounce_hydra` → `2026-11-26/run_hydra`, `Marauder Front Walk` 원본 `2026-11-26/bandit1_walk_hydra` → `2026-11-26/bandit1_run_hydra`. 타이밍은 기존 채택 파일의 달리기 줄(검사 `2:67 4:133 6:67 8:133`, 도적1 `1:67 3:133 5:67 7:133`).
- 동작 이름 `Walk`는 "이동 상태" 이름으로 유지(`UnitSpriteClipNames.Walk` 주석 보강). 화면 코드 변경 없음.
- 크기: 가져오기는 원본 1번 프레임 기준으로 잰다. 달리기 1번이 시작 자세와 달라 대기와 크기가 어긋나면 캡처로 확인 후 보고(조정은 후속).

## 6. 검증

### 6.1 EditMode 테스트 (`BattleUnitAttackTimingTests` 확장)

| 테스트 | 내용 |
|---|---|
| 공격 중 이동 없음 | 공격 시작 후 대상이 사거리 밖으로 이동해도 공격 길이 동안 위치 불변(밀어내기 없는 단독 유닛), 끝나면 접근 이동 재개 |
| 애니메이션 없음 회귀 | 같은 시나리오에서 대상이 벗어나면 즉시 접근 이동 |
| 도주 ① | 타격 후 도주 결정 → 공격 끝날 때까지 위치 불변, 이후 도주 이동 |
| 도주 ② | 타격 전(딜레이보다 예비 동작이 길게 남은 클립) 도주 결정 → 0.25초 뒤 `OnAttackCanceled`, 피해 없음, 도주 이동 시작 |
| 도주 ①-딜레이 안 타격 | 딜레이 안에 타격 → 피해 발생, 공격 끝까지 보류 |
| 도주 ③ | 딜레이보다 짧게 남은 공격 → 공격 끝에 도주 이동 |

- 도주 유도 방법(사기 값을 낮추는 방법, `UnityEngine.Random` 시드 고정 등)은 제작자 판단. 확률 판정을 결정적으로 만들 수 없으면 도주 결정 진입점을 테스트에서 호출할 수 있게 하는 최소 변경을 허용(내부 공개 범위 `internal`, `InternalsVisibleTo("Game.Core.Tests")` 기존 설정 이용).
- 기존 전체 EditMode 회귀.

### 6.2 실행 확인 (Unity CLI)

1. `Tools/Game/Art/Import Unit Animations` → `Tools/Game/Debug/Build Battle Test Scene` → 저장.
2. Play: 달리기 표시, 공격 중 정지(위치 로그), 콘솔 오류 0. 달리기 크기 캡처.
