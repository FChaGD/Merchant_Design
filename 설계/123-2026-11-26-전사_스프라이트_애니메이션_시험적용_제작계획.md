# 전사 스프라이트 애니메이션 시험 적용 제작계획

> 실행: 이 세션에서 직접(executing-plans). 단계는 체크박스로 추적.

**Goal:** 배틀 테스트 씬 아군 전사에 대기(C v2)·이동(E v4) 스프라이트 애니메이션을 붙인다.
**Architecture:** 가져오기 메뉴가 ArtSource 타이밍 파일 → 프레임 PNG·데이터 에셋 생성. 전투 유닛이 세트를 표시 힌트로 들고, 유닛 표시 오브젝트가 그림 전용 자식 렌더러로 재생한다.
**Tech Stack:** Unity 6000.3, Built-in 렌더 파이프라인, NUnit EditMode, Unity CLI.
**Spec:** [설계 123](123-2026-11-26-전사_스프라이트_애니메이션_시험적용_아키텍처.md)

## Global Constraints

- 그림 높이 1m, 판정 크기 불변. 진영 색 곱하기 금지. 앞모습만, 좌우 반전 없음.
- 이동 판정: 0.05m/s 초과 = 이동, 이동→대기는 0.15초 연속 정지.
- 피격 덮기 0.1초, 사망 중 덮지 않음.
- Field(`LiveBattleSimulationRule`) 경로는 수정하지 않는다. 세트 null이면 기존 표시와 동일.
- `.unity`/`.prefab` 직접 편집 금지 - 인스톨러·빌더로만.

## Review Focus

1. 풀 재사용: 그림 유닛 → 그림 없는 유닛으로 재사용될 때 루트 렌더러가 다시 켜지고 게이지 위치가 기본값으로 돌아와야 한다(Task 4 테스트).
2. 정지 판정 첫 프레임: Bind 직후 첫 Update에서 위치 변화가 0이어도 대기로 시작해야 한다(Task 2 테스트).
3. 1회 재생 클립·delta가 클립 전체보다 큰 경우 프레임 인덱스가 범위를 넘지 않아야 한다(Task 2 테스트).
4. 같은 프레임 재사용(13→11→13) 타이밍이 그대로 재현되어야 한다 - 가져오기가 중복 프레임을 하나의 파일로 두고 배열에서 반복 참조(Task 3 검증).
5. 가져오기 재실행 시 설정에서 빠진 프레임 파일 삭제, 데이터 에셋 GUID 유지(Task 3 검증).
