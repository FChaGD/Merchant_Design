## 1. 핵심 결정 — `BattleUnitStats`는 그대로 두고, `BattleCharacterUnit`에 시작 체력만 별도로 받는다

설계 15번 §1은 "저장된 HP == 이번 전투 만피"로 취급해 `LiveBattleSimulationRule.BuildAllies()`가 `BattleUnitStats.MaxHp` 자체를 저장된 값으로 바꿔치기했다(`LiveBattleSimulationRule.cs:200-203`). 이 결정을 폐기한다.

대신 `BattleCharacterUnit` 생성자에 선택적 매개변수 `startingHp`를 추가한다 — 넘기지 않으면(`null`) 기존과 동일하게 `stats.MaxHp`로 시작한다(적/배틀테스트 씬 등 나머지 모든 호출부는 무변경).

```csharp
public BattleCharacterUnit(
    Vector2 startPosition, bool isAlly, BattleUnitStats stats, IDamageFormula damageFormula,
    PartyMorale partyMorale, MoraleWaveCoordinator waveCoordinator, IUnitSpatialQuery spatialQuery, float fleeTravelDistance,
    UnitTacticsBehaviors tacticsBehaviors = null, Sprite icon = null, float? startingHp = null)
{
    ...
    currentHp = Mathf.Clamp(startingHp ?? stats.MaxHp, 0f, stats.MaxHp);
}
```

`Mathf.Clamp` 상한을 두는 이유 — 저장된 값과 만피가 항상 일치한다는 보장이 없어졌다(직업 테이블 값이 나중에 바뀌는 등). 방어적으로 만피를 넘지 않게만 막는다. `BattleUnitStats`/`IDamageable`/`IBattleCombatant`는 필드·시그니처 무변경.

## 2. `LiveBattleSimulationRule.BuildAllies()` 변경

기존(196-203줄, 폐기):

```csharp
if (unitConditionRepository != null && unitConditionRepository.TryGetCurrentHp(unitId, out var currentHp))
{
    stats = new BattleUnitStats(currentHp, stats.Attack, stats.Defense, stats.MoveSpeed, stats.AttackInterval, stats.Range, stats.MoraleSyncRate, stats.HpRegenPerSecond, stats.EnemyType);
}
```

변경 후 — `stats`는 항상 `statProvider.GetStats(mercenaryClass)`(직업 기준 고정 만피) 그대로 두고, 저장된 값은 별도 지역 변수로만 뽑아 생성자에 전달한다:

```csharp
float? startingHp = null;
if (unitConditionRepository != null && unitConditionRepository.TryGetCurrentHp(unitId, out var savedHp))
{
    startingHp = savedHp;
}
```

```csharp
var characterUnit = new BattleCharacterUnit(position, isAlly: true, stats, damageFormula, allyMorale, allyWaveCoordinator, spatialQuery, fleeTravelDistance, tacticsBehaviors, startingHp: startingHp);
```

전투 종료 시 저장(`SyncRosterConditionFromBattle`, `Report()`)은 무변경 — `unit.CurrentHp`를 그대로 저장소에 되돌려 쓰는 경로라 이미 올바르다.

## 3. 이 설계가 건드리지 않는 것

- `BattleUnitStats` — 필드/생성자 무변경.
- `IUnitConditionRepository`/`InMemoryUnitConditionRepository`/`FieldUIController`의 상행 시작·종료 리셋 타이밍(설계 15번 §2/§4) — 기획 18번 §3에 따라 무변경.
- `BattleTestSimulationRule`(배틀 테스트 씬) — `startingHp`를 넘기지 않아 기존과 동일하게 동작.
- 적 유닛 생성(`BuildEnemies`) — `startingHp` 미사용, 무변경.

---

## 4. 제작 체크리스트

1. `BattleCharacterUnit` 생성자에 `float? startingHp = null` 추가, `currentHp` 초기화식 교체(§1).
2. `LiveBattleSimulationRule.BuildAllies()`의 `stats` 치환 로직을 `startingHp` 지역 변수 추출로 교체(§2).
3. 체력 게이지바로 실전 재검증 — 상행 중 두 번째 전투부터 시작 체력이 이전 전투 종료 시점 체력으로 정확히 표시되는지 확인.
