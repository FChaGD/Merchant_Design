## 1. 목적

설계 103에서 화면과 계약(`ICaravanAssetSaleService`)만 두고 Placeholder가 매각 실행을 무동작으로 채웠다. 이 문서는 실제 매각(골드 지급·보유 제거·대열 정리·마을 재고 반환)을 정하고 Placeholder를 제거한다. 화면은 바꾸지 않는다.

## 2. 결정 사항

| 항목 | 결정 | 출처 |
|---|---|---|
| 매각 불가 판정 | 미보유 → 화물 있는 마차 → 마지막 마차(기존 `CaravanAssetSaleRules` 유지) | 기획 94 4-20 |
| 매각가 | ⌊구매가 × 매각 비율(0.5, 인스펙터) × 현재 내구도 ÷ 최대 내구도⌋. 내구도 기록이 없거나 최대 ≤ 0이면 비율 1. 화면 표시가도 같은 계산 | 사용자 결정(2026-10-27) |
| 마을 재고 | 판 마을(현재 위치)의 그 종류 재고 +1. 그 마을에 해당 종류 행이 없으면 행을 새로 만든다(수량 1, 목록 끝) | 사용자 결정(2026-10-27) — 기획 80 §3-6 매각 예외 |
| 골드 지급처 | 개인 골드에 더한다(상한 없음 - 출발 시 초과분 버림, 기획 82) | 설계 판단 |
| 대열 정리 | 전투 파괴와 같은 공용 파괴 처리(`CaravanAssetDestroyer`) — 그 마차 영역의 유닛은 빈 칸으로 재배치, 둘 곳이 없으면 팔레트 복귀. 대열이 끊기면 상행 준비의 기존 출발 판정이 막는다 | 설계 판단 |
| 구조 | 접근안 A — 실제 서비스 1개 + 파괴 처리 재사용 + 좁은 계약 2개(골드 수입·재고 반환) | 사용자 승인(2026-10-27) |

기각안: B(Placeholder 확장 + 이벤트 골드 계약·재고 차감 계약 재사용 — 매각에 이벤트 전용 조작, 구매에 반환 권한이 노출되는 ISP 위반), C(매각 전용 대열 정리 — 파괴 처리와 중복).

## 3. 처리 순서

`TrySell(instanceId)`:

1. 판정이 Available이 아니면 false.
2. 매각가·종류 Id·재고 분류를 계산해 둔다 — 보유에서 빠지면 내구도 기록과 개체 정보가 사라지므로 **제거 전에** 계산한다.
3. 공용 파괴 처리로 대열 정리 + 보유 제거. 제거 후 여전히 보유 중이면(제거 실패) false — 골드·재고를 건드리지 않는다.
4. 현재 마을 재고에 반환. 실패해도(위치 없음·판매 불가 마을) 매각은 유지하고 경고만 남긴다 — 구매의 재고 차감 실패 처리(설계 81 §4.1)와 같은 방침.
5. 개인 골드 지급, true.

보유 제거와 함께 화물 섹션·내구도 기록이 보유 변경 알림으로 지워지고, 같은 종류 개체 번호가 당겨진다(기존 동작). 화면은 보유 변경 이벤트로 목록으로 돌아간다(설계 103 §4.6 기존 동작).

## 4. 계약과 구현체

| 대상 | 내용 |
|---|---|
| `IGoldIncome`(신규, `GoldContracts.cs`) | `int Earn(int amount)` — 개인 골드에 더하고 실제 더한 양(0 이하 요청은 0). 이벤트 골드 계약(`IGoldEventAdjuster`)에 넣지 않은 이유: 매각 소비자에게 "가진 만큼 잃기"·골드 아이템 판별 같은 이벤트 전용 조작을 노출하지 않기 위해(ISP). `GoldHoldingsService`가 구현·등록하고 내부는 기존 `GoldLedger.Gain`을 쓴다 |
| `ITownStockReturner`(신규, `TownStockContracts.cs`) | `bool TryReturn(int cityId, TownStockCategory category, string itemId)` — 반환 전용(ISP, 매각 서비스만 사용). 차감 계약(`ITownStockConsumer`) 주석의 "늘리는 연산이 없는 이유"를 "파손·파괴로는 늘지 않고 매각만 예외(기획 80 §3-6 개정)"로 고친다. `InMemoryTownStockRepository`가 구현·등록, 성공 시 `OnStockChanged` |
| `TownStockLedger.TryReturn` | 같은 종류 행이 있으면 남은 수량 +1, 없으면 행 추가(수량 1, 끝). 판매 불가 마을(시설 없음으로 빈 목록 저장된 조합)·`itemId` null이면 false |
| `CaravanAssetSaleRules.SalePrice` | `SalePrice(int purchasePrice, float ratio, float durabilityRatio)`로 확장 — 비율은 0~1로 자른다. 기존 2인자 오버로드는 비율 1로 위임하거나 제거(제작 시 사용처 확인) |
| `CaravanAssetSaleService`(신규, `Core/Caravan/`, MonoBehaviour·`IManagedComponent`) | `ICaravanAssetSaleService` 구현. 판정·매각가는 Placeholder 로직을 옮기고 매각가에 내구도 비율을 곱한다. 매각 실행은 §3 순서. 매각 비율 인스펙터 값 0.5 |
| `PlaceholderCaravanAssetSaleService` | **삭제** |

### 4.1 서비스 의존성

모두 `TryResolve`이고 등록 타입으로 조회한다(읽기 타입 미등록 함정).

| 등록 타입 | 용도 | 없으면 |
|---|---|---|
| `IOwnedCaravanAssetRoster` | 보유 조회·종류별 수 | 전부 NotOwned(매각 불가) |
| `ITradeGoodsInventoryRepository` | 화물 판정(섹션 Id = 개체 Id) | 화물 없음으로 판정 |
| `ICaravanAssetDurabilityReader` | 매각가 내구도 비율 | 비율 1 |
| `IFormationRepository`·`ICaravanRosterProvider`·`IFieldFormationActivityRepository`·`IOwnedCaravanAssetRemover` | 공용 파괴 처리 생성 | 파괴 처리가 없는 쪽만 건너뜀. 단 제거 계약이 없으면 **대열을 건드리기 전에** 매각 거부(골드 수입 없음과 같은 경로 — 제작 시 §3-3보다 앞당김) |
| `ITripCurrentLocationRepository` | 판 마을 Id | 재고 반환 생략(경고) |
| `ITownStockReturner` | 재고 반환 | 반환 생략(경고) |
| `IGoldIncome` | 지급 | **매각 실행 거부** — 지급할 수 없는데 보유만 빠지는 경로를 막는다. 판정은 Available이어도 `TrySell`이 false |

테스트용 `Initialize(...)`로 DI 없이 주입할 수 있게 한다(Placeholder와 같은 방식).

## 5. 설치·Placeholder 제거

- `ManagerHierarchyInstaller`: `PlaceholderCaravanAssetSaleService` 생성 줄을 `CaravanAssetSaleService`(같은 UIManager 하위)로 교체하고 `managedComponents` 반환 목록도 교체. 삭제된 클래스 오브젝트는 이름 상수(`RemovedPlaceholderCaravanAssetSaleServiceName`)로 `DestroyChildIfExists` 정리 — 클래스가 없어 `nameof`를 쓰지 못하는 기존 패턴.
- 인스톨러 실행: Bootstrap 열기 → Build Bootstrap Scene → 저장(CLI로 직접).
- 제작 후 [현행 사양 구매 요소 재고](../현행 사양/2026-10-08-구매요소_재고_현행사양.md)의 "재고는 늘지 않음" 서술에 매각 예외를 반영한다.

## 7. 사용자 확인(Play)

Hub 마구간: 손상 마차 매각가가 내구도 비율대로 표시되고 수리 후 갱신, 매각 시 개인 골드 증가·보유 목록에서 사라지고 번호 당김, 같은 종류 후보 재고 +1(없던 종류는 후보 끝에 새로 표시), 정비창 배치 마차 매각 시 그 영역 유닛 재배치·팔레트 복귀.
