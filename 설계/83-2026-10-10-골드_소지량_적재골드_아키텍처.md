## 3. 데이터 계층

### 3.1 지갑 `InMemoryPlayerCurrencyWallet`

- 인스펙터 값 2개로 나눈다.
  - `personalLimit` = 500: 개인 소유 가능량(A1).
  - `startingAmount` = 10,000: 시작 금액(A4, 검증용).
- 상한 폐기: 획득은 양수 금액을 그대로 더하고 더한 양을 반환한다(C4). 0 이하는 무시한다.
- `IPlayerCurrencyReader.Capacity`는 `PersonalLimit`로 이름과 의미를 바꾼다. 개인 골드만 다루는 저수준 저장소로 남는다.

### 3.2 골드 보유 서비스 `GoldHoldingsService`

- Bootstrap 매니저 계층의 전역 매니저(`IManagedComponent`). `ManagerHierarchyInstaller`의 `managedComponents`에 등록한다.
- 의존성: 지갑(`IPlayerCurrencyWallet`), 교역품 저장소(`ITradeGoodsInventoryRepository`). 둘 다 `TryResolve`로 받고, 없으면 경고 후 해당 기능이 비활성이다. 이때 조회는 개인 골드만, 지출은 지갑만 쓴다.
- 인스펙터 값: 골드 아이템 Id(`gold-box`), 골드 상자 가치(500). 칸당 최대 효율 = 가치 ÷ (가로×세로)로 계산하고, 정의는 저장소 카탈로그에서 Id로 조회한다. 골드 아이템 종류 확장(기획 82 §5-1)은 이 두 값을 목록화하는 지점이다.
- DI 등록: 네 계약을 **각 타입으로 따로** 등록한다. 상위·하위 타입 등록으로는 조회되지 않는다(메모 "DI 읽기 타입 미등록").
- 변경 이벤트: 지갑 변경과 저장소 변경을 하나의 `Changed`로 합쳐 낸다. 저장소는 Bootstrap 상주이므로 재구독 시 이전 구독을 해제한다.

### 3.3 계약

| 계약 | 소비자 | 제공 |
|---|---|---|
| `IGoldHoldingsReader` | HUD, 변환 모달, 상행 준비 UI | 개인 골드, 개인 소유 가능량, 적재 골드, 빈 칸 수, 여유 공간 환산값, 소유 골드, 소지 가능 골드량, 버려질 골드, 변경 이벤트 |
| `IGoldSpender` | 구매·고용·마차 구매 서비스 | 지불 가능 판정(소유 골드 기준), 인출 미리보기(금액 → 인출될 상자 Id 목록), 지출(자동 인출 포함), 환불(개인 골드로 반환) |
| `IGoldBoxConverter` | 변환 모달 | 최대 변환 개수, "초과분 전부" 개수, N개 변환(실제 변환 개수 반환) |
| `IGoldDepartureSettlement` | 상행 준비 UI | 초과분 버림 |

### 3.4 교역품 저장소 변경

- 지갑 참조를 완전히 제거한다. 골드 상자 배치 시 차감·제거 시 환급을 모두 없애고 골드 상자도 일반 아이템과 같게 다룬다. 골드 상자 Id·가치 상수와 `TryGetGoldBoxDefinition`도 서비스 쪽으로 옮긴다(조회는 카탈로그 `TryGetDefinition`).
- `ITradeGoodsCargoSettlement`는 시그니처를 유지한다. 이제 일반 경로와 동작이 같지만, battle 브랜치 정산 코드가 쓰므로 이번에는 요약 주석만 갱신하고 통합은 후속 리팩토링으로 남긴다(§10).
- 시작 배치(Placeholder 시드)의 "골드 상자는 지갑 차감이 걸려 있어 넣지 않는다" 주석은 사유가 사라지므로 정리한다. 시드 품목은 바꾸지 않는다.

## 4. 계산·지출·변환 규칙 (`GoldHoldingsCalculator`, 순수 정적 클래스)

### 4.1 계산

| 값 | 계산 |
|---|---|
| 빈 칸 수 | Σ 섹션 사용 가능 칸 − Σ 그리드에 놓인 아이템 점유 칸(가로×세로). 임시 보관 제외 |
| 적재 골드 | (그리드 + 임시 보관)의 골드 상자 개수 × 가치 |
| 여유 공간 환산 | 빈 칸 수 × 칸당 최대 효율 |
| 소유 골드 | 개인 골드 + 적재 골드 |
| 소지 가능 골드량 | 개인 소유 가능량 + 여유 공간 환산 + 적재 골드 |
| 버려질 골드 | max(0, 개인 골드 − 개인 소유 가능량) |
| 섹션 점유율 | 섹션 점유 칸 ÷ 섹션 사용 가능 칸 |

### 4.2 인출 순서 (기획 82 C2 개정)

1. 임시 보관의 골드 상자(들어온 순서).
2. 마차: **점유율 내림차순**, 동률이면 보유 목록 **뒤쪽 마차** 먼저. 점유율은 인출 시작 시 **한 번만** 계산한다. 1위 마차의 상자를 다 쓰면 다음 마차로 넘어간다.
3. 마차 안: 아래 행부터, 같은 행은 오른쪽부터.

### 4.3 지출

1. 금액 ≤ 0 → 아무것도 하지 않고 성공.
2. 소유 골드 < 금액 → 아무것도 바꾸지 않고 실패.
3. 부족분 = 금액 − 개인 골드. 부족분 > 0이면 ⌈부족분 ÷ 가치⌉개를 §4.2 순서로 고른다.
4. 고른 상자를 저장소에서 제거 → 개수 × 가치를 개인 골드에 추가 → 금액 차감. 거스름돈은 개인 골드에 남는다.
5. 인출 미리보기는 3의 목록을 상태 변경 없이 반환한다. 같은 프레임의 지출과 같은 결과를 보장한다(같은 계산 함수 사용).
6. 환불은 개인 골드에 더하기만 한다. 인출한 상자는 복원하지 않는다.

### 4.4 변환

- 최대 변환 개수 = min(⌊개인 골드 ÷ 가치⌋, 빈 칸 수). 1×1 상자 전제라 빈 칸 수가 곧 놓을 자리 수다. 다른 크기의 골드 아이템이 생기면 자리 탐색으로 바꾼다(§10).
- "초과분 전부" = min(⌈(개인 골드 − 개인 소유 가능량) ÷ 가치⌉, 최대 변환 개수). 초과가 없으면 0.
- N개 변환: 요청 개수를 최대 변환 개수로 자른 뒤, 상자마다 보유 목록 순서(앞쪽 마차부터, 위 행·왼쪽부터)로 첫 빈자리를 찾는다(`InventoryAutoSorter.TryFindSlot` 재사용, 회전 불필요). 가치를 차감한 뒤 배치하고, 배치에 실패하면 그 상자분을 돌려주고 멈춘다. 실제 변환 개수를 반환한다.

### 4.5 출발 버림

- 버려질 골드 > 0이면 그만큼 지갑에서 차감한다. 적재 골드는 건드리지 않는다(E3).

## 5. 무역품 구매: 인출 반영 + 필요한 물품만 재배치

### 5.1 재배치 계획 `CargoPurchasePlanner` (순수 정적 클래스)

입력: 섹션 순서(보고 있는 마차 → 보유 순서, 기존 `OrderFrom`), 그리드 아이템에서 인출될 상자를 뺀 목록, 구매품 정의, 회전 허용 여부.
출력: 구매품 자리(섹션·위치·회전) + 이동 목록(`ItemPlacement`). 없으면 실패(공간 부족).

1. **바로 놓기**: 기존 자리 탐색으로 빈자리가 있으면 이동 없이 그 자리를 쓴다(기존 동작과 동일).
2. **재배치**: 섹션 순서대로, 각 섹션의 모든 후보 위치(회전 허용 시 회전 포함)에 대해:
   - 그 자리를 덮는 기존 물품을 구한다.
   - 그 물품들을 구매품 자리를 제외한 빈 칸으로 옮길 수 있는지 확인한다. 이동 대상은 **같은 마차 → 다른 마차(보유 순서)** 순으로 첫 빈자리를 찾는다. 회전 허용은 구매품과 같다. 여러 물품은 큰 것부터 차례로 놓는다.
   - 가능한 후보 중 이동 물품 수가 가장 적은 위치를 고른다. 동률이면 이동 칸 수가 적은 쪽, 그다음 위 행·왼쪽 순이다.
   - 처음으로 후보가 생긴 섹션에서 결정한다(보고 있는 마차 우선 규칙 유지).
3. 어느 섹션에서도 안 되면 실패.
- 한계: 1단계 이동만 한다. 옮겨지는 물품이 다른 물품을 다시 밀어내는 연쇄 이동은 하지 않는다(§10).

### 5.2 `ShopPurchaseService` 판정·확정

- 의존성: 지갑 → `IGoldSpender`, 교역품 저장소는 이동 적용을 위해 재배치 조작(`IInventoryArrangement`)을 함께 받는다.
- **판정**: 품절 → 소유 골드 부족 → 공간 순.
  - 공간 판정: 인출 미리보기 → 상자를 뺀 아이템 목록 → 재배치 계획 → 없으면 공간 부족.
- **확정**: 같은 계획으로 실행한다.
  1. 지출(인출 + 차감)
  2. 이동 목록을 원자적 재배치(`TryApplyPlacements`)로 한 번에 적용
  3. 구매품 배치
  4. 재고 차감
  - 2·3 실패 시 금액은 환불(개인 골드)하고, 인출한 상자와 적용된 이동은 되돌리지 않는다. 같은 프레임에서 검증한 계획이라 정상 경로에서는 일어나지 않는다.
- 구매 후 화면은 기존처럼 구매품이 들어간 마차로 전환한다. 다른 마차로 옮겨진 물품에 대한 별도 안내는 없다.

### 5.3 용병 고용·마차 구매

- `MercenaryHiringService`·`CaravanAssetPurchaseService`는 지갑 대신 `IGoldSpender`에 의존한다. 판정은 지불 가능 판정, 차감은 지출, 롤백은 환불로 바꾼다. 공간 판정이 없어 재배치 계획과 무관하다.
- 패널(`TradeGoodsMarketPanel`·`MercenaryContactPanel`·`StablePanel`)의 재화 변경 구독은 `IGoldHoldingsReader.Changed`로 바꾼다. 적재 골드가 바뀌어도 버튼 활성이 갱신돼야 하기 때문이다. `HubUIWiring`의 인자 타입도 함께 바꾼다.

## 6. UI

### 6.1 HUD (`PlayerCurrencyHudController` 수정)

- 구독: 지갑 → `IGoldHoldingsReader`. 표시값은 소유 골드(D1)다. 등록 인자 타입(`IPlayerCurrencyHudController`)도 바꾼다.
- 색(D4, 인스펙터 값): 소유 골드 > 소지 가능 골드량 → 빨강. 아니고 개인 골드 > 개인 소유 가능량 → 노랑. 아니면 흰색.
- 입력 대상: 금액 텍스트 → HUD 패널 전체(배경 Image가 레이캐스트 대상).
- 신규 범용 컴포넌트 `PointerPressRelay`(`PointerHoverRelay`와 같은 성격, 특정 UI 로직을 모름):
  - 누르면 코루틴으로 길게 누름 기준 시간(인스펙터 값, 0.3초)을 잰다. Update 폴링은 쓰지 않는다.
  - 시간이 차면 "길게 누름 시작" 이벤트, 뗄 때 "길게 누름 끝" 이벤트를 낸다.
  - 기준 시간 전에 떼면 "짧은 클릭" 이벤트를 낸다(D3).
  - 누른 채 영역 밖으로 나가면 클릭을 취소한다.
- 툴팁(D2): 호버 진입 또는 길게 누름 시작에 표시하고, 호버 이탈 또는 길게 누름 끝에 숨긴다. 문구는 `최대량 {소지 가능 골드량} (개인 {개인 소유 가능량} / 적재 {적재 골드} / 여유 공간 {여유 공간 환산})`이다.
- 짧은 클릭 → `UIManager.Open(변환 모달 Id)`.

### 6.2 변환 모달 `GoldConversionPanel`

- `IUIPanel`, 모달 팝업 채널 등록. 패널 로직은 Bootstrap(UIManager 오브젝트), 시각 요소는 Hub `SceneUIRoot`의 모달 팝업 레이어에 둔다. 요소 Id는 `GoldConversionUIElementIds`, 패널 Id는 `UIPanelIds`에 추가한다. 등록은 `HubUIWiring`에서 하며, 요소를 못 찾으면 `Debug.LogWarning`을 낸다.
- 상행 준비 UI가 열린 상태에서 HUD를 누르면 모달 채널의 기존 복귀 동작에 따라, 변환 모달을 닫을 때 상행 준비 UI로 돌아간다.
- 표시(B5): 개인 골드, 개인 소유 가능량, 빈 칸 수, 변환 후 개인 골드, 변환 후 출발 시 버려질 골드. 스테퍼 값과 `Changed` 이벤트에 맞춰 갱신한다.
- 조작:
  - 상하 스테퍼(0 ~ 최대 변환 개수), [초과분 전부](스테퍼 값을 그 개수로 설정), [변환], [닫기].
  - 0개면 [변환] 비활성.
  - 열 때 스테퍼 초기값은 "초과분 전부" 개수다.
  - 변환 후에도 모달은 열린 채 값만 갱신한다. 스테퍼 값은 새 "초과분 전부" 개수로 다시 맞춘다.
  - [닫기]는 `UIManager.Close(PanelId)`로 위임한다. 패널의 `Close()`는 표시/숨김만 하고, 이 규칙을 주석으로 남긴다.

### 6.3 출발 경고 (`TripPanel` 수정)

- 해당하는 경고만 순서대로 모아 같은 `ConfirmDialogView`를 연쇄로 띄운다. 순서는 **배치 유닛 0 → 골드**다(E4·E5).
  - 모두 확인 → 초과분 버림(`IGoldDepartureSettlement`) → 출발.
  - 어느 단계든 [취소] → 아무것도 바꾸지 않고 중단.
- 골드 경고 조건: 버려질 골드 > 0(E1).
- 골드 경고 문구:
  `개인 소유 가능량 {n1}을 넘는 {n2}골드가 버려집니다. 마차에 적재하거나 은행에 보관하지 않은 골드는 버려집니다. 그래도 출발하시겠습니까?`
  - n1 = `IGoldHoldingsReader`의 개인 소유 가능량, n2 = 버려질 골드. 출발 시점에 읽는다. 개인 소유 가능량이 바뀌면 문구·툴팁·모달이 모두 따라간다(상수 금지).
  - "은행"은 아직 없는 시설이다. 은행 기획 전까지는 안내용 문구로 둔다(사용자 지시 문구).
  - 버튼: [출발] / [취소].
- 배치 유닛 0 경고 문구는 기존을 유지한다.
- `IGoldHoldingsReader`·`IGoldDepartureSettlement`가 없으면(인스톨러 미실행) 골드 경고 없이 기존처럼 동작한다. 대화상자가 없으면 경고 없이 출발한다(기존 규칙).
- 금지 조건(버튼 비활성)은 변경하지 않는다(E6).

- `ManagerHierarchyInstaller`: `GoldHoldingsService`를 get-or-create로 등록하고 `managedComponents`에 추가한다. `GoldConversionPanel`을 UIManager 오브젝트에 부착한다.
