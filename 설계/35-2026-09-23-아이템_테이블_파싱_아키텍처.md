## 1. 목표

33번 문서에서 확정한 아이템 데이터 공통 뼈대를 실제로 동작하는 임포트 파이프라인 + 런타임 조회 구조로 구현한다. 카테고리별 세부 필드(장비 스탯 등)는 여전히 범위 밖이다 — 이번 설계는 "Id/FootprintWidth/FootprintHeight/IconPath + 표시명" 공통 컬럼만 다룬다.

## 2. 핵심 결정 — 카테고리 4개가 클래스 하나를 공유한다

`CharacterStatsTableAsset`/`EnemyStatsTableAsset`은 서로 스키마가 달라(캐릭터는 `MoraleSyncRate`, 적은 `HpRegenPerSecond`) 처음부터 별개 클래스였다. 반면 교역품/장비/소모품/개인물품 4개 카테고리는 33번 문서 §3.3에서 **지금 시점에 스키마가 완전히 동일**하다고 확정됐다. CLAUDE.md 규칙("새 클래스를 추가하기 전에 기존 것을 확장해 재사용할 수 있는지 먼저 확인")에 따라, 4개 카테고리가 **클래스 하나(`ItemDefinitionTableAsset`/`ItemStringTableAsset`/임포터 하나)를 공유**하고 자산 4벌(카테고리별 워크북·에셋 경로)만 따로 둔다.

나중에 카테고리별 전용 필드(예: 장비만 `EquipSlot` 컬럼)가 추가되면, 그 시점에 공통 클래스를 분기(상속 또는 카테고리 전용 클래스 신설)한다 — 지금 미리 분기하지 않는다(YAGNI).

## 3. 데이터 구조

```
Core/Table/SlugLocalizedStringEntry.cs   (신규 - 기존 LocalizedStringEntry는 Id가 int라 재사용 불가)
  struct SlugLocalizedStringEntry { string Id; string Ko; }

Core/Inventory/ItemDefinitionEntry.cs    (신규)
  struct ItemDefinitionEntry { string Id; int FootprintWidth; int FootprintHeight; Sprite Icon; }
```

`SlugLocalizedStringEntry`는 이름을 아이템 전용으로 짓지 않았다 — 34번 문서(기존 테이블 enum→문자열 슬러그 전환)가 착수되면 그쪽도 그대로 재사용할 수 있게 `Core/Table/`(공용 위치)에 둔다.

`ItemDefinitionEntry.Icon`은 `Sprite` 타입이다. 엑셀 셀에는 `IconPath`(문자열)만 있고, **임포터가 `AssetDatabase.LoadAssetAtPath<Sprite>(iconPath)`로 해석해 Sprite 참조를 직접 저장**한다(런타임에는 경로 문자열이 아니라 이미 로드된 에셋 참조만 남는다 — `LiveBattleSimulationRule.characterStatsTable`과 같은 성격의 "임포트 시점에 자산 참조까지 확정" 원칙).

## 4. TableAsset

```

  [CreateAssetMenu] ScriptableObject
  [SerializeField] List<ItemDefinitionEntry> entries;
  private Dictionary<string, ItemDefinitionEntry> lookup; // 최초 접근 시 1회 구축(지연 캐시)

Core/Inventory/ItemStringTableAsset.cs
  [CreateAssetMenu] ScriptableObject
  [SerializeField] List<SlugLocalizedStringEntry> strings;
  private Dictionary<string, string> lookup;
  public bool TryGetLabel(string id, out string ko);
```

**`Dictionary` 캐시를 쓰는 이유(기존 `TableEntryLookup` 선형 탐색과 다른 점)**: `TableEntryLookup`은 "설정 시점에만 조회되고 엔트리 수가 한 자릿수"라는 전제로 O(n)을 그대로 뒀다(그 클래스 요약 주석 참고). 아이템은 수십~수백 개로 늘어날 콘텐츠라 이 전제가 성립하지 않는다 — CLAUDE.md 최적화 규칙(ID 조회는 O(1))에 따라 `Dictionary`로 만든다. 지연 구축(첫 조회 시 1회, 이후 캐시 재사용)으로 해 임포트 직후 매번 즉시 재구축하지 않는다.

## 5. 임포터

```
Editor/ItemTableImporter.cs (신규, 정적 클래스, 카테고리 4개 공유)
  [MenuItem("Tools/Game/Table/Import Trade Goods Items")]  → Import("TradeGoods", ...)
  [MenuItem("Tools/Game/Table/Import Equipment Items")]    → Import("Equipment", ...)
  [MenuItem("Tools/Game/Table/Import Consumable Items")]   → Import("Consumable", ...)
  [MenuItem("Tools/Game/Table/Import Personal Items")]     → Import("PersonalItem", ...)

  private static void Import(string workbookName, string dataAssetPath, string stringAssetPath, bool hasVariableFootprint)
    → EditorTableReader.ReadSheet("Item/{workbookName}.xlsx", "ItemData")
    → 행마다 ParseSlug(row, "Id", seenIds)로 Id 파싱+중복/공백 검증
    → FootprintWidth/Height: hasVariableFootprint=true(교역품만)면 셀에서 파싱, false(나머지 3종)면 코드 상수 1로 고정
      (2026-09-23 정정 - 33번 §3.3, 나머지 3개 워크북엔 이 컬럼 자체가 없음)
    → IconPath 셀 → AssetDatabase.LoadAssetAtPath<Sprite> (못 찾으면 경고 로그 + null, 임포트는 계속)
    → ItemDefinitionTableAsset/ItemStringTableAsset에 SerializedObject로 기록(CharacterStatsTableImporter와 동일 패턴)
```

**`EditorTableReader`에 `ParseSlug` 추가**(기존 `ParseEnum`과 나란히):

```csharp
public static string ParseSlug(IReadOnlyDictionary<string,string> row, string column, HashSet<string> seenIds)
{
    var value = row[column];
    if (string.IsNullOrWhiteSpace(value))
        throw new FormatException($"컬럼 '{column}'이 비어있다.");
    if (!seenIds.Add(value))
        throw new FormatException($"컬럼 '{column}' 값 '{value}'이(가) 같은 시트에 중복됐다.");
    return value;
}
```

`seenIds`는 호출자(임포터)가 시트 하나를 읽을 때마다 새로 만든 `HashSet<string>`을 넘긴다 — `Enum.IsDefined`(정의되지 않은 Id 즉시 예외)에 대응하는 "빈 값/중복 Id 즉시 예외" 검증이다.

### 7.1 골드 상자 처리 (33번 §3.4)

`PlaceholderTradeGoodsInventoryRepository`에서 `[SerializeField] Sprite goldBoxIcon`과 `GoldBoxItemDefinition` 생성 코드, `goldBoxDefinition` 필드를 제거한다. 대신:

```csharp
private const string GoldBoxItemId = "gold-box"; // TradeGoods.xlsx의 한 행

public bool TryPlaceItem(IInventoryItemDefinition definition, GridPosition position, out InventoryItemInstance placed)
{
    var isGoldBox = definition.Id == GoldBoxItemId;
    // 이하 로직(지갑 차감/롤백)은 동일 - definition 객체 identity가 아니라 Id 문자열로 판별하도록만 바뀐다.
}
```

`GoldBoxItemDefinition.cs` 클래스 자체는 삭제 대상이다 — 데이터(Id/아이콘/크기)는 전부 테이블 행이 대신하고, 지갑 연동이라는 **행동**만 저장소가 Id 문자열로 식별해 특수 처리한다(코드 분기가 여러 카테고리를 가르는 게 아니라 "이 특정 Id 하나"를 가르는 것이므로 33번 §3.1의 "코드 분기 없음" 전제와 상충하지 않는다).
