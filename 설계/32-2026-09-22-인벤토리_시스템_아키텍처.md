## 1. 범위

- 그리드 기반 인벤토리 저장/조회 계약(카테고리 4종 공통 + 마커 인터페이스)을 설계한다.
- 교역품/전리품 그리드 크기가 보유 마차 수에서 계산되는 방식(Placeholder)을 설계한다.
- 골드 상자 아이템과 `IPlayerCurrencyWallet` 간 양방향 연동 지점을 설계한다.
- 카테고리별 팝업 4개를 `UIManager`의 단일 활성 패널 정책(`PanelNavigationStack`)과 분리해 동시 다중 오픈 가능하게 하는 구조를 설계한다.
- 범위 밖: 개별 아이템 카탈로그/데이터, 팝업의 실제 시각 레이아웃(그리드 뷰 컴포넌트), 그리드 아이템 회전/자동 정렬, New Input System 실제 액션 맵/키 바인딩, 마차 실제 스탯 시스템.

## 2. 데이터 모델 — `Core/Inventory/`(신규 폴더)

`Core/Player`와 같은 이유로 신규 최상위 도메인 폴더로 분리한다 — 인벤토리는 특정 씬 소유가 아니라 마을 시설과 (향후) Field 양쪽에서 조회·조작돼야 하는 상단 전역 상태다.

```csharp
    /// <summary>
```

```csharp
namespace Game.Core
{
    /// <summary>
    /// 그리드 좌표/점유 칸 계산을 전담하는 자료구조. 31번 §3.1 "아이템이 WxH칸을 점유"를 그대로
    /// 구현한다 - FormationLayout(슬롯 1칸=유닛 1개, 회전식 인덱스 배열)과 달리 아이템이 여러 칸을
    /// 동시에 차지할 수 있어 좌표 기반 점유 배열을 쓴다. 회전/자동 정렬은 다루지 않는다(31번 §4).
    /// </summary>
    public class InventoryGrid
    {
        private readonly Dictionary<string, InventoryItemInstance> itemsByInstanceId = new();
        private string[,] occupancy; // 칸 별 점유 InstanceId(null=빈칸)

        public int Width { get; private set; }
        public int Height { get; private set; }
        public IReadOnlyCollection<InventoryItemInstance> Items => itemsByInstanceId.Values;

        public InventoryGrid(int width, int height) => Resize(width, height);

        public bool TryPlace(IInventoryItemDefinition definition, GridPosition position, out InventoryItemInstance placed)
        {
            placed = default;
            if (!FitsAndFree(position, definition.FootprintWidth, definition.FootprintHeight)) return false;

            var instanceId = Guid.NewGuid().ToString("N");
            placed = new InventoryItemInstance(instanceId, definition, position);
            itemsByInstanceId[instanceId] = placed;
            MarkOccupancy(position, definition.FootprintWidth, definition.FootprintHeight, instanceId);
            return true;
        }

        public bool Remove(string instanceId)
        {
            if (!itemsByInstanceId.Remove(instanceId, out var item)) return false;
            MarkOccupancy(item.Position, item.Definition.FootprintWidth, item.Definition.FootprintHeight, null);
            return true;
        }

        public bool TryGetAt(GridPosition position, out InventoryItemInstance item)
        {
            if (position.X < 0 || position.X >= Width || position.Y < 0 || position.Y >= Height
                || occupancy[position.X, position.Y] is not { } id)
            {
                item = default;
                return false;
            }
            return itemsByInstanceId.TryGetValue(id, out item);
        }

        // 마차 증감(§3.1) 시 총 칸 수가 바뀔 때 호출한다. 줄어든 영역에 걸린 아이템 처리 규칙은
        // 범위 밖(31번 §4/§6) - 지금은 걸린 아이템을 그대로 유지하되 겹침 검사에서 제외한다(제작
        // 단계에서 재검토 여지, FormationLayout.Resize의 "밀려나는 배치는 버린다" 정책과 다르게
        // 인벤토리는 아이템 손실을 함부로 일으키지 않는 쪽을 기본값으로 삼는다).
        public void Resize(int newWidth, int newHeight) { /* 폭/높이 갱신 + occupancy 재계산 */ }

        private bool FitsAndFree(GridPosition position, int w, int h) { /* 범위/겹침 체크 */ return default; }
        private void MarkOccupancy(GridPosition position, int w, int h, string instanceId) { /* 칸 채우기/비우기 */ }
    }
}
```

## 3. 카테고리 공통 계약 — `IInventoryReader`/`IInventoryRepository`

```csharp
namespace Game.Core
{
    public interface IInventoryReader
    {
        int GridWidth { get; }
        int GridHeight { get; }
        IReadOnlyCollection<InventoryItemInstance> Items { get; }
        bool TryGetItemAt(GridPosition position, out InventoryItemInstance item);
        event Action OnChanged; // Update 폴링 금지 - 그리드 뷰가 이 이벤트로만 갱신
    }

    public interface IInventoryRepository : IInventoryReader
    {
        bool TryPlaceItem(IInventoryItemDefinition definition, GridPosition position, out InventoryItemInstance placed);
        bool RemoveItem(string instanceId);
    }
}
```

**읽기 전용 분리(`IFormationReader` 패턴)는 지금 하지 않는다.** 현재 4개 인벤토리 모두 유일한 소비자가 자신의 팝업(읽기+쓰기 동시 필요)뿐이라 별도 읽기 전용 소비자가 없다 — CLAUDE.md "새 인터페이스는 기존 것 확장 재사용 확인 후" 원칙에 따라, 실제 읽기 전용 소비자(예: 정비창에서 장비 인벤토리 열람)가 생기는 시점에 `IEquipmentInventoryReader`를 그때 추출한다.

```csharp

    public interface IEquipmentInventoryRepository : IInventoryRepository { }
    public interface IConsumableInventoryRepository : IInventoryRepository { }
```

## 4. 구현체

### 4.1 고정 크기 3종 — `PlaceholderXxxInventoryRepository`

`PlaceholderEquipmentInventoryRepository`(6×4)/`PlaceholderConsumableInventoryRepository`(5×4)/`PlaceholderPersonalItemInventoryRepository`(3×3) 세 클래스는 동일한 형태다. `InventoryGrid`를 합성하고 인터페이스 멤버를 그대로 위임한다.

```csharp
namespace Game.Core
{
    /// <summary>
    /// 31번 §3.2 잠정치(6×4). 실제 아이템 데이터/밸런싱 시스템 설계 후 대체/제거 대상.
    /// </summary>
    public class PlaceholderEquipmentInventoryRepository : MonoBehaviour, IEquipmentInventoryRepository, IManagedComponent
    {
        private const int Width = 6;
        private const int Height = 4;
        private InventoryGrid grid;

        public int GridWidth => grid.Width;
        public int GridHeight => grid.Height;
        public IReadOnlyCollection<InventoryItemInstance> Items => grid.Items;
        public event Action OnChanged;

        public void RegisterSelf(IDependencyRegistrar registrar) => registrar.Register<IEquipmentInventoryRepository>(this);
        public void ResolveDependencies(IDependencyResolver registrar) => grid = new InventoryGrid(Width, Height);

        public bool TryGetItemAt(GridPosition position, out InventoryItemInstance item) => grid.TryGetAt(position, out item);

        public bool TryPlaceItem(IInventoryItemDefinition definition, GridPosition position, out InventoryItemInstance placed)
        {
            if (!grid.TryPlace(definition, position, out placed)) return false;
            OnChanged?.Invoke();
            return true;
        }

        public bool RemoveItem(string instanceId)
        {
            if (!grid.Remove(instanceId)) return false;
            OnChanged?.Invoke();
            return true;
        }
    }
}
```

소모품/개인 물품 저장소도 상수(`Width`/`Height`)와 등록 인터페이스만 다르고 나머지는 동일 — 반복 코드지만 "세 줄 비슷한 코드가 섣부른 추상화보다 낫다"(CLAUDE.md) 기준에 부합, 무리하게 공통 베이스 클래스로 뽑지 않는다.

### 4.2 교역품/전리품 — `PlaceholderTradeGoodsInventoryRepository`

31번 §3.3(마차 스탯 합산)을 구현한다. 마차 자체 스탯 시스템이 없으므로, 기존 `PlaceholderCaravanRosterProvider`가 이미 제공하는 "마차 카테고리 재고 5개"(11번 문서 §3 확정치)를 보유 마차 수의 Placeholder로 재사용한다 — 새 마차 데이터 소스를 따로 만들지 않는다(25번 §5/CLAUDE.md 재사용 원칙).

```csharp
namespace Game.Core
{
    /// <summary>
    /// 그리드 총 크기가 고정이 아니라 보유 마차 수 × 마차당 칸수로 계산된다(31번 §3.3). 마차 자체의
    /// 스탯 시스템이 없어 ICaravanRosterProvider의 FormationUnitKind.Wagon 재고 수(11번 문서 - 카테고리당
    /// 5개, "재고 수량" 의미)를 보유 마차 수 Placeholder로 쓴다. 마차당 칸수(PlaceholderCellsPerWagon)도
    /// 마차 스탯 기획 전까지의 잠정 상수 - 실제 마차 스탯 시스템이 생기면 이 클래스와 아래 상수를 통째로
    /// 대체한다.
    /// </summary>
    public class PlaceholderTradeGoodsInventoryRepository : MonoBehaviour, ITradeGoodsInventoryRepository, IManagedComponent
    {
        private const int PlaceholderCellsPerWagon = 8;
        private const int MaxGridColumns = 10; // 총 칸수를 가로 10칸 기준으로 접어 세로를 늘리는 임시 배치 규칙

        // 골드 상자(31번 §3.4)는 아이템 카탈로그가 없는 지금, 이 저장소가 직접 소유하는 유일한 특수 정의다.
        [SerializeField] private Sprite goldBoxIcon;
        private IInventoryItemDefinition goldBoxDefinition;
        private const int GoldBoxCurrencyValue = 500;

        private ICaravanRosterProvider caravanRosterProvider;
        private IPlayerCurrencyWallet currencyWallet; // 선택적 - 없으면 골드 상자 변환 불가(TryPlaceItem이 false)
        private InventoryGrid grid;

        public int GridWidth => grid.Width;
        public int GridHeight => grid.Height;
        public IReadOnlyCollection<InventoryItemInstance> Items => grid.Items;
        public event Action OnChanged;

        public void RegisterSelf(IDependencyRegistrar registrar) => registrar.Register<ITradeGoodsInventoryRepository>(this);

        public void ResolveDependencies(IDependencyResolver registrar)
        {
            caravanRosterProvider = registrar.Resolve<ICaravanRosterProvider>();
            registrar.TryResolve(out currencyWallet); // 재화 지갑도 아직 선택적 의존성 취급 - 일관성 유지
            goldBoxDefinition = new GoldBoxItemDefinition(goldBoxIcon);

            RecomputeGridSize(); // 지금은 재고 수가 세션 내내 고정이라 1회만 계산 - 마차 획득/손실 이벤트가
                                  // 생기면(실제 마차 시스템) 그 이벤트 구독으로 대체해야 한다(23번 §5와 동일 훅 필요).
        }

        private void RecomputeGridSize()
        {
            var wagonCount = caravanRosterProvider.GetRoster().Count(u => u.Kind == FormationUnitKind.Wagon);
            var totalCells = wagonCount * PlaceholderCellsPerWagon;
            var width = Mathf.Min(totalCells, MaxGridColumns);
            var height = width == 0 ? 0 : Mathf.CeilToInt(totalCells / (float)width);
            grid = new InventoryGrid(width, height);
        }

        public bool TryGetItemAt(GridPosition position, out InventoryItemInstance item) => grid.TryGetAt(position, out item);

        public bool TryPlaceItem(IInventoryItemDefinition definition, GridPosition position, out InventoryItemInstance placed)
        {
            placed = default;
            // 골드 상자는 재화 지갑에서 먼저 차감해야 성립한다 - 아이템만 놓고 재화가 안 줄면 재화 복제 버그.
            if (ReferenceEquals(definition, goldBoxDefinition) && (currencyWallet == null || !currencyWallet.TrySpend(GoldBoxCurrencyValue)))
            {
                return false;
            }

            if (!grid.TryPlace(definition, position, out placed))
            {
                if (ReferenceEquals(definition, goldBoxDefinition)) currencyWallet.Add(GoldBoxCurrencyValue); // 배치 실패 시 롤백
                return false;
            }

            OnChanged?.Invoke();
            return true;
        }

        public bool RemoveItem(string instanceId)
        {
            if (!grid.TryGetAt(default, out _)) { } // (실제 구현은 InstanceId로 조회하는 grid 내부 메서드 사용)
            var wasGoldBox = grid.Items.Any(i => i.InstanceId == instanceId && ReferenceEquals(i.Definition, goldBoxDefinition));
            if (!grid.Remove(instanceId)) return false;

            if (wasGoldBox) currencyWallet?.Add(GoldBoxCurrencyValue); // 골드 상자 제거=환급(31번 §4 "역변환 필요 여부"는 범위 밖이나, 최소한 인벤토리에서 사라지면 재화가 증발하지 않게는 함)
            OnChanged?.Invoke();
            return true;
        }
    }
}
```

**골드 상자 변환 UI(재화 → 골드 상자 생성 버튼 등)는 이번 설계에 없다** — 31번 §4가 "변환 트리거·UI"를 범위 밖으로 남겼기 때문에, 위 `TryPlaceItem`/`RemoveItem`은 "골드 상자 정의로 호출되면 지갑과 연동된다"는 지점만 캡슐화했을 뿐, 실제로 이걸 누가 언제 호출하는지(전당포 판매 후 자동 생성? 플레이어가 직접 변환 버튼을 누름?)는 후속 기획 대상이다.

## 5. UI 오케스트레이션 — `IInventoryPopupCoordinator`

`UIManager.Open`/`Close`는 `PanelNavigationStack`을 통해 "패널 하나를 열면 이전 패널을 숨기고, 닫으면 되돌아간다"는 단일 활성 패널 정책을 강제한다. 인벤토리 팝업 4종은 31번 §3.5에서 이 정책과 반대(동시 중첩 오픈)로 확정됐으므로, `panelsById`/`PanelNavigationStack`에 편입시키지 않고 완전히 별도 협력 객체로 분리한다(CLAUDE.md SRP — `UIManager`↔`PanelNavigationStack` 분리와 같은 이유).

```csharp
namespace Game.Core
{
    /// <summary>
    /// 인벤토리 팝업 4종의 개별 열림 상태만 다룬다 - PanelNavigationStack과 달리 "하나를 열면 다른 걸
    /// 숨긴다" 정책이 없다(31번 §3.5, 동시 중첩 오픈). UIManager와 같은 GameObject에 부착하는 형제
    /// 컴포넌트로, 전역 DI 대상이 아니다(HubUIController/FormationPanel과 같은 성격 - CLAUDE.md DI 규칙).
    /// </summary>
    public interface IInventoryPopupCoordinator
    {
        void RegisterPopup(IUIPanel popup);
        void Toggle(string popupId);
        bool IsOpen(string popupId);
    }
}
```

`UIManager`는 이 코디네이터를 `GetComponent<IInventoryPopupCoordinator>()`로 조회해(없으면 `InvalidOperationException`, CLAUDE.md 하위 컴포넌트 조회 규칙) `IUIManager`에 얇은 위임 메서드를 추가한다:

```csharp
// IUIManager 추가분
void ToggleInventoryPopup(string popupId);
```

패널 Id 상수는 기존 명명 규칙(`XxxUIElementIds`)을 따라 `InventoryPopupIds`(또는 `InventoryUIElementIds`)에 4개 상수로 모은다(교역품/장비/소모품/개인물품).

각 팝업 자체는 기존 `IUIPanel`(`PanelId`/`Open`/`Close`)을 그대로 구현하는 `XxxInventoryPopupPanel` 클래스가 될 것으로 예상된다(제작 단계 — 실제 그리드 뷰 렌더링은 `FormationGridView`류를 참고할 새 컴포넌트가 필요, 이번 설계는 데이터 계층까지만 다룬다).

## 6. 입력 — New Input System 훅 (조사 결과 및 제약)

조사 결과 프로젝트에 New Input System(`UnityEngine.InputSystem`)이 아직 연동돼 있지 않다 — `IInputManager`는 `SetContext(string contextId)` 뼈대만 있고 실제 액션/바인딩 처리가 없다(TODO 주석만 존재). 즉 "New Input System 키"(31번 §3.5)를 실제로 동작시키려면 이 설계 범위를 넘어서는 InputManager 자체의 선행 작업이 필요하다 — **이번 설계는 그 전제를 그대로 남겨두고, 인벤토리 쪽에서 준비해야 할 훅만 정의한다**: 키가 눌렸을 때 호출될 대상은 `IUIManager.ToggleInventoryPopup(popupId)` 하나로 확정한다. 실제 액션 맵/바인딩 값 및 `InputManager` 자체의 New Input System 연동은 범위 밖(별도 후속 과제로 남김 — 필요하면 별도 설계 세션 권장).

화면 버튼(항상 표시되는 4개 아이콘 버튼, 27번 문서의 재화 HUD와 유사한 상시 표시 UI)은 New Input System과 무관하게 바로 구현 가능 — 버튼 `onClick`에서 같은 `ToggleInventoryPopup(popupId)`를 호출하면 된다.

## 7. DI 등록

`ManagerHierarchyInstaller.DataRepositoryNames`(현재 9개)에 4개 추가:

```
PlaceholderTradeGoodsInventoryRepository
PlaceholderEquipmentInventoryRepository
PlaceholderConsumableInventoryRepository
PlaceholderPersonalItemInventoryRepository
```

`BuildUIManagerDataRepositories`에서 `EditorUIBuilder.GetOrAddComponent<T>(...)`로 각각 생성해 반환 배열에 포함한다(기존 저장소들과 서로 순서 의존성 없음 — `PlaceholderTradeGoodsInventoryRepository`만 `ICaravanRosterProvider`를 `Resolve`하므로 `PlaceholderCaravanRosterProvider`보다 나중에 `ResolveDependencies`가 불려야 하지만, 기존 배열 순서상 `PlaceholderCaravanRosterProvider`가 이미 맨 앞이라 그 뒤 어디에 추가해도 안전하다).

`IInventoryPopupCoordinator` 구현체는 전역 DI 미등록 — `UIManager`와 같은 GameObject에 `GetOrAddComponent`로 부착(`WireUIManagerPanels` 또는 인접 메서드에서).

## 8. 이 설계가 건드리지 않는 것

- 개별 아이템 카탈로그/데이터 정의(장비 스탯, 소모품 효과, 개인 물품 종류) — `IInventoryItemDefinition`은 계약만 정의, 실제 구현체(카탈로그)는 후속.
- 마차 실제 스탯 시스템(칸수/모양, 마차 종류별 차등) — `PlaceholderCellsPerWagon` 상수로 대체.
- 그리드 아이템 회전, 자동 정렬, 드래그앤드롭 UX, 아이템 획득/구매 트리거.
- 골드 상자 변환 UI/트리거(재화→골드 상자를 누가 언제 생성하는지).
- 팝업의 실제 시각 컴포넌트(그리드 뷰 렌더링, 드래그 처리) — `IUIPanel` 구현체와 `FormationGridView` 참고 대상만 명시.
- New Input System 실제 액션 맵/바인딩 값, `InputManager`의 New Input System 연동 자체.
- `InventoryGrid.Resize`가 축소로 인해 아이템이 그리드 밖으로 밀려날 때의 최종 정책(지금은 "제거하지 않고 겹침 검사만 제외"를 잠정 채택 — 재검토 여지 명시).

1. `Core/Inventory/`에 `GridPosition`, `IInventoryItemDefinition`, `InventoryItemInstance`, `InventoryGrid`, `IInventoryReader`, `IInventoryRepository`, 카테고리 마커 4종(`ITradeGoodsInventoryRepository` 등) 생성.
2. `PlaceholderEquipmentInventoryRepository`/`PlaceholderConsumableInventoryRepository`/`PlaceholderPersonalItemInventoryRepository`(고정 크기 3종) 생성.
3. `PlaceholderTradeGoodsInventoryRepository`(§4.2, 골드 상자 정의 포함) 생성.
4. `IInventoryPopupCoordinator`/구현체, `IUIManager.ToggleInventoryPopup` 추가.
5. `ManagerHierarchyInstaller.DataRepositoryNames` + `BuildUIManagerDataRepositories`에 4개 저장소 추가, `UIManager`에 `IInventoryPopupCoordinator` 형제 컴포넌트 부착.
6. Unity 컴파일 확인 후 `Tools > Game > Build Bootstrap Scene` 재실행 → Ctrl+S.
7. (검증) EditMode 테스트: 그리드 배치/제거, 범위 초과·겹침 거부, 교역품 그리드 크기가 마차 재고 수(5개 고정)×8칸으로 계산되는지, 골드 상자 배치 시 지갑 차감/배치 실패 시 롤백/제거 시 환급이 올바른지.
