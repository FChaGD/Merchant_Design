## 2. 도시 워크북 (`Assets/Table/City/City.xlsx`)

| 시트 | 열 | 행 단위 |
|---|---|---|
| `CityData` | Id, X, Y, Scale | 도시 1개 |
| `CityStrings` | Id, Name, Description | 도시 1개 |
| `CityDetailData` | CityIdA, CityIdB | 경로 1개 |

- 기존 워크북 내용을 그대로 옮기고 `Scale`만 채운다(4 = `Metropolis`, 2·6·7·10 = `City`, 1·3·5·8·9 = `Village` — 기획 57번 §4.3). 이관은 제작 단계에서 스크립트로 수행하고 `TripCityMap.xlsx`는 삭제한다.
- `Scale` 값은 규모 Id 문자열. 빈칸 허용(= 미지정, §5.3).

## 3. 임포터

`TripCityMapTableImporter` → 새 워크북·시트 이름으로 수정(메뉴 이름 `Import City Table`로 변경, 자동 임포트 등록 유지).

| 검증 | 처리 | 근거 |
|---|---|---|
| `CityData` Id 중복 | 오류(임포트 중단) | 기존 파싱 규칙 |
| `CityStrings`·`CityDetailData`가 `CityData`에 없는 도시 Id를 가리킴 | 경고 후 해당 행 무시 | 기획 57번 §4.3 — 도시를 지웠을 때 남은 행을 드러냄 |
| `Scale` 빈칸 | 경고(자산에는 빈 값 그대로) | 기획 57번 §4.3. 규모 판정은 런타임 규칙(§5.3)이 처리 |

- 규모 Id가 정의된 규모인지는 임포트 시 검사하지 않는다 — 규모 정의가 인스펙터(씬) 데이터라 에디터 임포터가 알 수 없다. 런타임에서 경고한다(§5.3).

## 4. 디버그 도시 배치 저장 (`TripCityMapPersistence`)

- 저장 대상 시트 이름 변경(`CityData`/`CityDetailData`/`CityStrings`).
- `CityData`를 다시 쓰기 전에 기존 시트의 `Id → Scale`을 읽어 두고, 같은 Id 행에 다시 기록한다. 새로 배치한 도시는 빈칸(= 미지정 경고 대상).
- 이름 시트 자리표시자 추가 규칙(기존)은 그대로.

## 5. 규모와 시설 제공 여부

### 5.1 규모 정의 — 확장 가능한 목록 (기획 57번 §3 확장성)

규모를 enum으로 두지 않는다. **순서가 곧 등급인 목록**으로 둔다.

| 필드 | 예 | 비고 |
|---|---|---|
| 규모 Id | `Village` / `City` / `Metropolis` | 도시 테이블 `Scale` 열 값 |
| 이름 | 촌락 / 도시 / 대도시 | 표시용 |
| 순서 | 목록 위치(작은 규모 → 큰 규모) | 포함 관계 판정 기준 |

- 규모 추가(예: 소도시)는 목록에 한 항목을 원하는 위치에 끼우는 것으로 끝난다 — 코드·테이블 구조 변경 없음.

### 5.2 시설 최소 규모

- 시설 Id → 최소 규모 Id 목록. 포함 관계는 "마을 규모 순서 ≥ 시설 최소 규모 순서"로 판정한다.
- 기본값(기획 57번 §4.1)은 코드 상수 `TownScaleDefaults`에 둔다. 인스톨러가 인스펙터 목록을 이 기본값으로 채우되, 사용자가 바꾼 값은 유지하고 카탈로그에 새로 생긴 시설만 기본값으로 추가하며 사라진 시설은 걷어낸다(설계 37번의 시설 토글 동기화와 같은 규칙).
- 확장 지점(이번 미구현): 마을별 예외(도시 Id + 시설 Id + 추가/제외). 판정 순서 "마을별 예외 → 규모 규칙"에 끼울 자리만 판정 클래스 주석에 남긴다.

### 5.3 판정 규칙 (`TownScaleFacilityRule`, plain C#)

| 상황 | 결과 |
|---|---|
| 마을 규모 순서 ≥ 시설 최소 규모 순서 | 제공 |
| 도시 Id가 도시 자산에 없음(현재 위치 미지정 등) | 가장 작은 규모로 취급 |
| 도시의 규모가 빈칸이거나 정의되지 않은 규모 Id | 가장 작은 규모로 취급 + 경고(도시별 1회) |
| 시설이 최소 규모 목록에 없음 | 가장 작은 규모에서부터 제공(= 항상 제공) + 경고 1회 | 

- 판정 로직을 MonoBehaviour와 분리해 EditMode 테스트 대상으로 둔다.

### 5.4 구성 요소

| 요소 | 역할 |
|---|---|
| `ITownScaleReader` | 마을 Id → 규모(Id·이름·순서) 조회. 규모를 쓰는 다른 소비자(향후 판매 품목 등)를 위한 계약 |
| `TownScaleFacilityRule` | §5.3 판정. 규모 목록·시설 최소 규모·도시별 규모를 받아 만든다 |
| `TownScaleFacilityAvailabilityProvider` | MonoBehaviour + DI. `ITownFacilityAvailabilityReader`·`ITownScaleReader` 등록. 인스펙터: 규모 목록, 시설 최소 규모 목록, 도시 자산 참조 |
| `TownScaleDefaults` | 규모 기본 목록·시설 최소 규모 기본값(코드 상수) |

- `PlaceholderTownFacilityAvailabilityProvider`는 삭제한다(요약 주석의 "실제 시스템 설계 후 대체/제거 대상"). 인스톨러는 옛 오브젝트를 `DestroyChildIfExists`로 정리.

## 8. 검증 절차 (제작 후)

1. **반드시 Play를 먼저**(자동 임포트로 도시 자산 갱신) → 종료 → Bootstrap.unity `Build Bootstrap Scene` → Ctrl+S.
2. EditMode 테스트 전체 통과.
3. 상행 도착(또는 현재 위치 지정)으로 마을별 확인: 4번(대도시) 카테고리 4개·시설 11개 / 2·6·7·10번(도시) 시청 방면 없음·시설 8개 / 나머지(촌락) 시설 3개.
4. Bootstrap 인스펙터에서 시설 최소 규모를 바꾸면 해당 마을의 버튼이 바뀜.
5. 디버그 도시 배치 → 저장 → `City.xlsx`의 기존 규모 값 보존, 새 도시는 빈칸 + Play 시 경고.

## 10. 제작 메모 (2026-09-28)

- 임포터 파일은 `TripCityMapTableImporter.cs` → `CityTableImporter.cs`로 이름 변경(스크립트 GUID 유지), 메뉴 `Tools/Game/Table/Import City Table`.
