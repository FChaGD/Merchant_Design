## 1. 배경 / 범위

2026-09-24 Hub 버튼 재배치로 상단 배치·방향성 지시 버튼이 상행 준비 버튼 위(우측 정렬)로 옮겨져 좌측 열이 비었다. 이 자리에 24번 §3.1의 **시설 카테고리 버튼 4개를 마을 루트 depth에 직접** 둔다. 동시에 Hub UI를 **화면 depth에 따라 바뀌는 UI**와 **depth와 무관하게 항상 활성인 UI**로 구조적으로 분리한다.

**사용자 확정 사항(2026-09-24)**
1. 카테고리 버튼 위치: 기존 방향성 지시 자리 위 1칸 + 방향성 지시 자리 + 상단 배치 자리 + 상단 배치 자리 아래 1칸 = 세로 4칸(좌측 열).
2. 카테고리 버튼을 누르면 **화면 depth가 한 단계 깊어진다**(오버레이 패널 방식이 아님). 그 depth에서는 **해당 카테고리의 시설 버튼 + 뒤로 가기 버튼**만 보이고 나머지 마을 UI는 비활성화된다. 재화 HUD는 계속 보인다.
3. 시설 버튼과 뒤로 가기 버튼은 **카테고리 버튼 4칸 자리를 그대로 사용**하고, **뒤로 가기 버튼은 최하단**에 둔다.
4. **확장성**: 마을마다 제공 기능이 다르거나 없는 기능이 생길 수 있다. 제공되지 않는 버튼은 빠지고 남은 버튼은 **위에서부터 빈칸 없이** 채운다.
5. 명칭·순서는 24번 기획 확정값을 그대로 쓴다.
6. **depth 의존 UI와 상시 활성 UI를 분리 관리**한다.

**범위 안**: Hub UI 레이어 분리(§3), 카테고리 버튼 4개(루트 depth), 카테고리 depth(시설 버튼 + 뒤로 가기), 마을별 제공 여부 계약 + Placeholder, 버튼 열 동적 배치.
**범위 밖**: 각 시설 화면(시설 버튼 클릭 시 동작 — 이번엔 "미구현" 경고 로그만), 마을별 제공 여부 실제 데이터, Field 씬 레이어 분리(§3.5).

## 2. 명칭 / 순서 (24번 §3.1·§3.2 그대로)

| 카테고리(위→아래) | 하위 시설(위→아래) |
|---|---|
| 시장 지구 | 무역품 구매 / 특산물 구매 / 전당포 |
| 주점 지구 | 숙소 / 용병단 접촉 / 주점 |

코드 식별자는 `TownFacilityCategoryIds`(4개) / `TownFacilityIds`(11개) 문자열 상수로 두고(34/36번 enum→문자열 방침), 카테고리→시설 목록·표시 순서·한글 라벨은 `TownFacilityCatalog`(정적, `Core/Town/`) 한 곳에 모은다. 시설 문자열 테이블(엑셀)은 시설별 기획이 진행될 때 옮긴다 — 지금은 라벨 외 데이터가 없다.

## 3. Hub UI 레이어 분리

### 3.1 현재 문제

| 현재 방식 | 문제 |
|---|---|
| `HubUIController`가 루트 버튼(상행 준비/상단 배치/방향성 지시)을 **버튼마다 개별 필드로** 들고 패널 열림 시 하나씩 숨김·커튼 중 하나씩 비활성 | 버튼이 늘 때마다 필드·null 체크·토글 코드가 2곳씩 늘어난다. 카테고리 버튼 4개가 추가되면 그대로 반복된다. |
| `TacticsButton`은 "모달 패널보다 앞 형제"로, 재화 HUD는 "마지막 형제"로 **인스톨러가 개별적으로 형제 순서를 강제** | 요소가 늘 때마다 형제 순서 규칙을 요소별로 다시 맞춰야 하고, 실제로 오프바이원 버그가 있었다(`feedback_setsiblingindex_offbyone`). |
| "depth와 무관하게 항상 보이는 UI"라는 구분이 코드 구조에 없고, 재화 HUD가 숨김 대상에 **우연히 포함되지 않았을 뿐** | 새 상시 UI(예: 인벤토리 호출 버튼)를 추가할 때 어느 쪽에 속하는지 판단할 기준이 없다. |

### 3.2 계층 구조

```
ContentRoot                     (씬 전환 슬라이드 대상 - 기존 그대로, 설계 10번 §8)
 ├ Background                   (기존)
 ├ DepthLayer                   ← 신규: 화면 depth에 따라 바뀌는 UI 전부
 │   ├ RootDepth                ← 신규: 루트 depth 그룹 (CanvasGroup)
 │   │   ├ 상행 준비 버튼 (기존 DepartureButton)
 │   │   ├ 상단 배치 버튼 (기존 FormationButton)
 │   │   ├ 방향성 지시 버튼 (기존 TacticsButton)
 │   │   └ TownCategoryColumn   ← 신규: 카테고리 버튼 4개
 │   ├ TownCategoryDepth        ← 신규: 카테고리 depth (시설 버튼 11개 + 뒤로 가기)
 │   ├ FormationPanel           (기존, 위치만 이동)
 │   ├ TripPanel                (기존, 위치만 이동)
 │   └ TacticsPanel             (기존, 위치만 이동)
 └ PersistentLayer              ← 신규: depth와 무관하게 항상 활성인 UI
     └ PlayerCurrencyHud        (기존, 위치만 이동)
```

- **레이어 순서가 곧 렌더 순서다**: `PersistentLayer`가 `ContentRoot`의 마지막 자식이므로 상시 UI는 항상 depth UI 위에 그려진다. `RootDepth`가 `DepthLayer`의 첫 자식이므로 루트 버튼은 항상 모달 패널 아래에 그려진다. 인스톨러는 **레이어 2개와 `RootDepth`의 형제 순서만** 고정하고, 요소별 형제 순서 강제(`TacticsButton` 이동 로직, 재화 HUD `SetAsLastSibling`)는 제거한다.
- **`ContentRoot`는 그대로 슬라이드 대상**이다 — 두 레이어 모두 그 안에 있으므로 씬 전환 연출 동작은 바뀌지 않는다.
- 모달 패널(배치/상행 준비/방향성 지시)도 depth UI다 — "열리면 루트 depth를 대신한다"는 점에서 카테고리 depth와 같은 성격이라 `DepthLayer`에 함께 둔다.

### 3.3 런타임 관리 규칙

| 레이어 | 관리 주체 | 규칙 |
|---|---|---|
| `DepthLayer/RootDepth` | `HubUIController` | 패널(depth)이 하나라도 열리면 `RootDepth` **그룹 하나**를 끄고, 전부 닫히면 켠다(`UIManager.OnAnyPanelOpenChanged`, 기존 경로). 씬 전환 커튼 중 비활성은 `RootDepth`의 `CanvasGroup.interactable`로 **그룹 단위** 처리한다. 버튼이 늘어도 컨트롤러 코드는 바뀌지 않는다. |
| `DepthLayer`의 나머지(카테고리 depth, 모달 패널) | 각 `IUIPanel` | 기존 규칙 그대로 — 자기 루트의 표시/숨김만, 전환은 `UIManager.Open/Close`에 위임. |
| `PersistentLayer` | 각 요소의 컨트롤러(`PlayerCurrencyHudController` 등) | **depth 로직(`HubUIController`/`UIManager`/패널)은 이 레이어를 참조하지도 토글하지도 않는다.** 새 상시 UI는 이 레이어 아래에 만들기만 하면 된다. |

- `HubUIController`의 개별 버튼 필드(`departureButton`/`formationButton`/`tacticsButton`)와 `SetTopLevelButtonsInteractable`/`SetTopLevelButtonsVisible`의 버튼별 반복은 `RootDepth` 그룹 토글로 대체한다. 버튼 클릭 바인딩(`BindButton`)은 그대로 버튼마다 한다.
- 요소 Id: `HubUIElementIds.DepthLayer`, `RootDepth`, `PersistentLayer` 추가.

### 3.4 인스톨러 이동 처리 (재실행 안전성)

- `HubSceneInstaller`는 `DepthLayer`/`RootDepth`/`PersistentLayer`를 get-or-create한 뒤, 기존 요소를 **마커로 찾아 새 부모로 옮긴다**(기존 `ReparentIfFound` 재사용): 상행 준비·상단 배치 버튼(씬 원본 요소) → `RootDepth`, `TacticsButton` → `RootDepth`, `FormationPanel`/`TripPanel`/`TacticsPanel` → `DepthLayer`, `PlayerCurrencyHud` → `PersistentLayer`.
- 이후 빌드 메서드는 새 부모를 인자로 받아 그 안에서 get-or-create한다(`FormationUIBuilder.Build`/`TacticsUIBuilder.Build`는 이미 부모 Transform을 인자로 받으므로 호출부만 바뀐다). 옮긴 뒤 빌드하므로 옛 위치에 중복 생성되지 않는다.
- `StackActionButtonsAboveDeparture`는 앵커만 계산하므로 부모가 바뀌어도 그대로 동작한다(`RootDepth`는 전체 스트레치).

### 3.5 Field 씬

Field도 같은 성격의 구분(상시 버튼/패널/전투 뷰)이 있지만 이번 범위 밖이다. Hub에서 이 구조가 검증되면 Field에 같은 레이어 규칙을 적용하는 것을 후속 후보로 남긴다.

## 4. 화면 depth 구조 (카테고리)

```
[RootDepth]  상행 준비 / 상단 배치 / 방향성 지시 / 카테고리 버튼(최대 4)   + [PersistentLayer] 재화 HUD
      │ 카테고리 버튼 클릭 → uiManager.Open("Town.{categoryId}")
      ▼
[TownCategoryDepth]  시설 버튼(해당 카테고리) / 뒤로 가기(최하단)          + [PersistentLayer] 재화 HUD
      │ 뒤로 가기 → uiManager.Close("Town.{categoryId}") → RootDepth 복귀
      │ (후속) 시설 버튼 → uiManager.Open("Facility.{facilityId}") → 닫으면 카테고리 depth로 복귀
```

### 4.1 depth를 IUIPanel로 표현하는 이유

카테고리 depth는 시각적으로 오버레이가 아니지만, 동작 계약은 기존 패널과 같다: 열면 `RootDepth`가 숨고 닫으면 돌아온다. 그래서 `IUIPanel` + `UIManager.Open/Close`를 그대로 쓴다.

- `RootDepth` 숨김/복귀는 §3.3의 기존 경로를 그대로 탄다 — 새 네비게이션 코드가 필요 없다.
- 후속 시설 화면: `PanelNavigationStack`이 "새 패널을 열면 이전 패널을 숨기고, 닫으면 이전 패널로 복귀"를 이미 처리하므로, 시설 화면을 닫으면 카테고리 depth로 돌아오는 3단 depth가 추가 구조 없이 성립한다.
- 대안(Hub 전용 depth 상태 머신 신설)은 `UIManager`의 열림 이벤트/복귀 로직을 중복 구현하게 되어 채택하지 않는다.

### 4.2 카테고리 depth 패널

- `TownCategoryPanel : IUIPanel` — MonoBehaviour가 아닌 순수 C# 클래스, 생성자로 카테고리 Id를 받는다. `HubUIWiring`이 카테고리 4개에 대해 인스턴스를 만들어 `RegisterPanel`한다(PanelId `"Town.{categoryId}"`). `IUIPanel.Open()`이 매개변수를 받지 않으므로 카테고리마다 인스턴스를 나눈다 — 같은 클래스라 코드 중복은 없다.
- 시각 요소는 **4개 인스턴스가 공유하는 `TownCategoryDepth` 하나**(배경 없음): 시설 버튼 11개 전체 + 뒤로 가기 버튼 1개. `Open()`은 루트를 켜고 자기 카테고리 시설 버튼만 배치하며(§5), `Close()`는 루트를 끈다. 단일 패널 정책상 동시에 두 카테고리가 열리지 않으므로 공유가 안전하다.
- 뒤로 가기 버튼은 열려 있는 카테고리 패널의 `uiManager.Close(PanelId)`로 위임한다 — 패널이 자기 `Close()`를 직접 부르지 않는다(CLAUDE.md, `Close()` 위 주석 명시). 리스너는 `Open()` 시점에 현재 카테고리로 다시 연결한다.
- 시설 버튼 클릭: 이번 범위에선 `Debug.LogWarning("'{facilityId}' 시설 화면 미구현")`.

## 5. 확장성 — 마을별 제공 여부 + 빈칸 없는 배치

### 5.1 제공 여부 계약

```csharp
// 읽기 전용 - 소비자(Hub UI)는 조회만 한다(ISP).
public interface ITownFacilityAvailabilityReader
{
    bool IsFacilityAvailable(int cityId, string facilityId);
}
```

- **시설 단위로만 판단하고 카테고리 제공 여부는 파생한다**: 카테고리 버튼은 "제공되는 시설이 1개 이상"일 때만 보인다. 데이터 원천이 하나라 "카테고리는 보이는데 들어가면 빈 화면" 같은 불일치가 생기지 않는다.
- 마을 식별자는 기존 `ITripCurrentLocationReader.CurrentCityId`(int)를 그대로 쓴다.
- `PlaceholderTownFacilityAvailabilityProvider`(`IManagedComponent`, DI 등록, 요약 주석에 "실제 시스템 설계 후 대체/제거 대상" 명시). 기본은 전부 제공이고, **인스펙터에서 시설별 제공 여부를 끌 수 있는 체크 목록**을 둬 코드 수정 없이 빈칸 재배치를 검증할 수 있게 한다.
- Hub 배선은 `TryResolve`로 선택 조회한다. provider 또는 현재 위치 저장소가 없으면 전부 제공으로 간주한다.

### 5.2 슬롯 좌표 (카테고리 depth와 루트 depth가 같은 4칸 공유)

좌측 열 x 0.105~0.241, 높이 0.1154. 슬롯 i(0부터)의 윗변 = 0.6848 − i × 0.1254.

**2026-09-24 조정(사용자 확정)**: 최초안(슬롯 1 윗변 0.8002, 간격 0.02 — 기존 방향성 지시 자리 위 1칸부터 4칸)이 위로 치우쳐 보여, 간격을 절반(0.01)으로 줄이고 열 전체를 버튼 1개 높이(0.1154)만큼 내렸다.

| 슬롯 | y |
|---|---|
| 1 | 0.5694 ~ 0.6848 |
| 2 | 0.4440 ~ 0.5594 |
| 3 | 0.3186 ~ 0.4340 |
| 4 | 0.1932 ~ 0.3086 |

### 5.3 배치 규칙

`TownButtonColumnView`(순수 표시 담당, 카테고리 열과 시설 열이 **같은 클래스를 재사용**):

- **공통**: 입력 목록(순서 유지)에 있는 버튼만 켜고 나머지는 끈 뒤, 켜진 버튼을 슬롯 1부터 위에서 차례로 앵커 재계산해 채운다.
- **카테고리 depth**: 시설 버튼을 위에서부터 채우고, **뒤로 가기 버튼을 마지막(최하단) 슬롯에 고정**한다. 시설 슬롯은 1~3(최대 3개) — 24번 기준 카테고리당 시설 최대 3개라 들어맞는다.
  - 예: 시설 3개 → 슬롯 1~3 시설, 슬롯 4 뒤로 가기. 시설 2개(시청 방면, 또는 마을 사정으로 1개 제외) → 슬롯 1~2 시설, 슬롯 3 빈칸, 슬롯 4 뒤로 가기.
  - 뒤로 가기 위치가 시설 수와 무관하게 항상 같은 자리라 조작 위치가 흔들리지 않는다. 대신 시설이 3개 미만이면 시설과 뒤로 가기 사이에 빈 슬롯이 생긴다 — "빈칸 없이"는 시설 버튼끼리에 적용된다.
- **한계**: 한 카테고리의 시설이 4개 이상이 되면 4칸 안에 들어가지 않는다 — `TownButtonColumnView`가 슬롯 수를 넘는 입력을 받으면 경고 로그를 남겨 조기에 드러낸다.
  - **결정(2026-09-27, 미구현)**: 열이 차지하는 전체 영역(현재 슬롯 1 윗변~최하단 슬롯 아랫변)은 유지하고, 슬롯 수를 늘리는 만큼 버튼 높이와 버튼 간 간격을 줄인다. 열을 아래로 늘리거나 스크롤을 넣지 않는다. 4개째 시설이 생길 때 제작한다.
- `VerticalLayoutGroup`을 쓰지 않는 이유: Hub 캔버스는 `ConstantPixelSize`라 레이아웃 그룹의 픽셀 기반 크기로는 다른 Hub 버튼(앵커 비율 기반)과 해상도별 크기가 어긋난다. 또 "뒤로 가기는 마지막 슬롯 고정" 규칙이 레이아웃 그룹으로는 표현되지 않는다.
- 호출 시점: 카테고리 열은 Hub UI 등록 시 1회(마을 이동은 항상 Field→Hub 씬 재로드를 거침) + 방어적으로 `ITripCurrentLocationReader.Changed` 구독. 시설 열은 카테고리 depth `Open()` 때마다.

## 7. 제작 체크리스트

1. §6 신규 파일 작성.
2. `HubUIController`/`HubUIWiring` 수정.
3. `ManagerHierarchyInstaller`에 Placeholder provider 등록.
4. `HubSceneInstaller`: 레이어 구조 + 이동 + 카테고리 UI 생성.
5. 사용자 실행: `Tools > Game > Build Bootstrap Scene` → 저장, Hub 씬에서 `Tools > Game > Build Hub Scene` → 저장.

## 8. 검증 항목

1. **레이어 분리 회귀**: Hub 계층이 §3.2 구조로 정리됨, 인스톨러 2회 연속 실행 시 중복 생성 없음, 씬 전환(Hub↔Field) 슬라이드 연출 정상, 재화 HUD가 모든 패널·depth 위에 보임.
2. **기존 패널 회귀**: 상행 준비/상단 배치/방향성 지시 열기·닫기, 상행 준비→배치→복귀, 열린 동안 루트 버튼 숨김, 커튼 중 루트 버튼 비활성.
3. 루트 depth: 카테고리 버튼 4개 위치·순서·라벨.
4. 각 카테고리 → `RootDepth` 숨김(재화 HUD만 유지) + 시설 버튼 위에서부터 + 뒤로 가기 최하단.
5. 뒤로 가기 → 루트 depth 복귀.
6. 시설 버튼 클릭 → 미구현 경고 로그.
7. Placeholder 인스펙터에서 시설을 끈 뒤: 시설 열이 위로 당겨짐 / 한 카테고리 시설을 전부 끄면 그 카테고리 버튼이 사라지고 카테고리 열이 위로 당겨짐.
