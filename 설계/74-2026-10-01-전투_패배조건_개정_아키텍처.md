## 2. 변경

### 2.1 보호 대상 종류

- `BattleProtectedUnit`에 `ProtectedUnitKind Kind { get; }`(신규 enum: `Wagon`, `Facility`) 추가(생성자 인자).
- `LiveBattleSimulationRule.BuildProtectedPlacements`가 로스터 종류(`FormationUnitKind.Wagon`/`Facility`)를 변환해 넘긴다.
- 기존 `FormationUnitKind`를 그대로 쓰지 않는 이유: `Character`가 섞여 있어 보호 대상에 넣을 수 없는 값이 생긴다(§7-1).

### 2.2 패배 판정 `BattleDefeatRule` (static, 신규)

```csharp
public static bool IsDefeated(int totalWagons, int aliveWagons, int aliveCharacters, int aliveFacilities)
    => (totalWagons > 0 && aliveWagons == 0)     // 조건 1 — 마차 0대 전투는 미적용(기획 73 §4-1)
    || (aliveCharacters == 0 && aliveFacilities == 0); // 조건 2 — 전투 가능 아군(캐릭터+시설) 없음
```

- 판정 규칙을 루프 밖 순수 함수로 두어 EditMode에서 숫자만으로 검증한다(루프는 협력 객체가 많아 테스트 구성이 크다).

### 2.3 `BattleSimulationLoop`

- 보호 대상 카운터를 `aliveWagonCount` / `aliveFacilityCount`로 나누고 `totalWagonCount`를 둔다. 보호 대상의 `OnDied`에서 종류별로 줄인다.
- 보호 대상 목록 타입을 `List<IDamageable>` → `List<BattleProtectedUnit>`으로 좁힌다 — 종류를 읽어야 한다. 외부 노출(`ProtectedUnits`)은 `IReadOnlyList<IDamageable>` 그대로(공변성으로 대입 가능, 뷰·방진 조율자 무변경).
- `IsProtectionTargetDestroyed` 삭제 → `IsDefeated => BattleDefeatRule.IsDefeated(totalWagonCount, aliveWagonCount, aliveAllyCount, aliveFacilityCount)` 추가.
- `IsAllyWiped`는 유지(배틀 테스트·디버그 결과 뷰가 사용).

### 2.4 `LiveBattleSimulationRule`

- 패배 판정을 `simulation.IsDefeated`로 바꾼다. 승리(`IsEnemyWiped`) 우선 순서는 그대로.
- 전투 뒤 마차·시설 상태는 저장하지 않는다(기획 73 §4-4 — 지금 코드도 저장하지 않으므로 변경 없음).
- 증원(설계 25)은 캐릭터만 — 영향 없음(`aliveAllyCount`를 늘리는 기존 경로 그대로).

### 2.5 `BattleTestSimulationRule`

- 생성 시 넘기는 빈 보호 대상 목록 타입만 `List<BattleProtectedUnit>`로 맞춘다. 판정은 `IsAllyWiped` 그대로.

### 2.6 장애물에서 파괴된 것 제외 (기획 73 §4-3)

- `BattleObstacleField`가 매 조회 때 소유 유닛의 `IsAlive`를 본다 — 조향(막는 장애물 찾기)·목적지 보정·빼내기에서 파괴된 장애물을 건너뛴다.
- 통로는 양 끝 두 유닛이 모두 살아 있을 때만 감속 구역이다(끝 인덱스 보관).
- 목록을 다시 만들지 않는 이유: 파괴는 전투 중 몇 번뿐이고, 살아 있는지 확인은 bool 하나라 매 틱 비용이 거의 없다. 이벤트로 목록을 고치면 조향 기억(`ObstacleAvoidanceState`)이 가리키는 Id가 흔들린다.
- 기즈모는 살아 있는 장애물·통로만 그린다(필드가 `IsObstacleActive(i)`/`IsPassageActive(i)` 노출).

### 2.7 주석·문서 정리

- `BattleProtectedUnit`·`LiveBattleSimulationRule`·`BattleSimulationLoop`·`BattleObstacleField` 요약 주석의 "하나라도 파괴 = 패배", "파괴 = 전투 종료" 서술을 새 조건으로 고친다.
- 기획 08 머리에 대체 표시 줄(§7.7·§9 → 73), 설계 72 §3.4의 "바뀌지 않는다" 서술에 74 참조.

## 3. 테스트 (EditMode)

- `BattleDefeatRule`: 마차 일부 파괴 → 패배 아님 / 마차 전부 파괴 → 패배 / 마차 0대 → 조건 1 미적용 / 캐릭터 0 + 시설 남음 → 패배 아님 / 캐릭터 0 + 시설 0 → 패배 / 캐릭터 남음 + 시설 0 → 패배 아님.
- `BattleObstacleField`: 파괴된 장애물은 피하지 않음(직진), 빼내기 대상 아님, 한쪽 끝이 파괴된 통로는 감속 없음.

## 5. 검증 (Field 전투)

- 마차 2대 중 1대 파괴 → 전투 계속.
- 마차 전부 파괴 → 패배.
- 캐릭터 전멸 + 시설 남음 → 전투 계속(적이 시설·마차 공격) → 시설 전부 파괴 시 패배(또는 마차 전부 파괴 시 패배).
- 파괴된 마차 자리를 캐릭터가 피하지 않고 지나감, 그 마차와 붙어 있던 통로에서 감속 없음.
