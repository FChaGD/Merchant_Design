## 2. 영역 모양 값 타입 `FormationAreaShape` (신규, `Core/UI/Formation/`)

```csharp
public sealed class FormationAreaShape
{
    public IReadOnlyList<Vector2Int> Offsets { get; } // 기준 칸 기준 (열 차, 행 차) - 행 차 음수 = 위쪽
    public int MaxReach { get; }                       // 오프셋의 |열 차|·|행 차| 중 최댓값 - 마을 칸 표시 범위
    public static FormationAreaShape Single { get; }    // 기준 칸 1칸(모양이 없는 유닛의 기본값)
    public static FormationAreaShape Square(int reach);  // (2 × reach + 1)² 전부 대열, 가운데 기준 - 테스트·핀 기본값
    public static bool TryParse(string mask, out FormationAreaShape shape, out string error);
    public override string ToString();                  // 마스크 문자열로 되돌림(디버그 입력 기본값 표시)
}
```

- 파싱 규칙(기획 65번 §3.1): `/` 줄 구분, `0`/`1`/`2`, `2`는 정확히 1개, 줄 길이가 모두 같아야 한다. 떨어진 조각은 허용한다(§3.5).
- 파싱 결과를 **기준 칸 기준 오프셋 목록**으로 저장한다. 영역 계산은 배치할 때마다 여러 번 호출되므로 마스크를 매번 훑지 않고 대열 칸 목록만 돈다.
- 불변 클래스라 카탈로그·유닛·핀이 같은 인스턴스를 공유해도 안전하다.

### 2.1 마스크 줄 파싱 공용화 (§8-1 확정)

적재 모양(`InventoryShape`, `0`/`1`)과 대열 모양(`0`/`1`/`2`)은 줄 나누기·줄 길이 검사·허용 문자 검사가 같다. 이 부분을 공용 정적 클래스 `CellMaskParser`(`Core/`)로 뽑는다. 두 모양 타입은 각자의 규칙만 더한다(적재: 적재 칸 1개 이상 / 대열: 기준 칸 정확히 1개).

```csharp
internal static class CellMaskParser
{
    // 성공하면 cells[x, y]에 문자를 담는다(y = 위 줄부터). 허용 문자 밖이거나 줄 길이가 다르면 error.
    public static bool TryParse(string mask, string allowedChars, out char[,] cells, out string error);
}
```

## 3. 데이터

- 엑셀: `Wagon`·`Facility` 데이터 시트에서 `Up`/`Down`/`Left`/`Right` 열을 삭제하고 `AreaShape` 열을 추가한다(§8-2). 전 행 값은 `1111111/1111111/1111111/1112111/1111111/1111111/1111111`(지금 값 3/3/3/3과 같음).
- `CaravanAssetEntry`: 필드 4개를 삭제하고 `AreaShape`(string)를 추가한다.
- 임포터: 두 시트 모두 `AreaShape`를 필수 열로 읽고 `FormationAreaShape.TryParse`로 검증한다. 실패하면 `FormatException`(시트·Id·이유). 설계 62번의 음수 검사는 삭제한다.
- `CaravanAssetProfile.AreaShape`(`FormationAreaShape`). 파싱에 실패하면(임포트 전 자산) §8-3의 처리.

## 4. 유닛·영역 계산

- `IAreaAnchorUnit.AreaSpan` → `FormationAreaShape AreaShape`. `PlaceholderFormationUnit` 생성자 기본값은 `null`이고, 속성은 null이면 `FormationAreaShape.Single`을 돌려준다.
- `FormationAreaPin.Span` → `FormationAreaShape Shape`.
- `FormationArea`: 직사각형 추가 로직을 "기준 칸 + 오프셋 목록" 추가로 바꾼다. 판 밖 칸은 기존처럼 버린다. 합집합·자리 칸·연결 칸·경계 상자·마차 중심 계산은 그대로다.
- 떨어진 조각: 조각 칸도 대열·자리·연결 칸에 들어간다(기획 65번 §3.5). 연결 판정은 "모든 마차 칸이 연결 칸 한 덩어리 안에 있는가"라서, 조각은 **다른 마차들 사이를 이어 줄 수는 있지만**, 조각만 다른 영역에 맞닿고 기준 칸(자기 마차)이 떨어져 있으면 그 마차는 이어진 것으로 보지 않는다(2026-09-30 제작 중 확인, 테스트로 고정).

## 5. 마을 칸 표시 범위

- `HubFormationPanel`: 로스터 마차들의 `AreaShape.MaxReach` 최댓값 + 1, 최소 2(기획 65번 §3.4). 방향 범위 최댓값을 쓰던 자리만 바뀐다.

## 7. 테스트 (EditMode, `FormationAreaTests`)

- 기존: 유닛·핀 생성을 `FormationAreaShape.Square(n)`/마스크 문자열로 교체하고, 기대값은 그대로 둔다.
- 교체: 비대칭 직사각형 테스트 2개(27칸·20칸, 가장자리 잘림)를 같은 모양의 마스크로 다시 쓴다.
- 삭제: 방향 범위 음수 테스트.
- 추가
  - 파싱: 정상, 줄 길이 불일치, 허용 밖 문자, `2`가 0개·2개.
  - 영역: 십자 `010/121/010` = 5칸, 기준 칸이 가장자리에 있는 모양, 떨어진 조각이 대열·연결에 포함되는지, `MaxReach`.
  - `ToString` 왕복(마스크 → 모양 → 같은 마스크).
- 적재 모양 테스트(`InventoryGridTests`)는 공용 파서로 바뀌어도 기대값이 같다.
