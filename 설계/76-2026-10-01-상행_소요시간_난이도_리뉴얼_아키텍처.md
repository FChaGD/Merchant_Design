## 4. 계산

### 4.1 `TripDurationFormula` (static)

```
소요시간(초) = 최소 시간 + (시간 폭 − n) × 거리 비율 + n × 난이도 비율
거리 비율   = max(0, 구간 거리 − 시작 거리) ÷ 거리 폭   (긴 거리는 1을 넘어도 그대로 — 상한 없음)
난이도 비율 = (난이도 − 1) ÷ 99
거리 구분   = 지역을 넘는 구간이면 항상 긴 거리, 아니면 거리로 구분(600 / 1100)
```

### 4.2 `TripDifficultyGrades` (static)

- 난이도 → 등급(상한 이하 중 첫 등급), 등급 → 5분 평균 횟수.
- 판정 확률 = 5분 평균 횟수 × 판정 간격 ÷ 300 (보통: 2.0 × 5 ÷ 300 ≈ 3.3%).

### 4.3 `TripRoutePlanner` (plain C#)

1. **최단 경로**: 노드 = 도시·관문, 간선 = 도로(가중치 = 같은 지역 안 두 끝점 거리) + 관문 짝(가중치 0). 다익스트라. 노드는 수십 개라 비용 무시.
2. **구간 나누기**: 경로를 도시 노드에서 자른다 — 출발 도시 → 다음 도시까지가 구간 하나(사이 관문 포함).
3. **구간 값**:
   - 거리 = 구간 안 도로 길이 합(관문 짝 0).
   - 난이도 = 구간 안 도로들의 **길이 가중 평균**(보통 도로 하나라 그 값, 관문 구간만 여러 도로 — §10-2). 반올림해 정수.
   - 지역을 넘는지 = 구간 안에 관문이 있는지.
   - 소요시간·등급·5분 평균 횟수 = §4.1·§4.2.
4. 결과 `TripPlan`: 구간 목록 + 합계 시간. 경로가 없으면 실패(도착지 지정 단계에서 이미 막히므로 방어용).

- 도달 판정(`IsReachable`, 도착지 지정)은 지금 BFS 그대로 — 같은 그래프라 결과가 일치한다.

### 4.4 도로 난이도 현재값 `RoadDifficultyState` (MonoBehaviour, Bootstrap, DI)

> 2026-10-16: 바뀐 값 저장 단위를 도로 조각(`RoadKey`)에서 **도시 쌍**으로 교체하기로 결정 — [설계 89](89-2026-10-12-이벤트_인카운터_아키텍처.md) §2·§5.2. 아래 도로별 저장 서술은 89 제작 시 대체된다.

- `IRoadDifficultyReader.GetDifficulty(RoadKey)` = 바뀐 값 있으면 그 값, 없으면 지도 기본값.
- `IRoadDifficultyRepository.SetDifficulty(RoadKey, 값)` / `ResetDifficulty` — 이벤트(향후, 기획 75 §6)용. 지금 호출하는 곳은 없다.
- 플레이 세션 동안만 유지(현재 위치 저장소와 같은 수준).
- 상행 계획은 **출발 시점의 난이도로 고정**한다 — 상행 중 이벤트로 값이 바뀌어도 진행 중 여정은 그대로(§10-3).

## 6. 흐름

### 6.1 `SessionStateTracker`

- `ISessionState.Begin()` → `Begin(float durationSeconds)`. 인스펙터 `testDurationSeconds` 삭제.
- 나머지(Pause/Resume, 도착 시 `OnArrived`)는 그대로 — 구간 하나가 지금의 상행 하나와 같은 단위.

### 6.2 `FieldTripLegCoordinator` (plain C#, 신규, `FieldUIController` 소유)

`FieldUIController`의 "화면 드러남 → Begin"과 "도착 처리"를 옮겨 구간 단위로 조율한다(SRP — 뷰 조율과 여정 진행 분리).

| 시점 | 처리 |
|---|---|
| 화면 드러남 | 첫 구간 시작: `sessionState.Begin(구간 시간)`, 게이지 라벨 "구간 1/N · 등급" |
| `OnArrived`, 남은 구간 있음 | 현재 위치 = 구간 도착 도시 → "구간 도착: 도시 이름" 알림(약 2초, 자동으로 사라짐) → `AdvanceLeg` → 다음 구간 `Begin`·라벨 갱신 |
| `OnArrived`, 마지막 구간 | 지금의 도착 흐름 그대로(배치 확정, 전원 회복, 현재 위치 = 도착지, 도착지 해제, "도착 성공" 팝업 → Hub) + `itinerary.Clear()` |

- 중간 도시 도착에서는 회복·배치 확정·Hub 진입을 하지 않는다(기획 75 §4-17 — 자동 다음 구간).
- 알림 중에는 진행이 멈춰 있다(도착 시 `SessionStateTracker`가 이미 정지 상태). 알림 동안 인카운터도 일어나지 않는다.
- 정비창 배치·이동 타이머는 시간 단위라 구간이 바뀌어도 이어진다(기획 75 §4-21) — 별도 처리 없음.

### 6.3 `EncounterManager`

- `RandomEncounterRule`이 확률을 인자로 받는다. 매 판정마다 `IEncounterRateSource`(TryResolve)의 값으로 확률을 계산.
- 판정 간격은 설정 자산 값(지금 인스펙터 5초와 같은 값).

### 6.4 패배 결과와 구간

| 결과 | 지금 | 구간 도입 후 |
|---|---|---|
| 승리 / 도주(Flee) | 상행 재개 | 현재 구간 재개(그대로) |
| 궤주(Rout) | Hub 귀환 | Hub 귀환. 현재 위치 = 마지막으로 도착한 도시(구간마다 갱신하므로 자연히), 여정 `Clear` |
| 사망 / 포로 | 플레이 종료 | 그대로 |

- 기획 75 §4-19의 "남은 구간 취소"는 궤주에서 성립한다. 도주는 지금처럼 속행이다.
- 궤주 시 여정 정리는 Hub 진입 시점(`TripPanel` 열기 전)에 `Clear` — 전환 흐름 코드를 건드리지 않는다.

## 8. 디버그

- **상행 시간 배속**(§10-4): 디버그 인스톨러로 Field에 배속 버튼(1× / 10× / 60×)을 붙인다. `SessionStateTracker`의 진행 시간에만 곱한다 — 인카운터 판정도 같은 진행 시간에 얹혀 있어 함께 빨라진다(빈도 비율 유지). 디버그 도구 규칙대로 Install/Remove 서브메뉴 + 일괄 설치 등록.

## 9. 테스트 (EditMode)

- `TripDurationFormula`: 기획 75 예시(329/731/1256 × 난이도 1/50/100), 경계(599/600/1099/1100), 지역을 넘는 구간 합 1100 미만 → 15분, 상한 없음.
- `TripDifficultyGrades`: 등급 경계(14/15, 57/58, 100), 확률 계산.
- `TripRoutePlanner`: 다익스트라가 짧은 길 선택, 도시마다 구간 분리, 관문 구간 합치기·긴 거리·길이 가중 난이도, 도로 하나면 그 난이도.
- `TripItineraryState`: Start/Advance/Clear, 여정 없을 때 기본 확률.

- 신규(Field): `FieldTripLegCoordinator`, `FieldLegArrivalNoticeView`. 디버그: `Core/Debug/Trip/TripTimeScaleDebugView`, `Editor/Debug/TripTimeScaleDebugInstaller`(+일괄 설치 등록). 테스트 `TripTravelTests`(규칙 21 케이스 + 경로 5건).
- 삭제: `PlaceholderTripInfoProvider`(+인스톨러 잔재 정리 `DestroyChildIfExists`).
- 수정: `WorldMap`/`IWorldMapReader`(도로 난이도 기본값, `RestoreRoad(a, b, difficulty)`), `TripCityMapAsset`(`Difficulty`), `WorldMapProvider`, `CityTableImporter`(열 없음/빈 칸 = 50, 범위 밖 오류), `TripCityMapPersistence`(`Difficulty` 열 쓰기), `ISessionState`/`SessionStateTracker`(`Begin(초)`, 인스펙터 30초 삭제), `EncounterManager`/`RandomEncounterRule`(확률 주입), `FieldUIController`/`IFieldUIController`/`FieldUIWiring`(구간 조율자), `FieldProgressGaugeView`(구간 라벨), `FieldUIElementIds`, `TripPanel`/`ITripPanel`/`HubUIWiring`(출발 시 여정 확정, 도착지 변경 시 요약 갱신), `ManagerHierarchyInstaller`, `FieldUIInstaller`.
- 데이터: `City.xlsx` `RoadData`에 `Difficulty` 열 추가(15행 전부 50).
- 설계와 달라진 점
  - 이동 수치는 별도 ScriptableObject 자산이 아니라 **`TripItineraryState` 인스펙터**에 둔다 — §10-1 근거("마을 규모 시설 배정과 같은 방식")가 컴포넌트 인스펙터라 그쪽에 맞췄고, 자산 파일·배선이 필요 없다.
  - 소요시간 공식과 등급 판정을 `TripTravelRules` 하나로 합쳤다(둘 다 같은 설정을 읽는 작은 순수 함수).
  - 인카운터 판정 간격은 설정이 아니라 기존 `EncounterManager` 인스펙터(5초)에 그대로 둔다.
  - 계획기는 지도 조회 뒤에 만들어져 DI에 직접 못 올린다 — `TripItineraryState`가 `ITripPlanner`로 등록하고 위임한다(정보 패널과 실제 상행이 같은 수치를 쓰도록).
  - 디버그 배속은 진행 시간만이 아니라 `Time.timeScale` 전체를 바꾼다 — 게임 코드에 배속 계약을 더하지 않기 위해. Field를 벗어나면 1×로 복원.
  - 궤주 시 여정을 따로 지우지 않는다 — 다음 "상행 시작"(`TryDepart`)이 항상 먼저 비우므로 남은 여정이 쓰이는 경로가 없다.
- 확인: `dotnet build`(Core·Editor·Tests) 오류 0. Unity 밖 실행으로 신규 26 + 기존 지도·장애물 회귀 23 = 49건 통과. 2026-10-01 사용자 검증 통과(정보 패널·디버그 버튼 수정 포함), 커밋+push `c345710`.

### 11.1 수정 기록 — 정보 패널 "값 없음" (2026-10-01 검증)

- 원인: `TripPlanSummaryProvider`가 현재 위치·도착지를 읽기 타입(`ITripCurrentLocationReader`, `ITripDestinationReader`)으로 조회했는데, DI에는 쓰기 타입(`ITripCurrentLocationRepository`, `ITripDestinationAssigner`)으로만 등록된다 → 조회 실패로 항상 "값 없음".
- 수정: 쓰기 타입으로 조회해 읽기 전용 필드에 담는다(`HubUIWiring`과 같은 규칙). 다른 신규 조회는 등록 타입과 일치함을 확인.

### 11.2 수정 기록 — 디버그 버튼 겹침 + 버튼 추가 (2026-10-01 사용자 요청)

- 배속 버튼이 전투 강제 승패 버튼(`BattleDebugResultView`, 좌상단 y 10~80)과 겹쳐, 상행 디버그 버튼을 그 아래(y 90~)로 옮겼다.
- 배속 도구를 상행 디버그 묶음 `TripDebugView`로 넓혔다(파일·`.meta` GUID를 옮겨 이미 설치된 씬 참조 유지, 설치 메뉴 `Install/Trip Debug Buttons`).
  - **인카운터 발생**: `EncounterManager.DebugTriggerEncounter`(에디터 전용) — 확률 판정 없이 정상 인카운터 흐름을 즉시 시작.
  - **상행 완료**: 여정을 마지막 구간으로 넘기고 그 구간을 즉시 끝내 최종 도착 흐름을 실행.
  - 두 버튼은 이동 중에만 활성(진행 이벤트가 오는 동안 = 이동, 인카운터 발생 ~ 다음 진행 이벤트 = 전투).
