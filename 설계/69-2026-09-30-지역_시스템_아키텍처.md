## 1. 현재 구조와 문제 (코드 확인)

## 2. 계층 구성

```
[데이터]  City.xlsx ──(CityTableImporter)──▶ TripCityMapAsset + TripCityStringsTableAsset + RegionStrings
                                                   │
[모델]    WorldMapProvider(Bootstrap, DI) ──▶ WorldMap(plain C#)
              registers: IWorldMapReader, ITripRouteReader      (+ 에디터: IWorldMapEditor)
                                                   │
[정식 표시] TripPanel ──소유──▶ TripMapPresenter ── 지역 1개를 그림, 도시 클릭→도착지, 관문 클릭·드롭다운→지역 전환
                                                   │
[디버그]  TripMapDebugEditor(#if UNITY_EDITOR) ── IWorldMapEditor로 편집, 저장(TripCityMapPersistence)
```

## 3. 데이터

### 3.1 엑셀 (`Assets/Table/City/City.xlsx`, 안 A)

| 시트 | 열 | 비고 |
|---|---|---|
| `RegionData` (신규) | `Id`, `Width`, `Height` | 지역 지도 크기. 전 행 2400 |
| `RegionStrings` (신규) | `Id`, `Name` | 지역 이름 |
| `CityData` | `Id`, **`RegionId`**, `X`, `Y`, `Scale` | `RegionId` 추가. X·Y = 그 지역 지도 기준(좌하단 원점) |
| `CityStrings` | `Id`, `Name`, `Description` | 변경 없음 |
| `GateData` (신규) | `Id`, `RegionId`, `X`, `Y`, `PairGateId` | 관문(지역 아이콘). 짝은 서로를 가리킨다 |
| `RoadData` (**`CityDetailData` 대체**) | `NodeA`, `NodeB` | 끝점 = `C`+도시 Id 또는 `G`+관문 Id(예: `C4`, `G1`) |

- 기획 57의 "도시 테이블 3종(데이터·스트링·세부 데이터)"에서 세부 데이터 자리는 도로 시트(`RoadData`)가 된다.
- **첫 변환(1회)**: `CityDetailData`의 `CityIdA/B` → `RoadData`의 `C` 접두어 값, `CityData.RegionId` = 1, `RegionData` 1·2, `RegionStrings` "지역1"·"지역2". 이후는 저장 버튼이 새 형식으로 쓴다.

### 3.2 임포트 검증 (`CityTableImporter`)

| 검사 | 실패 시 |
|---|---|
| 도시·관문의 `RegionId`가 `RegionData`에 있음 | 임포트 오류 |
| 관문 짝: 짝이 존재, 서로를 가리킴, **서로 다른 지역** | 임포트 오류(기획 68 §3.5) |
| 도로 끝점 형식(`C`/`G` + 정수)과 존재 | 임포트 오류 |
| 도로 두 끝점이 **같은 지역** | 임포트 오류(§9-4) — 지역 사이는 관문 짝이 잇는다 |

### 3.3 런타임 자산 (`TripCityMapAsset` 확장, §9-1)

- 목록 추가: 지역(Id·크기), 관문(Id·지역·좌표·짝). 도시 항목에 `RegionId` 추가. 도로 항목을 도시 Id 쌍에서 **끝점 쌍**(`MapNodeId` 직렬화 — 종류·Id)으로 바꾼다.
- 지역 이름은 스트링 자산(`TripCityStringsTableAsset`과 같은 방식의 지역 스트링 자산, 신규)으로 둔다.
- 좌표 변환(`TripCityMapCoordinateConverter`)은 지역 지도 크기를 인자로 받는다(지금은 2400 상수).

## 4. 모델

### 4.1 끝점 식별 `MapNodeId` (신규, readonly struct)

- `Kind`(City/Gate) + `Id`(int). 문자열 표기 `C4`/`G1` 파싱·출력(엑셀·임포터·저장 공용).
- 도시 Id와 관문 Id는 번호 공간이 따로다(`C1`과 `G1`은 다른 끝점).

### 4.2 `WorldMap` (plain C#, 신규)

- 지역·도시·관문·도로를 갖는 편집 가능한 모델. 도시·관문은 Id로 O(1) 조회, 지역별 목록을 따로 유지해 지역 하나 그리기가 전체를 훑지 않게 한다.
- **읽기 계약 `IWorldMapReader`**: 지역 목록·이름, 지역별 도시·관문·도로, 도시·관문 조회, 도시가 속한 지역. 변경 이벤트(디버그 편집 시 다시 그리기용).
- **도달 판정**: 끝점 그래프 = 도로 간선 + **관문 짝 간선**. `ITripRouteReader.IsReachable(cityA, cityB)`를 이 그래프 BFS로 구현한다 — 지역을 넘어 판정된다. `TripDestinationAssigner`는 바꾸지 않는다.
- **편집 계약 `IWorldMapEditor`**(에디터 전용 등록): 도시 추가·이동·삭제, 관문 쌍 추가(짝 자동 생성)·이동·삭제(짝 동반), 도로 추가·삭제, 지역 추가·삭제, 전체 스냅샷(저장용). 규칙(기획 68 §3.5·§3.6)은 모델 안에서 지킨다:
  - 관문 쌍 추가: 대상 지역 ≠ 지금 지역, 짝은 대상 지역 지도 중앙.
  - 관문 삭제 → 짝 삭제 → 두 관문의 도로 삭제.
  - 도로: 같은 지역 끝점끼리만, 중복·자기 연결 거부.
  - 지역 삭제: 지역 1개뿐이거나 현재 위치 도시의 지역이면 거부. 그 지역 도시·관문, 다른 지역 짝 관문, 연결 도로를 함께 삭제하고 삭제된 도시 Id를 알린다(도착지 해제용).
  - 지역 추가: Id = 최대 + 1, 크기 2400.

### 4.3 `WorldMapProvider` (MonoBehaviour, Bootstrap, 전역 DI, 신규)

- 자산(지도·도시 스트링·지역 스트링)을 인스펙터로 받아 `WorldMap`을 만들고 `IWorldMapReader`·`ITripRouteReader`를 등록한다. 에디터에서는 `IWorldMapEditor`도 등록한다.
- `ManagerHierarchyInstaller`의 저장소 목록에 추가하고 자산을 코드로 배선한다(마을 규모 제공자와 같은 방식).
- 기존 `InMemoryTripCityRepository`·`InMemoryTripRouteRepository`·`ITripCityReader/Repository`·`ITripRouteRepository`는 삭제한다(모델이 대체).

## 5. 정식 지도 표시 — `TripMapPresenter` (plain C#, `Core/UI/Trip`, 신규)

| 기능 | 설계 |
|---|---|
| 보이는 지역 | 상태로 보관. 패널을 열 때 **현재 위치 도시의 지역**(기획 68 §4-5) |
| 그리기 | 보이는 지역의 도시 마커·관문 마커·도로 선만. 오브젝트는 풀로 재사용(지역 전환마다 파괴·생성하지 않음). 도로 선은 마커 뒤에 그린다(기존 규칙) |
| 도시 클릭 | `TripDestinationAssigner.HandleCityClicked` — 지역을 넘어도 그대로 |
| 관문 클릭 | 짝 관문의 지역으로 전환(도착지 아님, §4-4) |
| 지역 드롭다운 | 지도 상단 `TMP_Dropdown`. 전 지역 이름 목록, 고르면 전환. 보이는 지역이 바뀌면 선택 표시도 맞춘다 |
| 역할 표시 | 현재 위치·도착지 도시가 보이는 지역에 있을 때만 강조(§4-7) |
| 정보 패널 | 출발지·도착지 패널에 도시 이름과 **지역 이름** 표시(§4-6). 이름 없는 도시는 기존 자리표시자 |
| 다시 그리기 | 모델 변경 이벤트(디버그 편집)·도착지 변경·현재 위치 변경 시 |

- 마커·선 뷰는 디버그 폴더에서 정식 폴더로 옮기고 이름을 바꾼다(`TripCityMarkerView`, `TripRoadLineView`) — 파일과 `.meta`를 함께 옮겨 GUID를 유지하므로 기존 프리팹 참조가 끊기지 않는다(§9-2). 드래그·더블클릭 삭제 같은 편집 입력은 핸들러 주입으로 남기고, 정식 표시에서는 주입하지 않는다.
- 관문 마커 `TripGateMarkerView`(신규): 도시와 다른 모양 + 가리키는 지역 이름 라벨.
- `TripPanel`: 빌드·에디터 공통으로 프레젠터를 만든다. 지도가 빌드에도 있으므로 **"상행 시작"은 빌드에서도 도착지가 있어야 활성**(§9-3) — 지금의 `#if UNITY_EDITOR`/`#else` 분기를 없앤다.

## 6. 디버그 편집 — `TripMapDebugEditor` (`#if UNITY_EDITOR`, `Core/Debug/Trip`)

`TripMapInteractionCoordinator`의 편집 부분을 옮겨 `IWorldMapEditor` 위에서 동작하게 한다(표시는 프레젠터가 맡는다).

| 기능 | 설계 |
|---|---|
| 도시 팔레트 | 드래그해 놓으면 **보이는 지역**에 도시 추가 |
| 관문 팔레트 + `연결할 지역` 드롭다운 | 드롭다운은 보이는 지역을 뺀 지역 목록(기본 첫 항목). 놓으면 관문 쌍 추가(짝은 대상 지역 중앙). 다른 지역이 없으면 팔레트 비활성 |
| 이동 | 도시·관문 드래그 이동(도로 모드가 아닐 때) |
| 도로 모드 | 도시·관문 사이 드래그로 도로 추가(같은 지역), 선 더블클릭 삭제 |
| 삭제 | 기존 방식(지도 밖으로 드래그 등 현재 코드 그대로) + 관문 짝 동반 삭제 |
| 전체 삭제 | 도시 전체 삭제·도로 전체 삭제는 **보이는 지역만** 대상 |
| 지역 추가 | 버튼 → 지역 추가 후 그 지역으로 전환 |
| 지역 삭제 | 버튼 → 거부 조건 확인 → 내용이 있으면 확인 패널("도시 N개·관문 M개가 함께 삭제됩니다" + 확인/취소) → 삭제 → 삭제된 도시가 도착지면 해제 → 현재 위치 지역으로 전환 |
| 저장 | `TripCityMapPersistence.Save(모델 스냅샷)` — §3.1의 시트 전부를 다시 쓴다. `Scale`·`CityStrings`·`RegionStrings`의 사람이 입력한 값은 보존하고 새 도시·지역에만 자리표시자 행 추가 |

- 확인 패널은 디버그 패널 안에 간단히 둔다(§9-5).

## 10. 테스트 (EditMode)

- `MapNodeId` 파싱·출력(`C4`, `G1`, 잘못된 형식).
- `WorldMap`: 지역 너머 도달 판정(관문 짝 경유), 관문 쌍 추가(짝 위치·대상 지역), 관문 삭제 시 짝·도로 동반 삭제, 다른 지역 끝점 도로 거부, 지역 삭제 거부 조건·동반 삭제·삭제된 도시 알림, 지역 추가 Id.
- 임포트 검증 규칙(§3.2)은 검증 함수를 분리해 테스트한다.

## 11. 제작 순서 (단일 단계, 그룹별 빌드 확인)

1. 데이터: `MapNodeId`, 자산 확장, 임포터(검증), 엑셀 1회 변환, 좌표 변환.
2. 모델: `WorldMap`·계약·`WorldMapProvider`, 테스트.
3. 정식 표시: 뷰 승격, `TripMapPresenter`, `TripPanel`, 지역 드롭다운·관문 마커.
4. 디버그: `TripMapDebugEditor`, 드래그 동작 끝점화, 관문 팔레트·지역 추가/삭제·확인 패널, 저장.
5. 인스톨러 → 사용자 검증(EditMode → Build Bootstrap·Hub Scene → Ctrl+S → Play).
