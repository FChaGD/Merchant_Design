## 2. 현재 코드 조사 (2026-10-20)

| 항목 | 현황 |
|---|---|
| 활성 판정 | `TripPanel.RefreshStartButtonInteractable` 한 곳 — `sceneRevealed && hasDestination && connected`. 도착지 배정기·편성 저장소 `Changed`와 커튼 신호에서 호출 |
| 대열 끊어짐 안내 | `DisconnectedNotice` TMP 레이블(버튼 오른쪽, 빨강). `HubSceneInstaller.BuildTripDisconnectedNotice`가 만들고 `TripPanel`이 SetActive 토글. 문구 상수는 `TripPanel.DisconnectedNoticeText` |
| 버튼 | `StartButton`(상행 준비 패널 하단, 앵커 x 0.30~0.70, y 0.03~0.14), `TripUIElementIds.StartButton` |
| 골드 HUD 툴팁 | 범용 중계 `PointerHoverRelay`(진입·이탈)·`PointerPressRelay`(짧은 클릭·길게 누름 0.3초, 코루틴)가 있고, 표시 판정(`hovering || longPressing`)은 `PlayerCurrencyHudController` 안에 있음. 모양(검은 배경 + 흰 글씨 자동 크기, 배경/글씨 부모·자식 분리)은 `HubSceneInstaller` 안에서 직접 조립 |

## 3. 접근안과 결정

| 안 | 내용 | 판단 |
|---|---|---|
| **A (채택)** | 공용 툴팁 부품(표시 판정 + 조립 유틸리티)으로 분리. 상행 시작이 첫 사용처, 숙소·골드 HUD가 이어 사용 | 중복 없음, 기존 중계 컴포넌트 재사용 |
| B | 씬당 툴팁 1개 + 공용 표시 서비스(위치 동적 계산) | 최상위 층 신설·동적 위치 계산 필요, UI 관리 축 정리(이번 작업 후 리팩토링)와 범위 겹침 |
| C | `TripPanel`에 골드 HUD 로직 복사 | 숙소에서 다시 복사 |

**소속(사용자 결정, 2026-10-20)**: 툴팁 표시 관리는 **UIManager 하위 컴포넌트** `UITooltipController`가 맡는다. 툴팁을 쓰는 곳(골드 HUD, 상행 시작, 숙소 휴식)이 각자 상태를 들고 있지 않고 한 소유자에 모이며, 이후 UI 관리 축 정리 때 그대로 관리 대상이 된다.

## 4. 구조

```
Bootstrap  Managers/UIManager (GameObject)
├─ UIManager
├─ UITooltipController : ITooltipController   — 신규, 툴팁 등록·표시 판정·정리
├─ TripPanel (기존)                           — GetComponent<ITooltipController>()
└─ ... (HubUIWiring, PlayerCurrencyHudController 등)

Hub 씬  상행 준비 패널 루트
├─ StartButton  (+PointerHoverRelay, +PointerPressRelay)
└─ StartBlockTooltip (패널 루트의 마지막 자식, 배경)
   └─ 문구(TMP)
```

### 4.1 툴팁 컨트롤러

```csharp
public interface ITooltipController
{
    // 중계 2개·툴팁 루트·문구 칸을 묶어 등록한다. 루트는 숨긴 채 시작한다. 반환 핸들로 문구를 바꾸고, Dispose로 해제한다.
    ITooltipHandle Register(PointerHoverRelay hover, PointerPressRelay press, GameObject tooltipRoot, TMP_Text text);
}

public interface ITooltipHandle : IDisposable
{
    // 빈 문자열(또는 null)이면 표시하지 않는다 - 떠 있으면 즉시 닫힌다.
    void SetText(string text);
}
```

| 구성 | 책임 |
|---|---|
| `UITooltipController`(MonoBehaviour, UIManager 하위) | 등록 시 중계 이벤트(진입·이탈·길게 누름 시작·끝) 구독, 항목 목록 보유. 핸들 Dispose 시 구독 해제·숨김·목록 제거. 등록 때마다 요소가 파괴된(Unity null) 항목을 정리 |
| `TooltipVisibilityState`(순수 C#) | 상태 `hovering`, `longPressing`, `text`. `IsVisible = (hovering \|\| longPressing) && !string.IsNullOrEmpty(text)`. 각 입력 변경 후 표시 여부·문구 반영 필요 여부를 돌려준다 |

- 항목 반영: 판정이 바뀌면 루트 SetActive, 보이는 동안 문구가 바뀌면 TMP 갱신. 루트·문구가 Unity null이면 무시(Hub 언로드 뒤 사유 변경 이벤트가 와도 안전).
- 컨트롤러는 화면 상태를 모른다 — "비활성일 때만"은 사용처가 문구를 비우는 것으로 표현한다.
- 전역 DI 등록하지 않는다. 사용처(UIManager 하위 컴포넌트)가 같은 GameObject에서 `GetComponent<ITooltipController>()`로 조회하고, 없으면 `InvalidOperationException`.

### 4.2 사유 계산 — `TripStartBlockReasons`(순수 정적)

```csharp
public static class TripStartBlockReasons
{
    public const string NoDestination = "도착지를 지정하세요.";
    public const string Disconnected = "대열이 끊어져 있습니다. 정비창에서 마차를 이어 붙이세요.";
    public const string SceneNotRevealed = "화면 전환 중입니다.";

    // 순서 B → C → A(기획 97 4-2). 비어 있으면 출발 가능.
    public static IReadOnlyList<string> Collect(bool sceneRevealed, bool hasDestination, bool formationConnected);
}
```

- 버튼 활성 = `Collect(...).Count == 0`. 활성 판정과 툴팁 문구가 같은 계산에서 나와 어긋나지 않는다.
- 호출 빈도가 낮아(상태 변경 시) 리스트 할당은 문제없다.

### 4.3 `TripPanel` 변경

- 필드 `ITooltipHandle startBlockTooltip`. `RegisterTripUI`에서 같은 GameObject의 `GetComponent<ITooltipController>()`로 조회(없으면 `InvalidOperationException`).
- Hub 바인딩(`RegisterTripUI` 경로)마다 이전 핸들 Dispose → `StartButton`의 중계 2개, `TripUIElementIds.StartBlockTooltip`(루트)·`StartBlockTooltipText`(문구)를 찾아 등록. 하나라도 못 찾으면 `Debug.LogWarning`, 핸들 없이 진행(버튼 활성 판정은 그대로).
- `RefreshStartButtonInteractable`: `reasons = TripStartBlockReasons.Collect(sceneRevealed, hasDestination, IsFormationConnected())` → `startButton.interactable = reasons.Count == 0` → `startBlockTooltip?.SetText(string.Join("\n", reasons))`.
- 삭제: `disconnectedNoticeLabel` 필드·조회·토글, `DisconnectedNoticeText` 상수(→ `TripStartBlockReasons.Disconnected`), `TripUIElementIds.DisconnectedNotice`.

## 5. 화면 요소·설치

### 5.1 공용 조립 — `EditorUIBuilder.EnsureTooltip`

```csharp
// 배경(Image, 검정, raycastTarget=false) + 자식 문구(TMP, 흰색, raycastTarget=false). 배경/글씨는 부모·자식으로 분리한다
// (같은 오브젝트에 Image+TMP를 붙이면 AddComponent 실패, 2026-09-21 사례). 저장 상태는 비활성. 위치는 호출부가 정한다.
internal static (GameObject root, TMP_Text text) EnsureTooltip(Transform parent, string name, string rootId, string textId);
```

- 높이 내용 맞춤: 배경에 `VerticalLayoutGroup`(패딩 8/4) + `ContentSizeFitter`(세로 PreferredSize). 문구 폰트 18 고정·줄바꿈 허용(최대 3줄).
- 모양 값은 골드 HUD 툴팁 조립 코드에서 가져온다. 골드 HUD 자체의 이관은 재화 HUD 설계에서 한다.

### 6.2 Play(CLI 실측)

- 도착지 미지정 상태에서 비활성 버튼 호버 → B 한 줄.
- 대열 끊어짐 + 도착지 미지정 → B·C 두 줄.
- 호버 유지 중 도착지 지정 → B 사라짐. 모든 사유 해소 → 툴팁 즉시 닫힘.
- 0.3초 이상 누름 → 툴팁 표시, 뗌 → 닫힘(호버 중이면 유지).
- 겹침 점검: 툴팁 표시 상태에서 지도·요약 패널·디버그 지도 컨트롤과의 겹침 목록(Game 뷰 실제 해상도).
- 사유 A(커튼 중)는 순간이라 호버 실측 어려움 → 테스트로만, "미확인" 보고.
