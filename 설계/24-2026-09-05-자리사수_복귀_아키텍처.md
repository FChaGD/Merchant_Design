## 1. 개요

기획 19번의 결정을 코드에 반영한다 — `StationaryPositioningStrategy`가 타겟이 사거리 밖(공격 불가)이면 `homePosition`으로 이동하고, 사거리 안(공격 가능)이면 제자리를 유지하도록 바꾼다. `IPositioningStrategy.ComputeMoveTarget`이 이미 `homePosition`을 매개변수로 받고 있어(`ChargePositioningStrategy`의 `target.Position` 대신 `homePosition`을 쓰는 것뿐) 인터페이스 변경은 필요 없다.

## 2. `StationaryPositioningStrategy` 변경

```csharp
using System.Collections.Generic;
using UnityEngine;

namespace Game.Core
{
    /// <summary>
    /// LocalPositioning.Stationary(원거리딜러) - 사거리 안이면 제자리에서 사격, 사거리 밖(공격 불가)이면
    /// 배치 위치(HomePosition)로 복귀한다(Docs/기획/19번). 자기보호(RetreatOnHit 등)가 위치를 강제로
    /// 옮겨도, 발동이 끝나 이 전략으로 제어가 돌아오면 원인과 무관하게 이 판정 하나로 복귀가 자연히
    /// 성립한다 - "자기보호 종료 시점"을 별도로 감지할 필요가 없다(기획 19번 §3).
    /// </summary>
    public class StationaryPositioningStrategy : IPositioningStrategy
    {
        public Vector2 ComputeMoveTarget(IBattleCombatant self, Vector2 selfPosition, IDamageable target, float range, Vector2 homePosition, IReadOnlyList<IBattleCombatant> sameSideUnits)
        {
            var distance = (target.Position - selfPosition).magnitude;
            return distance > range ? homePosition : selfPosition;
        }
    }
}
```

`ChargePositioningStrategy`와 조건식이 완전히 동일한 모양(`distance > range ? A : selfPosition`)이지만 `A`가 `target.Position` 대신 `homePosition`이라는 점만 다르다 — 별도 클래스를 유지할 이유가 되는 최소한의 차이(기획 17번 §4에서 "클래스 공유 vs 분리" 논쟁이 있었던 것과 달리, 이번엔 애초에 로직이 달라 분리가 자명함).

## 3. 영향 범위 확인

- **`PositioningStrategyFactory`**: 변경 없음. `LocalPositioning.Stationary => new StationaryPositioningStrategy()` 매핑 그대로 유지.
- **자기보호 모디파이어(`RetreatOnHitSelfPreservationModifier`/`FallBackOnHeavyDamageSelfPreservationModifier`)**: 무변경. 이들이 `TryGetOverrideMovement`로 true를 반환하는 동안은 여전히 `MoveTowardTacticalDestination`(`BattleCharacterUnit.cs`)이 그 결과를 우선 사용한다(§4 기존 우선순위 그대로) - 이번 변경은 모디파이어가 **더 이상 개입하지 않을 때**만 실행되는 이후 단계 로직이다.
- **`target == null` 케이스**: `TickEngageWithTactics`(`BattleCharacterUnit.cs` §197)가 타겟이 없으면 `MoveTowardTacticalDestination` 자체를 호출하지 않고 조기 반환한다 - 이 전략의 `ComputeMoveTarget`은 타겟이 있을 때만 호출되므로 null 참조 위험이 없다(기존 `ChargePositioningStrategy`도 같은 전제를 공유).
- **다른 포지셔닝 전략(Charge/ApproachAttack/Blocking/Surround/Disperse)**: 무변경.
- **테이블/카탈로그(`RoleGroupTactics.xlsx` 등)**: 무변경 - 이번 수정은 `LocalPositioning.Stationary`가 가리키는 전략의 내부 알고리즘만 바뀔 뿐, enum 값이나 옵션 구성에는 손대지 않는다.

## 5. 실전 검증 체크리스트

- 자리 사수 원거리딜러가 자기보호(피격 후 후퇴, 또는 중상 시 일시 후퇴)로 밀려난 뒤, 후퇴가 끝나고 타겟이 여전히 사거리 밖이면 배치 위치로 스스로 이동하는지.
- 배치 위치로 복귀해 사거리 안에 타겟이 들어오면 다시 정지하고 사격을 재개하는지(왕복 진동 없이).
- 자기보호가 발동하지 않은 상태에서 우연히(예: 타겟이 스스로 이동) 사거리 밖이 된 경우도 동일하게 복귀하는지 - 자기보호 유무와 무관한 일반 규칙임을 확인.
- 기존 "사거리 안에서는 제자리 유지" 동작에 회귀가 없는지(계속 정지 사격하는지).
