# 씬 로딩 로딩바·페이드 인 아키텍처

## 1. 요구 (사용자 확정, 2026-09-30)

| 항목 | 결정 |
|---|---|
| 흐름 | Bootstrap → 로딩 → 로딩 완료 → 검은 화면 페이드 인 → 마을 |
| 로딩 중 표시 | 검은 화면 위에 **로딩바**: "로딩 중" 문구 + 게이지 + **현재 작업 이름** + **백분율** |
| 게이지 기준 | **실제 작업 개수로 나눈다** — 진행률 = 끝난 작업 수 ÷ 전체 작업 수 |
| 연동 단위 | **작업 단위**. 작업 내부의 세부 진행(칸 1개 생성 등)은 로딩바와 연동하지 않는다 — 앞으로 어떤 작업이 추가될지 모르므로 작업을 추가하는 것만으로 로딩바가 따라오게 한다 |
| 페이드 시간 | 2초(마을↔필드와 같은 값·같은 곡선) |
| 적용 범위 | **모든 씬 전환**(최초 진입 + 마을↔필드) |
| 로딩에 포함 | 씬 로드 + UI 연결 + **정비창 칸 미리 생성**(마을 상단 배치, 필드 상행 정비창 모두) |

## 2. 현재 구조 (코드 확인)

| 요소 | 역할 | 이번 요구와 맞지 않는 점 |
|---|---|---|
| `SceneLoader`(Bootstrap) | 콘텐츠 씬 추가 로드 → 이전 씬 언로드 → 로드 완료 이벤트. 최초 진입도 이 경로 | 작업 진행을 밖에 알리지 않음 |
| `UIManager` | 로드 완료 이벤트에서 새 씬 UI 연결 | — |
| `SceneTransitionEffectController`(Bootstrap) | 마을↔필드: 슬라이드 + 커튼 → 로드 완료 즉시 커튼 2초 페이드 → "화면 드러남" 신호. **최초 진입은 연출 없이 즉시 드러남 신호** | 최초 진입에 커튼이 없음, 추가 작업을 기다리지 않음 |
| `SceneTransitionCurtainView`(Bootstrap) | 검은 커튼 표시·위치·페이드 | 로딩바 없음 |
| `HubFormationPanel`·`FieldFormationPanel`(Bootstrap, 영속) + `FormationGridEditor`/`FormationGridView` | 패널 로직은 Bootstrap에 상주하고, 칸 등 시각 요소는 콘텐츠 씬에 있다. 칸 오브젝트는 처음 열 때 한 프레임에 생성, 이후 풀 재사용 | 첫 클릭 지연 |

- 로드 완료 이벤트 구독 순서는 `UIManager` → 연출 컨트롤러로 보장돼 있다(`ManagerHierarchyInstaller` 목록 순서).

## 3. 로딩 절차 (모든 전환 공통)

```
[최초 진입] 커튼 즉시 표시(검정, 불투명)          [마을↔필드] 슬라이드 + 커튼 동행(기존)
                 └──────────────┬──────────────┘
          작업 목록 확정 → 로딩바 표시(0 / N)
  작업 1  씬 불러오기         (예: "마을 불러오는 중")
  작업 2  이전 화면 정리       (최초 진입은 목록에 넣지 않음)
  작업 3  화면 연결           (UIManager의 새 씬 UI 연결)
  작업 4… 대상 씬에 등록된 준비 작업 (예: "상단 배치 준비 중")
          작업이 하나 끝날 때마다 게이지 = 끝난 수 / N, 이름 = 다음 작업
          N / N(100%) → 1프레임 유지 → 로딩바 숨김
          커튼 2초 페이드 → "화면 드러남" 신호(버튼 활성화)
```

- **전체 작업 수 N은 로딩을 시작할 때 확정**한다 — 도중에 작업이 늘어 게이지가 뒤로 가는 일이 없다(§4.3의 등록 시점이 이를 보장).
- 예: 최초 진입(마을) = 불러오기·연결·상단 배치 준비 = 3개(33% → 66% → 100%). 필드→마을 = 4개(25%씩).
- 백분율은 정수 %(끝난 수 × 100 / N). 새 씬 첫 프레임 초기화 부하도 검은 화면 뒤에서 끝난다.

## 4. 구성 요소

### 4.1 작업 계약 `ISceneLoadingTask` (신규)

```csharp
public interface ISceneLoadingTask
{
    string Label { get; }  // 로딩바 작업 이름
    IEnumerator Run();     // 끝나면 작업 1개 완료. 내부 진행은 보고하지 않는다(작업 단위 연동)
}
```

- 작업은 여러 프레임에 걸쳐도, 한 프레임에 끝나도 된다 — 로딩바는 "끝났는지"만 본다.

### 4.2 진행 모델 `SceneLoadingProgress` (plain C#, 신규)

- 작업 목록을 받아 전체 수, 끝난 수, 현재 작업 이름을 갖고, 값이 바뀌면 변경 이벤트를 낸다.
- 읽기 계약 `ISceneLoadingProgressReader`(끝난 수, 전체 수, 현재 작업 이름, 변경 이벤트)만 로딩바 뷰에 준다(ISP).

### 4.3 준비 작업 등록 — `ISceneLoadingTaskRegistry` (신규)

```csharp
public interface ISceneLoadingTaskRegistry
{
    void Register(ContentSceneId scene, ISceneLoadingTask task); // 대상 씬에 들어갈 때마다 실행할 작업
}
```

- **등록 시점: Bootstrap 의존성 해결 때(영속)**. 정비창 패널 로직은 Bootstrap에 상주하므로 `HubFormationPanel`은 마을용, `FieldFormationPanel`은 필드용 "칸 미리 생성" 작업을 한 번 등록한다. 그래서 전환을 시작하는 순간 대상 씬의 작업 수를 이미 안다(§3 "N 확정").
- 작업의 실행은 화면 연결(작업 3) 뒤라, 새 씬 시각 요소가 연결된 상태에서 돈다. 연결에 실패해 요소가 없으면 작업은 아무것도 하지 않고 끝난다.
- 새 작업을 추가할 때는 이 등록 한 줄만 더하면 로딩바가 따라온다(요구 "작업 단위 연동").

### 4.4 정비창 칸 미리 생성 작업 — `FormationGridEditor` / `FormationGridView`

- 편집기에 "미리 생성"을 추가한다: 열 때와 같은 방식으로 표시 범위를 계산해 필요한 칸 수만큼 칸 풀을 채우고, 로스터 유닛 수만큼 아이콘 풀도 채운다. 한 번에 만든다(내부 진행은 로딩바와 무관).
- 표시 범위 계산에 뷰포트 크기가 필요해 패널을 잠깐 켰다 끈다. 커튼이 최상단에서 덮고 있는 동안이라 보이지 않는다(Bootstrap 커튼 캔버스가 콘텐츠 씬 캔버스보다 위인지는 제작 시 확인).
- 미리 만든 칸은 기존 풀 재사용 규칙에 그대로 들어간다. 실제로 열 때 새로 만들 칸이 없거나 적다.

### 4.5 조율 — `SceneLoadingCoordinator` (Bootstrap 전역 DI, 신규)

- 작업 등록 목록과 진행 모델을 갖는다(`ISceneLoadingTaskRegistry`, `ISceneLoadingProgressReader` 구현).
- 전환 시작 시 대상 씬 기준 작업 목록(불러오기·정리·연결 + 등록 작업)을 만들어 진행 모델에 넘긴다.
- 불러오기·정리는 `SceneLoader`가 끝날 때 조율자에 완료를 알리고, 연결은 로드 완료 이벤트 처리 뒤 완료, 등록 작업은 조율자가 차례로 실행한다.
- 모든 작업이 끝나면 완료 콜백 → 연출 컨트롤러가 페이드한다.

### 4.6 연출 — `SceneTransitionEffectController`

- **최초 진입**: 의존성 해결 시점(첫 화면이 그려지기 전)에 커튼을 화면 중앙에 불투명으로 띄우고 로딩바를 보인다. 기존 "연출 없이 즉시 드러남" 분기는 없어진다.
- **마을↔필드**: 슬라이드가 끝나 로드를 요청할 때 로딩바를 보인다.
- 조율자의 완료 콜백 → 100% 1프레임 유지 → 로딩바 숨김 → 커튼 2초 페이드 → 드러남 신호.
- "언제 보여 주고 걷을지"만 담당하고, 작업 목록·진행은 조율자가 맡는다(SRP).

### 4.7 로딩바 뷰 `SceneLoadingBarView` (Bootstrap, 신규)

- 커튼 오브젝트의 자식. "로딩 중" 문구, 게이지(가로 채움 이미지), 현재 작업 이름, 백분율.
- 진행 읽기 계약의 변경 이벤트로만 갱신한다(폴링 없음).

### 4.8 조립

- `ManagerHierarchyInstaller`: 커튼 아래 로딩바 요소 조립, `SceneLoadingCoordinator` 추가 및 DI 목록 등록(연출 컨트롤러·정비창 패널보다 앞). **Build Bootstrap Scene 재실행 필요.**

## 6. 테스트 (EditMode)

- `SceneLoadingProgress`: 작업 수 확정, 완료마다 끝난 수·현재 이름 전환, 백분율 계산, 모든 작업 완료 시 100%.
- 조율자의 작업 목록 구성: 최초 진입(정리 없음) / 전환(정리 포함), 대상 씬 등록 작업만 포함.
- 코루틴·화면은 Play 검증.

## 7. 검증 (제작 후)

1. Build Bootstrap Scene → Ctrl+S, Build Hub Scene·Build Field Scene → Ctrl+S.
2. Play(Bootstrap부터): 검은 화면 + 로딩바(작업 이름·% 변화) → 100% → 로딩바 사라짐 → 2초 페이드 → 마을. 페이드가 끝나기 전에는 버튼이 눌리지 않는지.
3. 상단 배치 첫 클릭에 지연이 없는지(Profiler로 첫 클릭 프레임 확인 권장). 필드 정비창도 같은지.
4. 마을→필드, 필드→마을 전환에도 로딩바가 나오는지.

## 9. 제작 기록 (2026-09-30)

- 신규: `Core/Game/Loading/` — `SceneLoadingContracts`(작업·등록·작업 제공자·진행 읽기·절차 계약 + 한 번에 끝나는 작업 `ActionSceneLoadingTask`), `SceneLoadingProgress`, `SceneLoadingCoordinator`, `SceneLoadingBarView`. 테스트 `SceneLoadingProgressTests`.
- 수정: `SceneLoader`(시작·불러오기·정리 완료 보고), `SceneTransitionEffectController`(최초 진입 커튼, 작업 완료 뒤 페이드, 로딩바 표시·숨김), `UIManager`(작업 제공자 수집·등록), `HubFormationPanel`·`FieldFormationPanel`(작업 제공), `FormationGridEditor.Prewarm`, `ManagerHierarchyInstaller`(조율자·로딩바 조립).
- 설계와 달라진 점
  - 패널이 조율자에 직접 등록하지 않고, 패널은 `ISceneLoadingTaskSource`로 작업만 내놓고 **UIManager가 모아 등록**한다 — 패널은 전역 DI 대상이 아니라 조율자를 모른다(CLAUDE.md 하위 컴포넌트 규칙).
  - 게이지는 Filled 이미지 대신 채움 오브젝트의 가로 앵커 끝을 진행률로 옮긴다(스프라이트 없이 동작).
  - 준비 작업이 예외를 내면 로그만 남기고 끝난 것으로 친다(로딩이 멈추지 않게).
- 확인: 커튼 캔버스 정렬 순서 100(콘텐츠 씬보다 위). 배틀 테스트 씬의 `SceneTransitionEffectController`는 DI 목록에 없는 잔재라 동작하지 않음(영향 없음).
- `dotnet build`(Editor·Tests) 오류 0. 미커밋. 사용자 검증 대기.
