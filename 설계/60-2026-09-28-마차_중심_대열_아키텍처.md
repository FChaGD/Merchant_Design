|---|---|

| 연결 영역 | 마차·핀 영역만의 합집합(시설 제외, 기획 59 §3.1/§4.5). 4방향 인접으로 이어진 덩어리 |
| 마차 연결 여부 | 모든 마차 칸이 연결 영역의 같은 덩어리에 속하면 연결 |
| 경계 상자 | 대열 칸들의 최소·최대 열·행 — 화면 표시 범위·전투 좌표 기준(§6·§7) |

- 판정 비용: 판 2,500칸, 유닛 최대 25개 수준이라 편집 동작마다 다시 계산해도 충분하다(프레임마다 호출하지 않음).

## 4. 배치 규칙 판정 — `FormationAreaRules` (plain C#)

편집 동작을 "후보 배치"에 적용해 본 뒤 규칙을 검사하고, 결과(허용/거부 + 자동 해제 목록)를 돌려준다. 마을·상행 편집 정책이 같은 판정기를 쓴다.

| 동작 | 판정 |
|---|---|
| 팔레트 → 칸 배치 | 목표 칸이 **현재** 대열 칸이어야 함. 마차 0대면 마차만 허용(핀 영역 예외 — §11-2) |
| 칸 → 칸 이동·교환 | 제거 + 배치로 본다: 목표 칸이 현재 대열 칸, 이동 후 마차 연결 유지, 영역 밖이 된 다른 유닛은 자동 해제 |
| 제거 | 제거 후 마차 연결이 끊기면 **거부**. 허용되면 새 영역 밖 유닛을 자동 해제 |
| 디버그 핀 추가 | 판 안 어디든 허용 |
| 디버그 핀 제거 | 제거 후 마차 연결이 끊기면 **거부**. 허용되면 마차·시설 영역과 겹치지 않는 핀 칸만 사라지고, 영역 밖 유닛 자동 해제 |

- 거부 시 편집 화면은 조용히 무시하지 않고 짧은 안내 문구를 띄운다(예: "마차 대열이 끊어져 제거할 수 없습니다.").
- 자동 해제 = 배치에서 빠져 팔레트 재고로 돌아감(기획 59 §3.2).

## 6. 격자 화면

### 6.1 구조
- 표시 범위 = 대열 경계 상자 + 여백(§11-3), 판 경계로 자름. 표시 범위의 칸만 슬롯 오브젝트를 만든다(재사용 풀) — 2,500칸을 만들지 않는다.
- 슬롯 ↔ 판 칸 인덱스 매핑을 뷰가 가진다. 경로선·활동 오버레이·이동 아이콘은 "판 칸 인덱스 → 표시 좌표" 조회를 쓰도록 바꾼다(표시 범위 밖이면 그리지 않음).
- `GridLayoutGroup` 대신 좌표 직접 배치(칸 크기 × 열·행) — 확대/축소 시 칸 크기만 바꿔 다시 배치.

### 6.2 표시
| 요소 | 표시 |
|---|---|
| 판 바탕 | 민트색 그리드 — 표시 범위 전체 |
| 대열 칸 | 주황색 사각 타일 — 대열 칸에만 |
| 대열 밖 칸 | 타일 없음(민트 바탕), 드롭 불가 |

### 6.3 확대/축소·스크롤
- 기본 화면 = 표시 범위 전체가 들어오는 배율(가장 축소). 이보다 더 축소하지 않는다.
- 확대: 마우스 휠(입력 시스템 콜백). 최대 배율은 칸 크기 120px(지금 기본 칸 크기).
- 스크롤: 확대 상태에서 `ScrollRect` 드래그. 내용 크기 = 표시 범위라 범위 밖으로 나가지 않는다.
- 영역이 바뀌어 표시 범위가 달라지면 배율을 "범위 전체 보기"로 다시 맞춘다.

## 7. 전투 좌표

### 7.1 문제
| 지점 | 지금 가정 |
|---|---|
| 아군 위치 `ComputeAllyPosition(column, row, columnCount)` | 열은 판 중앙 기준, 행은 `(행 − 0.5)` — 행 2개 고정 |
| 반경 계산(`IBattleFieldGeometry` 4종) | 열 수만 받고 행 방향 폭은 고정 |

### 7.2 변경
- 계약 인자 `columnCount` → `FormationExtent`(중심 열·행, 열·행 반폭) 값 타입.
- `FormationExtent`는 대열 경계 상자(§3)에서 만든다. 배치가 없으면 기준 칸 1칸짜리.
- 아군 위치 = `((열 − 중심 열) × 열 간격, (행 − 중심 행) × 행 간격)`을 기존 축 회전 규칙대로 전장 좌표로. 반경 = 두 반폭으로 만든 대각 거리 + 기존 마진.
- 소비자(`LiveBattleSimulationRule`, 활동 반경 영역, 전투 카메라·배경 격자)는 `FormationExtent`를 넘기도록 수정.

### 7.3 배틀 테스트 씬
- 배틀 테스트 격자는 자기 전체 격자로 `FormationExtent`를 만들어 넘긴다 — 결과 좌표·반경이 지금과 같아야 한다(회귀 확인 대상).

### 11.1 제작 단계 (사용자 허가로 분할, 2026-09-28)

| 단계 | 내용 | 단계 끝 검증 | 이유 |
|---|---|---|---|

## 12. 검증 절차 (제작 후)

1. Play 1회(자동 임포트로 마차·시설 반경 반영) → 종료 → Bootstrap `Build Bootstrap Scene`, Hub `Build Hub Scene`, Field `Build Field Scene`(격자 화면 재구성) → 각 Ctrl+S. 디버그 핀은 `Tools/Game/Debug/Install/Formation Debug Pins`.
2. EditMode 테스트 전체 통과.
3. 마을 정비창: 마차 0대 = 중앙 1칸만 주황, 캐릭터 드롭 거부 → 마차 배치 → 9 × 9 정사각형 영역 주황 → 캐릭터 배치.
4. 마차 3대 일렬 → 중간 제거 거부(문구), 끝 제거 허용 + 영역 밖 캐릭터 팔레트 복귀.
5. 확대/축소·스크롤: 기본 = 범위 전체, 더 축소 불가, 확대 후 스크롤.
6. 상행 중: 배치·이동이 영역 안에서만, 영역 밖 경로 우회, 마차 제거 시 영역 밖 활동 취소.
7. 전투: 대형이 전장 중앙에 오고, 세로로 넓은 대열도 치우침 없음.
8. 디버그 핀: 판 아무 곳 핀 → 영역 생성, 핀 제거(연결 끊김 시 거부, 겹침 칸 유지).
9. 배틀 테스트 씬: 기존과 같은 배치·전투.

## 14. 개정 설계 — 시설 영역의 연결 포함 (2026-09-29, 기획 59번 §3.3)

### 14.1 변경 요지

| 구분 | 현재 | 개정 |
|---|---|---|
| 연결 판정에 쓰는 칸 | 마차 + 핀 영역 | 마차 + 핀 + **시설** 영역 |
| 시설 자리 판정에 쓰는 칸 | 마차 + 핀 영역 | 변경 없음 |
| 마차 이동으로 시설이 마차 영역 밖 | 이동 거부(`FacilityOutside`, §13 A안) | **A안 제거** — 시설 해제 후 연결 판정 |
| 마차 제거로 시설이 마차 영역 밖 | 해제(연결 판정은 해제 **전** 상태) | 해제 후 **최종 상태**로 연결 판정 |
| 시설 이동·제거로 연결 끊김 | 판정 대상 아님(시설은 연결 무관) | 거부(연결 판정에 시설이 포함되므로 자동으로 성립) |

### 14.2 영역 계산 — `FormationArea`

- 칸 집합을 역할별로 나눈다.
  - 자리 칸(host) = 마차 + 핀 영역 — 시설을 놓을 수 있는 칸. `CanHost`(시설)가 본다.
  - 연결 칸(connect) = 자리 칸 + **자리 칸 위에 있는 시설**의 영역 — `WagonsConnected`가 본다.
  - 대열 칸(cells) = 마차가 없으면 기준 칸 + 핀, 있으면 연결 칸과 같다.
- **자리 칸 밖에 있는 시설은 영역 계산에서 무시**한다(대열·연결 모두 기여 없음). 이유: 해제될 시설이 해제 전 계산에서 연결을 이어 주는 것으로 잡히면 판정 순서에 따라 결과가 달라진다 — 영역 계산 자체가 "유효한 시설만 센다"로 일관되게 한다. 이런 시설은 판정(§14.3)에서 해제된다.
- 계산 순서: 마차·핀 → 자리 칸 → 자리 칸 위 시설 판별 → 연결 칸·대열 칸.

### 14.3 편집 판정 — `FormationAreaRules.Validate`

현재: 연결 판정 → (통과 시) 영역 밖 유닛 해제 반복.
개정: **해제 반복 → 최종 상태로 연결 판정**.

1. 후보 배치(편집을 적용한 사본)로 영역을 계산한다.
2. 있을 수 없는 칸의 유닛을 해제한다 — 시설은 자리 칸 밖, 캐릭터는 대열 칸 밖. 시설 해제로 대열이 줄면 캐릭터가 추가로 밖이 될 수 있어 해제할 유닛이 없을 때까지 반복한다(마차는 늘 자기 영역 안이라 해제되지 않음).
3. 최종 영역에서 마차가 모두 이어져 있지 않으면 **거부** — 후보는 사본이라 해제도 반영되지 않는다.
4. 통과하면 최종 배치와 해제 목록을 돌려준다.

- `Move`: §13 A안의 `FacilityOutside` 검사와 열거값을 제거한다. 목표 칸 검사(이동 전 영역 기준)와 교환 시 밀려나는 유닛 검사는 유지한다 — 사용자가 직접 옮기는 유닛이 들어갈 수 없는 칸으로 가는 것은 해제가 아니라 거부가 맞다.
- `Remove`·`Place`·디버그 핀 제거: `Validate`를 그대로 쓰므로 순서 변경이 함께 적용된다.

### 14.4 상행 중(Field)

- 마차·시설 이동 시작 시 `Move` 판정, 완료 시 `NormalizeToArea`(`Validate`)로 해제 반영 — 구조 변경 없음. 순서가 바뀌어도 완료 시점에 연결이 끊기면 지금처럼 경고만 남기고 반영하지 않는다.
- 해제된 시설의 진행 중 활동 취소, 영역 밖 목표 활동 취소는 기존 `ApplyAndCancelOutside`가 처리한다.

### 15.10 핀 저장소가 없으면 디버그 패널 숨김 (2026-09-29 사용자 결정 A)

- 디버그 패널은 게임 UI 인스톨러(`FormationUIBuilder` ← Build Hub/Field Scene)가 늘 만들고, 핀 저장소만 Install/Remove 메뉴로 켜고 끈다(서로 다른 씬). 저장소를 Remove해도 패널이 남던 문제 → `IFormationEditingHandler.HasDebugPinStore`(에디터 전용 블록)를 두고, `FormationGridEditor.Open`이 저장소가 없으면 패널을 끈다. 씬 수정 없음.
- D 그룹 검증: D-01~D-11 사용자 확인 통과(2026-09-29), D-09는 이 개정 후 재확인 대상.
- 2026-09-29 핀 표시가 줌 후 어긋나는 버그: 핀 표시는 칸 좌표로 놓는데, 격자를 다시 그릴 때만 갱신해 확대/축소(휠)로 칸 좌표가 바뀌면 옛 위치·고정 22px로 남았다. → `FormationGridEditor`가 `FormationGridView.ViewChanged`에 핀 다시 놓기를 연결(에디터 전용), 핀 크기 = 칸 크기 × 0.3(최소 8px).
- 2026-09-29 편집 거부 시 화면이 초기 중앙으로 튀고 중앙 칸이 깜빡이던 버그: 거부로 대열이 그대로일 때도 `SetView`가 칸 범위를 대열 중앙 기준으로 다시 계산해, 보던 중앙 기준(§14.8)으로 깔아 둔 창이 바뀌었다 → 화면 이동 + 풀 재사용 칸의 판 좌표가 바뀌어 깜빡임이 다른 칸(중앙)에 보임. → 범위 불변·전체 보기 아님·포커스 없음이면 기존 칸 범위를 재사용.
