## 4. 구조

### 4.1 입력 액션 자산 — `Assets/Settings/Input/GameInput.inputactions`

| 액션 맵 | 액션 | 바인딩 | 텍스트 입력 중 차단 |
|---|---|---|---|
| `Shortcut` | `OpenTradeGoods` | `<Keyboard>/i` | O |
| | `OpenEquipment` | `<Keyboard>/b` | O |
| | `OpenConsumable` | `<Keyboard>/c` | O |
| | `OpenPersonalItem` | `<Keyboard>/p` | O |
| `Inventory` | `RotateHeldItem` | `<Keyboard>/q` | O |
| `Pointer` | `Press` | `<Pointer>/press` | X |

- 모든 액션은 Button 타입, `performed`로 전달한다.
- 프로젝트 전역 액션으로 등록한다(§6.1). 런타임 접근은 `InputSystem.actions`.
- 액션 Id는 `"맵/액션"` 문자열(`"Shortcut/OpenTradeGoods"`)이며 정적 클래스 `GameInputActionIds`에 상수로 모은다. 인벤토리 팝업 Id → 액션 Id 대응도 여기에 둔다(`ForInventoryPopup(popupId)`).
- 차단 대상은 맵 단위로 정한다: `Shortcut`·`Inventory` 차단, `Pointer` 통과. 차단 맵 목록도 `GameInputActionIds`에 둔다.

### 4.2 InputManager와 하위 컴포넌트

```
Managers/InputManager (GameObject, Bootstrap)
├─ InputManager            : IInputManager, IManagedComponent   — 제어만
├─ GameInputActionSource   : IGameInputActionSource            — 하위 컴포넌트
└─ TextInputFocusGuard     : ITextInputFocusGuard              — 하위 컴포넌트
   (InputActionDispatcher  — 순수 C#, InputManager가 소유)
```

| 구성 요소 | 책임 | 비고 |
|---|---|---|
| **InputManager** | 시작 시 하위 컴포넌트를 `GetComponent<IXxx>()`로 조회(없으면 `InvalidOperationException`), Dispatcher를 만들어 둘을 연결, 액션 맵 Enable/Disable(OnEnable/OnDisable). `IInputManager` 요청을 하위로 위임 | 판단·저장 로직 없음 |
| `GameInputActionSource` | `InputSystem.actions`에서 Id로 액션 조회, 각 액션의 `performed`를 Dispatcher 입력으로 연결, 맵 Enable/Disable, 키 글자 조회(`InputAction.GetBindingDisplayString()`). 전역 액션이 없거나 Id가 없으면 경고 1회 | Unity 입력 의존부를 여기로 격리 |
| `TextInputFocusGuard` | `EventSystem.current.currentSelectedGameObject`에 `TMP_InputField`(또는 `InputField`)가 있고 `isFocused`면 true | 전역 DI 대상 아님 |
| `InputActionDispatcher` | Id별 구독 목록, `Subscribe(id, Action)` → `IDisposable` 핸들, `Dispatch(id)` 시 차단 판정(차단 맵 && 가드 true면 무시) 후 목록 **복사본**으로 호출(콜백 안 해제 안전) | Unity 입력 비의존 → EditMode 테스트 |

**계약 교체**

```csharp
public interface IInputManager
{
    // 액션 Id(GameInputActionIds)의 performed를 구독한다. 반환 핸들을 Dispose하면 해제.
    // Id가 없거나 전역 액션이 없으면 경고 후 아무것도 하지 않는 핸들을 돌려준다 - 소비자는 null 처리가 필요 없다.
    IDisposable Subscribe(string actionId, Action onPerformed);
    // 버튼에 표시할 키 글자("I"). 없으면 빈 문자열.
    string GetBindingLabel(string actionId);
}
```

- `SetContext(string)` 삭제(호출처 없음). 소비자가 두 기능을 모두 쓰므로 인터페이스를 더 나누지 않는다.
- 하위 계약(`IGameInputActionSource`, `ITextInputFocusGuard`)은 InputManager 내부용이며 DI 등록하지 않는다.

### 4.3 동작 조건의 소유

InputManager는 화면 상태를 모른다. 소비자가 판단한다.

| 소비자 | 판단 | 구독 수명 |
|---|---|---|
| 인벤토리 키 | 연결된 버튼이 `IsActive() && IsInteractable()`일 때만 `onClick.Invoke()` | Hub 로드마다 재구독 |
| Q 회전 | 드래그 중에만 구독 | 드래그 시작~종료/취소 |
| 팝업 맨 위로 | 항상 | `HubUIWiring` 수명 |

## 5. 소비자 이관

### 5.1 인벤토리 상시 호출 키

- `HubInventoryShortcutBinder`를 정적 클래스 → 인스턴스(`IDisposable`)로 바꾼다. `HubUIWiring`이 소유하고, Hub 로드마다 `Bind` 시 이전 키 구독을 먼저 해제한다(`PopupFocusOnPress`와 같은 수명 방식).
- 버튼 onClick 연결은 지금과 같다. 추가로 각 팝업 Id의 액션을 구독하고, 콜백은 `ShortcutKeyGate.ShouldInvoke(button)`이 true일 때 `button.onClick.Invoke()` — 버튼 클릭과 같은 경로라 토글·인벤토리 팝업 규칙이 그대로 적용된다.
- `ShortcutKeyGate.ShouldInvoke`: 버튼이 Unity null이 아니고 `IsActive()`·`IsInteractable()`. `IsInteractable()`이 부모 CanvasGroup `interactable`을 반영하므로 모달 팝업·시설 화면(PopupLayerGate)에서 자동으로 false. 이후 휴식 진행 화면(설계 94 대상)도 이 레이어를 상호작용 불가로 만들면 별도 처리 없이 무시된다.
- 키 글자: 각 버튼 오른쪽 위 모서리에 TMP 레이블(`HubUIElementIds.InventoryShortcutKeyLabel(popupId)`, `raycastTarget=false`). 글자는 `Bind`에서 `GetBindingLabel`로 채운다. 레이블을 못 찾으면 경고만 하고 키 동작은 유지.
- `IInputManager`가 없으면(`TryResolve` 실패) 버튼만 연결하고 키 구독·글자 표시는 생략한다.
- Field는 상시 호출 버튼이 없으므로 구독하지 않는다.

### 5.2 Q 회전

- `InventoryItemDragController`: 내부 `InputAction` 생성 삭제. 생성자에 `IInputManager input`(null 허용)을 받는다. `Begin`에서 `allowsRotation && input != null`이면 `Subscribe(Inventory/RotateHeldItem, Rotate)`, `Cancel`(End 포함)과 `Dispose`에서 핸들 해제.
- 전달 경로(생성자 인자): `HubUIWiring`/`FieldUIWiring` → `InventoryPopupPanel`·`TradeGoodsMarketPanel`·`FieldCargoRecoveryPanel` → `InventoryArrangementController` → `InventoryItemDragController`. 배선은 `Wire`에서 `TryResolve<IInputManager>`로 조회.
- 버리기 선택 상태(95 4-9)에서는 드래그가 시작되지 않으므로 구독도 생기지 않는다 — 이 설계에서 추가 처리 없음.

### 5.3 팝업 맨 위로

- `PopupFocusOnPress`: 내부 `InputAction` 생성 삭제. 생성자에 `IInputManager`를 받아 `Pointer/Press`를 구독, `Dispose`에서 해제. 창 선택 로직(`SelectWindowToFront`)과 포인터 위치 읽기(`Pointer.current`)는 그대로.
- `HubUIWiring`의 `inventoryPopupFocus ??= new PopupFocusOnPress(input)`. `IInputManager`가 없으면 만들지 않는다(앞으로 가져오기만 꺼짐).
