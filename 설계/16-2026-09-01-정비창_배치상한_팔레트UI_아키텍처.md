## 1. 조사 결과 — 현재 상태

`FormationPaletteView.cs` 요약 주석: "무제한 소스로 취급되므로 아이콘을 드래그해도 목록에서 제거하지 않는다." `SetRoster(IReadOnlyList<IFormationUnit> roster, ...)`는 로스터 항목 하나당 아이콘 하나를 그대로 만든다(1:1). `PlaceholderCaravanRosterProvider`는 카테고리(직업 3종+마차+시설)당 **1개체씩**만 제공한다.

## 2. 로스터 개체화 — `PlaceholderCaravanRosterProvider`

카테고리당 5개 인스턴스로 확장한다. Id 패턴: `"{category-slug}-{n}"`(예: `character-warrior-1`~`5`, `wagon-1`~`5`, `facility-1`~`5`) — 기존 Id(`"character-warrior"`, `"wagon-01"`)와 겹치지 않게 새 규칙으로 통일한다(기존 배치 저장 데이터는 인메모리라 상행 재시작/앱 재시작 시 소멸하므로 마이그레이션이 필요 없다).

같은 카테고리의 5개체는 아이콘·표시명이 완전히 동일하다(기획 11번 §3 "인스턴스 간 차이는 없다") — 반복문으로 생성한다.

```csharp
private static List<IFormationUnit> BuildRoster(/* 아이콘 필드들 */)
{
    var roster = new List<IFormationUnit>();
    AddMercenaryInstances(roster, "character-warrior", "전사", warriorIcon, MercenaryClass.Warrior);
    AddMercenaryInstances(roster, "character-archer", "궁수", archerIcon, MercenaryClass.Archer);
    AddMercenaryInstances(roster, "character-shieldbearer", "방패병", shieldBearerIcon, MercenaryClass.ShieldBearer);
    AddFormationInstances(roster, "wagon", "마차", wagonIcon, FormationUnitKind.Wagon);
    AddFormationInstances(roster, "facility", "시설", facilityIcon, FormationUnitKind.Facility);
    return roster;
}
```

(헬퍼 2개가 `InstancesPerCategory = 5`만큼 `for` 루프를 돌며 `PlaceholderMercenaryUnit`/`PlaceholderFormationUnit`을 생성 — 기존 생성자 무변경.)

## 3. 카테고리 그룹핑 — 새 값 타입

정비창 팔레트는 이제 "개체 하나당 아이콘 하나"가 아니라 "카테고리 하나당 아이콘 하나(+ 잔여수)"를 보여줘야 한다. 로스터 자체(`IFormationUnit`)는 여전히 개체 단위이므로, 그룹핑 키와 요약을 새로 정의한다.

`Core/UI/Formation/FormationCategoryKey.cs`:

```csharp
public readonly struct FormationCategoryKey : IEquatable<FormationCategoryKey>
{
    public FormationUnitKind Kind { get; }
    public MercenaryClass? MercenaryClass { get; } // Kind==Character일 때만 값 있음, 그 외엔 null

    private FormationCategoryKey(FormationUnitKind kind, MercenaryClass? mercenaryClass)
    { Kind = kind; MercenaryClass = mercenaryClass; }

    public static FormationCategoryKey Of(IFormationUnit unit) =>
        unit is IMercenaryUnit mercenary
            ? new FormationCategoryKey(FormationUnitKind.Character, mercenary.Class)
            : new FormationCategoryKey(unit.Kind, null);

    public bool Equals(FormationCategoryKey other) => Kind == other.Kind && MercenaryClass == other.MercenaryClass;
    public override bool Equals(object obj) => obj is FormationCategoryKey other && Equals(other);
    public override int GetHashCode() => HashCode.Combine(Kind, MercenaryClass);
}
```

`Core/UI/Formation/FormationCategorySummary.cs`:

```csharp
public sealed class FormationCategorySummary
{
    public FormationCategoryKey Key { get; }
    public string DisplayName { get; }
    public Sprite Icon { get; }
    public int TotalCount { get; }
    public int AvailableCount { get; } // 사망X, 미배치인 개체 수

    public FormationCategorySummary(FormationCategoryKey key, string displayName, Sprite icon, int totalCount, int availableCount)
    { Key = key; DisplayName = displayName; Icon = icon; TotalCount = totalCount; AvailableCount = availableCount; }
}
```

### 요약 계산 — `FormationPanel`이 소유

새 클래스를 따로 뽑지 않고 `FormationPanel`의 private 메서드로 둔다 — 이 계산은 그 순간의 `roster`+`currentLayout`+(선택적)`IUnitConditionRepository` 세 가지를 조합해야 하는데, 셋 다 이미 `FormationPanel`이 들고 있는 상태라 별도 클래스로 뽑으면 그 셋을 다시 파라미터로 넘겨야 해서 간접비만 늘어난다(SRP 위반이 아니라 "이미 응집된 상태를 인위적으로 쪼개는" 경우 — `RefreshAllSlots`/`BuildInitialLayout`도 같은 이유로 이미 private 메서드다).

```csharp
private List<FormationCategorySummary> BuildCategorySummaries(IReadOnlyList<IFormationUnit> roster)
{
    var placedIds = new HashSet<string>();
    for (var i = 0; i < currentLayout.SlotCount; i++)
    {
        var id = currentLayout.GetUnitId(i);
        if (!string.IsNullOrEmpty(id)) placedIds.Add(id);
    }

    var groups = new Dictionary<FormationCategoryKey, (string name, Sprite icon, int total, int available)>();
    foreach (var unit in roster)
    {
        var key = FormationCategoryKey.Of(unit);
        var isDead = conditionRepository != null && unit is IMercenaryUnit && conditionRepository.IsDead(unit.Id);
        var isAvailable = !isDead && !placedIds.Contains(unit.Id);

        groups.TryGetValue(key, out var existing);
        groups[key] = (unit.DisplayName, unit.Icon, existing.total + 1, existing.available + (isAvailable ? 1 : 0));
    }

    return groups.Select(kv => new FormationCategorySummary(kv.Key, kv.Value.name, kv.Value.icon, kv.Value.total, kv.Value.available)).ToList();
}
```

`conditionRepository`(신규 `IUnitConditionRepository`, [설계 15번](15-2026-09-01-유닛_상태_지속_아키텍처.md) 참고)는 없을 수도 있다(TryResolve 실패, 또는 마차/시설처럼애초에 대상이 아님) — null-조건부로 안전하게 처리한다.

`Open()`(현재 167줄)과 `RefreshAllSlots()` 이후 호출부(배치가 바뀔 때마다, 즉 `RefreshSlot`이 불릴 때마다)에서 이 요약을 다시 계산해 `paletteView.SetCategories(...)`를 호출해야 한다 — 슬롯 배치가 바뀌면 잔여수도 바뀌기 때문이다. 정확한 재계산 시점(매 `RefreshSlot`마다 vs `RefreshAllSlots`에서만)은 제작 단계에서 성능/정확성 트레이드오프를 보고 결정한다(팔레트 카테고리는 최대 5개뿐이라 매번 다시 그려도 비용은 미미할 것으로 보임).

## 4. 팔레트 뷰 — `FormationPaletteView`/신규 `FormationPaletteRowView`

`FormationUnitIconView`는 팔레트/그리드/드래그 고스트 3곳에 공용 재사용되는 컴포넌트라(요약 주석 참고) 여기에 "잔여수 라벨"·"비활성화 흐림 처리"를 얹으면 그리드/고스트 용도에도 불필요한 필드가 섞인다. 대신 팔레트 전용 합성 뷰를 새로 만든다.

`Core/UI/Formation/FormationPaletteRowView.cs`(신규):

```csharp
public class FormationPaletteRowView : MonoBehaviour
{
    [SerializeField] private FormationUnitIconView iconView; // 아이콘 표시는 기존 컴포넌트 재사용
    [SerializeField] private TMP_Text countLabel; // "3/5"
    [SerializeField] private CanvasGroup canvasGroup; // 비활성화 시 alpha↓ + interactable=false

    private FormationCategorySummary summary;

    public void Bind(FormationCategorySummary summary, /* 기존 SetRoster와 같은 4개 델리게이트 */)
    {
        this.summary = summary;
        iconView.Bind(/* 대표 IFormationUnit 하나 - Icon 표시용, 실제 드래그 대상 해석은 FormationPanel */);
        countLabel.text = $"{summary.AvailableCount}/{summary.TotalCount}";

        var isEmpty = summary.AvailableCount <= 0;
        canvasGroup.alpha = isEmpty ? 0.4f : 1f;
        canvasGroup.interactable = !isEmpty;
        canvasGroup.blocksRaycasts = !isEmpty; // 드래그 시작 자체를 막는다(기획 11번 §4)
        iconView.SetHandlers(/* ... */);
    }
}
```

`FormationPaletteView.SetRoster(IReadOnlyList<IFormationUnit>, ...)` → `SetCategories(IReadOnlyList<FormationCategorySummary> categories, Action<FormationCategoryKey> categoryClicked, Action<FormationCategoryKey, PointerEventData> categoryBeginDrag, ...)`로 시그니처 변경. get-or-create 재사용 로직(현재 44-57줄, 개수 변화분만큼 Instantiate/Destroy)은 그대로 유지하되 대상이 `FormationUnitIconView`에서 `FormationPaletteRowView`로 바뀐다.

## 5. 드래그 시작 시 "가용 인스턴스 하나" 해석 — `FormationDragCoordinator`는 무변경

`FormationDragCoordinator.BeginFromPalette(IFormationUnit unit, ...)`는 이미 구체적인 `IFormationUnit` 하나를 받는 시그니처다(§5 참고 코드, `FormationDragCoordinator.cs:43`). 카테고리 행이 드래그를 시작하면, **`FormationPanel`이 그 카테고리에서 가용한 개체 하나를 골라 넘기기만 하면** 코디네이터/그리드/레이아웃 쪽은 한 줄도 안 바뀐다.

```csharp
private void HandlePaletteRowBeginDrag(FormationCategoryKey key, FormationUnitIconView icon, PointerEventData eventData)
{
    var placedIds = CollectPlacedIds(); // §3과 같은 계산, 헬퍼로 공유
    var available = roster.FirstOrDefault(u => FormationCategoryKey.Of(u).Equals(key)
        && !placedIds.Contains(u.Id)
        && !(conditionRepository != null && u is IMercenaryUnit && conditionRepository.IsDead(u.Id)));

    if (available == null) return; // 방어적 - 잔여 0이면 행 자체가 비활성화라 정상 흐름에선 안 불림

    unitsById[available.Id] = available; // 드래그로 처음 나타나는 Id일 수 있어 갱신 보장
    dragCoordinator.BeginFromPalette(available, eventData);
}
```

이 시점부터는 `HandleSlotDropped`/`HandleIconEndDrag`(현재 코드 그대로) — `draggedUnit.Id`가 실제 개체 Id이므로 `FormationLayout`에 그 Id가 정확히 기록된다.

## 6. `IUnitConditionRepository` 연동 — 유일한 교차 의존

`FormationPanel`이 [설계 15번](15-2026-09-01-유닛_상태_지속_아키텍처.md)의 `IUnitConditionRepository`를 새로 참조한다(§3/§5의 `conditionRepository`). `RegisterFormationUI(...)` 시그니처에 파라미터 추가:

```csharp
public void RegisterFormationUI(ICaravanRosterProvider rosterProvider, IFormationRepository repository,
    IUnitConditionRepository conditionRepository, IUIManager uiManager, string sceneName)
```

`HubUIWiring.cs:46`/`FieldUIWiring.cs:36` 둘 다 기존 `TryResolve<ICaravanRosterProvider>`/`TryResolve<IFormationRepository>`와 나란히 `registrar.TryResolve<IUnitConditionRepository>(out var conditionRepository);`를 추가하고 호출부에 인자를 더한다.

**사망한 유닛만 이 저장소를 참조한다** — 마차/시설은 애초에 `IMercenaryUnit`이 아니라 `IsDead` 체크 자체가 스킵된다(§3/§5의 `u is IMercenaryUnit` 가드).

## 7. 이 설계가 건드리지 않는 것

- `FormationLayout`, `FormationGridView`, `FormationInfoPanelView` — 그리드 슬롯/정보패널은 여전히 개체 단위(`IFormationUnit`)로 동작, 무변경.
- `FormationUnitIconView` — 그리드/드래그 고스트 용도는 무변경. 팔레트 전용 잔여수/비활성화는 새 `FormationPaletteRowView`가 감싼다.
- `IFormationUnit`/`IMercenaryUnit`/`PlaceholderMercenaryUnit`/`PlaceholderFormationUnit` 자체의 필드 — 개체 수만 5배로 늘어날 뿐 계약은 무변경.
