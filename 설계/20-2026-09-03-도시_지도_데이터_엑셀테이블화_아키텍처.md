## 1. 무엇이 바뀌는가 (범위 확인)

v1(설계 19번)에서 이미 만든 것 — **전부 그대로 유지**:
- `ITripCityReader`/`ITripCityRepository.AddWithId`/`ITripRouteRepository.GetAllRoutes` (전체 조회 API)
- `TripCityMapAsset`(SO, `Core/UI/Trip/`) — 소비자(`EnsureSavedMapLoaded`)가 읽는 컴파일된 데이터 구조 자체는 변경 없음(`CityId`/`MapPosition`, `CityIdA`/`CityIdB`)
- `TripMapInteractionCoordinator.EnsureSavedMapLoaded()` + `TripPanel.Open()` 배선(패널 활성화 이후 불러오기) — 이전 세션에서 겪은 버그 수정분 그대로 유효

**이번에 바뀌는 것은 오직 "저장" 버튼이 무엇에 쓰는가** — 지금까지는 `TripCityMapAsset`에 직접 `SerializedObject`로 썼는데, 이제 **엑셀 워크북에 쓰고, 그 워크북을 임포터가 읽어 `TripCityMapAsset`을 채운다**(데이터 테이블 v1/v2와 완전히 같은 파이프라인 구조). `EnsureSavedMapLoaded()`는 여전히 `TripCityMapAsset`만 읽으므로 **변경이 필요 없다**.

## 2. 좌표 변환 — `TripCityMapCoordinateConverter`

기획 §7.2가 정의한 정규화 좌표(좌하단 (0,0) ~ 우상단 (지도가로, 지도세로))와 콘텐츠 좌표(중심 기준, `TripCity.MapPosition`이 이미 쓰는 좌표계)를 서로 변환하는 공용 함수. `TripCityMapPersistence`(저장, `Core/Debug/Trip/`)와 신설할 임포터(불러오기, `Assets/Scripts/Editor/`) 양쪽이 필요로 하므로, 둘 다 참조 가능한 위치(`Core/UI/Trip/`, 어셈블리 경계상 Editor→Core는 항상 허용)에 둔다.

```csharp
// Core/UI/Trip/TripCityMapCoordinateConverter.cs
namespace Game.Core
{
    // 지도 콘텐츠는 pivot=(0.5,0.5)로 중심에 고정돼 있어(TripMapView), 저장된 MapPosition은 항상
    // "중심 기준"(-ContentSize/2 ~ +ContentSize/2)이다. 엑셀에서 사람이 보는 좌표는 "좌하단 기준"
    // (0 ~ ContentSize, 항상 양수)이라 상호 변환이 필요하다(기획 15번 §7.2).
    public static class TripCityMapCoordinateConverter
    {
        public static Vector2 ToNormalized(Vector2 contentPosition)
        {
            var half = TripMapView.ContentSize / 2f;
            return contentPosition + new Vector2(half, half);
        }

        public static Vector2 ToContentSpace(Vector2 normalizedPosition)
        {
            var half = TripMapView.ContentSize / 2f;
            return normalizedPosition - new Vector2(half, half);
        }
    }
}
```

### 2.1 `MapContentSize`를 `TripMapView.ContentSize`로 이전

지금 지도 크기(2400×2400)는 `HubSceneInstaller.cs`(Editor 전용 어셈블리)의 `private const float MapContentSize`다 — `Core/UI/Trip/`(일반 어셈블리)에서 참조할 수 없는 방향이라(설계 19번 §5와 같은 종류의 제약) 위 변환기가 쓸 수 없다. `TripMapView.cs`(이미 지도 콘텐츠를 소유하는 클래스, `Core/UI/Trip/`)로 상수를 옮긴다:

```csharp
// TripMapView.cs
public const float ContentSize = 2400f; // 인스톨러(HubSceneInstaller)가 실제 RectTransform 크기를 맞출 때도 이 값을 쓴다.
```

`HubSceneInstaller.cs`의 `private const float MapContentSize = 2400f;`를 지우고, `contentRect.sizeDelta = new Vector2(MapContentSize, MapContentSize);`를 `TripMapView.ContentSize`로 교체한다 — Editor는 Core를 참조할 수 있는 방향이라 문제없고, 부수 효과로 매직넘버 중복(값이 두 곳에 따로 있던 것)도 해소된다.

## 3. 엑셀 쓰기 — ClosedXML 도입 (기획 §7.3 확인)

**ClosedXML**(MIT 라이선스, 순수 .NET, 읽기/쓰기 모두 지원)을 도입한다. `Assets/Plugins/Editor/ClosedXML/`에 배치 — `ExcelDataReader`와 같은 폴더 구조 관례(`Assets/Plugins/Editor/ExcelDataReader/`).

**제작 단계에서 실제로 겪은 종속성 문제(2026-09-03, 2단계)**: ClosedXML의 전이 의존성 트리를 재귀 조회해 DLL 9개(`ClosedXML.Parser`/`DocumentFormat.OpenXml`(+`.Framework`)/`ExcelNumberFormat`/`Microsoft.Bcl.HashCode`/`RBush`/`SixLabors.Fonts`/`System.IO.Packaging`)를 배치했다.

1. **1차**: `Microsoft.Bcl.HashCode.dll` 포함 상태로 컴파일 → **CS0433 타입 중복 에러**(Unity 프로젝트 전체, 관계없는 Unity 번들 패키지·기존 코드까지). Unity가 .NET Standard 2.1 API 호환성으로 `System.HashCode`를 이미 자체 제공하는데, 이 DLL도 같은 정규 타입명을 정의해서 충돌.
2. **2차**: 그 DLL을 통째로 제거 → 이번엔 **`ClosedXML.dll` 자체가 로드 거부**("Unable to resolve reference 'Microsoft.Bcl.HashCode'") → `Game.Core`/`Game.Core.Editor`/`Game.Core.Tests`까지 연쇄 로드 실패. `ClosedXML.dll`의 컴파일된 메타데이터가 그 어셈블리를 실제로 참조하고 있어(NuGet netstandard2.0 빌드 시점엔 `System.HashCode`가 표준에 없어 폴리필이 필수 종속성이었음), DLL이 아예 없으면 참조 자체가 깨진다.

**최종 해결**: DLL은 다시 포함하되(있어야 `ClosedXML.dll`의 참조가 풀림), Unity Plugin Inspector에서 `Microsoft.Bcl.HashCode.dll`의 **"Auto Reference"를 끈다** — 이러면 물리적으로 프로젝트에 존재해 `ClosedXML.dll` 로드 시 참조가 해소되지만, Roslyn이 `Game.Core` 등 다른 어셈블리를 컴파일할 때 이 DLL을 자동으로 참조 목록에 넣지 않아 `System.HashCode` 타입이 Unity 내장분 하나로만 보인다(CS0433 재발 안 함). 이건 Unity가 "정식 참조하면 안 되지만 다른 정식 참조 어셈블리가 필요로 하는 전이 의존성"을 다룰 때 쓰는 표준 메커니즘이다 - Unity 에디터에서 수동 설정 필요(자동화 불가, `.meta` 스키마를 코드로 직접 조작하는 건 잘못될 위험이 커 피함).

`TripCityMapPersistence.Save`는 이제 `TripCityMapAsset`에 직접 쓰지 않고 xlsx를 쓴다(항상 **워크북 전체를 새로 만들어 덮어쓴다** — `XLWorkbook.SaveAs`가 기존 파일을 그대로 대체):

```csharp
// Core/Debug/Trip/TripCityMapPersistence.cs (일부)
using ClosedXML.Excel;

public static void Save(ITripCityReader cities, ITripRouteRepository routes)
{
    var allCities = cities.GetAll();
    var allRoutes = routes.GetAllRoutes();

    using var workbook = new XLWorkbook();

    var citySheet = workbook.Worksheets.Add("TripCities");
    citySheet.Cell(1, 1).Value = "Id";
    citySheet.Cell(1, 2).Value = "X";
    citySheet.Cell(1, 3).Value = "Y";
    for (var i = 0; i < allCities.Count; i++)
    {
        var normalized = TripCityMapCoordinateConverter.ToNormalized(allCities[i].MapPosition);
        citySheet.Cell(i + 2, 1).Value = allCities[i].Id;
        citySheet.Cell(i + 2, 2).Value = normalized.x;
        citySheet.Cell(i + 2, 3).Value = normalized.y;
    }

    var routeSheet = workbook.Worksheets.Add("TripRoutes");
    routeSheet.Cell(1, 1).Value = "CityIdA";
    routeSheet.Cell(1, 2).Value = "CityIdB";
    var row = 0;
    foreach (var route in allRoutes)
    {
        routeSheet.Cell(row + 2, 1).Value = route.CityIdA;
        routeSheet.Cell(row + 2, 2).Value = route.CityIdB;
        row++;
    }

    workbook.SaveAs(WorkbookPath);
    Debug.Log($"{nameof(TripCityMapPersistence)}: 도시 {allCities.Count}개, 경로 {allRoutes.Count}개를 엑셀로 내보냈다.");
}
```

`TryLoad(out TripCityMapAsset)`는 **변경 없음** — 여전히 `TripCityMapAsset`(컴파일된 데이터)만 읽는다. 다만 그 에셋 경로가 §4에서 바뀐다.

## 4. 워크북/에셋 위치 재정리 — 다른 데이터 테이블과 통일

이전 세션에서 사용자 요청으로 `TripCityMap.asset`(컴파일된 SO)을 `Assets/Table/Trip/`으로 옮겼는데, 이제 그 자리에 **워크북(xlsx)**이 들어와야 하므로 원래의 데이터 테이블 관례(기획 14번 §6.3 — `Assets/Table/` = 워크북, `Assets/Prefabs/ScriptableObejct/` = 컴파일된 SO)로 되돌린다:

| 구분 | 경로 |
|---|---|
| 워크북(사람이 편집/엑셀에서 여는 원본) | `Assets/Table/Trip/TripCityMap.xlsx` (신규) |
| 컴파일된 SO(임포터 산출물, `CharacterStatsTable.asset` 등과 같은 폴더) | `Assets/Prefabs/ScriptableObejct/TripCityMap.asset` (기존 `Assets/Table/Trip/TripCityMap.asset`에서 되돌림) |

제작 시 기존 `Assets/Table/Trip/TripCityMap.asset`(+ `.meta`)을 `Assets/Prefabs/ScriptableObejct/`로 이동하고, `TripCityMapPersistence.AssetPath`/신설 임포터의 에셋 경로 상수를 그에 맞춘다. 이미 저장돼 있던 도시 10개/경로 9개는 최초 워크북 생성 시 시드 데이터로 활용할 수 있다(§7 참고, 값 손실 없이 이전 가능).

## 5. 임포터 신설 — `TripCityMapTableImporter`

데이터 테이블 임포터들과 완전히 같은 자리(`Assets/Scripts/Editor/`)와 패턴이다 — 이번엔 `EditorTableReader.GetOrCreateAsset<T>`를 **그대로 재사용할 수 있다**(설계 19번 §5에서 `TripCityMapPersistence`가 재사용 못 했던 것과 대조적 — 그건 `Core/Debug/Trip/`이라 에디터 전용 어셈블리를 참조할 수 없었지만, 이 임포터는 애초에 `Assets/Scripts/Editor/`에 있어 같은 어셈블리다).

```csharp
// Assets/Scripts/Editor/TripCityMapTableImporter.cs
public static class TripCityMapTableImporter
{
    private const string WorkbookRelativePath = "Trip/TripCityMap.xlsx";
    private const string AssetPath = "Assets/Prefabs/ScriptableObejct/TripCityMap.asset";

    [MenuItem("Tools/Game/Table/Import Trip City Map")]
    public static void Import()
    {
        var workbookPath = Path.Combine(Application.dataPath, "Table", WorkbookRelativePath);
        if (!File.Exists(workbookPath))
        {
            Debug.LogError($"{nameof(TripCityMapTableImporter)}: 워크북을 찾을 수 없다 - '{workbookPath}'.");
            return;
        }

        var cityRows = EditorTableReader.ReadSheet(workbookPath, "TripCities");
        var routeRows = EditorTableReader.ReadSheet(workbookPath, "TripRoutes");

        var asset = EditorTableReader.GetOrCreateAsset<TripCityMapAsset>(AssetPath);
        var so = new SerializedObject(asset);

        var citiesProp = so.FindProperty("cities");
        citiesProp.arraySize = cityRows.Count;
        for (var i = 0; i < cityRows.Count; i++)
        {
            var normalized = new Vector2(EditorTableReader.ParseFloat(cityRows[i], "X"), EditorTableReader.ParseFloat(cityRows[i], "Y"));
            var contentPosition = TripCityMapCoordinateConverter.ToContentSpace(normalized);
            var element = citiesProp.GetArrayElementAtIndex(i);
            element.FindPropertyRelative("CityId").stringValue = cityRows[i]["Id"];
            element.FindPropertyRelative("MapPosition").vector2Value = contentPosition;
        }

        var routesProp = so.FindProperty("routes");
        routesProp.arraySize = routeRows.Count;
        for (var i = 0; i < routeRows.Count; i++)
        {
            var element = routesProp.GetArrayElementAtIndex(i);
            element.FindPropertyRelative("CityIdA").stringValue = routeRows[i]["CityIdA"];
            element.FindPropertyRelative("CityIdB").stringValue = routeRows[i]["CityIdB"];
        }

        so.ApplyModifiedProperties();
        EditorUtility.SetDirty(asset);
        AssetDatabase.SaveAssets();
        Debug.Log($"{nameof(TripCityMapTableImporter)}: 도시 {cityRows.Count}개, 경로 {routeRows.Count}개 임포트 완료.");
    }
}
```

`Id`/`CityIdA`/`CityIdB`는 이 도메인에서 enum이 아니라 **자유 문자열**이라(사람이 엑셀에서 직접 `"seoul"` 같은 이름을 붙일 수 있어야 함, 기획 §7.7-4) `EditorTableReader.ParseEnum`을 쓰지 않는다 — 셀 값을 그대로 문자열로 읽는다. `TripRoutes`가 참조하는 `CityIdA`/`CityIdB`가 `TripCities`에 실제로 존재하는지는 검증하지 않는다(데이터 테이블 v2의 교차 파일 FK 미검증 결정과 같은 판단, 설계 18번 §7).

## 6. 자동 임포트 연결

`TableAutoImportOnPlay.cs`(플레이 진입 시 자동 재임포트)와 `TableImportAll.cs`(수동 일괄 임포트 메뉴)에 `TripCityMapTableImporter.Import();` 호출을 추가한다 — 기획 §7.1-3("엑셀에 수치를 입력하면 플레이 진입 시 자동으로 지도에 반영")이 정확히 이 한 줄로 충족된다. 호출 순서는 기존 4개 임포터와 무관한 도메인이라 순서 제약 없음 — 목록 끝에 추가.

## 7. `DEBUG_FEATURES.md` 갱신 지침

- `TripCityMapPersistence.cs`의 설명을 "저장 버튼이 xlsx로 내보낸다"로 갱신(기존 "TripCityMapAsset에 직접 저장"에서 변경).
- **`TripCityMapTableImporter.cs`/`TripCityMapCoordinateConverter.cs`는 디버그 기능 목록에 넣지 않는다** — 데이터 테이블 임포터들(`CharacterStatsTableImporter` 등)과 같은 성격의 정식 콘텐츠 파이프라인이라, 실제 지역 시스템이 생겨도 제거 대상이 아니다(오히려 그 시스템이 이어받을 것). 디버그 폴더/제거 목록에는 여전히 드래그 배치 도구(`TripDebugCityPaletteView` 등)와 `TripCityMapPersistence.cs`(저장 버튼 배선)만 남는다.
- `Assets/Plugins/Editor/ClosedXML/`을 `ExcelDataReader`와 같은 성격의 상시 의존성으로 문서에 언급할 필요는 없다(DEBUG_FEATURES.md는 "디버그 전용 기능" 목록이지, 전체 의존성 목록이 아니므로) — 대신 이 설계 문서(§3)가 그 근거 문서 역할을 한다.

## 9. Id 전면 정수화 + 도시 이름/설명 String 시트 (기획 §8 반영, 2026-09-03)

기획 15번 §8이 두 가지를 요구한다 — (1) 도시도 Data/String 시트 분리, (2) Id를 관리 가능한 정수로. 처음엔 (2)를 "엑셀/`TripCityMapAsset` 경계에서만 정수, 나머지는 문자열 유지"로 좁혀 잡았으나, 사용자가 "그 경계 변환이 유지보수에 악영향을 준다"고 판단해 **정식 코드(`Core/UI/Trip/`)까지 포함한 전면 정수화**로 확정했다(기획 §8.2 재정정). 이 절이 그 전면 계획이다.

### 9.1 타입 변경 대상 전체 목록

### 9.2 "미배정" 표현 — `null` 대신 `int?`

`string` 시절엔 `OriginCityId == null`이 "미배정"을 자연스럽게 표현했다. `int`는 값 타입이라 `int?`(nullable)로 바꿔야 같은 의미를 유지한다 — `TripOriginDestinationAssigner`/`DrawRoadDragBehavior`의 모든 `cityId == null` 비교가 `int?`의 `HasValue`/`== null`(nullable은 `==null` 비교를 그대로 지원)로 자연스럽게 치환된다. 문법적으로는 `string`→`int?` 치환이 거의 기계적이다.

`InMemoryTripCityRepository`의 자동 Id 생성도 단순해진다 - 지금은 `"debug-city-{n}"`을 만들고 `AddWithId`가 대시 뒤 숫자를 파싱해 순번을 재개했는데, Id 자체가 `int`면 그 파싱이 필요 없다:

```csharp
public int Add(Vector2 mapPosition)
{
    var id = nextSequence++;
    citiesById[id] = new TripCity(id, mapPosition);
    return id;
}

public void AddWithId(int cityId, Vector2 mapPosition)
{
    citiesById[cityId] = new TripCity(cityId, mapPosition);
    if (cityId >= nextSequence) nextSequence = cityId + 1; // 충돌 방지(기획 §6-4와 동일 목적)
}
```

### 9.3 경로 저장소 최적화 — 문자열 키 대신 튜플 키

기존 `InMemoryTripRouteRepository`는 두 도시 Id를 정렬해 `"A|B"` 문자열로 합친 뒤 `HashSet<string>`/`Dictionary<string,HashSet<string>>`으로 관리했다 — 경로를 추가/조회할 때마다 문자열 생성+비교 비용이 든다. Id가 `int`가 되면서 문자열 연결 없이 **튜플 키**로 바로 관리할 수 있다(사용자가 요청한 "최적화"):

```csharp
private static (int A, int B) Key(int a, int b) => a < b ? (a, b) : (b, a);

private readonly HashSet<(int, int)> routeKeys = new();
private readonly Dictionary<int, HashSet<int>> adjacency = new();
```

`TripMapInteractionCoordinator.linesByRouteKey`도 `Dictionary<(int,int), TripDebugRoadLineView>`로 바뀐다 - 문자열 키 생성 헬퍼(`RouteKey`) 자체가 필요 없어진다.

### 9.5 저장(Save) 시 기존 `TripCityStrings` 보존 — 핵심 주의사항

`TripCityStrings`는 **사람이 엑셀에서 직접 채우는 시트**라(입력 UI 없음, 기획 §8.1), 드래그 배치 결과를 내보내는 "저장" 버튼은 이 시트의 존재를 아예 모른다. 그런데 기존 `Save()`는 `new XLWorkbook()`(빈 워크북)에서 시작해 `SaveAs`로 파일 전체를 덮어썼다 — 이대로 두면 **사람이 입력해둔 이름/설명이 저장 버튼을 누를 때마다 통째로 날아간다.**

**수정**: 기존 파일이 있으면 그 워크북을 열어서 `TripCities`/`TripRoutes` 시트만 지우고 새로 쓰고, `TripCityStrings`의 **기존 행**은 손대지 않는다.

```csharp
var workbookPath = Path.Combine(Application.dataPath, "Table", WorkbookRelativePath);
using var workbook = File.Exists(workbookPath) ? new XLWorkbook(workbookPath) : new XLWorkbook();

if (workbook.Worksheets.TryGetWorksheet("TripCities", out var oldCitySheet)) oldCitySheet.Delete();
if (workbook.Worksheets.TryGetWorksheet("TripRoutes", out var oldRouteSheet)) oldRouteSheet.Delete();
AppendPlaceholderStringRowsForNewCities(workbook, allCities); // 아래 9.5.1
// ... TripCities/TripRoutes 새로 씀 ...
workbook.SaveAs(workbookPath);
```

#### 9.5.1 신규 도시에 자리표시자 행 자동 추가 (2026-09-03, 실기 테스트로 발견)

실제 기능 검증 중 사용자가 지적: 드래그로 새 도시를 추가하면 `TripCities`(Data)에는 등록되지만 `TripCityStrings`(String)에는 아무 행도 안 생겨서, 그 도시에 이름을 붙이려면 사람이 직접 새 행을 처음부터 만들어야 했다 — "기본 문구가 자동으로 들어가 있어서 그걸 고쳐 쓰게" 해달라는 요청. `TripCityStrings`가 없으면(최초 저장) 헤더를 만드는 것에 더해, **`TripCities`에 있는데 `TripCityStrings`엔 없는 Id마다 자리표시자 행을 추가**한다 — 값은 `BuildLocationInfo`의 기존 자동 생성 문구(`"디버그 도시 {id}"`/`"값 없음"`)와 동일하게 맞춰 창작하지 않는다. 이미 있는 행(사람이 입력했을 수 있는 값)은 Id 존재 여부만 보고 절대 덮어쓰지 않는다.

```csharp
private static void AppendPlaceholderStringRowsForNewCities(XLWorkbook workbook, IReadOnlyList<TripCity> allCities)
{
    var stringsSheet = workbook.Worksheets.TryGetWorksheet("TripCityStrings", out var existing) ? existing : null;
    if (stringsSheet == null)
    {
        stringsSheet = workbook.Worksheets.Add("TripCityStrings");
        stringsSheet.Cell(1, 1).Value = "Id";
        stringsSheet.Cell(1, 2).Value = "Name";
        stringsSheet.Cell(1, 3).Value = "Description";
    }

    var knownIds = new HashSet<int>();
    foreach (var usedRow in stringsSheet.RowsUsed().Skip(1)) // 헤더 제외
    {
        var idCell = usedRow.Cell(1);
        if (!idCell.IsEmpty()) knownIds.Add(idCell.GetValue<int>());
    }

    var nextRow = (stringsSheet.LastRowUsed()?.RowNumber() ?? 1) + 1;
    foreach (var city in allCities)
    {
        if (knownIds.Contains(city.Id)) continue;
        stringsSheet.Cell(nextRow, 1).Value = city.Id;
        stringsSheet.Cell(nextRow, 2).Value = $"디버그 도시 {city.Id}";
        stringsSheet.Cell(nextRow, 3).Value = "값 없음";
        nextRow++;
    }
}
```

### 9.6 `BuildLocationInfo` 실데이터 연동 (기획 §8.4)

코디네이터가 `TripCityStringsTableAsset` 참조를 새로 들고 있어야 한다 - `TripCityMapPersistence`에 `TryLoadStrings(out TripCityStringsTableAsset)`를 추가하고, `EnsureSavedMapLoaded()`(또는 그 직전)에서 함께 불러와 필드에 저장한다.

```csharp
private ITripLocationInfo BuildLocationInfo(int cityId)
{
    if (cityStringsTable != null && cityStringsTable.TryGetEntry(cityId, out var entry))
    {
        return new PlaceholderTripLocationInfo(cityId, entry.Name, entry.Description, cityIconSprite);
    }

    // String 시트에 아직 이름이 없는 도시(갓 드래그 배치 등) - 기존 placeholder 동작 유지.
    return new PlaceholderTripLocationInfo(cityId, $"디버그 도시 {cityId}", "값 없음", cityIconSprite);
}
```

`ExtractSequence` 헬퍼(대시 뒤 숫자 추출)는 제거한다 - `cityId` 자체가 이미 정수라 그대로 쓰면 된다.
