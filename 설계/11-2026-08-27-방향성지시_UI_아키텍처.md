## 1. 개요

12번 기획 문서가 확정한 3계층(파티 전체/역할군/개체) 중 파티 전체·역할군 2계층을 조작하는 화면을 설계한다(개체 계층은 기획 범위 밖 — §0 참고). 정비창(Formation)과 마찬가지로 Hub 씬과 Field 씬 양쪽에서 열 수 있어야 한다(01번 §2: 상행 전/중 언제든 변경 가능) — 이 요구사항은 `FormationPanel`이 이미 같은 문제를 풀어둔 선례가 있어 그 구조를 그대로 따른다.

### 0. 이번 설계 범위 밖

- 개체별 예외 행동(§4 개체 축) — 후보 자체가 미정이라 UI도 없음.
- 서포터/암살자 역할군 행 — 대응하는 직업이 없어 이번엔 화면에 노출하지 않는다(§5 참고). 새 직업이 생기면 행을 추가하는 것으로 확장(OCP).
- 01번 §2의 지략/행정력 소모 + 적응 시간(추상 타이머) + 미완료 시 디버프 — 인프라 자체가 없어 이번 화면에는 반영하지 않는다.

## 2. 데이터 모델

```
public enum RoleGroup { Frontline, RangedDealer, Supporter, Assassin }

public enum EnemyRecognitionType { OneSecondDelay, FiveSecondOrProximity, ProximityOrHit }
public enum ActivityRadiusPreset { Fixed, Standard, Wide }  // 고정(4m,개체 슬롯 기준) / 표준(대형 중심→모서리 사선거리+5m,대형 중심 기준, 기본값) / 광역(전장 전체)
public enum PursuitPreset { Autonomous, HuntToKill, OffensiveJudgment, NoPursuit, HoldPosition }
// 자율행동(반경 무시) / 추살(타겟 사망·도주까지 무제한) / 공세판단(반경밖 5초 미공격시, 기본값) /
// 추적금지(반경밖 3초 경과시) / 위치사수(반경 자체를 벗어나지 않음) — 기획 12번 §2.3

public readonly struct PartyTacticsSettings
{
    EnemyRecognitionType RecognitionType;
    ActivityRadiusPreset RadiusPreset;
    PursuitPreset Pursuit;
}

public enum TargetPriority { Nearest, DeepestPenetration, Unengaged, HighestAttack, LowestHp }  // 역할군별로 후보 부분집합만 사용
public enum LocalPositioning { Charge, Blocking, MaintainRange, Stationary }
public enum SelfPreservation { Resilient, FallBackOnHeavyDamage, Kiting, RetreatOnHit }

public readonly struct RoleGroupTacticsOverride
{
    bool IsOverridden;  // false = "상단 지침"(구 "파티 따르기" — 명칭 변경, 12번 AI 아키텍처 문서 §6-1)
    TargetPriority TargetPriority;
    LocalPositioning Positioning;
    SelfPreservation SelfPreservation;
}
```

### 2.1 데이터 구조 확정 사항 (2026-08-27)

`TargetPriority`/`LocalPositioning`/`SelfPreservation`는 역할군마다 유효한 후보가 다르다(12번 §3.1~§3.3) — enum 자체는 공유하되, "이 역할군엔 뭐가 허용되는지 + 화면에 뭐라고 표시할지"를 담는 표가 별도로 필요하다. 새 직업/역할군이 자주 추가될 수 있다는 점을 고려해 **코드가 아니라 유니티 에디터에서 기획자가 직접 편집하는 ScriptableObject 데이터 에셋**으로 둔다 — 새 역할군이나 새 직업이 생겨도 코드 수정 없이 에셋만 추가/편집하면 된다.

```
// 직업(MercenaryClass)은 그대로 유지 - 이 에셋은 그 위에 "역할군이 무엇인가"만 추가로 정의한다.
[CreateAssetMenu(...)]
public class MercenaryRoleGroupMapAsset : ScriptableObject
{
    [Serializable] public struct Entry { public MercenaryClass MercenaryClass; public RoleGroup RoleGroup; }
    public List<Entry> Entries;  // 전사→Frontline, 궁수→RangedDealer, 방패병→Frontline
}

[CreateAssetMenu(...)]
public class RoleGroupTacticsCatalogAsset : ScriptableObject
{
    [Serializable] public struct OptionEntry<TEnum> { public TEnum Value; public string DisplayLabel; }  // 예: (DeepestPenetration, "최전방 침투 적")

    [Serializable]
    public struct RoleGroupEntry
    {
        public RoleGroup RoleGroup;
        public List<OptionEntry<TargetPriority>> TargetPriorityOptions;      // 이 역할군에서 고를 수 있는 후보 + 한국어 라벨, 순서 = 드롭다운 표시 순서
        public List<OptionEntry<LocalPositioning>> PositioningOptions;
        public List<OptionEntry<SelfPreservation>> SelfPreservationOptions;
    }
    public List<RoleGroupEntry> Entries;  // Supporter/Assassin은 대응 직업이 없어 이번엔 빈 목록으로 둠(§0)
}
```

**제작 단계 반영(2단계, 2026-08-27)**: 위 `OptionEntry<TEnum>` 열린 제네릭은 유니티 시리얼라이저가 인스펙터에 안정적으로 그려주지 못해, 실제 코드(`RoleGroupTacticsCatalogAsset.cs`)에서는 `TargetPriorityOption`/`LocalPositioningOption`/`SelfPreservationOption` 3개의 닫힌 타입으로 나눠 구현했다 — 데이터 구조 의도(축별 후보+라벨)는 동일, 표현 방식만 Unity 제약에 맞춰 조정.

- **override 초기값(확정)**: 역할군 override를 처음 켤 때("상단 지침"→"직접 지정") 3개 드롭다운은 각 옵션 목록의 **첫 번째 항목**을 그대로 사용한다 — 역할군별 별도 기본값 필드는 두지 않는다. 목록 순서 자체가 기본값을 겸한다(예: 전열 타겟우선순위 목록의 첫 항목이 "최근접"이면 override를 켜는 순간 그게 기본으로 뜬다).
- **확정(12번 AI 아키텍처 문서 §6-1)**: 상단 지침(파티 축)과 역할군 축은 애초에 겹치는 축이 없어 override 관계가 아니지만, 향후 개체별 방향성이 이 자리에 실제 override 관계를 붙일 예정이라 **토글 UI 형태는 남겨둔다**. 이번 단계에서는 토글을 화면에 두되 **비활성(disabled) 상태로 렌더링** — 클릭해도 동작이 바뀌지 않는 자리 확보용이고, 역할군 값은 토글 상태와 무관하게 항상 override 필드(초기값=카탈로그 첫 항목)를 그대로 쓴다.
- `MercenaryRoleGroupMapAsset`/`RoleGroupTacticsCatalogAsset` 둘 다 `Assets/Data/` 같은 위치에 에셋으로 저장하고, `TacticsPanel`/`InMemoryTacticsRepository`가 이를 주입받아 조회한다(실행 중 값은 그대로, 편집은 에디터에서만).

## 3. 컴포넌트 구조

`FormationPanel`/`IFormationPanel`/`InMemoryFormationRepository` 선례를 그대로 따른다.

```
public interface ITacticsPanel : IUIPanel
{
    void RegisterTacticsUI(ITacticsRepository repository, IUIManager uiManager, string sceneName);
}

public enum TacticsTab { Party, RoleGroup, Individual }  // 탭 3개 — Individual은 이번 세션엔 내용 없이 자리만 확보(§4)

public class TacticsPanel : MonoBehaviour, ITacticsPanel { ... }  // 내부에 activeTab 상태를 갖고 탭 버튼 클릭 시 콘텐츠 루트를 전환(SetActive)

public interface ITacticsRepository
{
    PartyTacticsSettings GetPartySettings();
    void SetPartySettings(PartyTacticsSettings settings);
    RoleGroupTacticsOverride GetRoleGroupOverride(RoleGroup roleGroup);
    void SetRoleGroupOverride(RoleGroup roleGroup, RoleGroupTacticsOverride value);
}

public class InMemoryTacticsRepository : MonoBehaviour, ITacticsRepository { ... }  // 세션 한정, Placeholder 아님(FormationRepository와 동급)
```

- `TacticsPanel`은 전역 DI 대상이 아니라 `UIManager` 산하 형제 컴포넌트다(`ManagerHierarchyInstaller.cs`에 `EnsureSiblingComponent<TacticsPanel>(uiManager.gameObject)` 추가) — 프로젝트 컨벤션(HubUIController/FormationPanel/TripPanel과 동일 위치).
- `InMemoryTacticsRepository`도 `InMemoryFormationRepository`와 같은 위치(`GetOrCreateManager<InMemoryTacticsRepository>(root.transform, ...)`)에 둔다 — 정비창 배치와 마찬가지로 "이번 상행 세션 동안만 유지"가 자연스러운 성격이라 저장/불러오기 시스템을 기다릴 필요가 없다.
- `TacticsPanel.RegisterTacticsUI`는 `FormationPanel.RegisterFormationUI`와 동일하게 씬 이름을 받아 `SceneManager.GetSceneByName(sceneName)`으로 그 씬의 `SceneUIRoot`를 찾아 재바인딩한다 — Hub/Field 양쪽 `IContentSceneUIWiring`(`HubUIWiring`/`FieldUIWiring`)에서 각각 호출.

## 4. 진입점

- `HubUIElementIds.TacticsButton` — Hub 씬, `Hub.FormationButton` **바로 위**에 배치.
- `FieldUIElementIds.TacticsButton` — Field 씬, `Field.FormationButton`("정비창" 버튼) **바로 위**에 배치.
- 두 버튼 모두 `uiManager.Open(UIPanelIds.Tactics)` 호출 — `HubUIController`/`FieldUIController`의 기존 버튼 바인딩 패턴(`BindButton`) 재사용.
- `UIPanelIds.cs`에 `Tactics = "Tactics"` 추가.
- 씬 전환/커튼 중 상호작용 차단 규칙(`ISceneRevealSignal` 기반, `HubUIController.SetTopLevelButtonsInteractable` 참고)을 이 버튼에도 동일 적용.

## 5. 화면 레이아웃 (확정 — 위젯은 드롭다운, 좌표는 검수용 초안)

**위젯 형태(확정)**: 드롭다운(`TMP_Dropdown`)으로 결정 — 프로젝트에 선례는 없지만(정비창/상행 준비 UI는 버튼 기반) 이번엔 드롭다운을 신규 도입한다. `EditorUIBuilder`에 `EnsureDropdown` 계열 유틸리티가 새로 필요(§6).

```
[방향성 지시 패널] (전체 화면 스트레치, FormationPanel/TripPanel과 동일 컨벤션)
 ├─ 타이틀 "방향성 지시"
 ├─ 닫기 버튼
 ├─ 탭 바: [파티 전체] [역할군] [개체별]   ← 클릭 시 아래 콘텐츠 루트를 전환(한 번에 하나만 표시)
 └─ 콘텐츠 영역 (활성 탭에 따라 셋 중 하나만 활성)
     ├─ [파티 전체 탭] 3행 스택 — 적 인식 유형 / 활동 반경 / 추적 드롭다운
     ├─ [역할군 탭] 전열·원거리딜러 2블록 스택 — 각각 override 토글 + 3개 드롭다운
     └─ [개체별 탭] 플레이스홀더 텍스트("이번 버전에서는 지원하지 않음") — §4, 향후 확장용 자리만 확보
```

서포터/암살자 행 없음(§0). "상단 지침 ⇄ 직접 지정" 토글은 화면에 존재하되 이번 단계에서는 비활성(disabled) — 클릭해도 3개 드롭다운 상태가 바뀌지 않는다(§2.1 참고, 향후 개체별 방향성 구현 시 실제 기능 연결 예정).

## 6. 인스톨러 계획

기존 씬 편집 컨벤션(`.unity`/`.prefab` 직접 편집 금지, get-or-create 인스톨러) 그대로 적용.

- **`TacticsUIInstaller.cs`**(신규, `Assets/Scripts/Editor/`, `[MenuItem("Tools/Game/Install Tactics UI")]`)
  - Hub 씬: `Hub.TacticsButton` 생성/배치(`Hub.FormationButton` 앵커 위쪽), 방향성 지시 패널 시각 요소 트리 생성(탭 버튼 3개 + 콘텐츠 루트 3개, §5.1).
  - Field 씬: `Field.TacticsButton` 생성/배치(`Field.FormationButton` 앵커 위쪽), 같은 패널 시각 요소 트리를 Field의 `SceneUIRoot`에도 생성(정비창 UI가 Hub·Field에 각각 사본을 두는 것과 동일 패턴).
  - 탭 버튼 3개는 `TacticsPanel`이 클릭 시 `activeTab`을 갱신하고 3개 콘텐츠 루트 중 하나만 `SetActive(true)`로 전환하도록 바인딩(설치 시점엔 오브젝트 생성/마커 부착만, 바인딩은 `TacticsPanel.RegisterTacticsUI`가 담당).

## 7. SOLID 메모

- **ISP**: `ITacticsRepository`가 파티/역할군 조회+수정을 모두 가진 것은 `IFormationRepository`와 동급 크기 — 소비자가 패널 하나뿐이라 당장 분리 불필요. 향후 전투 시뮬레이션(`BattleCharacterUnit` 등)이 "읽기만" 필요해지면 그때 `ITacticsReader` 상위 인터페이스를 추출한다(`IFormationReader` 선례와 동일 판단 기준).
- **SRP**: `TacticsPanel`은 화면 조율만, 실제 값 저장/조회는 `ITacticsRepository`에 위임 — `FormationPanel`/`InMemoryFormationRepository` 분리와 동일 구조.
- **DIP**: `TacticsPanel`은 `ITacticsRepository`에 의존하고 구현체는 `RegisterTacticsUI` 인자로 주입.
