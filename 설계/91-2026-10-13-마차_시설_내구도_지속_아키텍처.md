# 마차·시설 내구도 지속 아키텍처

작성일: 2026-10-13
상태: 섹션별 사용자 승인 완료(2026-10-13), 문서 검토 대기. 작업 브랜치 `system`.
기획: [90 마차·시설 내구도 지속](../기획/90-2026-10-13-마차_시설_내구도_지속_기획.md)
관련 설계: 56(마구간 화면), 72·74(장애물·패배 조건), 79(전투 결과 정리·회수 적재·대열 정리), 81(보유 개체 Id·재고), 83(골드 지출), 85(궤주 날짜 정산), 89(이벤트 효과 명령 — 이 문서가 §5.1 명령 추가)

## 1. 기획 요약

- 마차·시설의 개체별 현재 내구도를 저장한다. 상행을 넘어 유지하고 자동 회복은 없다.
- 최대 내구도는 `Wagon.xlsx`·`Facility.xlsx`의 새 열(초기값 200)이 정한다. 코드 상수 200을 대체한다.
- 손상: 전투 피격(전투 종료 시 저장), 이벤트 효과. 회복: 마구간 수리(골드), 이벤트 효과.
- 전투 중 0 → 마차·시설 모두 영구 제거. 시설도 잔해(장애물만)를 남기며, 시설 파괴는 상행 시간을 늘리지 않는다.
- 마구간: 보유 목록에 내구도 표시 → 행 클릭 시 개별 정보 화면(수리·목록으로)으로 교체, 목록 하단에 전체 수리.
- 수리비 = 올림(가격 × 손상 비율 × 계수), 계수는 지금 0.5 단일.
- 이벤트 효과: 종류(마차/시설/둘 다) 지정, 최대치 대비 %. 감소는 무작위 1개, 회복은 가장 손상된 1개. 이벤트로 0이 되면 마차는 화물 이동(마지막 마차면 화물 포기 + 궤주), 시설은 제거만.
- 세부 규칙은 기획 90 §4(추천안 그대로 확정)를 따른다.

## 3. 데이터·저장소

### 3.1 테이블

| 항목 | 내용 |
|---|---|
| 열 | `Wagon.xlsx`·`Facility.xlsx`에 `MaxDurability` 추가, 초기값 전부 200 |
| 임포트 | `CaravanAssetTableImporter` — 정수, 1 이상이 아니면 임포트 오류(행 Id 포함) |
| 종류 정보 | `CaravanAssetTableAsset` 항목과 `CaravanAssetProfile`에 최대 내구도 추가 |

### 3.2 `CaravanAssetDurabilityManager`

- Bootstrap 상주 `IManagedComponent`. `ManagerHierarchyInstaller`의 `managedComponents`에 등록.
- 등록 타입: `ICaravanAssetDurabilityReader`, `ICaravanAssetDurabilityWriter` **둘 다 각각** 등록한다(읽기 타입 미등록으로 TryResolve가 조용히 null이 되는 사례 방지).
- 저장 단위: 보유 개체 Id(`종류Id#n`, 설계 81) → 현재 내구도(float, 소수 허용).
- 보유 동기화: `IOwnedCaravanAssetReader.OnOwnedChanged`를 구독한다.
  - 새 개체 → 최대치로 등록(신규 구매·시작 보유 공통, 기획 90 §4-1·2).
  - 사라진 개체 → 기록 삭제.
- 조회 시 테이블 최대치로 자른다(기획 90 §4-5 — 데이터 수정으로 최대치가 줄어든 경우).
- DI 재해결 시 기록을 비우고 현재 보유 목록으로 다시 채운다.

| 계약 | 내용 |
|---|---|
| Reader | 현재값·최대값 조회(없는 Id면 false), 변경 이벤트(값 변경·등록·삭제 모두) |
| Writer | 현재값 설정(0~최대로 자름), 최대치로 복원 |

- 보유 목록 이벤트를 받아 지우므로, 개체 제거 경로(정산·이벤트)는 내구도 기록을 직접 지우지 않는다.

### 3.3 순수 정책 클래스

| 단위 | 역할 |
|---|---|
| 대상 선정 | 감소: 후보 중 무작위 1개(손상 여부 무관, 난수 함수 주입). 회복: 비율(현재 ÷ 최대) 최저, 동률이면 보유 순서 앞쪽, 모두 가득이면 없음 |
| 수리비 | 개별 = 올림(가격 × (최대 − 현재) ÷ 최대 × 계수), 손상 없으면 0. 전체 = 손상 개체 개별 합. 계수는 "종류 → 계수" 한 지점(지금 전부 0.5) |
| 표시값 | 정수 올림(0.4 → 1, 기획 90 §4-4). 마구간·결과 줄이 같은 함수를 쓴다 |

- 보유 순서 = 정비창 팔레트 순서 = `IOwnedCaravanAssetReader`의 종류별 보유 Id 순서(마차 → 시설).

## 4. 전투 연결 · 시설 잔해 · 파괴 제거

### 4.1 전투 시작

- `LiveBattleSimulationRule`의 보호 유닛 생성에서 최대치를 `ProtectedUnitTuning.MaxHp` 대신 종류 정보의 `MaxDurability`로 쓴다(개체 Id로 보유 개체 조회).
- `BattleProtectedUnit`에 선택 인자 "시작 내구도"를 추가한다(캐릭터 `startingHp`와 같은 방식). 시작값 = 매니저의 현재값.
- 매니저가 없거나 기록이 없으면 최대치로 시작한다(Bootstrap 재빌드 전에도 지금 동작 유지).
- 배틀 테스트 씬은 자체 로스터라 상수(`ProtectedUnitTuning.MaxHp`)를 유지한다.

### 4.2 전투 종료 — 결과에 싣고 정산이 한 번에 반영

- `BattleResult`에 보호 유닛 기록 목록(개체 Id·종류·남은 내구도·파괴 여부)을 추가한다. 파괴 마차 목록을 결과에 실어 정산이 처리하는 방식(설계 79 §15-2)과 같다.
- 정산 계획(`BattleAftermathCalculator`)에 파괴 시설 Id를 추가한다. 상행 시간 추가는 **파괴 마차 수 × 20초만**(시설 제외, 기획 90 §3-7).
- 정산(`BattleAftermathApplier`) 순서:

| 순서 | 처리 |
|---|---|
| 1 | 화물 제거(기존) |
| 2 | 생존 개체 내구도 저장(Writer) |
| 3 | 공용 파괴 처리(§4.4)에 파괴 마차 + 파괴 시설을 넘김 — 대열 정리 → 진행 중 배치 취소 → 보유 제거 |
| 4 | 회수 물품 임시 보관(기존) |
| 5 | 상행 시간 추가(마차만) |

- 적용 범위: 승리·패배-도주. 포로·사망은 지금처럼 정산 자체를 건너뛴다.
- 결과 요약(`BattleAftermathSummary`·포매터)에 "시설 파괴 n" 한 줄 추가(마차 파괴와 같은 형식).

### 4.3 시설 잔해

| 지점 | 변경 |
|---|---|
| 장애물 | `BattleProtectedUnit.BlocksMovement`를 시설도 파괴 후 막도록 변경(지금은 마차만) |
| 표시 | `BattleProtectedUnitView`가 시설 파괴도 잔해 표시(연두색 계열, 원 모양 유지, 체력 게이지 숨김) |
| 공격 대상 | 변경 없음 — 잔해 공격 대상은 화물 원장(`WreckTargets`)이 마차만 등록 |
| 패배 판정 | 변경 없음 — 마차만 셈(기획 73). 시설은 이미 전투 가능 수에서 빠진다 |

### 4.4 공용 파괴 처리 (정산·이벤트 공유)

- 지금 정산기 안에 있는 "대열 조회 생성 → `FormationWreckRelocator` 재배치 → 진행 중 배치 취소 → 보유 제거" 순서를 별도 단위로 추출한다.
- 순서 제약(보유 제거 **전에** 대열 조회를 만든다 — 제거 뒤엔 파괴 개체를 마차·시설로 인식하지 못함)을 이 단위 한 곳에만 둔다.
- 입력: 파괴 개체 Id 목록(마차·시설 혼합). 출력: 재배치·배치 해제 수, 대열 끊김 여부(정산 요약·대열 정리 단계 진입 판정에 사용).
- 재배치기는 시설 Id도 대열에서 빼도록 확인·보완한다(시설 영역이 빠지면 영역이 줄어 유닛 재배치가 필요할 수 있음).

## 5. 마구간 수리

### 5.1 `CaravanAssetRepairService` (plain C#)

- 구매 처리(`CaravanAssetPurchaseService`)와 같이 판정과 실행을 나눈다.
- 판정: 수리 가능 / 수리 불필요(가득) / 골드 부족. 전체 수리 판정: 손상 없음 / 골드 부족 / 가능.
- 실행: 골드 지출(`IGoldSpender` — 개인 소지 → 적재 상자, 기획 82) → 최대치 복원. 복원 실패(기록 없음) 시 환급.
- 전체 수리: 합계를 한 번에 지출 → 손상 개체 전부 복원. 합계 부족이면 아무것도 고치지 않는다(부분 수리 없음).
- 의존: 골드 지출, 보유 목록 읽기, 내구도 Reader·Writer.

### 5.2 화면

| 영역 | 지금 | 변경 |
|---|---|---|
| 보유 목록 | 용병 화면과 공용 텍스트 레이블(`RosterShopElements.OwnedListLabel`) | 마구간만 행 단위 목록으로 교체. 용병 화면은 그대로 |
| 구매 후보·정보·구매 버튼 | 공용 요소 | 그대로(기획 90 §4-19) |

- 마구간 보유 영역 요소는 `StableUIElementIds`와 요소 묶음 클래스로 새로 둔다.
  - 목록 화면: 종류별 제목, 개체 행(이름 + `현재/최대`, 손상된 행은 수치 색 변경), 하단 [전체 수리 (합계)] 버튼 + 사유 레이블.
  - 개별 정보 화면: 이름, 종류, 내구도 `현재/최대`, 수리비, [수리], 사유 레이블, [목록으로].
  - 두 화면은 같은 자리에 겹쳐 두고 하나만 켠다.
- 비활성 사유: 가득 → "수리할 필요 없음", 골드 부족 → "골드 부족"(기획 90 §4-14·16). 확인 창 없음.
- 보유 영역 상태(목록/개별, 선택 개체)와 수리 버튼은 협력 객체 `StableOwnedSection`(plain C#)이 맡는다. `StablePanel`은 구매만 맡고 열기·닫기·Dispose를 이 객체에 넘긴다.
- 행 오브젝트는 템플릿 복제 + get-or-create 재사용(후보 목록과 같은 방식).
- 갱신: 골드 변경·보유 변경·내구도 변경 이벤트를 받아 열려 있을 때만 다시 그린다. 매 프레임 확인 없음.
- 마구간을 열 때마다 목록 화면부터. 개별 화면의 개체가 사라지면 목록으로.
- 매니저·수리 서비스가 없으면 내구도 "값 없음", 수리 버튼 비활성.

### 5.3 인스톨러·반영 경로

- 공용 조립(`RosterShopUIBuilder`)은 그대로 두고, 마구간 화면에만 보유 영역 조립 단계를 추가한다(get-or-create).
- 마구간의 옛 보유 텍스트 레이블은 정리 로직(`DestroyChildIfExists` 등)으로 제거. 용병 화면 레이블은 유지.
- `HubUIWiring.RegisterStable`에 내구도 Reader·Writer를 선택적으로 넘긴다.
- 마구간 화면 코드는 develop 경유로 system에 이미 병합되어 있으므로 system에서 작업, ui에는 develop 경유로 반영.

## 6. 이벤트 효과 (설계 89 §5.1 추가)

### 6.1 명령

| 명령 | 동작 | 결과 줄 |
|---|---|---|
| `<<durability 대상 퍼센트>>` | 대상 `wagon`/`facility`/`any`, 퍼센트 = 최대치 대비 증감(부호 포함). 변화량 = 최대치 × %, 0~최대로 자름 | 「마차이름1 내구도 −20」「시설이름1 내구도 +15」「마차이름1 파괴」「시설이름1 파괴」 |

- 대상 선정은 §3.3 정책: 감소 = 지정 종류 보유 중 무작위 1개(진행자 난수 함수), 회복 = 비율 최저 1개.
- 지정 종류 보유 0, 또는 회복 대상이 모두 가득 → 효과 없음, 결과 줄 생략.
- 결과 줄 숫자 = 표시값(올림) 기준 변화량 — 마구간 표시와 일치.
- 이름 표기는 보유 개체 이름(`OwnedCaravanAssetNames`) 그대로.
- 인자 오류(대상 이름 오류, 숫자 아님) → 효과 건너뜀 + 경고 로그, 대본 계속(설계 89 §5.1 규칙).
- E3 대본: `<<delay 20>>` 다음 줄에 `<<durability wagon -10>>`.

### 6.2 내구도 0 처리

| 경우 | 처리 |
|---|---|
| 시설 0 | 공용 파괴 처리(§4.4)만. 대본 바로 계속 |
| 마차 0, 남은 마차 있음 | ① 파괴 마차 적재 공간의 화물을 임시 보관으로 옮김 ② 공용 파괴 처리 ③ `<<goods_add>>` 공간 부족 흐름 재사용(상단 물류품 팝업 → 정리 → 남으면 포기 확인, 기획 86 §3.6) ④ 대열이 끊겼으면 전투와 같은 대열 정리 단계 ⑤ 대본 계속. 화면이 닫힐 때까지 대기 |
| 마지막 마차 0 | 화물 포기(환급 없음 제거) → 이벤트 종료 기록 → 궤주 처리 |

- ①은 명시 단계로 둔다. 보유 제거 시 남은 화물을 임시 보관으로 옮기는 기존 안전장치(`PlaceholderTradeGoodsInventoryRepository`)는 "정산 순서 버그" 경고를 내므로 정상 흐름이 기대지 않는다. 상단 물류품 쪽에 "섹션 화물 → 임시 보관" 조작을 추가한다.
- ④ 대열 정리는 기획 86 §3.9에 없는 추천안(섹션 4 승인) — 마차가 빠져 끊긴 대열로 상행을 재개하지 않게 한다.
- 궤주: 전투 마무리(`FinishStep`)의 궤주 분기(날짜 정산 → 상행 종료 → Hub 귀환)를 공용 진입점으로 추출해 이벤트 진행자도 부른다. 설계 89 §4.2의 "패배 시 종료 기록" 규칙을 지킨다.
- "마지막 마차" 판정 = 감소 적용 전 보유 마차 수 1.

## 7. 디버그

- 내구도 디버그는 전용 인스톨러로 분리(Install/Remove 서브메뉴, `DebugToolsBulkInstaller` 등록).
- Hub: 보유 개체 선택 → 내구도 −10% / +10% / 0 직전(최대치의 1%). 마구간 수리·이벤트 파괴 준비용.
- Field: 별도 버튼 없음 — 설계 89 이벤트 디버그(강제 발생)로 E3을 부른다.
- 배치는 제작 단계에서 Play 실측으로 기존 디버그 UI·마구간 화면과 겹침을 점검해 정한다.

## 8. 테스트 (EditMode)

| 대상 | 항목 |
|---|---|
| 임포트·종류 정보 | `MaxDurability` 1 미만·비정수 오류, 정상 값 반영 |
| 매니저 | 보유 추가 → 최대치 등록, 제거 → 기록 삭제, 설정 시 0~최대 자르기, 조회 시 최대치 축소 반영, 변경 이벤트 |
| 대상 선정 | 감소 무작위(손상 개체 포함), 회복 비율 최저·동률 순서, 모두 가득이면 없음, 보유 0이면 없음, `any` 후보 범위 |
| 수리비 | 올림, 손상 없으면 0, 계수 적용, 전체 = 개별 합 |
| 수리 서비스 | 판정 3종, 골드 부족이면 변경 없음, 성공 시 지출 + 복원, 전체 수리 전부/전무, 복원 실패 시 환급 |
| 전투 | 시작 내구도 인자로 만든 보호 유닛 값, 시설 파괴 후 `BlocksMovement` |
| 정산 | 시설 파괴가 시간 추가에서 빠지고 제거 목록에 들어감, 생존 내구도 저장 |
| 공용 파괴 처리 | 마차·시설이 대열·보유에서 빠짐, 제거 전 조회 순서, 대열 끊김 여부 |
| 이벤트 효과 | 증감·자르기, 결과 줄 표시값 차이, 0 처리 3분기, 인자 오류 |

## 9. 제작 순서

| 묶음 | 내용 | 선행 |
|---|---|---|
| A. 데이터·저장소 | 열 추가·임포트 검증, 종류 정보, 매니저, 정책 클래스 | 없음 |
| B. 전투 연결 | 시작 내구도, 결과 기록, 공용 파괴 처리 추출, 시설 잔해, 요약 "시설 파괴 n" | A |
| C. 마구간 수리 | 수리 서비스, 보유 영역 요소·협력 객체, 인스톨러, 내구도 디버그 | A |
| D. 이벤트 효과 | `<<durability>>`, 0 처리 분기(화물 이동·대열 정리·궤주 공용 진입점), E3 대본 | A·B, 설계 89 제작 완료 |

- A~C는 89와 독립. 추천 순서: 89 → 91(A~D) — 89가 다음 제작으로 잡혀 있고 D까지 한 번에 끝낼 수 있다. 최종 순서는 사용자가 정한다.
- 새 테이블 열 추가 후 Play(자동 임포트) → Build Bootstrap Scene → Ctrl+S 순서(매니저 신설).

### 9.1 Play 확인 항목 (사용자 실행)

1. 전투에서 마차 피격 → Hub 마구간 보유 목록에 줄어든 내구도
2. 다음 전투가 줄어든 내구도로 시작(체력 게이지)
3. 시설 파괴 → 연두색 잔해로 남아 길을 막고 공격받지 않음. 전투 뒤 보유·대열에서 빠지고 상행 시간 불변
4. 마구간: 행 클릭 → 개별 정보 → 수리(골드 차감, 가득) → 목록으로. 전체 수리 합계, 비활성 사유 2종
5. 개인 골드 부족 시 적재 골드 상자에서 지출
6. E3 → 무작위 마차 내구도 −10%, 결과 줄
7. 디버그로 0 직전 → E3 → 마차 파괴, 화물 정리 화면, 대열 정리
8. 마지막 마차만 남긴 상태에서 7 → 궤주, Hub 귀환
9. 마구간 화면 UI 겹침(디버그 UI 포함)
