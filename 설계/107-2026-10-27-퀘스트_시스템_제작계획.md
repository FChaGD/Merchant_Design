# 퀘스트 시스템 제작 계획

> 실행: 이 세션에서 직접 제작(이전 시스템과 같은 방식), 끝난 뒤 검진 여부 확인. 단계는 `- [ ]` 체크박스로 추적.

**목표:** 설계 107대로 퀘스트 공통 체계 + 상인조합 의뢰 수락형을 동작시키고 `PlaceholderGuildQuestBoard`를 제거한다.

**구조:** 데이터(Quest.xlsx → `QuestTableAsset`) → 순수 판정·배치 규칙(`QuestRules`, `QuestEventPlacement`, `CargoFitSimulator`) → Bootstrap 상주 상태(`QuestManager`, `ReputationManager`, `TripArrivalSignal`, `GuildQuestBoard`) → 기존 시스템 연결(전투 결과·이벤트·난이도·버리기·Field 정리 화면) → UI(게시판·평판 HUD).

**기술:** Unity 6000.3.7f1, C#, NUnit EditMode, ClosedXML(에디터 임포트), Yarn Spinner(기존 이벤트).

**설계:** `Docs/설계/107-2026-10-27-퀘스트_시스템_아키텍처.md`(기획 106). 실행자는 두 문서를 함께 읽는다.

## 공통 제약

- 네임스페이스 `Game.Core`(에디터 `Game.Core.Editor`), 폴더 `Assets/Scripts/Core/Quest/`(순수·상태), UI는 `Core/UI/Town/Guild/`, 테스트 `Assets/Scripts/Tests/EditMode/`.
- Bootstrap 상주 상태 저장소 이름은 `XxxManager`(사용자 규칙). 의존성은 `TryResolve`로 **등록 타입**을 조회(읽기 타입 미등록 함정).
- 선택 의존성이 없으면 경고 1회 후 그 기능만 건너뛴다. 예외로 상행을 멈추지 않는다.
- 상태는 직렬화 가능한 순수 데이터로만 둔다(저장 대비, 설계 §5.3).
- 값 없는 텍스트는 `PlaceholderText.Missing`("값 없음").
- `.unity`/`.prefab` 직접 편집 금지 — 인스톨러 get-or-create, 옛 오브젝트 `DestroyChildIfExists`. 인스톨러 실행·씬 저장은 CLI로 직접(Play 상태 확인 후).
- 주석은 한국어, "왜"를 우선.
- 테스트 실행: `~/.claude/projects/C--Users-addmin-Desktop-Merchant/tools/ut.sh ALL`(재컴파일 + EditMode 전체). 기대: 기존 856 + 신규 전부 통과.

### 설계 대비 제작 시 확정 사항

- 의뢰 화물 구분은 무역품 테이블에 새 열을 만들지 않고 기존 `TradeKind` 열의 새 값 `QuestCargo = 3`(`TradeGoodsKind`)으로 한다 — 이미 있는 일반/특산 구분 열이라 데이터·임포터 변경이 가장 작다(설계 §4 "`QuestCargo` 열"의 구현 형태). `TownStockTableImporter`는 QuestCargo 아이템 행을 거부한다(재고·구매 목록 제외).
- 위약금은 `IPlayerCurrencyWallet`에서 min(위약금, 보유)만 차감(설계 §7 "개인 골드에서 가진 만큼").

## 검토 초점

1. 퀘스트 자신의 납품 차감·화물 회수가 인벤토리 변경 신호를 일으켜 같은 퀘스트를 "의뢰 화물 손실 → 실패"로 오판 — 처리 중 플래그로 무시(Task 7 테스트 `OwnDeduction_DoesNotFailPreserve`).
2. 같은 신호에서 여러 퀘스트가 동시에 완료·실패하며 목록을 순회 중 수정 — 순회 전 복사(Task 7 `TwoQuestsCompleteOnSameArrival`).
3. 날짜가 여러 날 한 번에 넘어감(숙소 휴식 N일, 궤주 정산) — 만료 판정은 `>`, 재게시는 `<=` 비교라 건너뛰어도 누락 없음(Task 7 `DateJumpsPastDeadlineAndRepost`).
4. 정리하지 못한 대기 표시가 남아 다음 상행 Field에서 엉뚱하게 열림 — 다음 상행 시작(TripStarted) 시 대기 해제(Task 12 `PendingClearedOnTripStart`).
5. 의뢰 화물이 임시 보관에 있다가 출발 시 일괄 버림 — 출발 경고에 퀘스트명 표시 후 확인하면 실패 판정(Task 11 `DepartureWarning_ListsQuestCargo`).

### Task 4: 확정 사건 발생 위치(순수)

**파일:** 생성 `Core/Quest/QuestEventPlacement.cs` / 테스트 `QuestEventPlacementTests.cs`

**생산:** `readonly struct QuestEventSpot { int LegIndex; float LegProgress; }`, `static QuestEventSpot QuestEventPlacement.Resolve(QuestEventTiming timing, IReadOnlyList<float> legDurations, float min, float max, Func<float> random01)`.
- Progress: 전체 비율 `p = Clamp01(min)`, 누적 소요시간으로 구간을 찾아 구간 내 비율. `p == 1` → 마지막 구간 1.0. 구간 경계(누적이 정확히 p)는 다음 구간 0.0(그 구간에 들어서는 순간 발생). 소요시간 합 0 또는 구간 없음 → (0, p).
- Random: 구간 = `Min(floor(random01()*count), count-1)`, 진행률 = `min + (max-min)*random01()`(min>max면 교환, 0~1 자르기).
