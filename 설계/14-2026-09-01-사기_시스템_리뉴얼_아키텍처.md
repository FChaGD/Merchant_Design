## 1. 개요 및 범위

07번 문서가 구현한 "PartyMorale 변경 시 즉시 동기화" 사기 모델을 기획 §7 리뉴얼에 맞춰 전면 교체한다. 핵심 변경 7가지:

1. PartyMorale 하락 트리거를 사망(−10)/도주(−15)로 분리하고 처치 시 +4 회복 트리거 신설(§7.1).
2. PartyMorale에 3단계(고/보통/저사기) 도입, 저사기 구간은 증감폭 자기증폭(§7.2).
3. "즉시 동기화"를 폐기하고, 델타를 나르는 원형 파동이 발생 지점에서 공간적으로 퍼져나가는 방식으로 교체(§7.3).
4. UnitMorale이 더 이상 PartyMorale을 직접 참조하지 않고, 파동으로만 갱신되는 개인 목표치를 따라간다(§7.4).
5. 동기화 속도를 유닛 타입/직업별 개체값으로 전환(§7.4).
6. UnitMorale에도 3단계 도입 — 고사기 스탯 버프, 저사기 동기화 가속(§7.5).
7. 붕괴(도주) 판정을 "임계치 이하 즉시 도주"에서 "임계치 이하 후보 상태 + 이벤트 기반 확률 판정"으로 전환(§7.6).

07번 문서의 `PartyMorale`/`MoraleTuning`/`BattleCharacterUnit` 사기 관련 부분을 대체한다. 보호 목표(`BattleProtectedUnit`) 관련 부분(07번 §5)은 무변경이라 다시 다루지 않는다.

## 3. 수치 단일 출처 — `MoraleTuning` 전면 교체

```csharp
/// <summary>기획 08번 문서 §7 테스트 수치(2026-09-01 리뉴얼). 플레이테스트 후 조정 대상.</summary>
public static class MoraleTuning
{
    public const float Initial = 60f;               // PartyMorale/UnitMorale/개인 목표치 공통 초기값

    // §7.1 PartyMorale 트리거
    public const float DeathLoss = 10f;
    public const float FleeLoss = 15f;
    public const float EnemyKilledGain = 4f;

    // §7.2/§7.5 3단계 임계치 — PartyMorale/UnitMorale이 공유(사용자 확정)
    public const float HighTierThreshold = 70f;
    public const float LowTierThreshold = 30f;
    public const float LowTierAmplifier = 1.5f;      // PartyMorale 저사기 자기증폭 배율

    // §7.3 파동 팽창 속도 = min(WaveSpeedCap, WaveSpeedPerDeltaUnit * |delta| / 10)
    public const float WaveSpeedPerDeltaUnit = 2f;
    public const float WaveSpeedCap = 15f;

    // §7.5 UnitMorale 고사기 버프 / 저사기 동기화 가속
    public const float HighTierDefenseMultiplier = 1.2f;
    public const float HighTierMoveSpeedMultiplier = 1.5f;
    public const float LowTierSyncMultiplier = 2f;

    // §7.6 붕괴(도주) 확률제 — probability(%) = FleeProbabilityFloor +
    //   (100 - FleeProbabilityFloor) * ((FleeCandidateThreshold - UnitMorale) / FleeCandidateThreshold) ^ FleeProbabilityExponent
    public const float FleeCandidateThreshold = 10f;
    public const float FleeProbabilityFloor = 2f;
    public const float FleeProbabilityExponent = 4f;
}
```

기존 `SyncRatePerSecond`/`PartyMoraleLossOnUnitLost`/`FleeThreshold` 상수는 삭제한다 — 각각 `BattleUnitStats.MoraleSyncRate`(§7), 트리거별 상수(위), 확률제(위)로 대체됐다.

## 4. `MoraleTier` — PartyMorale/UnitMorale 공유 3단계

```csharp
public enum MoraleTier { Low, Normal, High }

public static class MoraleTierExtensions
{
    public static MoraleTier ToMoraleTier(this float moraleValue) => moraleValue switch
    {
        >= MoraleTuning.HighTierThreshold => MoraleTier.High,
        < MoraleTuning.LowTierThreshold => MoraleTier.Low,
        _ => MoraleTier.Normal,
    };
}
```

## 5. `PartyMorale` — 트리거별 메서드 + 자기증폭 + 클램프

```csharp
/// <summary>
/// 진영 하나의 전체 사기(기획 §7). 트리거 메서드가 배율까지 반영한 "실제 적용된 델타"를 반환한다 —
/// 호출부(BattleCharacterUnit)가 이 값 그대로 사기 파동(§7.3)을 생성하는 데 쓴다.
/// </summary>
public class PartyMorale
{
    public float CurrentValue { get; private set; } = MoraleTuning.Initial;
    public MoraleTier CurrentTier => CurrentValue.ToMoraleTier();

    public float NotifyDeath() => ApplyDelta(-MoraleTuning.DeathLoss);
    public float NotifyFled() => ApplyDelta(-MoraleTuning.FleeLoss);
    public float NotifyEnemyKilled() => ApplyDelta(MoraleTuning.EnemyKilledGain);

    // 이벤트 적용 "직전" 티어를 기준으로 배율을 매긴다(기획 §7.2) — CurrentTier를 먼저 읽고 나서
    // CurrentValue를 갱신하는 순서가 중요하다.
    private float ApplyDelta(float rawDelta)
    {
        var amplified = CurrentTier == MoraleTier.Low ? rawDelta * MoraleTuning.LowTierAmplifier : rawDelta;
        CurrentValue = Mathf.Clamp(CurrentValue + amplified, 0f, 100f);
        return amplified;
    }
}
```

**설계 선택**: 반환값은 클램프 **이전**의 논리적 델타다 — `CurrentValue`가 이미 3인데 −15가 들어오면 실제 `CurrentValue`는 0에서 멈추지만 반환값은 −15 그대로다. 파동이 나르는 값과 유닛 개인 목표치의 클램프는 파동 수신 시점(§9.3)에서 별도로 처리하므로(기획 §7 "개인 목표치도 0~100 클램프"), `PartyMorale`이 델타를 미리 잘라낼 이유가 없다 — 클램프 책임을 한 곳에 섞지 않는다(SRP).

## 6. 사기 파동 — `MoraleWave` / `MoraleWaveCoordinator`

```csharp
// 파동 1개의 상태 — 순수 데이터, 변경(팽창)은 코디네이터가 담당한다(SRP).
public readonly struct MoraleWave
{
    public Vector2 Center { get; }
    public float Delta { get; }     // §7.1/§7.2 최종 델타(배율 반영 후)
    public float Speed { get; }     // §7.3 공식으로 생성 시점에 1회 계산해 고정
    public float Radius { get; }

    public MoraleWave(Vector2 center, float delta, float radius = 0f)
    {
        Center = center;
        Delta = delta;
        Speed = Mathf.Min(MoraleTuning.WaveSpeedCap, MoraleTuning.WaveSpeedPerDeltaUnit * Mathf.Abs(delta) / 10f);
        Radius = radius;
    }

    public MoraleWave WithExpandedRadius(float deltaTime) => new(Center, Delta, Radius + Speed * deltaTime);
}
```

```csharp
/// <summary>
/// 진영 하나의 사기 파동 전체를 관리한다(§7.3) — PartyMorale과 같은 자리, 진영별로 하나씩 만들어진다.
/// 매 틱 각 파동을 팽창시키고, "이전 반지름~이번 반지름" 사이(=테두리가 스쳐 지나간 순간)에 들어온
/// 같은 진영 유닛에게 델타를 전달한 뒤, 전장 반지름을 넘어선 파동은 제거한다.
/// </summary>
public class MoraleWaveCoordinator
{
    private readonly List<MoraleWave> waves = new();
    private readonly float fieldRadius;

    public MoraleWaveCoordinator(float fieldRadius) => this.fieldRadius = fieldRadius;

    public void SpawnWave(Vector2 center, float delta) => waves.Add(new MoraleWave(center, delta));

    public void Update(float deltaTime, IReadOnlyList<IBattleCombatant> units)
    {
        for (var i = waves.Count - 1; i >= 0; i--)
        {
            var previousRadius = waves[i].Radius;
            var expanded = waves[i].WithExpandedRadius(deltaTime);

            foreach (var unit in units)
            {
                if (!unit.IsAlive) continue;
                var distance = (unit.Position - expanded.Center).magnitude;
                if (distance > previousRadius && distance <= expanded.Radius)
                {
                    unit.ReceiveMoraleWave(expanded.Delta);
                }
            }

            if (expanded.Radius >= fieldRadius) waves.RemoveAt(i);
            else waves[i] = expanded;
        }
    }
}
```

- **`fieldRadius`를 생성자에서 고정으로 받는 이유**: `BattleFieldLayout.ComputeFieldRadius(columnCount)`가 전투 시작 시 1회만 계산되는 값이라(기획 §2-1), 매 틱 다시 계산할 필요가 없다 — `BattleSimulationLoop.FieldRadius`와 같은 출처.
- **진영별로 코디네이터를 따로 두는 이유**: "상대 진영에는 영향 없음"(§7.3)을 매 틱 필터링 조건문 없이, 애초에 "그 진영 유닛 목록만 넘긴다"는 구조 자체로 보장한다 — `allyWaveCoordinator.Update(dt, allies)` / `enemyWaveCoordinator.Update(dt, enemies)`로 완전히 분리(§10).
- **화면 비표시**: 기획 §7.3에서 이미 확정된 대로, 이 클래스는 순수 판정용이며 어떤 `MonoBehaviour`/렌더링 컴포넌트와도 연결되지 않는다.

## 9. `BattleCharacterUnit` 변경

### 9.1 필드/프로퍼티

```csharp
private readonly PartyMorale partyMorale;
private readonly MoraleWaveCoordinator waveCoordinator;      // 신규 — partyMorale과 항상 짝을 이뤄 주입
private float unitMorale = MoraleTuning.Initial;
private float personalTargetMorale = MoraleTuning.Initial;   // 신규 — §7.4 "개인 목표치"
private Vector2 fleeDecisionPosition;                         // 신규 — §7.6 도주 "결정" 시점 위치 스냅샷

public float Defense => stats.Defense * DefenseMoraleMultiplier;
private float EffectiveMoveSpeed => stats.MoveSpeed * MoveSpeedMoraleMultiplier;

private MoraleTier UnitTier => unitMorale.ToMoraleTier();
private float DefenseMoraleMultiplier => UnitTier == MoraleTier.High ? MoraleTuning.HighTierDefenseMultiplier : 1f;
private float MoveSpeedMoraleMultiplier => UnitTier == MoraleTier.High ? MoraleTuning.HighTierMoveSpeedMultiplier : 1f;
private float EffectiveSyncRate => stats.MoraleSyncRate * (UnitTier == MoraleTier.Low ? MoraleTuning.LowTierSyncMultiplier : 1f);
```

`MoveToward`/`TickFlee`/`FleeVelocity`/`ApplySeparation` 등 기존에 `stats.MoveSpeed`를 직접 읽던 자리는 전부 `EffectiveMoveSpeed`로 교체한다 — 이동속도 버프(§7.5)가 이동 로직 전체에 일관되게 적용되도록 계산 지점을 하나로 모은다(DRY).

### 9.2 동기화 (기존 `TickMorale` 대체)

```csharp
private void TickMorale(float deltaTime)
{
    unitMorale = Mathf.Clamp(
        Mathf.MoveTowards(unitMorale, personalTargetMorale, EffectiveSyncRate * deltaTime), 0f, 100f);
    // 기존처럼 "0 이하 = 즉시 도주"가 아니다 — §7.6 확률 체크는 아래 세 지점(파동 수신/타겟 결정/피격)
    // 에서만 굴린다. 여기서는 붕괴 판정을 하지 않는다.
}
```

### 9.3 파동 수신 (신규, `IBattleCombatant.ReceiveMoraleWave` 구현)

```csharp
public void ReceiveMoraleWave(float delta)
{
    personalTargetMorale = Mathf.Clamp(personalTargetMorale + delta, 0f, 100f);
    if (delta < 0f) TryRollFleeCheck();   // §7.6 체크 이벤트 1 — 하락 파동만
}
```

### 9.4 처치 통지 (신규, `IBattleCombatant.NotifyKilledEnemy` 구현)

```csharp

{
```

### 9.5 확률적 붕괴 체크 (신규, 기존 고정 임계치 트리거 대체)

```csharp
// §7.6 체크 이벤트 3곳(파동 수신 §9.3, 타겟 결정 §9.7, 피격 §9.6)에서 공통으로 호출한다.
private void TryRollFleeCheck()
{
    if (isFleeing || unitMorale > MoraleTuning.FleeCandidateThreshold) return;

    var x = (MoraleTuning.FleeCandidateThreshold - unitMorale) / MoraleTuning.FleeCandidateThreshold;
    var probability = MoraleTuning.FleeProbabilityFloor
        + (100f - MoraleTuning.FleeProbabilityFloor) * Mathf.Pow(x, MoraleTuning.FleeProbabilityExponent);

    if (UnityEngine.Random.value * 100f >= probability) return;

    isFleeing = true;
    fleeDirection = ComputeFleeDirection(currentTargets);   // 기존 §7.6 방향 로직 그대로
    fleeDecisionPosition = Position;                         // 이 순간 위치가 파동 중심(§9.8)
}
```

**설계 선택**: `currentTargets`는 이 메서드가 `Tick` 바깥(피격/파동 수신 시점)에서도 호출되기 때문에 필요하다 — `Tick` 시작 시점에 그 프레임의 `targets` 인자를 필드에 캐시해두고, 프레임 동안의 모든 이벤트 훅이 이 캐시를 참조한다. 매개변수로 매번 넘기면 `TakeDamage`/`ReceiveMoraleWave` 시그니처까지 오염된다.

### 9.6 피격 훅 (기존 `TakeDamage` 확장)

```csharp
public void TakeDamage(float amount, IBattleCombatant attacker)
{
    if (!IsAlive) return;
    currentHp = Mathf.Max(0f, currentHp - amount);
    OnDamaged?.Invoke(amount);
    // ...기존 재탐색 트리거(retargetRequested)/인식/자기보호 로직 그대로...

    if (currentHp <= 0f)
    {
        var delta = partyMorale.NotifyDeath();
        waveCoordinator.SpawnWave(Position, delta);   // §7.3 중심 좌표 = 사망한 캐릭터 위치
        attacker.NotifyKilledEnemy();                  // §9.4
        OnDied?.Invoke();
    }
    else
    {
        TryRollFleeCheck();   // §7.6 체크 이벤트 3 — 피격 시
    }
}
```

### 9.7 타겟 결정 훅 (기존 `TickEngageWithoutTactics`/`TickEngageWithTactics` 확장)

두 메서드 모두 `target = spatialQuery.FindNearest(...)` / `target = tacticsBehaviors.TargetSelector.Select(...)` 직후에 `TryRollFleeCheck()` 한 줄만 추가한다(§7.6 체크 이벤트 2) — 재탐색이 트리거되지 않는 한(스티키 타겟팅) 매 프레임 호출되지 않으므로, "고정 주기 체크 금지"(사용자 확정) 요건을 그대로 만족한다.

### 9.8 도주 완료 훅 (기존 `TickFlee` 확장)

```csharp
private void TickFlee(float deltaTime)
{
    var step = EffectiveMoveSpeed * deltaTime;   // §9.1 버프 반영
    Position += fleeDirection * step;
    fledDistance += step;

    if (fledDistance >= fleeTravelDistance)
    {
        hasLeftBattle = true;
        var delta = partyMorale.NotifyFled();
        waveCoordinator.SpawnWave(fleeDecisionPosition, delta);   // 완료 시점이 아니라 결정 시점 위치(§7.6)
        OnFled?.Invoke();
    }
}
```

## 10. `BattleSimulationLoop` / `LiveBattleSimulationRule` 통합

- `BattleSimulationLoop` 생성자에 `MoraleWaveCoordinator allyWaveCoordinator, MoraleWaveCoordinator enemyWaveCoordinator` 추가 — `frontlineCoordinator`/`rangedSurroundCoordinator`와 같은 자리.

  ```csharp
  allyWaveCoordinator.Update(deltaTime, allies);
  enemyWaveCoordinator.Update(deltaTime, enemies);
  ```

## 12. 최적화 요약

- `MoraleWaveCoordinator.Update`는 파동 수 × 유닛 수 O(w·n) — 현재 규모(진영당 유닛 20명 이하, 동시 파동은 대개 1~3개)에서는 무시할 만하다. 파동이 비정상적으로 누적되는 극단적 상황을 대비해 별도 공간 분할을 도입하지 않는다(YAGNI, `IUnitSpatialQuery`의 확장 여지와는 별개 문제).
- `TryRollFleeCheck`는 이미 존재하는 이벤트 훅(파동 수신/피격/타겟 결정)에만 붙어 별도의 폴링이 없다 — "고정 주기 체크 금지"(기획 §7.6, 사용자 확정)와 최적화 요건이 동시에 만족된다.
- 진영별 코디네이터 분리(§6)로 "상대 진영 필터링" 조건문이 매 틱 추가되지 않는다.

## 13. 남은 이슈 (구현 단계에서 결정, 기획에 없는 세부)

1. `MoraleWave`를 불변 구조체(위 스케치)로 할지 가변 클래스로 할지 — 구조체+`waves[i] = expanded` 교체 방식은 `List` 인덱싱이 다소 번잡해질 수 있어 구현 시 재검토 여지.
2. `fleeDecisionPosition` 필드는 기존 `debugMoveTarget`과 달리 디버그 전용이 아니라 §7.3 파동 생성에 실제로 쓰이는 로직용 값이다 — 혼동 방지를 위해 네이밍/주석에서 명확히 구분할 것.
3. 여러 파동이 한 프레임에 같은 유닛을 동시에 스치는 경우의 처리 순서는 `List<MoraleWave>` 순회 순서에 의존한다 — 델타가 가산이라 최종 값에는 순서가 영향을 주지 않는다(기획 §7.3에서 이미 확정).
4. `IBattleCombatant.NotifyKilledEnemy()`가 파라미터 없이 자기 `Position`만 쓰는 설계라, 향후 "협공 처치"(막타가 아닌 딜량 배분) 같은 확장이 생기면 이 메서드부터 재검토 대상이 된다 — 지금은 기획 §7.1 "처치한(공격자) 쪽"이 단일 주체라는 전제로 충분하다.
5. §7.5 고사기 버프(`DefenseMoraleMultiplier`/`MoveSpeedMoraleMultiplier`)가 `Attack`/`Range`/`AttackInterval`에는 적용되지 않는다 — 기획이 명시한 "이동속도·방어력"만 반영했다. 다른 스탯까지 확장할지는 범위 밖(기획 §7.5 확정 사항 그대로).
