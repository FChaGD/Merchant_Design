# 전사 스프라이트 애니메이션 시험 적용 아키텍처

작성일: 2026-11-26
상태: 확정(2026-11-26 승인), 제작 완료(2026-11-26, EditMode 1075/1075, CLI 실행 확인) - 사용자 인게임 판단 대기
근거: [기획 122 유닛·전투 표현 에셋](../기획/시스템/122-2026-11-25-유닛_전투_표현_에셋_기획.md) §5·§7
범위: 짧은 설계(시험 적용)

---

## 1. 목적

Ludo로 생성한 검사 정면 애니메이션(대기·이동)을 **배틀 테스트 씬의 아군 전사**에 붙여, 미리보기 창이 아닌 실제 전투 화면에서 카툰 타이밍을 판단한다.

## 2. 범위

| 구분 | 내용 |
|---|---|
| 목표 | 배틀 테스트 씬 아군 전사: 대기 = C(Hydra) 카툰 v2, 이동 = E(Hydra 들썩 걷기) 카툰 v4 |
| 비목표 | Field 실전투(직업 전달 경로 없음), 궁수·방패병·적, 뒷모습, 공격·사망 등 다른 동작, 진영 HUD |
| 실패 조건 | 그림을 넣은 뒤 체력 게이지 위치·크기가 어긋남 / 이동·대기가 매 프레임 깜빡이며 바뀜 / 풀 재사용 시 이전 유닛 그림이 남음 / 그림 없는 유닛(Field 전체, 다른 직업)의 표시가 바뀜 |

## 3. 결정 사항 (2026-11-26 사용자)

| 항목 | 결정 |
|---|---|
| 방향 | 앞모습을 모든 방향에 사용(하·좌하·우하 공유는 기획 122 §3, 위쪽 3방향은 뒷모습 생성 전까지 앞모습 대체). 좌우 반전 없음 |
| 표시 크기 | 그림만 1m(기본 줌 약 55px). 전투 판정 크기는 그대로 |
| 진영 색 | 그림에 곱하지 않음(기획 122 5-1) |
| 피격 연출 | 흰색 곱하기 대신 그림 위에 흰색을 잠깐 덮는 방식 |
| 방식 | A안(아래 §4) + 확장 대비 데이터 구조 |

## 4. 접근안

| 안 | 내용 | 판단 |
|---|---|---|
| **A. 프레임 묶음 + 타이밍 데이터 + 코드 재생** | 가져오기 메뉴가 `ArtSource`의 타이밍 파일을 읽어, 쓰는 프레임만 프로젝트로 복사하고 데이터 에셋을 만든다. 표시 오브젝트가 위치 변화로 상태를 판정해 재생 | **채택**. 타이밍 출처가 하나(미리보기 창과 공유). 풀 재사용 초기화가 단순 |
| B. Animator + 생성 클립 | 클립·상태 그래프 생성, 유닛은 "이동 중" 값만 전달 | 보류. 동작 종류가 늘면 유리하지만, 생성 클립을 직접 고치면 출처가 둘로 갈라짐. A 데이터로 나중에 클립 생성 가능 |
| C. 시트 + 플립북 셰이더 | 한 장 시트를 셰이더로 넘김 | 제외. 규모 대비 과함 |

확장 대비 조건(사용자 승인): 클립에 반복/1회 재생 구분과 이벤트 프레임 칸을 두고, 동작은 고정 필드가 아닌 이름으로 찾는 목록으로 둔다.

## 5. 구조

### 5.1 데이터

| 타입 | 위치·역할 |
|---|---|
| `UnitSpriteClip` (직렬화 클래스) | 동작 이름(`Idle`·`Walk`), 프레임 `Sprite[]`, 프레임별 표시 시간 `float[]`(초), 반복 여부, 이벤트 프레임 목록(이번에는 비움) |
| `UnitSpriteAnimationSet` (ScriptableObject) | 한 캐릭터·한 모습(앞/뒤)의 클립 목록. 이름으로 클립 조회 |
| `UnitSpriteAnimationLibrary` (ScriptableObject) | 직업 문자열(`"Warrior"`) → 세트. 없는 직업은 null |

- 에셋 위치: 프레임 PNG `Assets/Art/Units/Warrior/Front/<동작>/`, 데이터 `Assets/Art/Units/`(Resources 밖 - 직접 참조로만 쓰므로).
- 같은 프레임을 여러 번 쓰는 타이밍(v2의 13→11→13)은 `Sprite[]`에 같은 스프라이트를 반복해 담는다.

### 5.2 가져오기 (에디터)

- 메뉴 `Tools/Game/Art/Import Unit Animations`. 설정 파일 `ArtSource/UnitAnim/import.txt` 한 줄 = 한 클립:
  `Warrior Front Idle: 2026-11-26/idle_hydra @ cartoon_timing_v2 loop`
- 하는 일: 타이밍에 쓰인 프레임만 복사 → 임포트 설정(Sprite, 필터 Bilinear, 압축 없음) → 데이터 에셋 get-or-create로 갱신. 다시 실행해도 안전, 설정에서 빠진 프레임 파일은 삭제.
- 정규화(클립마다): 첫 프레임의 **무기 제외 몸("머리 위~발")** 기준. **PPU = 몸 높이**(몸 키 1유닛), **피벗 = 가로 머리 폭 중심·세로 몸 중간**. 발 = 캐릭터 폭 35~75% 세로 띠의 최저점(2026-11-26 개정 - 처음에는 전체 그림 영역 기준이었으나 칼끝이 발 아래로 내려온 검사 대기만 약 8% 작게 나와 변경). 같은 클립의 프레임은 Ludo 출력 크기가 같아 같은 값을 쓴다. 대기와 이동은 Ludo 출력 크기가 달라도 첫 프레임(서 있는 자세) 기준으로 맞춰 전환할 때 튀지 않는다.
  - 피벗을 발이 아닌 중심으로 두는 이유: 유닛 위치는 지금 도형의 중심이고, 판정·투사체·게이지가 이를 기준으로 한다.

### 5.3 전투 유닛에 세트 전달

- `BattleCharacterUnit` 생성자에 선택 인자 `UnitSpriteAnimationSet animationSet`(기본 null) - 기존 `Icon`과 같은 "표시 전용 힌트".
- `IBattleCombatant`에 `AnimationSet` 읽기 속성 추가. 테스트 가짜 2곳(`BattleCargoLedgerTests`, `BattleUnitViewLifecycleTests`)은 null 반환.
- `BattleTestSimulationRule`: 직렬화 필드 `UnitSpriteAnimationLibrary` 추가 → `BattleTestAllySide` 생성자로 전달(null 허용) → 미리보기·전투 유닛 생성 시 `library?.Find(kind.ToMercenaryClass())`.
- `BattleTestSceneInstaller`가 라이브러리 에셋을 이 필드에 연결.
- Field(`LiveBattleSimulationRule`)는 손대지 않는다 - 세트가 null이라 기존 표시 그대로.

### 5.4 표시

- 표시 원본(`EditorBattleWorldBuilder`의 `BattleCharacterUnitView` 프리팹)에 자식 `ArtBody`(SpriteRenderer, 흰색 덮기 재질) 추가. 이 프리팹은 Field와 공유하지만, 세트가 없으면 `ArtBody`는 꺼진 채로 둔다. 프리팹 갱신 판정에 `ArtBody` 보유 여부를 더해 옛 프리팹을 재생성.
- `BattleCharacterUnitView.Bind`:
  - 세트 있음: 루트 렌더러 끔, `ArtBody` 켬, 색 흰색(진영 색 없음). `ArtBody` 로컬 크기 = 1m ÷ 루트 크기(루트는 기존대로 0.6m × 체력 비율이라 게이지가 그대로 유지됨 - 그림 크기만 보정). 전사 체력 100 → 비율 1.0.
  - 세트 없음: 지금과 동일, `ArtBody` 끔.
  - 게이지: 그림이 있을 때 그림 위 끝 위로 올린다(게이지 뷰에 세로 위치 지정 추가). Unbind 때 기본값으로 복귀.
- 정렬 순서·사망 틴트·페이드·피격은 "지금 쓰는 렌더러"(루트 또는 `ArtBody`)에 적용.
- 재생: 순수 클래스 `SpriteClipPlayer`(시간 누적 → 현재 프레임, 반복/1회). 기존 `Update`에서 진행 - 새 `Update` 추가 없음.
- 이동/대기 판정: 순수 클래스 `MovementStateTracker`. 위치 변화 속도 > 0.05m/s면 이동. 이동→대기는 0.15초 연속 정지일 때만(깜빡임 방지). 상태가 바뀌면 해당 클립 처음부터.
- 피격: 셰이더 `Game/SpriteFlash`(Built-in, 기본 스프라이트 + `_Flash` 0~1로 흰색 보간, 정점 색 곱하기 유지 - 사망 틴트·페이드가 계속 동작). `MaterialPropertyBlock`으로 0.1초간 1. 사망 중에는 덮지 않음(기존 규칙과 같음).
- Unbind: 재생·판정 상태 초기화, `_Flash` 0, `ArtBody` 끔.

## 7. 영향 범위

- 신규: 데이터 3종, 재생·판정 클래스 2종, 셰이더 1개+재질, 가져오기 에디터 1개, `import.txt`, `Assets/Art/Units/` 에셋.
- 수정: `BattleCharacterUnit`·`IBattleCombatant`(+가짜 2곳), `BattleTestAllySide`, `BattleTestSimulationRule`, `BattleTestSceneInstaller`, `EditorBattleWorldBuilder`(프리팹), `BattleCharacterUnitView`, `BattleHealthGaugeView`(세로 위치).
- Field 실전투 표시는 바뀌지 않아야 한다(세트 null 경로). 단, 공유 프리팹 재생성으로 Field 씬도 Build Field Scene 재실행 필요 여부를 제작 시 확인.

## 8. 남은 사항 (제작자 재량 / 이후 결정)

- 제작자 재량: 이동 판정 임계값·지연 시간 미세 조정, `ArtBody` 정렬 순서 계산 방식.
- 이후 결정: 진영 HUD, 뒷모습 생성·방향 전환, Field 적용(직업 전달), 다른 직업·적, 공격·피격·사망 동작.

## 9. 제작 결과 (2026-11-26)

- 가져오기: Idle 8칸(고유 프레임 6장), Walk 4칸(4장). PPU Idle 393·Walk 344, 피벗 그림 중심.
- 배틀 테스트 씬 Build·저장. 공유 프리팹은 같은 경로에 재생성되어 GUID 유지 - Field·Bootstrap 참조는 그대로(재빌드 불필요).
- CLI Play 확인: 전사만 그림(높이 1m), 궁수·적은 기존 도형. 게이지는 그림 위 0.57m. 적 접근 시 이동(E v4 정점 프레임) → 정지 0.15초 후 대기(C v2) 전환 확인. Y 정렬 정상.
