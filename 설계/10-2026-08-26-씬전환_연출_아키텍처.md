## 1. 개요

[[10-2026-08-26-씬전환_연출_기획]]의 흐름(현재 씬 콘텐츠 슬라이드 아웃 + 커튼 동행 → 씬 전환 → 커튼 페이드 아웃)을 구현한다.

핵심 제약은 두 가지다.

1. **재사용 대상은 "타이밍을 구동하는 로직"이지 "그 결과로 무엇을 움직이는가"가 아니다.** `FieldCameraController.SlideRoutine`은 같은 씬에 이미 공존하는 두 `RectTransform`(나가는 뷰·들어오는 뷰)을 전제로 짜여 있다. Hub↔Field는 서로 다른 씬이라 슬라이드 시점엔 "들어오는 콘텐츠"가 아직 존재하지 않는다 — 그래서 이번 전환은 **나가는 콘텐츠 1개 + 커튼**만 움직인다(§3). 이 차이 때문에 `SlideRoutine` 함수 전체가 아니라, 그 안의 "지속시간 동안 이징 곡선을 따라 매 프레임 진행률을 흘려보내는" 부분만 공용 유틸리티로 뽑아 두 곳(기존 Field 내부 전환, 신규 씬 전환)이 같이 쓴다(§2 `SlideTransitionTimeline`).
2. **Hub는 지금 슬라이드 가능한 단일 콘텐츠 루트가 없다.** `Background` + 버튼 2개가 낱개로 존재한다(`HubUIElementIds`). 이번 설계에서 이를 감싸는 `ContentRoot`를 새로 만든다(§6).

## 3. 공용 타이밍 유틸리티 — `SlideTransitionTimeline`

`FieldCameraController.SlideRoutine`에서 "무엇을 움직이는가"와 "언제·얼마나 움직이는가"를 분리한다. 후자만 공용화한다.

```csharp
internal static class SlideTransitionTimeline
{
    public const float DurationSeconds = 0.9f; // 기존 FieldCameraController 값 그대로 재사용

    public static float EaseInCubic(float t) => t * t * t;

    // runner: 코루틴을 실행할 MonoBehaviour. onStep(t): 매 프레임 이징된 진행률(0~1)을 받아
    // 호출부가 원하는 만큼의 RectTransform 위치를 계산해 반영한다 - "몇 개를 움직이는지"는
    // 이 유틸리티가 몰라도 된다(Field 내부 전환은 2개+커튼, 씬 전환은 1개+커튼).
    public static void Run(MonoBehaviour runner, Action<float> onStep, Action onComplete)
        => runner.StartCoroutine(RunRoutine(onStep, onComplete));

    private static IEnumerator RunRoutine(Action<float> onStep, Action onComplete)
    {
        var elapsed = 0f;
        while (elapsed < DurationSeconds)
        {
            elapsed += Time.deltaTime;
            onStep(EaseInCubic(Mathf.Clamp01(elapsed / DurationSeconds)));
            yield return null;
        }
        onStep(1f);
        onComplete?.Invoke();
    }
}
```

`FieldCameraController.SlideRoutine`은 이제 `onStep` 콜백 안에서 기존과 동일한 위치 계산식(`exitingView`/`enteringView`/`transitionCurtainRoot`)만 수행한다 — 곡선·지속시간·코루틴 구동 방식은 100% 동일하게 유지되므로 기존 전투 전환 체감은 변하지 않는다.

## 4. 방향/씬 판정의 의도적 단순화

콘텐츠 씬이 Hub/Field 단 둘뿐이라는 현재 범위를 그대로 이용한다 — "현재 씬"을 별도로 추적하지 않고, `targetSceneId`의 반대를 현재 씬으로 취급한다.

```csharp
private static ContentSceneId InferCurrentScene(ContentSceneId target)
    => target == ContentSceneId.Field ? ContentSceneId.Hub : ContentSceneId.Field;

private static bool ExitsToLeft(ContentSceneId target) => target == ContentSceneId.Field; // Hub→Field
```

콘텐츠 씬이 3개 이상으로 늘어나면 이 추론은 깨진다 — 그때는 `SceneLoader`가 현재 씬 id를 명시적으로 노출하도록 바꿔야 한다(§8 남은 이슈). 지금은 2개뿐이므로 `FieldCameraController`의 앵커 2개 제한과 같은 이유로 미리 일반화하지 않는다([[04-2026-08-25-Field씬_아키텍처]] §11 "카메라 전환 API의 의도적 범위 제한"과 동일 판단).

## 5. `SceneTransitionCurtainView` — Bootstrap 상주 커튼

기존 `FieldTransitionCurtainView`를 재사용하지 못하는 이유는 씬 스코프이기 때문이다(Field 씬이 언로드되면 같이 파괴됨). 이번 커튼은 씬 전환 자체를 가려야 하므로 Bootstrap의 `Managers` 루트 하위에 별도로 둔다(`BootstrapRoot.DontDestroyOnLoad` 적용 범위 안).

```csharp
public class SceneTransitionCurtainView : MonoBehaviour
{
    [SerializeField] private CanvasGroup canvasGroup;
    private RectTransform rectTransform;

    public RectTransform RectTransform => rectTransform;

    public void Show()
    {
        gameObject.SetActive(true);
        canvasGroup.alpha = 1f;
    }

    public void SetAnchoredPosition(Vector2 position) => rectTransform.anchoredPosition = position;

    public void FadeOut(MonoBehaviour runner, float duration, Action onComplete)
        => runner.StartCoroutine(FadeRoutine(duration, onComplete));

    private IEnumerator FadeRoutine(float duration, Action onComplete)
    {
        var elapsed = 0f;
        while (elapsed < duration)
        {
            elapsed += Time.deltaTime;
            canvasGroup.alpha = 1f - Mathf.Clamp01(elapsed / duration);
            yield return null;
        }
        canvasGroup.alpha = 0f;
        gameObject.SetActive(false);
        onComplete?.Invoke();
    }
}
```

- 전용 `Canvas`(Screen Space - Overlay, `sortingOrder`를 Hub/Field 콘텐츠 씬 캔버스보다 높게)에 배치해, 로드된 콘텐츠 씬이 무엇이든 항상 위에 그려지게 한다.
- `CanvasScaler` 설정(Scale With Screen Size, 참조 해상도)은 콘텐츠 씬 캔버스와 동일하게 맞춰야 한다 — 그래야 `Width()` 계산과 슬라이드 거리가 화면상 정확히 일치한다. 제작 단계에서 반드시 확인할 항목으로 남긴다(§8).
- 슬라이드 중에는 `Image.raycastTarget = true`로 두어 전환 중 입력을 막는다(전환 도중 이전 씬 EventSystem이 파괴/미생성 상태를 거치므로 큰 위험은 아니지만, 커튼이 화면을 덮은 동안 클릭이 새지 않도록 방어).

## 6. `SceneTransitionEffectController`

Bootstrap 상주 매니저. `IManagedComponent`로 등록되며 두 개의 좁은 인터페이스를 구현한다(ISP — `IUIManager`/`IPanelRegistrar` 분리와 동일한 판단).

```csharp
public interface ISceneTransitionEffectPlayer
{
    void PlayTransition(ContentSceneId targetSceneId);
}

public interface ISceneTransitionContentRootRegistry
{
    void RegisterContentRoot(ContentSceneId sceneId, RectTransform contentRoot);
}
```

```csharp
public class SceneTransitionEffectController : MonoBehaviour,
    ISceneTransitionEffectPlayer, ISceneTransitionContentRootRegistry, IManagedComponent
{
    [SerializeField] private SceneTransitionCurtainView curtain;
    private const float FadeOutDurationSeconds = 0.4f; // 테스트 값 - 실플레이 조정 대상

    private ISceneLoader sceneLoader;
    private readonly Dictionary<ContentSceneId, RectTransform> contentRootsBySceneId = new();
    private bool isTransitioning;

    public void RegisterSelf(IDependencyRegistrar registrar)
    {
        registrar.Register<ISceneTransitionEffectPlayer>(this);
        registrar.Register<ISceneTransitionContentRootRegistry>(this);
    }

    public void ResolveDependencies(IDependencyRegistrar registrar)
    {
        sceneLoader = registrar.Resolve<ISceneLoader>();
        // UIManager가 먼저 구독해 Wire(...)를 끝낸 뒤에 커튼을 걷어야 한다 - managedComponents
        // 목록에서 이 컴포넌트를 UIManager보다 뒤에 둬 구독 순서를 보장한다(§7).
        sceneLoader.OnSceneLoaded += HandleSceneLoaded;
    }

    public void RegisterContentRoot(ContentSceneId sceneId, RectTransform contentRoot)
        => contentRootsBySceneId[sceneId] = contentRoot;

    public void PlayTransition(ContentSceneId targetSceneId)
    {
        if (isTransitioning)
        {
            return; // 연출 도중 중복 트리거 방지
        }

        var currentSceneId = InferCurrentScene(targetSceneId); // §4
        if (!contentRootsBySceneId.TryGetValue(currentSceneId, out var contentRoot) || contentRoot == null)
        {
            Debug.LogWarning($"'{currentSceneId}'의 콘텐츠 루트가 등록되어 있지 않아 연출 없이 즉시 전환한다.");
            sceneLoader.Transition(targetSceneId.ToString());
            return;
        }

        isTransitioning = true;
        var exitsToLeft = ExitsToLeft(targetSceneId);
        var width = contentRoot.rect.width;
        var exitEndX = exitsToLeft ? -width : width;
        var curtainStartX = -exitEndX; // 반대편에서 동행 - 기존 FieldCameraController와 동일한 관계

        curtain.Show();
        curtain.SetAnchoredPosition(new Vector2(curtainStartX, 0f));

        SlideTransitionTimeline.Run(this,
            onStep: t =>
            {
                contentRoot.anchoredPosition = new Vector2(exitEndX * t, 0f);
                curtain.SetAnchoredPosition(new Vector2(curtainStartX * (1f - t), 0f));
            },
            onComplete: () =>
            {
                contentRoot.gameObject.SetActive(false);
                sceneLoader.Transition(targetSceneId.ToString());
            });
    }

    private void HandleSceneLoaded(string sceneName)
    {
        if (!isTransitioning)
        {
            return; // 최초 진입 등 이 컨트롤러가 시작하지 않은 로드는 무시
        }

        isTransitioning = false;
        curtain.FadeOut(this, FadeOutDurationSeconds, onComplete: null);
    }
}
```

- `contentRoot.gameObject.SetActive(false)`는 기존 `FieldCameraController`의 `exitingView.gameObject.SetActive(false)`와 동일한 이유 — 슬라이드가 끝난 뒤에도 화면 밖에서 계속 레이아웃/렌더링 비용을 쓰지 않게 한다. 다음에 그 씬으로 돌아왔을 때는 `HubUIWiring`/`FieldUIWiring`이 씬 로드마다 다시 `RegisterHubUI`/`RegisterFieldUI`를 실행해 요소를 새로 찾으므로(씬 자체가 언로드→재로드되는 콘텐츠 씬이라 매번 새 오브젝트) `SetActive(false)`가 다음 진입을 막지 않는다.

## 8. 콘텐츠 루트 등록 — `HubUIWiring` / `FieldUIWiring`

```csharp
// HubUIWiring.Wire(...) 안, RegisterHubUI(...) 호출 직후
contentRootRegistry.RegisterContentRoot(ContentSceneId.Hub, hubUIController.ContentRoot);

// FieldUIWiring.Wire(...) 안, RegisterFieldUI(...) 호출 직후 — 기존 movementViewRoot를 그대로 재사용,
// Field 전용 새 요소는 만들지 않는다(§1-2).
contentRootRegistry.RegisterContentRoot(ContentSceneId.Field, fieldUIController.MovementViewRoot);
```

`IContentSceneUIWiring.Wire(...)`가 이미 `IPanelRegistrar` 등 협력 객체를 인자로 받는 구조이므로, `ISceneTransitionContentRootRegistry`도 같은 방식으로 `UIManager.HandleSceneLoaded` → `wiring.Wire(registrar, this, this, contentRootRegistry)`에 실어 넘긴다(또는 `registrar.Resolve<ISceneTransitionContentRootRegistry>()`로 Wiring이 직접 조회 - 기존 `gameManager`/`caravanRosterProvider` 등을 조회하는 방식과 동일하므로 이쪽이 기존 패턴과 더 일치한다).

Field는 `movementViewRoot`를 재사용하므로 `FieldUIElementIds`에 새 상수를 추가하지 않는다. Hub만 새 `ContentRoot` 요소가 필요하다(§9).

## 9. Hub 씬 구조 변경 — `HubUIInstaller`

Hub는 지금 `HubUIElementIds.Background`/`DepartureButton`/`FormationButton`이 낱개 형제로 존재한다. 이들을 감싸는 `ContentRoot`(화면 전체를 채우는 stretch 앵커 `RectTransform`)를 새로 만들고 그 아래로 재배치한다.

```
SceneUIRoot
 └─ ContentRoot          (신규, UIElementMarker: Hub.ContentRoot, stretch)
     ├─ Background
     ├─ DepartureButton
     └─ FormationButton
```

`HubUIInstaller.cs`(신규, `Tools/Game/Build Hub UI`)를 `EditorUIBuilder`(공용 유틸리티, 컨벤션 §씬 편집)로 작성한다 — get-or-create로 `ContentRoot`를 만들고, 기존 `Background`/버튼이 이미 다른 부모 아래 있으면 `SetParent`로 옮긴다(재실행 안전). `TripUIInstaller`/`FormationUIInstaller`와 동일한 패턴.

`HubUIElementIds`에 상수 추가:

```csharp
public const string ContentRoot = "Hub.ContentRoot";
```

## 10. 씬 배치

- `SceneTransitionEffectController`(로직) + `SceneTransitionCurtainView`(뷰) + 전용 Canvas: Bootstrap 씬 `Managers` 루트 하위(신규) — `ManagerHierarchyInstaller`가 get-or-create로 생성.
- `SceneTransitionEffectController`는 `SyncManagedComponents` 목록에서 **`uiManager` 뒤**에 배치해, `OnSceneLoaded` 구독 순서를 `UIManager.Wire(...)` → `SceneTransitionEffectController.HandleSceneLoaded`(커튼 페이드) 순으로 고정한다(§6).
- Hub `ContentRoot`: Hub 씬의 `SceneUIRoot` 하위(신규, `HubUIInstaller`).
- Field `MovementViewRoot`: 기존 그대로(신규 요소 없음).

## 12. 남은 이슈 / 후속 결정 사항

- **씬 3개 이상으로 확장 시**: §4의 "현재 씬 = target의 반대"라는 추론이 깨진다. 그때는 `ISceneLoader`가 현재 씬 id를 명시적으로 노출해야 한다.
- **CanvasScaler 정합성**: 커튼 Canvas와 Hub/Field 콘텐츠 씬 Canvas의 스케일러 설정이 다르면 슬라이드 거리·커튼 커버리지가 화면상 어긋난다 — 제작 단계에서 실제 값 확인 필요.
- **연출 중 입력 차단 범위**: 커튼의 `raycastTarget=true`가 슬라이드~페이드 구간 전체를 덮지만, 슬라이드 시작 직후~커튼이 완전히 덮이기 전 짧은 구간은 콘텐츠 루트가 아직 일부 보이는 상태로 클릭 가능하다 — 필요하면 `PlayTransition` 시작 시점에 트리거 버튼을 즉시 `interactable = false`로 두는 처리를 호출부(TripPanel 등)에 추가해야 할 수 있다(이번 설계 범위 밖, 실플레이 확인 후 필요 시 추가).
- **지속시간 수치**: 슬라이드 0.9초(재사용) + 페이드 0.4초(신규 제안값) 모두 실플레이 조정 대상 — [[10-2026-08-26-씬전환_연출_기획]] §7과 동일한 방침.
