# 입력 체계 제작 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 키보드 단축키(I/B/C/P, Q)와 포인터 누르기 전역 입력을 프로젝트 전용 입력 액션 자산 + InputManager 구독 창구로 옮긴다.

**Architecture:** InputManager는 하위 컴포넌트(`GameInputActionSource`, `TextInputFocusGuard`)와 순수 C# `InputActionDispatcher`를 연결만 한다. 소비자(인벤토리 키 바인더, 드래그 컨트롤러, 팝업 맨 위로)는 `IInputManager.Subscribe`로 구독하고, 동작 여부는 소비자가 UI 상태로 판단한다.

**Tech Stack:** Unity 6000.3.7f1, Input System 1.18.0(Input System 전용), UGUI, TMP, NUnit EditMode.

**Spec:** `Docs/설계/99-2026-10-20-입력_체계_아키텍처.md`

## Review Focus

1. **Play 재진입/씬 재로드 시 중복 구독** — 전역 액션 자산의 `performed`에 붙인 처리기가 Play 종료 후 남거나 Hub 재로드마다 키 구독이 누적되면 키 1회에 팝업이 두 번 토글(열렸다 닫힘)된다. → Task 2 `OnDestroy` 해제, Task 4 `Bind` 재호출 테스트.
2. **콜백 안에서 구독 해제** — 키 콜백이 팝업을 열고 그 과정에서 다른 구독이 해제되면 순회 중 컬렉션 변경 예외. → Task 1 테스트.
3. **모달·시설 화면 중 키 입력** — CanvasGroup `interactable=false` 부모 아래 버튼은 무시돼야 한다. → Task 4 `ShortcutKeyGate` 테스트 + Task 6 실측.
4. **드래그 중 Q 후 드롭/취소 뒤 Q** — 드래그가 끝난 뒤 Q가 회전을 계속 일으키면 안 된다(구독 핸들 해제). → Task 5 실측 항목.
5. **전역 액션 미등록 상태로 Play** — `InputSystem.actions`가 null이거나 다른 자산이면 경고 1회 후 무동작 핸들, 예외 없음. → Task 1 "없는 Id" 테스트 + Task 2 Source 구현 규칙.
