## 2. 데이터 — 적재 모양

### 2.1 값 타입 `InventoryShape` (신규, `Core/Inventory/`)

```csharp
public sealed class InventoryShape
{
    public int Width { get; }
    public int Height { get; }
    public int UsableCount { get; }
    public bool IsUsable(int x, int y);                              // 범위 밖이면 false
    public bool ContainsRect(GridPosition topLeft, int w, int h);    // 모든 칸이 적재 가능인지
    public static InventoryShape Rectangle(int width, int height);    // 나머지 인벤토리 3종·테스트용
    public static bool TryParse(string mask, out InventoryShape shape, out string error);
}
```

- 마스크 규칙(기획 63번 §3.1): `/`로 줄을 나누고 `1`은 적재 가능, `0`은 막힌 칸. 줄 길이가 모두 같아야 하고 적재 가능 칸이 1개 이상이어야 한다.
- 파서는 런타임 어셈블리에 둔다. 임포터(검증)와 카탈로그(변환)가 같은 규칙을 한 곳에서 쓰게 하기 위해서다.

### 2.2 테이블·임포터·카탈로그

- `Wagon.xlsx` 데이터 시트에 `CargoShape` 열을 추가한다. 전 행 값은 `11111/11111/11111/11111`. `Facility.xlsx`에는 추가하지 않는다.
- `CaravanAssetEntry.CargoShape`(string)를 추가한다. 시설 행은 빈 문자열.
- `CaravanAssetTableImporter`: 마차 시트에서만 `CargoShape`를 필수 열로 읽고 `InventoryShape.TryParse`로 검증한다. 실패하면 `FormatException`(시트·Id·오류 내용 포함). 시설 시트는 읽지 않는다. 호출부 두 곳(마차·시설)을 구분하는 인자를 하나 추가한다.
- `CaravanAssetProfile.CargoShape`(`InventoryShape`, 시설은 null)를 추가한다.

## 3. 자료구조 — 섹션(마차별 그리드)을 가진 `InventoryGrid`

### 3.1 방식 (§10-1 확정)

`InventoryGrid` 하나가 **여러 섹션**(섹션 = 모양 1개 + 점유 배열)과 공용 임시보관을 가진다. 섹션 Id는 마차 Id다.

- 재배치 원자 처리(`ApplyPlacements`)는 지금 알고리즘 그대로 쓴다. 점유 배열을 "섹션 → 배열"로 한 단계 나누기만 하면 된다. 마차 간 이동·교환도 기존처럼 한 번의 재배치 목록으로 처리되므로 지갑 연동 문제가 생기지 않는다.
- 나머지 인벤토리 3종(장비·소모품·개인 물품)은 섹션 1개짜리 그리드다. 기존 생성자(`width, height`)는 "직사각형 섹션 1개"로 남긴다.
- 대안: 마차마다 `InventoryGrid`를 따로 두고 상위 클래스가 조율하는 방식. 그리드 사이를 넘나드는 원자 처리(검사 → 확정 → 실패 시 복구)를 상위에 새로 짜야 해서 기존 알고리즘과 중복된다.

### 3.2 데이터 변경

| 타입 | 변경 |
|---|---|
| `InventoryItemInstance` | `SectionId`(string) 추가. 임시보관이면 의미 없음 |
| `ItemPlacement` | `SectionId`(string) 추가. `Position == null`(임시보관)이면 무시 |
| `InventoryGrid` | 섹션 목록(순서 유지) + 섹션별 점유. `AddSection(id, shape)`, 판정 `Fits`에 `shape.ContainsRect` 조건 추가. `TryPlace`·`TryGetAt`에 섹션 인자 |
| `Resize` | 섹션 1개짜리 그리드용으로만 유지. 마차 섹션은 추가만 있고 제거·크기 변경은 없다(마차 판매·손실은 기획 63번 범위 밖) |

### 3.3 섹션 정보 `InventorySection` (읽기 전용)

`Id`, `DisplayName`, `Shape`. 표시명은 저장소가 마차 이름으로 채운다(나머지 3종은 빈 문자열).

## 4. 조회·조작 계약

### 4.1 `IInventoryReader` 변경 (§10-2 확정)

| 현재 | 변경 |
|---|---|
| `int GridWidth`, `int GridHeight` | **삭제** → `IReadOnlyList<InventorySection> Sections` |
| `bool TryGetItemAt(GridPosition, out item)` | `bool TryGetItemAt(string sectionId, GridPosition, out item)` |
| `Items` | 그대로(모든 섹션의 아이템, 각 아이템이 `SectionId`를 가짐) |

- 크기 정보를 한 곳(섹션 모양)에만 두기 위해 가로·세로 속성은 없앤다. 나머지 3종 저장소(`PlaceholderFixedGridInventoryRepository`)와 테스트도 같이 바꾼다.
- `IInventoryRepository.TryPlaceItem`에 `string sectionId` 인자를 추가한다. 섹션이 1개인 저장소는 null이면 첫 섹션으로 처리한다.
- `IInventoryArrangement`는 그대로다. 재배치 목록에 섹션이 들어가므로 계약을 바꿀 필요가 없다.

### 4.2 계산 클래스

| 클래스 | 변경 |
|---|---|
| `InventoryDropResolver.ResolveGridDrop` | 섹션 인자 추가. 범위 검사를 `shape.ContainsRect`로 바꿈. 교환할 때 밀려난 아이템은 드래그한 아이템의 **원래 섹션·원래 칸**으로 간다(기획 39번 §4.1 규칙 그대로, 섹션만 추가) |
| `InventoryAutoSorter` | 가로·세로 인자를 `InventoryShape`로 교체. 계산용 점유 배열을 만들 때 **막힌 칸을 미리 점유로 표시**해서 채우기 알고리즘은 바꾸지 않는다 |
| 정렬 | 현재 섹션 아이템 + 임시보관 → 현재 섹션 안에서만(기획 63번 §3.5) |
| 닫기 비우기 | 새 메서드: 섹션 순서 목록(현재 섹션부터 순환)을 받아 임시보관 아이템을 큰 것부터 차례로 첫 번째로 들어가는 섹션에 넣는다. 하나라도 못 넣으면 실패(전부 아니면 아무것도) |
| 빈자리 찾기(구매) | 섹션 순서 목록을 받아 첫 번째로 들어가는 섹션·칸·회전을 돌려준다 |

## 5. 저장소 — 보유 마차와 섹션 동기화

- `PlaceholderTradeGoodsInventoryRepository`: 40칸 고정 상수와 가로 10칸 접기 규칙을 삭제한다. 보유 마차 목록 + 카탈로그 적재 모양으로 섹션을 만든다.
- 보유 순서가 필요하므로 `IOwnedCaravanAssetRoster`에 **보유 순서대로 된 Id 목록 조회**(종류별)를 추가한다. 지금 로스터는 보유 목록을 Dictionary로만 갖고 있어 순서가 없다. 획득 순서 리스트를 함께 둔다.
- 동기화 시점: `ResolveDependencies`에서 한 번 + `OnOwnedChanged`를 구독해 구매할 때마다. 섹션은 없는 마차만 **추가**한다. 로스터가 시작 마차를 넣은 뒤 `OnOwnedChanged`를 발생시키게 하면, DI 호출 순서(로스터와 저장소 중 누가 먼저 해결되는지)와 관계없이 동기화된다.
- 로스터나 카탈로그가 없으면 섹션 0개로 시작하고 경고를 남긴다. 팝업은 빈 화면이 되고 구매는 "공간 없음"이 된다.
- 검증용 초기 배치는 **첫 섹션이 생길 때 한 번** 그 섹션에 놓는다. 5 × 4에 맞게 좌표를 바꾼다: 1×1 (0,0)·(0,1), 2×1 (1,0), 1×2 (3,0), 2×2 (1,2).
- 골드 상자 규칙(배치 시 차감, 제거 시 환급, 재배치는 무관)은 그대로다.

## 6. 편집 본문 (UI 로직)

### 6.1 `InventoryArrangementController`

- **현재 섹션 Id**를 상태로 갖는다. 표시(Show) 시 기본값은 첫 섹션이고, 팝업을 닫았다 다시 열어도 마지막 섹션을 유지한다(같은 컨트롤러 인스턴스가 사는 동안).
- 섹션이 여러 개인 화면(§6.4 사양 플래그)에서는 스테퍼 ◀/▶ 클릭으로 이전/다음 섹션으로 순환하고, 상단 표기를 `{이름} ({순번}/{총수})`로 갱신한다.
- 그리드 뷰는 현재 섹션의 모양과 그 섹션 아이템만 그린다.
- 외부에서 보는 섹션을 바꾸는 진입점을 둔다(구매 후 다른 마차에 들어갔을 때 그 마차로 전환, 기획 63번 §3.5).
- 섹션 목록이 바뀌면(마차 구매) 저장소 변경 이벤트에서 표기 총수가 다시 그려진다.

### 6.2 드래그 중 스테퍼 호버 전환

| 요소 | 설계 |
|---|---|
| 호버 감지 | 스테퍼 버튼에 포인터 진입/이탈 중계 컴포넌트(`PointerHoverRelay` — 재화 HUD에서 쓰는 기존 컴포넌트 재사용 여부는 제작 시 확인). 드래그 중에도 EventSystem은 진입/이탈 이벤트를 보낸다 |
| 0.5초 반복 | 진입했을 때 드래그 중이면 코루틴(실시간 기준 0.5초 대기 → 섹션 전환 → 반복)을 시작하고, 이탈·드래그 종료 시 멈춘다. `Update` 폴링이 아니라 진입 이벤트가 시작점이다. 코루틴을 돌릴 MonoBehaviour는 편집 본문 루트의 중계 컴포넌트가 맡는다 |
| 전환 후 | 그리드 뷰를 새 섹션으로 다시 그리고, 고스트·잡은 칸·회전은 그대로 유지한다. 미리보기는 새 섹션 기준으로 판정한다 |
| 드래그 원본 뷰 | EventSystem이 드래그 대상으로 붙잡은 오브젝트가 비활성화되면 드래그 종료 이벤트가 오지 않을 수 있다. 그래서 원본 뷰는 **섹션을 전환해도 비활성화하거나 재사용하지 않고**, 다른 섹션을 보는 동안에는 투명하게만 처리한다. 그리드 뷰의 재사용 풀에서 드래그 중 원본을 제외한다 |
| 드롭 | 목표 = (현재 섹션, 칸). 판정·적용은 `ResolveGridDrop` → `TryApplyPlacements` 한 번. 실패하면 아무것도 적용하지 않으므로 아이템은 원래 섹션·원래 칸에 남는다(기획 63번 §3.4 원위치) |
| 스테퍼 위에서 놓기 | 그리드·임시보관 밖 드롭 = 원위치(기획 39번 §3.2) |

### 6.3 임시보관 가로 목록

- `InventoryStagingView`: 아이템을 왼쪽에서 오른쪽으로 나열하고, 내용 폭을 목록 길이에 맞춰 늘린다(가로 스크롤). 칸 크기는 `min(그리드 칸 크기, 영역 높이 / 아이템 높이)`.

### 6.4 사양 `InventoryPopupSpec`

- `HasSections`(마차 전환 UI 사용 여부) 플래그를 추가한다. 상단 물류품만 켠다. 조립(인스톨러)과 바인딩(런타임)이 같은 플래그를 읽는다(설계 42번 원칙).

## 8. 구매 — `ShopPurchaseService`

- 판정·구매에 **우선 섹션 Id**를 받는다. 섹션 순서 = 우선 섹션부터 순환하며 빈자리를 찾는다(§4.2).
- 구매 성공 시 배치된 아이템의 섹션 Id를 알려 주고, 구매 패널이 편집 본문에 그 섹션으로 전환하라고 전달한다.
- 버튼 활성 판정(공간 없음)도 모든 섹션 기준이 된다.

## 11. 테스트 (EditMode)

- `InventoryShape`: 마스크 파싱(정상, 줄 길이 불일치, 잘못된 문자, 적재 칸 0개), `ContainsRect`(막힌 칸 포함 시 false).
- `InventoryGrid`: 막힌 칸 배치 거부, 섹션 간 이동·교환 원자성(실패 시 양쪽 섹션 모두 원상태), 섹션 1개 그리드의 기존 동작 유지.
- `InventoryAutoSorter`: 막힌 칸을 피해 정렬, 현재 섹션 + 임시보관 정렬이 다른 섹션을 건드리지 않음, 여러 섹션 비우기(현재 섹션부터, 전부 아니면 아무것도), 우선 섹션부터 빈자리 찾기.
- `InventoryDropResolver`: 다른 섹션으로 드롭 시 이동/교환(밀려난 아이템이 원래 섹션으로), 막힌 칸 위 드롭 불가.
- 저장소: 보유 마차 수만큼 섹션 생성, 마차 구매 시 섹션 추가, 섹션 간 이동 시 골드 상자 지갑 변화 없음, 초기 배치가 첫 섹션에 들어감.

## 12. 제작 순서 (단일 단계, 그룹별 빌드 확인)

1. 데이터: `InventoryShape` + 테이블 열 + 임포터·카탈로그.
2. 자료구조·계산·계약: 섹션, 정렬·비우기·빈자리 찾기, 드롭 판정, 나머지 3종 저장소 적응, 테스트.
3. 저장소 동기화: 로스터 보유 순서, 물류품 저장소 섹션 동기화, 구매 서비스.
4. UI: 편집 본문 섹션 전환·스테퍼 호버·임시보관 가로 목록·조립 변경.
5. 사용자 검증: EditMode → Build Bootstrap Scene·Build Hub Scene → Ctrl+S → Play.

## 13. 제작 기록 (2026-09-30)

- 설계와 달라진 점
  - 보유 순서 조회는 `IOwnedCaravanAssetRoster`에 직접 넣지 않고 읽기 전용 상위 계약 `IOwnedCaravanAssetReader`(보유 순서 목록 + 변경 이벤트)로 뽑았다(ISP — 물류품 저장소에 구매 조작을 노출하지 않음). 로스터가 두 타입으로 등록한다.
  - `InventoryGrid.Resize`는 삭제했다. 호출처가 테스트뿐이었고 마차 증감은 섹션 추가로 대체됐다. Resize 테스트 2개는 모양·섹션 테스트로 교체했다.
  - 섹션 인자·재배치 섹션은 null이면 첫 섹션이다(섹션 1개짜리 인벤토리 호출부 유지). 상단 물류품 쪽 호출부는 항상 섹션을 명시한다.
  - 스테퍼 문자는 폰트 글리프 누락을 피해 `<` / `>`를 쓴다.
  - 드래그를 마친 뒤(성공·실패 무관) 편집 본문을 다시 그린다 — 다른 마차에서 놓기에 실패하면 저장소 변경 이벤트가 없어, 숨겨 둔 원본 뷰가 그대로 남기 때문이다.
- 테스트 추가: 마스크 파싱(정상·오류 4종), 막힌 칸 배치 거부, 섹션 간 이동·교환 원자성, 섹션 중복 거부, 다른 섹션 드롭(이동·교환 시 원래 섹션 복귀), 막힌 칸 드롭 불가, 막힌 칸 회피 정렬·다른 섹션 불변, 현재 섹션부터 비우기, 우선 섹션 빈자리 찾기, 보유 마차 수만큼 섹션·구매 시 추가, 마차 간 골드 상자 이동 시 지갑 불변, 구매 우선 섹션·넘침.
