# "상행 시작" 비활성 사유 툴팁 제작 계획

> **For agentic workers:** superpowers:executing-plans로 직접 실행(사용자 지시 2026-10-21 — 100~103 연속 자동 진행, 검진은 전체 제작 후).

**Goal:** "상행 시작" 버튼이 비활성일 때 호버·길게 누름으로 사유(B→C→A)를 툴팁으로 보이고, 기존 대열 끊어짐 레이블을 없앤다.

**Architecture:** UIManager 하위 컴포넌트 `UITooltipController`가 중계(호버·길게 누름)와 툴팁 요소를 등록받아 표시를 관리한다. 표시 판정은 순수 C# `TooltipVisibilityState`, 사유 계산은 순수 정적 `TripStartBlockReasons`. 활성 판정과 문구가 같은 계산에서 나온다.

**Tech Stack:** Unity 6000.3.7f1, UGUI, TMP, NUnit EditMode.

**Spec:** `Docs/설계/100-2026-10-20-상행_시작_비활성_사유_툴팁_아키텍처.md`

## Global Constraints

- 브랜치 `ui`. 커밋은 사용자 지시 시에만. `Docs/` 커밋 금지.
- 씬은 인스톨러 메뉴로만 변경(CLI 직접 실행). 공용 조립은 `EditorUIBuilder`.
- 문구(스펙 그대로): A "화면 전환 중입니다." / B "도착지를 지정하세요." / C "대열이 끊어져 있습니다. 정비창에서 마차를 이어 붙이세요." 순서 B→C→A, 줄바꿈 `\n`.
- 테스트: `bash ~/.claude/projects/C--Users-addmin-Desktop-Merchant/tools/ut.sh <클래스|ALL>`.

## Review Focus

1. Hub 언로드 뒤 도착지·편성 `Changed` 발화 → 파괴된 툴팁 요소 접근 없이 무시(컨트롤러 Unity null 검사).
2. Hub 재방문마다 툴팁 재등록 → 이전 핸들 Dispose로 중계 구독 누적 없음.
3. 툴팁이 떠 있는 중 모든 사유 해소 → 즉시 닫힘(`TooltipVisibilityState` 테스트).
4. 출발 확인 대화상자가 툴팁 위에 그려져야 한다(툴팁을 대화상자 앞 형제로).
5. 활성 버튼 호버 → 문구가 비어 툴팁 없음.
