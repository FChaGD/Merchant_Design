- 팝업 2종 추가: 설계 42번 확장 경로 그대로(스펙·저장소 계약·배선·인스톨러 한 줄씩).

## 4. Placeholder 저장소 중복 정리

### 4.1 현재 상태 (코드 확인)

| 저장소 | 상태 |
|---|---|
| 장비 / 전투 소모품 / 개인 물품 | 클래스 요약 주석·그리드 상수·등록 인터페이스만 다르고 나머지 코드가 **줄 단위로 동일**(비교 확인). 이번 작업으로 세 곳 모두에 초기 배치 + 정리 조작 위임이 들어가면 같은 코드가 3벌이 된다 |
| 교역품/전리품 | 마차 수로 그리드 크기 계산 + 골드 상자 지갑 연동이 있어 구조가 다름. 초기 배치 코드만 같다 |

설계 42번 §5.2는 "중복이 2벌이고 실제 시스템 대체 시 함께 제거되므로 공용화하지 않는다"고 판단했다. 이번에 3벌(초기 배치는 4벌)이 되므로 재검토한다.

### 4.2 추천: 고정 크기 3종 공용 기반 클래스 + 초기 배치 공용 함수

```csharp
// 고정 크기 1×1 인벤토리 3종(장비/전투 소모품/개인 물품)의 공통 구현. 하위 클래스는 크기·초기 배치·
// 등록 타입만 정한다. Placeholder 전용 - 실제 아이템 시스템이 생기면 하위 클래스와 함께 제거한다.
public abstract class PlaceholderFixedGridInventoryRepository : MonoBehaviour, IInventoryRepository, IItemCatalogReader, IInventoryArrangement, IManagedComponent
{
    [SerializeField] private ItemDefinitionTableAsset itemTable;   // 필드 이름 유지 - 기존 씬 직렬화 값·인스톨러 배선 그대로
    [SerializeField] private ItemStringTableAsset itemStrings;

    protected abstract int Width { get; }
    protected abstract int Height { get; }
    protected abstract IReadOnlyList<(string itemId, int x, int y)> InitialItems { get; }
    public abstract void RegisterSelf(IDependencyRegistrar registrar); // 카테고리 마커 타입으로 등록
    // 나머지(그리드·카탈로그·배치/제거·정리 조작·OnChanged)는 전부 기반 클래스
}

public sealed class PlaceholderConsumableInventoryRepository : PlaceholderFixedGridInventoryRepository, IConsumableInventoryRepository { ... }
```

```csharp
// 초기 배치 공용 함수 - 교역품 저장소도 같이 쓴다(4벌 → 1벌).
internal static class PlaceholderInventorySeeder
{
    public static void PlaceAll(InventoryGrid grid, IItemCatalogReader catalog, IEnumerable<(string itemId, int x, int y)> items, string ownerName);
}
```

- 근거: 3벌이 된 시점부터 한 곳을 고치고 나머지를 빠뜨리는 위험이 실제로 생긴다(이번 작업만 해도 같은 수정을 세 파일에 해야 함). 기반 클래스도 Placeholder라 실제 시스템 도입 시 함께 제거하면 되어 "제거 편의"는 유지된다.
- 직렬화 호환: `[SerializeField]` 필드를 기반 클래스로 옮겨도 필드 이름이 같으면 Unity는 기존 씬 값을 그대로 읽는다. 인스톨러(`ManagerHierarchyInstaller.WireItemCatalog`)는 필드 이름으로 찾으므로 수정 불필요.
- 테스트: 기존 장비 저장소 테스트가 기반 클래스 동작을 대표로 검증한다(현재 테스트 주석의 "3종 동작 동일" 전제가 코드로 보장됨).

### 4.3 대안: 공용화하지 않음
- 세 파일에 같은 초기 배치·정리 조작 코드를 각각 추가. 설계 42번 판단 유지. 변경 범위가 가장 작지만 중복 3벌.

## 5. 검증

- EditMode: 두 저장소 초기 배치(행 있을 때 4개), 기존 장비 저장소 테스트 전부 통과(기반 클래스 전환 회귀), 교역품 저장소 초기 배치 테스트 통과(공용 함수 전환 회귀).
- Unity 실전(Play만 — 테이블은 Play 진입 시 자동 임포트): 두 버튼으로 열기·닫기, 창 제목이 정식 명칭인지, 드래그 이동·교환·정렬·이름 표시·창 드래그, 네 팝업 동시 열기 시 계단식 배치, 기존 두 팝업 회귀. Bootstrap 씬의 저장소 컴포넌트가 기반 클래스 전환 후에도 테이블 참조를 유지하는지(인스펙터 확인).
