# 유닛 공격 애니메이션·타격 판정 아키텍처

작성일: 2026-11-27
상태: 확정(2026-11-27 승인), 제작 완료(2026-11-27, EditMode 1084/1084, CLI 가져오기·씬 빌드·Play 확인) - 사용자 인게임 판단 대기, 메인 미커밋
근거: [기획 122 유닛·전투 표현 에셋](../기획/시스템/122-2026-11-25-유닛_전투_표현_에셋_기획.md) §8, [설계 123 전사 스프라이트 애니메이션 시험 적용](123-2026-11-26-전사_스프라이트_애니메이션_시험적용_아키텍처.md)

---

## 1. 목적

채택된 공격 애니메이션(기획 122 §8.5 - 검사 베기 루프 A+, 도적1 휘두르기 B)을 배틀 테스트 씬에 넣고, **칼이 닿는 프레임에 피해가 들어가도록** 전투 판정 시점을 애니메이션에 맞춘다. 도적1(대기·걷기·공격)은 적 약탈자에 연결해 검사와 맞붙는 화면을 판단할 수 있게 한다.

## 2. 범위

| 구분 | 내용 |
|---|---|
| 목표 | 배틀 테스트 씬 아군 전사 공격(A+), 적 약탈자 대기·걷기·공격(도적1), 타격 프레임 시점 피해 판정 |
| 비목표 | Field 실전투 적용, 뒷모습·방향 전환·측면 공격(B안), 달리기 사용 조건, 진영 HUD, 궁수·방패병·괴수·적대자 그림, 사망 애니메이션 |
| 실패 조건 | 그림 없는 유닛의 공격 시점·동작이 바뀜(회귀) / 화면이 없거나 프레임이 밀릴 때 판정이 달라짐 / 공격 후 대기·걷기로 돌아오지 않음 / 타격 프레임과 피격 번쩍임이 어긋남 / Field 실전투 동작이 바뀜 |

## 3. 기획 확정 사항 (기획 122 §8, 사용자 2026-11-27)

| 항목 | 내용 |
|---|---|
| 공격 방향 | 앞모습 공격 하나를 하·좌하·우하 공통(A안), 좌우 반전 없음 |
| 피해 시점 | 공격 애니메이션이 지정된 타격 프레임에 도달하면 피해 판정 |
| 예비 동작 중 대상 사라짐 | 헛손질, 쿨타임 소모 |
| 공격 간격 | 공격 시작 기준(초당 피해 불변, 첫 타격만 예비 동작만큼 늦어짐) |
| 0.5m 찌르기 | 유지, 인게임 테스트 후 제거 여부 결정 |
| 사망 | 애니메이션 미생성, 사망 순간 프레임 정지 + 기존 빨간 틴트·페이드 |
| 클립·타격 프레임 | 검사 `2026-11-27/sword_attack_loop` 8번, 도적1 `2026-11-27/bandit1_attack_hydra` 6번 |

## 4. 접근안 (2026-11-27 사용자 A안 선택)

| 안 | 내용 | 판단 |
|---|---|---|
| **A. 시뮬레이션이 타격 시점 계산** | 유닛 생성 시 공격 클립에서 타격 프레임 전까지의 시간을 읽어 두고, 공격 시작 후 그 시간이 지나면 시뮬레이션이 피해를 준다. 화면은 공격 시작 이벤트로 클립만 재생 | **채택.** 같은 데이터에서 계산해 화면상 타격 프레임과 일치. 화면 유무·프레임 지연과 무관하게 판정이 같고 EditMode로 검증 가능. 시뮬레이션이 화면을 모르는 현재 구조 유지 |
| B. 화면이 타격 프레임 도달을 시뮬레이션에 알림 | 재생기가 타격 프레임에서 판정 요청 | 기획 문구와 글자 그대로 같지만 판정이 화면 갱신에 묶임(화면 없는 전투·프레임 저하 시 피해 지연·누락), 결합 방향 역전, 테스트 어려움 |
| C. 스탯 테이블에 예비 동작 시간 | 테이블 값에 맞춰 클립 제작 | 같은 값이 테이블·타이밍 두 곳에 생겨 어긋날 위험 |

- A안은 기획의 "재생 프레임 도달 시 판정"을 **클립 타이밍 데이터로 계산한 시간**으로 대신한다. 화면이 멈춘 상태(에디터 일시정지 등)에서는 그림과 판정이 어긋날 수 있다 - 게임 속도는 시뮬레이션과 화면이 같은 시간을 쓰므로 정상 실행에서는 일치한다.

## 5. 설계

### 5.1 시뮬레이션 - 공격 시작과 타격 분리 (`BattleCharacterUnit`)

| 항목 | 내용 |
|---|---|
| 타격 지연 | 생성자에서 한 번 계산: 애니메이션 세트의 `Attack` 클립의 "첫 이벤트 프레임 전까지 시간"(§5.2). 세트·공격 클립·이벤트가 없으면 0. 현재 데이터 기준 검사 0.333초(4:83 + 6:250), 도적1 0.083초(5:83) |
| 공격 시작 | 기존 공격 조건(대상이 사거리 안, 쿨타임 0 이하)을 만족하고 **대기 중인 타격이 없을 때**: 쿨타임을 공격 간격으로 다시 채우고, 새 이벤트 `OnAttackStarted(IDamageable target)`를 낸 뒤, 대기 중인 타격(대상, 남은 시간 = 타격 지연)을 기록 |
| 타격 처리 | 대기 중인 타격의 남은 시간을 매 틱 줄이고 0 이하가 되면 해소: 대상이 살아 있고(`IsAlive`) 대상까지 거리가 사거리 이하이면 피해 계산·적용 후 기존 `OnAttacked(target)` 발행, 아니면 헛손질(이벤트 없음). 해소 후 대기 중인 타격을 비움 |
| 지연 0 | 공격 시작 직후 같은 틱에 해소한다 - 이벤트 순서 `OnAttackStarted` → (피해) → `OnAttacked`. 그림 없는 유닛은 피해·이벤트 시점이 현행과 같다 |
| 진행 위치 | 대기 중인 타격은 교전 분기(전술/비전술, 사거리 안/밖)와 무관하게 진행해야 한다 - 비전술 경로는 사거리 밖이면 공격 함수를 부르지 않기 때문. `Tick`에서 생존 확인 직후, 도주·복귀 분기보다 먼저 진행한다 |
| 취소 | 도주 상태면 대기 중인 타격을 취소(피해 없음). 공격자 사망 시에는 `Tick`이 돌지 않아 해소되지 않는다(사실상 취소). 복귀(Returning) 중에는 취소하지 않고 사거리 판정에 맡긴다 |
| 대상 고정 | 대기 중인 타격은 시작 시점 대상을 따로 보관한다 - 그사이 유닛의 현재 대상이 바뀌어도 원래 대상에 적용 |
| 쿨타임 | 감소 방식은 현행 유지(사거리 안에서만 감소). 대기 중에도 감소하므로 간격은 공격 시작 기준 |
| 추격 판단 | 전술 경로의 "방금 명중"(`justLandedHit`, `IPursuitPolicy.ShouldDisengage` 입력)은 **타격이 실제로 들어간 틱**에 참. 타격은 틱 앞부분(진행 위치 참고) 또는 지연 0일 때 공격 함수 안에서 해소되므로, 이번 틱 해소 여부를 틱 단위 값으로 들고 있다가 `ShouldDisengage`에 넘긴다 |
| 지연 ≥ 간격 | 데이터 오류로 타격 지연이 공격 간격 이상이면, 대기 중인 타격이 해소될 때까지 다음 공격을 시작하지 않는다(위 "공격 시작" 조건). 가져오기 시 경고는 두지 않는다(간격은 유닛 스탯이라 가져오기 시점에 모름) |
| 인터페이스 | `IBattleCombatant`에 `event Action<IDamageable> OnAttackStarted` 추가. 구현체: `BattleCharacterUnit`, 테스트 가짜 2개(`BattleCargoLedgerTests.FakeEnemy`, `BattleUnitViewLifecycleTests.FakeUnit`) |

- 사거리 판정은 기존 `stats.Range` 그대로, 여유값 없음(설계자 판단). 근접 유닛 간 밀어내기로 헛손질이 잦으면 여유값을 후속 검토한다.

### 5.2 데이터·가져오기

| 항목 | 내용 |
|---|---|
| 클립 이름 | `UnitSpriteClipNames.Attack = "Attack"` |
| 타격 프레임 | 기존 `UnitSpriteClip.EventFrames`(클립 프레임 배열 인덱스, 0부터) 사용. 클립에 "첫 이벤트 전까지 시간" 계산 추가(이벤트 인덱스 앞 프레임들의 표시 시간 합, 이벤트 없으면 0) |
| 가져오기 형식 | `import.txt` 줄 끝 선택 항목 `hit=<원본 프레임 번호>`. 가져오기 도구가 타이밍 순서에서 그 원본 번호가 **처음 나오는 위치**(0부터)로 바꿔 `EventFrames`에 저장. 타이밍에 없는 번호면 경고하고 이벤트 없이 가져옴 |
| 라이브러리 키 | `UnitSpriteAnimationLibrary` 항목 키(`mercenaryClass` 필드)를 직업 문자열과 적 타입 문자열 공용 "유닛 종류 키"로 쓴다. 필드 이름은 유지(직렬화 호환), 주석만 수정 |
| 채택 타이밍 | `ArtSource/UnitAnim/2026-11-27/cartoon_timing_채택.txt`의 공격 두 줄에서 맨 앞 `1:250`(미리보기 반복 구분용 쉼)을 뺀다 - 게임에서는 공격 클립 종료 후 대기 클립으로 넘어간다. 미리보기에서는 공격이 쉼 없이 반복돼 보인다 |

`import.txt` 추가 줄:

```
Warrior Front Attack: 2026-11-27/sword_attack_loop @ cartoon_timing_채택 once hit=8
Marauder Front Idle: 2026-11-26/bandit1_idle3_hydra @ cartoon_timing_채택 loop
Marauder Front Walk: 2026-11-26/bandit1_walk_hydra @ cartoon_timing_채택 loop
Marauder Front Attack: 2026-11-27/bandit1_attack_hydra @ cartoon_timing_채택 once hit=6
```

- 크기·피벗: 가져오기는 원본 1번 프레임(시작 자세)을 기준으로 잰다(설계 123). `sword_attack_loop`는 원본 1번이 A 1번(시작 자세)이고, 복귀 구간은 A 1번 기준으로 맞춰 합성돼 있어 대기와 크기가 맞는다. 도적1 공격도 1번이 시작 자세.

### 5.3 화면 재생 (`BattleCharacterUnitView`·`SpriteClipPlayer`)

| 항목 | 내용 |
|---|---|
| 공격 재생 | `OnAttackStarted` 구독. 그림 세트에 `Attack` 클립이 있을 때만 재생하고 "공격 재생 중" 상태로 둔다. 재생 중에는 이동/대기 판정 변화로 클립을 바꾸지 않는다(이동 판정 자체는 계속 갱신) |
| 종료 후 복귀 | `SpriteClipPlayer`에 한 번 재생 클립 종료 여부(`IsFinished`: 비반복 클립이고 경과 시간이 총 시간 이상) 추가. 종료되면 그 순간 이동 여부에 따라 `Walk`/`Idle`을 처음부터 재생 |
| 재생 중 새 공격 | 처음부터 다시 재생(현재 데이터는 클립 0.83초 < 간격 1초라 발생하지 않음) |
| 0.5m 찌르기·투사체 | 기존 `OnAttacked` 반응 그대로 - 이벤트가 타격 시점으로 옮겨져 화면 코드 변경 없음 |
| 피격 번쩍임 | 변경 없음(피해 시점 = 타격 프레임) |
| 그림 없는 유닛 | `OnAttackStarted` 무시 |
| 풀 재사용 | `Unbind`에서 구독 해제·공격 재생 상태 초기화 |

### 5.4 사망

- 사망 시 `Update`가 조기 반환해 **그 순간 표시 중인 프레임에서 정지**하고, 기존 빨간 틴트·1.1배·2초 페이드가 적용된다. 현행 코드가 이미 이렇게 동작해 **변경 없음**.
- 설계자 판단: 공격·걷기 중 사망은 그 프레임에서 정지(기획의 "대기 프레임 정지"를 "현재 프레임 정지"로 해석). 대기 그림으로 바꾸면 그림이 순간 튀기 때문.

### 5.5 적(약탈자) 연결 - 배틀 테스트 씬 한정

- `BattleTestEnemySide`에 애니메이션 라이브러리(선택적, null 허용)를 받아 `entry.Kind.ToEnemyType()` 문자열로 세트를 찾아 `BattleCharacterUnit`에 넘긴다(미리보기 유닛·전투 유닛 둘 다). 괴수(`Monster`)·적대자(`Adversary`)는 세트가 없어 기존 도형.
- `BattleTestSimulationRule`이 이미 보유한 `unitAnimationLibrary`를 적 진영 생성에도 넘긴다. 인스톨러 변경 없음.
- Field 실전투(`LiveBattleSimulationRule` 경로)는 라이브러리를 받지 않아 변화 없음.
- 알려진 한계: 그림에는 진영 색을 입히지 않으므로(기획 122 5-1), 진영 HUD가 생기기 전까지 아군·적은 캐릭터 모습으로만 구분된다.

## 6. 검증

### 6.1 EditMode 테스트

| 대상 | 내용 |
|---|---|
| `UnitSpriteClip` | 첫 이벤트 전까지 시간 계산, 이벤트 없으면 0 |
| `SpriteClipPlayer` | 비반복 클립 종료 판정, 반복 클립은 종료되지 않음 |
| `BattleCharacterUnit` | 지연 0 → 같은 틱 피해·이벤트 순서(회귀) / 지연 d → d 전 피해 없음, d에 피해 / 대기 중 대상 사망 → 피해 없음·쿨타임 소모(다음 공격은 시작 시점 + 간격) / 타격 시점 사거리 밖 → 헛손질 / 도주 시작 → 취소 / 대기 중 현재 대상 변경 → 원래 대상에 적용 |
| 가져오기 | `hit=` 원본 번호 → 타이밍 순서 위치 변환, 없는 번호 처리(파싱·변환을 순수 함수로 분리해 테스트) |
| 기존 | 전체 EditMode 회귀 |

### 6.2 실행 확인 (Unity CLI)

1. `Tools/Game/Art/Import Unit Animations` 실행 → 배틀 테스트 씬 인스톨러 실행·저장.
2. 배틀 테스트 씬 검사 대 약탈자 전투: 공격 재생 후 대기·걷기 복귀, 타격 프레임과 피격 번쩍임 일치, 사망 프레임 정지, 공격↔걷기 전환 시 그림 튐 없음, 그림·HP바 겹침 없음.
3. 사용자 인게임 판단: 0.5m 찌르기 유지 여부, 측면 공격(B안) 필요 여부.

## 7. 제작자에게 맡기는 것

- `hit=` 파싱 위치(`UnitAnimTimingFile` 또는 가져오기 도구)와 경고 문구.
- 테스트 클래스 구성.
