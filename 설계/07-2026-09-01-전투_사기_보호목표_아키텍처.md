## 1. 개요 및 범위

06번 문서는 "한쪽 진영 Character 전멸 = 패배"라는 단순화된 전멸전만 다뤘다. 이번 설계는 06번이 만든 시뮬레이션 루프를 **확장**해 기획 §7.4의 정식 승패 조건을 완성한다.

- **Victory**: 적 진영 유닛이 (사망+도주로) 0명이 됨 — 06번에서 이미 구조는 마련됐고(전멸=사망만 반영), 이번에 도주를 더한다.
- **Defeat**: 아군 진영 유닛이 (사망+도주로) 0명이 됨, **또는** 보호 목표(Wagon/Facility)가 하나라도 파괴됨 — 이번 설계에서 신규 추가.

새 클래스를 추가하는 게 아니라 06번 클래스 대부분을 **확장(변경)**하는 작업이다. 새로 추가되는 건 사기 데이터(`PartyMorale`)와 보호 목표(`BattleProtectedUnit`)뿐이다.

## 3. 사기(Morale) 데이터 모델 (기획 §7)

### 3.1 수치 — 단일 출처

```csharp
/// <summary>기획 08번 문서 §7 테스트 수치. 플레이테스트 후 조정 대상.</summary>
public static class MoraleTuning
{
    public const float Initial = 100f;              // §7 초기값
    public const float SyncRatePerSecond = 10f;      // §7.1 동기화 속도
    public const float PartyMoraleLossOnUnitLost = 20f; // §7.2 하락폭
    public const float FleeThreshold = 0f;           // §7.3 붕괴 임계치
    public const float FleeTravelDistance = 15f;      // §7.3 "화면 밖" 판정 — 기획에 없어 새로 제안하는 값
}
```

`FleeTravelDistance`는 기획 §7.3의 "화면 밖으로 이동해 사라진다"를 구현하기 위해 새로 도입한 값이다 — 도주 시작 지점에서 이 거리만큼 이동하면 전장을 벗어난 것으로 간주한다. 정확한 전장 경계(`BattleFieldLayout`의 스폰 반지름 등, [[06-2026-08-31-전투_핵심루프_아키텍처]] §4)에 연동하지 않고 독립된 상수로 둔 이유는, 유닛이 전장 어디서 도주를 시작하든 "탈출까지 걸리는 체감 시간"을 동일하게 유지하기 위해서다.

### 3.2 `PartyMorale`

```csharp
/// <summary>
/// 진영 하나의 전체 사기(기획 §7 PartyMorale). Character 유닛이 전투 불능(사망/도주)이 될 때마다 하락한다.
/// 전투마다 새로 생성된다 - 이전 전투의 사기가 이어지지 않는다(기획에 명시된 바 없어 매 전투 초기화로 단순화).
/// </summary>
public class PartyMorale
{
    public float CurrentValue { get; private set; } = MoraleTuning.Initial;

    public void NotifyUnitLost() =>
        CurrentValue = Mathf.Max(0f, CurrentValue - MoraleTuning.PartyMoraleLossOnUnitLost);
}
```

### 3.3 보호 목표 HP — 기획에 없던 값

기획 08번 문서 §4/§9는 Wagon/Facility가 "HP 스탯만 가진다"고만 정의했고 구체적인 수치는 없다. 이번 설계에서 테스트 값을 새로 제안한다.

```csharp
/// <summary>기획 문서에 수치가 없어 새로 제안 - Character 평균 체력(70~150)보다 튼튼하게 잡아
/// 사소한 교전 한 번으로 즉시 패배로 이어지지 않게 했다. 확정 전 확인 필요.</summary>
public static class ProtectedUnitTuning
{
    public const float MaxHp = 200f;
}
```

## 4. `IBattleCombatant` / `BattleCharacterUnit` 확장 (기획 §7.1~§7.3)

```csharp
public interface IBattleCombatant : IDamageable
{
    bool IsAlly { get; }
    bool IsFleeing { get; }
    event Action OnFled;   // 도주 완료(전장 이탈) 시 1회 발행 - 사망(OnDied)과는 별개 경로
    void Tick(float deltaTime, IReadOnlyList<IDamageable> targets);
}
```

`BattleCharacterUnit`은 생성자에 `PartyMorale`(동기화 대상)과 `retreatDirection`(도주 방향, 정규화된 벡터)을 추가로 받는다.

```csharp
public class BattleCharacterUnit : IBattleCombatant
{
    public Vector2 Position { get; private set; }
    public bool IsAlly { get; }
    // hasLeftBattle이 true가 되면(도주 완료) 더 이상 전투 참가자가 아니다 - HP는 남아있어도 IsAlive는 false.
    public bool IsAlive => currentHp > 0f && !hasLeftBattle;
    public bool IsFleeing => isFleeing;
    public float Defense => stats.Defense;
    public event Action OnDied;
    public event Action OnFled;

    private readonly BattleUnitStats stats;
    private readonly IDamageFormula damageFormula;
    private readonly PartyMorale partyMorale;
    private readonly Vector2 retreatDirection;

    private float currentHp;
    private float unitMorale = MoraleTuning.Initial;
    private bool isFleeing;
    private bool hasLeftBattle;
    private float fledDistance;
    private IDamageable target;
    private float attackCooldown;

    public BattleCharacterUnit(
        Vector2 startPosition, bool isAlly, BattleUnitStats stats, IDamageFormula damageFormula,
        PartyMorale partyMorale, Vector2 retreatDirection)
    {
        Position = startPosition;
        IsAlly = isAlly;
        this.stats = stats;
        this.damageFormula = damageFormula;
        this.partyMorale = partyMorale;
        this.retreatDirection = retreatDirection;
        currentHp = stats.MaxHp;
    }

    public void Tick(float deltaTime, IReadOnlyList<IDamageable> targets)
    {
        if (!IsAlive) return;

        TickMorale(deltaTime);                    // §7.1/§7.3
        if (isFleeing)
        {
            TickFlee(deltaTime);                   // §7.3
            return;
        }

        if (target is not { IsAlive: true })
        {
            target = FindNearestTarget(targets);   // §5.1 (06번 문서 그대로)
            if (target == null) return;
        }

        var toTarget = target.Position - Position;
        var distance = toTarget.magnitude;

        if (distance > stats.Range)                // §5.2 1번
        {
            Position += toTarget.normalized * stats.MoveSpeed * deltaTime;
            return;
        }

        attackCooldown -= deltaTime;                // §5.2 2~3번
        if (attackCooldown <= 0f)
        {
            target.TakeDamage(damageFormula.ComputeDamage(stats.Attack, target.Defense));
            attackCooldown = stats.AttackInterval;
        }
    }

    // 매초 PartyMorale 쪽으로 다가가고, 임계치 이하로 떨어지면 도주를 시작한다.
    private void TickMorale(float deltaTime)
    {
        unitMorale = Mathf.MoveTowards(unitMorale, partyMorale.CurrentValue, MoraleTuning.SyncRatePerSecond * deltaTime);
        if (!isFleeing && unitMorale <= MoraleTuning.FleeThreshold)
        {
            isFleeing = true;
        }
    }

    // retreatDirection으로 이동만 한다 - 타겟팅/공격 없음(기획 §7.3 "이동/공격을 멈추고").
    private void TickFlee(float deltaTime)
    {
        var step = stats.MoveSpeed * deltaTime;
        Position += retreatDirection * step;
        fledDistance += step;

        if (fledDistance >= MoraleTuning.FleeTravelDistance)
        {
            hasLeftBattle = true;
            partyMorale.NotifyUnitLost();          // §7.2 - 도주도 "전투 불능"에 포함된다
            OnFled?.Invoke();
        }
    }

    public void TakeDamage(float amount)
    {
        if (!IsAlive) return;
        currentHp = Mathf.Max(0f, currentHp - amount);
        if (currentHp <= 0f)
        {
            partyMorale.NotifyUnitLost();          // §7.2
            OnDied?.Invoke();
        }
    }

    private IDamageable FindNearestTarget(IReadOnlyList<IDamageable> targets)
    {
        IDamageable nearest = null;
        var nearestSqrDist = float.MaxValue;
        foreach (var candidate in targets)
        {
            if (!candidate.IsAlive) continue;
            var sqrDist = (candidate.Position - Position).sqrMagnitude;
            if (sqrDist < nearestSqrDist)
            {
                nearestSqrDist = sqrDist;
                nearest = candidate;
            }
        }
        return nearest;
    }
}
```

**설계 선택**: 도주 중인 유닛도 `IsAlive`가 `hasLeftBattle`이 되기 전까지는 `true`다 — 즉 완전히 전장을 벗어나기 전까지는 여전히 다른 유닛의 타겟이 될 수 있다. 기획 §7.3은 이를 금지하지 않으며, "도망치는 적을 따라잡아 처치할 수 있는가"라는 긴장감 있는 상호작용으로 해석해 의도적으로 허용했다.

`partyMorale.NotifyUnitLost()`를 `BattleCharacterUnit` 내부에서 직접 호출하는 이유: 이미 동기화를 위해 `partyMorale` 참조를 들고 있으므로, 외부(`BattleSimulationLoop`나 `LiveBattleSimulationRule`)가 `OnDied`/`OnFled`를 또 구독해서 사기를 깎는 것보다 응집도가 높다. `BattleSimulationLoop`는 §6에서 보듯 순전히 "생존 수 카운트"만을 위해 별도로 같은 이벤트를 구독한다 — 두 구독자가 각자의 단일 책임(사기 반영 / 생존 카운트)만 진다.

## 5. 보호 목표 (기획 §4/§9) — 2026-09-01 코드 기준 갱신

큰 구조(IDamageable만 구현, PartyMorale 미보유, 파괴 즉시 Defeat)는 아래 설계대로 유지됐다. 다만 `IDamageable` 계약 자체가 이후(방향성 지시 AI, 설계12) 대상 선택·인식 로직을 위해 크게 확장되면서 `BattleProtectedUnit`도 그 확장을 그대로 따라야 했다 — 아래는 실제 코드(`Core/Battle/Simulation/BattleProtectedUnit.cs`) 기준.

```csharp
public class BattleProtectedUnit : IDamageable
{
    public Vector2 Position { get; }
    public bool IsAlive => currentHp > 0f;
    public float Defense => 0f; // 기획 §4: 방어력 해당 없음(N/A)
    public float Attack => 0f;  // 방향성 지시 타겟 선택자(HighestAttack)가 요구해 IDamageable에 추가된 필드 - N/A
    public float Range => 0f;   // 방진 형성(설계12)이 "인식한 적의 최대 사거리" 계산에 필요해 추가 - N/A
    public float MaxHp { get; }
    public float CurrentHp => currentHp;
    public Sprite Icon { get; }             // 정비창 팔레트 아이콘(마차=삼각형/시설=원형) 재사용
    public event Action OnDied;
    public event Action<float> OnDamaged;   // 뷰의 피격 플래시 연출(설계08)이 구독

    private float currentHp;

    public BattleProtectedUnit(Vector2 position, float maxHp, Sprite icon)
    {
        Position = position;
        MaxHp = maxHp;
        Icon = icon;
        currentHp = maxHp;
    }

    // attacker는 쓰지 않는다 - 이동/공격하지 않는 대상이라 "누가 때렸는지"를 활용할 주체가 없다
    // (IDamageable 계약은 지키되 필요 없는 정보는 무시, LSP - 설계12 §5.1과 같은 논리).
    public void TakeDamage(float amount, IBattleCombatant attacker)
    {
        if (!IsAlive) return;
        currentHp = Mathf.Max(0f, currentHp - amount);
        OnDamaged?.Invoke(amount);
        if (!IsAlive) OnDied?.Invoke();
    }
}
```

보호 목표는 `PartyMorale`을 받지 않는다는 원래 결정은 그대로 유지된다 — Wagon/Facility 파괴는 사기와 무관하게 즉시 Defeat로 직결된다(§6). `Attack`/`Range`가 0(N/A)인 이유는 이동/공격하지 않는 대상이기 때문이라는 설계 의도도 변하지 않았다 — 필드 자체는 이 클래스가 아니라 `IDamageable`(다른 소비자들의 요구)이 넓어지며 함께 늘어난 것이다.

## 6. `BattleSimulationLoop` 확장 — 2026-09-01 코드 기준 갱신

여기서 확정한 뼈대(생존 카운터를 `OnDied`/`OnFled` 이벤트로 유지, "하나라도 파괴되면 패배") 자체는 그대로다. 다만 이후 방진 형성(설계12)·포위(설계12)·사기 파동(설계14)·전투 뷰 카메라(설계13)가 차례로 이 클래스에 생성자 인자를 추가해, 지금은 아래 스니펫보다 훨씬 많은 것을 들고 있다 — 각 인자의 설계 근거는 해당 문서를 참고하고, 이 문서는 보호 목표/승패 판정 관련 부분만 다룬다.

```csharp
public class BattleSimulationLoop
{
    private readonly List<IBattleCombatant> allies;
    private readonly List<IBattleCombatant> enemies;
    private readonly List<IDamageable> protectedUnits;
    // 아래 4개는 이 문서의 범위 밖(각각 설계12/설계12/설계14/설계14) - 매 틱 Tick() 앞부분에서
    // 유닛이 움직이기 전에 먼저 갱신된다.
    private readonly FrontlineFormationCoordinator frontlineCoordinator;
    private readonly RangedSurroundCoordinator rangedSurroundCoordinator;
    private readonly MoraleWaveCoordinator allyWaveCoordinator;
    private readonly MoraleWaveCoordinator enemyWaveCoordinator;
    private int aliveAllyCount;
    private int aliveEnemyCount;
    private int aliveProtectedCount;

    // FieldRadius/SpawnRadius: 이 문서 범위 밖(설계13) - 전투 뷰 카메라/배경 그리드가 시야 경계를
    // 잡을 때 쓴다. 시뮬레이션 로직 자체는 두 값을 쓰지 않고 렌더링 소비자를 위해 보관만 한다.
    public float FieldRadius { get; }
    public float SpawnRadius { get; }

    public BattleSimulationLoop(
        List<IBattleCombatant> allies, List<IBattleCombatant> enemies, List<IDamageable> protectedUnits,
        float fieldRadius, float spawnRadius, FrontlineFormationCoordinator frontlineCoordinator,
        RangedSurroundCoordinator rangedSurroundCoordinator, MoraleWaveCoordinator allyWaveCoordinator,
        MoraleWaveCoordinator enemyWaveCoordinator)
    {
        // ...대입은 생략(이 문서 범위 밖 인자들의 설계 근거는 각 문서 참고)
        aliveAllyCount = allies.Count;
        aliveEnemyCount = enemies.Count;
        aliveProtectedCount = protectedUnits.Count;

        // 사망(OnDied)과 도주(OnFled) 둘 다 "전장에서 사라짐"이므로 둘 다 카운트를 줄인다(기획 §7.4) - 그대로 유지.
        foreach (var ally in allies) { ally.OnDied += () => aliveAllyCount--; ally.OnFled += () => aliveAllyCount--; }
        foreach (var enemy in enemies) { enemy.OnDied += () => aliveEnemyCount--; enemy.OnFled += () => aliveEnemyCount--; }
        foreach (var unit in protectedUnits) unit.OnDied += () => aliveProtectedCount--;
    }

    public bool IsAllyWiped => aliveAllyCount <= 0;
    public bool IsEnemyWiped => aliveEnemyCount <= 0;
    // 전체가 아니라 "하나라도" 파괴되면 true - 기획 §9. 그대로 유지.
    public bool IsProtectionTargetDestroyed => aliveProtectedCount < protectedUnits.Count;

    public void Tick(float deltaTime)
    {
        // 방진/포위/사기 파동 갱신(이 문서 범위 밖, 각 문서 참고) - 유닛 Tick 전에 먼저 실행.
        frontlineCoordinator.Update(deltaTime, allies, protectedUnits);
        rangedSurroundCoordinator.Update(deltaTime, allies);
        allyWaveCoordinator.Update(deltaTime, allies);
        enemyWaveCoordinator.Update(deltaTime, enemies);

        // 적의 타겟 후보 = 아군 전투원 + 보호 목표(이 문서 §5/§9) - protectedUnits를 빼먹으면 적이
        // Wagon/Facility를 절대 공격하지 않아 "보호 목표 파괴 = 패배"가 죽은 코드가 된다.
        var enemyTargets = new List<IDamageable>(allies.Count + protectedUnits.Count);
        enemyTargets.AddRange(allies);
        enemyTargets.AddRange(protectedUnits);

        foreach (var unit in allies)
        {
            if (unit.IsAlive) unit.Tick(deltaTime, enemies, allies);   // sameSideUnits 인자는 이 문서 범위 밖(겹침 방지)
        }
        foreach (var unit in enemies)
        {
            if (unit.IsAlive) unit.Tick(deltaTime, enemyTargets, enemies);
        }
        // protectedUnits는 여전히 Tick하지 않는다 - 이동/공격하지 않으므로(IDamageable, IBattleCombatant 아님).
    }
}
```

## 7. `LiveBattleSimulationRule` / `BattleManager` 통합

### 7.1 `ICaravanRosterProvider` 주입 — 마커 인터페이스 재사용

`FormationLayout.GetUnitId(slotIndex)`는 유닛 Id만 주고 종류(`FormationUnitKind`)는 주지 않는다. Character/Wagon/Facility를 구분하려면 `ICaravanRosterProvider.GetRoster()`가 필요하다 — 06번 문서 §10-7이 미리 지적해 둔 지점이다. `IFormationReader` 때와 같은 이유로 같은 패턴(마커 인터페이스)을 재사용한다.

```csharp
// ICaravanRosterProvider가 필요한 IBattleResultRule 구현체만 선택적으로 구현하는 마커 인터페이스.
public interface IRequiresCaravanRoster
{
    void SetCaravanRoster(ICaravanRosterProvider provider);
}
```

**2026-09-01 갱신**: 위 §7.1 서두의 `IBattleResultEvaluator` 계층은 2026-08-26 리팩토링에서 삭제됐다(설계01/설계04 §6 참고) — 지금 `BattleManager`는 `IBattleResultRule`을 직접 `GetComponent`로 조회하고, 그 결과(`resultRule`)에 대해 "필요로 하면 주입한다"는 아래 패턴만 적용한다. 실제 코드는 `Core/Battle/BattleManager.cs`:

```csharp
public void ResolveDependencies(IDependencyRegistrar registrar)
{
    resultRule = GetComponent<IBattleResultRule>();
    if (resultRule == null)
        throw new InvalidOperationException($"{nameof(BattleManager)}와 같은 GameObject에 {nameof(IBattleResultRule)} 구현체가 없다.");

    if (resultRule is IRequiresFormationReader formationConsumer
        && registrar.TryResolve<IFormationRepository>(out var formationRepository))
    {
        formationConsumer.SetFormationReader(formationRepository);
    }
    if (resultRule is IRequiresCaravanRoster rosterConsumer
        && registrar.TryResolve<ICaravanRosterProvider>(out var rosterProvider))
    {
        rosterConsumer.SetCaravanRoster(rosterProvider);
    }
    // ITacticsRepository도 같은 패턴(설계12) - registrar.Resolve 강제 호출이 아니라 TryResolve로
    // 선택 조회하도록 바뀌었다(CLAUDE.md 컨벤션 - 아직 설계 전인 시스템은 선택적으로 다룬다).
}
```

`BattleManager`는 여전히 "규칙이 X를 필요로 하면 주입한다"는 패턴만 반복 적용할 뿐 `LiveBattleSimulationRule`을 이름으로 모른다(OCP 유지, 06번 §7.1과 동일 논리) — 다만 `Resolve` 강제 호출에서 `TryResolve` 선택 조회로 바뀐 점은 §7.1 스니펫과 다르다.

### 7.2 `LiveBattleSimulationRule` — 사기/보호 목표 빌드

```csharp
public class LiveBattleSimulationRule : MonoBehaviour, IBattleResultRule, IRequiresFormationReader, IRequiresCaravanRoster
{
    // 06번 문서의 필드(statProvider, classAssigner, spawnSelector, enemyProvider, fieldLayout, damageFormula)는 그대로 유지

    private IFormationReader formationReader;
    private ICaravanRosterProvider rosterProvider;

    public void SetFormationReader(IFormationReader reader) => formationReader = reader;
    public void SetCaravanRoster(ICaravanRosterProvider provider) => rosterProvider = provider;

    private void Update()
    {
        if (simulation == null || resultReported) return;

        simulation.Tick(Time.deltaTime);

        if (simulation.IsEnemyWiped) Report(BattleOutcome.Victory);
        // 아군 전멸 OR 보호 목표 파괴 - 기획 §9/§7.4.
        else if (simulation.IsAllyWiped || simulation.IsProtectionTargetDestroyed) Report(BattleOutcome.Defeat);
    }

    private BattleSimulationLoop BuildSimulation()
    {
        var hasLayout = formationReader != null && formationReader.TryLoadCurrent(out var layout);
        var spawnCenter = fieldLayout.ComputeSpawnPoint(spawnSelector.SelectSpawnPointIndex());
        var allyMorale = new PartyMorale();   // 전투마다 새로 시작(§3.2)
        var enemyMorale = new PartyMorale();

        var allies = hasLayout ? BuildAllies(layout, spawnCenter, allyMorale) : new List<IBattleCombatant>();
        var enemies = BuildEnemies(spawnCenter, enemyMorale);
        var protectedUnits = hasLayout ? BuildProtectedUnits(layout) : new List<IDamageable>();

        // 2026-09-01 갱신: 생성자 인자가 §6처럼 늘어나(fieldRadius/spawnRadius/방진·포위·사기파동
        // 코디네이터) 지금은 이 한 줄이 훨씬 길다 - 이 문서 범위 밖(각 문서 참고)이라 그대로 생략.
        return new BattleSimulationLoop(allies, enemies, protectedUnits, /* ...§6 참고 */);
    }

    private List<IBattleCombatant> BuildAllies(FormationLayout layout, Vector2 spawnCenter, PartyMorale allyMorale)
    {
        var allies = new List<IBattleCombatant>();
        var retreatDirection = (-spawnCenter).normalized;   // 적이 다가온 방향의 반대 = 후방

        for (var slotIndex = 0; slotIndex < layout.SlotCount; slotIndex++)
        {
            var unitId = layout.GetUnitId(slotIndex);
            if (unitId == null || !TryGetKind(unitId, out var kind) || kind != FormationUnitKind.Character) continue;

            var column = slotIndex % layout.ColumnCount;
            var row = slotIndex / layout.ColumnCount;
            var position = fieldLayout.ComputeAllyPosition(column, row, layout.ColumnCount);
            var stats = statProvider.GetStats(classAssigner.GetClass(slotIndex));
            allies.Add(new BattleCharacterUnit(position, isAlly: true, stats, damageFormula, allyMorale, retreatDirection));
        }
        return allies;
    }

    private List<IBattleCombatant> BuildEnemies(Vector2 spawnCenter, PartyMorale enemyMorale)
    {
        var retreatDirection = spawnCenter.normalized;   // 자기 스폰 지점 방향 = 후방(왔던 곳으로 되돌아감)
        return enemyProvider.GetEncounterComposition()
            .Select(enemyStats => (IBattleCombatant)new BattleCharacterUnit(
                spawnCenter, isAlly: false, enemyStats, damageFormula, enemyMorale, retreatDirection))
            .ToList();
    }

    private List<IDamageable> BuildProtectedUnits(FormationLayout layout)
    {
        var result = new List<IDamageable>();
        for (var slotIndex = 0; slotIndex < layout.SlotCount; slotIndex++)
        {
            var unitId = layout.GetUnitId(slotIndex);
            if (unitId == null || !TryGetKind(unitId, out var kind) || kind == FormationUnitKind.Character) continue;

            var column = slotIndex % layout.ColumnCount;
            var row = slotIndex / layout.ColumnCount;
            var position = fieldLayout.ComputeAllyPosition(column, row, layout.ColumnCount);
            result.Add(new BattleProtectedUnit(position, ProtectedUnitTuning.MaxHp));
        }
        return result;
    }

    // 슬롯의 unitId가 실제로 어떤 종류(Character/Wagon/Facility)인지는 로스터를 순회해야 알 수 있다
    // (FormationLayout 자체엔 종류 정보가 없다). 로스터가 커지면 Dictionary 캐싱으로 바꿀 대상(§10-4).
    private bool TryGetKind(string unitId, out FormationUnitKind kind)
    {
        kind = default;
        if (rosterProvider == null) return false;

        foreach (var unit in rosterProvider.GetRoster())
        {
            if (unit.Id != unitId) continue;
            kind = unit.Kind;
            return true;
        }
        return false;
    }
}
```

## 9. 최적화 요약

- `TickMorale`/`TickFlee`는 살아있는 유닛마다 매 프레임 호출되지만 각각 상수 시간 연산(`MoveTowards`, 벡터 덧셈)만 한다 — 추가 스캔 없음.
- `TryGetKind`가 로스터를 선형 탐색한다(슬롯 수 × 로스터 크기) — 전투 시작 시 1회(`BuildSimulation`)만 호출되므로 지금 규모(로스터 수십 개 이하)에선 무시할 만하다. 로스터가 커지면 `Dictionary<string, IFormationUnit>`로 캐싱하는 편이 낫다(§10-4).
- `IsProtectionTargetDestroyed`/`IsAllyWiped`/`IsEnemyWiped` 전부 06번에서 확립한 카운터 패턴(이벤트 구독, 매 프레임 스캔 없음)을 그대로 따른다 — 새 스캔형 최적화 이슈를 추가하지 않았다.
- `protectedUnits`는 `Tick`되지 않는다(§6) — 이동/공격이 없는 정적 대상이므로 루프 비용이 아예 없다.

## 11. 실제 구현 반영 사항 (2026-08-26)

이 문서 작성 이후 실제 구현·플레이테스트 과정에서 아래처럼 바뀌었다 — 위 코드 스니펫은 갱신하지 않고 이 절에 델타만 기록한다.

- **`retreatDirection`(§4 생성자 파라미터) 폐지**: 진영 전체가 공유하는 단일 도주 방향 대신, 도주 시작 시점에 유닛마다 "필드 중심(원점)→자기 위치" 방향과 "가장 가까운 적→자기 위치" 방향을 합산해 개별적으로 정한다(`BattleCharacterUnit.ComputeFleeDirection`). 적이 여러 스폰 지점에서 동시에 나타나는 경우로 확장돼도 무너지지 않게 하기 위함. `BuildAllies`/`BuildEnemies`도 `retreatDirection` 계산·전달을 하지 않는다.
- **`IBattleCombatant.FleeVelocity`(신규)**: 도주 방향×이동속도를 뷰 전용 힌트로 노출한다(`Icon`/`MaxHp`와 같은 성격). `OnFled` 이후에도 뷰가 같은 속도로 계속 이동하는 페이드아웃 연출(08번 문서 §11)에 쓰인다.
- **최근접 탐색/근접 반발이 `IUnitSpatialQuery`로 분리됨**: `BattleCharacterUnit.FindNearestTarget`(§4 코드 스니펫)은 실제로는 `IUnitSpatialQuery.FindNearest`에 위임한다. 전투 규모가 커져 탐색 방식을 공간 분할로 바꿔도 `BattleCharacterUnit`은 무변경이도록 하는 확장점(교체 가능한 구조로만 도입 — 실제 공간 분할 구현체는 아직 없음).
- **`Tick` 시그니처에 `sameSideUnits` 추가**: 같은 진영끼리 겹침을 방지하는 위치 보정(`ApplySeparation`)을 위해 필요해졌다 — 모든 적이 같은 스폰 지점에서 동일한 좌표로 출발해 "적이 하나로 뭉쳐 보이는" 문제를 해결하기 위해 실플레이 중 추가됐다.
- **§10 이슈 3(`ProtectedUnitTuning.MaxHp` 확정 필요)**: 200 유지, 별도 확정 없이 그대로 사용 중.
- **`MoraleTuning.FleeTravelDistance`(§3.1 고정 상수 15) 폐지**: 대형 크기와 무관한 임의 고정값이었던 걸, 대형 크기에서 파생되는 값으로 교체했다(기획 §2-1 "전장 범위" 신설). `BattleCharacterUnit`이 이제 이 값을 생성자 파라미터(`fleeTravelDistance`)로 받는다 — `MoraleTuning`은 더 이상 이 값을 갖지 않는다. 파생 공식(`BattleFieldLayout`, 전부 `columnCount` 인자를 받음):
  - `대형 반지름` = 대형 모서리(원점에서 가장 먼 지점)까지 거리 = `√(halfColumnExtent² + halfRowExtent²)` (행 폭은 2행 고정이라 상수, 열 폭만 `columnCount`에 비례)
  - `스폰 반지름` = 대형 반지름 + `SpawnRadiusMargin`(10) — `IBattleFieldLayout.ComputeSpawnPoint`도 `columnCount` 인자를 받도록 시그니처가 바뀌었다.
  - `전장 반지름` = 스폰 반지름 − `FieldBoundaryGap`(2) — 스폰 지점이 전장 경계보다 이 간격만큼 더 바깥이라는 뜻.
  - `도주 이탈 거리`(`IBattleFieldLayout.ComputeFleeTravelDistance(columnCount)`) = 전장 반지름과 동일한 값.
  - `LiveBattleSimulationRule`은 배치가 없을 때(`hasLayout=false`) `DefaultColumnCount`(8, `FormationGridView` 기본값과 동일)로 계산한다 — 이 경우 아군이 0명이라 어차피 즉시 패배하므로 정확한 값 자체는 중요하지 않다.
