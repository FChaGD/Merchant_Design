## 1. 기획 요약 (이 문서가 받치는 범위)

- 이벤트: 상행 정지 상태에서 진행. 랜덤(5초, 3.3%)·확정(조건 성립). 같은 이벤트는 상행당 1회, 1회성은 게임 전체 1회.
- 대화: 이동 중 진행. 20초 점검(랜덤 30%)·계기 4종·수동 걸기. 랜덤·수동 대화는 상행당 1회, 반복 대화·확정 대화는 제한 없음(기획 §8-9, 실전 테스트 후 재결정).
- 판정 시점: 전투 0 / 대화 +1.25 / 이벤트 +2.5초.
- 대사: 타자기(초당 12자, 공백 제외) → 길이 비례 대기(1 + 0.05×글자, 2.5~5초) → 자동 넘김(대화만). 2단계 클릭. 선택지는 출력 직후 표시, 대화만 10초 제한 → 무응답 분기. 다른 화면이 열리면 전부 일시정지.
- 대사·분기·명령은 Yarn Spinner 3.x(기획 §2.1).

기반은 대화(88)·이벤트(89)가 공통으로 쓰는 데이터·이력·조건·추첨·상행 정지·판정 시계·계기 신호·대사 실행기를 만든다. 화면(말풍선·선택 UI)과 효과 명령은 88·89에서 만든다.

## 2. 결정 사항과 접근안

### 2.1 스크립트 형식 — Yarn Spinner 3.x (Ink 대비)

| 기준 | Yarn | Ink | 판정 |
|---|---|---|---|
| 잠긴 선택지 | 조건 거짓 선택지도 "선택 불가"로 전달 | 목록에서 빠짐 — 잠김 판정을 C#에 따로 둬야 함 | Yarn |
| 효과 실행 | `<<명령>>`이 순서대로, 대기형 명령 가능 | 외부 함수는 미리 읽기 중 먼저 호출될 수 있어 태그 규약 필요 | Yarn |
| 화자·플래그 | `이름: 대사` 기본, 변수 저장소 교체 | 태그 규약, 변수 동기화 | Yarn(차이 작음) |
| 대화 중간 저장 | 노드 단위 | 정확히 복원 | Ink(저장은 범위 밖) |
| 도입 위험 | 패키지·의존 DLL(타 패키지와 `System.Memory` 계열 충돌 사례 보고) | 순수 C# 소스 | Ink |

결정: Yarn 유지. DLL 충돌은 제작 1단계 직후 검사하고, 문제 시 사용자 결정으로 Ink 전환(이 시점엔 대사 데이터가 없고 엑셀 메타 구조는 그대로라 비용이 작다).

### 2.2 발생 정보 저장 위치 (사용자 선택: A)

| 안 | 내용 | 판단 |
|---|---|---|
| **A** | 엑셀 메타(발생 방식·가중치·반복·계기·화자·조건) + Yarn 본문(대사·선택지·명령) | 채택. 기존 테이블 체계(엑셀 → Play 시 자동 임포트)와 같고, 발생 판정이 순수 C#이라 테스트 가능 |
| B | Yarn 노드 헤더 + `when:` 조건 + 추첨 전략 직접 구현 | 기각. 판정이 Yarn 실행기 안이라 단위 테스트가 어렵고 헤더 오타를 못 잡음 |
| C | 메타는 엑셀, 조건만 Yarn 식 | 기각. 판정이 두 곳으로 나뉨 |

### 2.3 조건 열 형식 (사용자 선택: ①)

한 열에 `키:값` 목록(`region:2; flag:helped_cart; !flag:paid_toll; month:3-5`). 새 조건 종류는 판정기 등록만으로 추가(기획 §5.3). 고정 열 방식(②)은 종류가 늘 때마다 열·임포터 수정이 필요해 기각.

### 2.4 상행 정지 위치 (사용자 지시)

`FieldManager`를 신설하고 그 하위 컴포넌트로 정지 조율자·판정 시계·계기 신호를 둔다. 상행 중에만 동작하는 조율 요소를 한곳에 모으고, 대화·이벤트 진행자(88·89)도 같은 자리에 하위 컴포넌트로 추가한다.

## 3. 콘텐츠 데이터

### 3.1 엑셀 `Assets/Table/Encounter/Encounter.xlsx`

기존 v2 체계(데이터 시트·문자열 시트 분리, Id 기반)를 따른다. 임포터는 `Tools/Game/Table/Import ...`·일괄 임포트·Play 시 자동 임포트·`TableAssetPaths`에 등록한다.

| 시트 | 열 |
|---|---|
| Event | Id, YarnNode, 발생(`Random` / `Fixed`), 중요도(`Scenario` / `Core` / `Side` / `Normal`), 반복(`Once` / `PerTrip`), 가중치(정수, 기본 100), 조건 |
| Dialogue | Id, YarnNode, 발생(`Random` / `Trigger` / `Manual` / `ManualRepeat`), 계기(`Departure` / `AfterBattle` / `AfterEvent` / `MidCityArrival`, 발생=Trigger일 때만), 화자(캐릭터 Id 목록, `;` 구분), 가중치, 조건 |
| Person | 외부 인물 Id, 일러스트 키 / 문자열 시트: 이름 |

- 중요도는 확정 이벤트 대기열 정렬에만 쓴다(§5.4). 메인 시나리오 시스템이 없어도 값은 지금부터 지정한다.
- 이벤트 1회성·상행당 1회: 반복=`Once`는 게임 전체 1회, `PerTrip`은 상행마다 1회까지(기획 §3.1).
- 화자 열: 대화의 고용 상태 판정 대상(§5.3). 외부 인물 Id는 판정에서 제외한다.

**임포트 검증(위반 시 임포트 오류)**: 조건 키가 알려진 키인지(§5.1), 열거형 값이 유효한지, 화자 Id가 캐릭터 테이블 또는 Person 시트에 있는지, Id 중복. YarnNode 존재 확인은 Yarn 프로젝트 컴파일 결과가 필요하므로 EditMode 콘텐츠 검증 테스트(§9)로 한다.

### 3.2 Yarn `Assets/Content/Dialogue/*.yarn` + Yarn 프로젝트 1개

노드 하나 = 이벤트·대화 하나. 작성 규약:

| 요소 | 규약 |
|---|---|
| 화자 | `화자Id: 대사`. 표시 이름은 캐릭터 테이블·Person 시트에서 찾는다. 화자 없는 줄 = 서술 |
| 잠긴 선택지 | `-> 낸다 <<if gold() >= 300>> #lock:골드_300_필요` — 조건 거짓이면 흐림 + `#lock` 문구. **Yarn 태그엔 공백을 넣을 수 없어 공백은 `_`로 쓰고, 표시할 때 공백으로 바꾼다**(제작 중 확인) |
| 무응답 선택지 | `-> (무응답) #timeout` — 화면에 표시하지 않음, 선택지 묶음당 0~1개 |
| 선택지 앞 질문 줄 | 출력이 끝나면 대기 없이 선택지를 띄운다. **Yarn이 선택지 바로 앞 줄에 `lastline` 태그를 자동으로 붙이므로 작가가 표시할 필요 없다**(제작 중 확인). `#ask`로 직접 표시해도 같게 동작한다 |
| 선택지 전부 잠김 | 보이는 선택지가 모두 잠겼고 `#timeout`도 없으면 선택 없음으로 넘긴다(Yarn이 그 선택지 묶음을 건너뜀) |
| 효과 | `<<명령 인자...>>` — 명령 이름·인자는 89(이벤트)에서 확정. 기반은 등록 구조만 제공(§7.3) |
| 플래그 | Yarn 참/거짓 변수(`$helped_cart`) = 이력 플래그(§4.2) |

## 4. 이력 저장소

### 4.1 구성

Bootstrap 상주 `IManagedComponent`. 플레이 세션 동안만 유지(저장 기능은 범위 밖, `RoadDifficultyState`와 같은 수준).

| 기록 | 내용 | 초기화 |
|---|---|---|
| 플래그 | 문자열 키 → 참/거짓 | 없음 |
| 발생 기록(전체) | 끝까지 진행된 이벤트·대화 Id | 없음 |
| 발생 기록(이번 상행) | 이번 상행에서 끝까지 진행된 Id | 상행 시작 신호(§6.4) |

| 계약 | 소비자 |
|---|---|
| 이력 조회(플래그 조회, 전체 발생 여부, 이번 상행 발생 여부) | 조건 판정 문맥, 후보 추첨, 디버그 표시 |
| 이력 기록(플래그 설정, 발생 기록) | 대화·이벤트 진행자(88·89), Yarn 변수 저장소, 디버그 초기화 |

- **발생 기록 시점: 끝까지 진행했을 때만**(사용자 결정). 중단된 대화는 기록하지 않아 다시 뜰 수 있다. 이벤트의 "끝"은 이벤트 흐름 전체의 종료(이벤트 전투 패배로 흐름이 끝난 경우 포함).

### 4.2 Yarn 변수 저장소

Yarn 3의 변수 저장소를 이력 저장소 위에 구현한다. 참/거짓 변수는 플래그와 같은 값(같은 원천). 스크립트 안에서만 쓰는 숫자·문자열 변수는 같은 저장소의 별도 사전에 보관하고 조건 판정에는 쓰지 않는다.

- (검진 후 보완) false로 설정한 플래그는 "미설정"과 구분해 false 값으로 돌려준다. Yarn은 저장소에 값이 없으면 선언 기본값을 쓰므로, `<<declare $x = true>>` 변수를 false로 바꾼 뒤 true로 되돌아가는 것을 막는다. 조건 `flag`는 참 여부만 본다.

## 5. 조건 판정 · 후보 추첨 · 확정 이벤트 대기열 (순수 C#)

### 5.1 조건

| 단위 | 역할 |
|---|---|
| 조건 해석기 | `region:2; !flag:x` → 조건 목록(키, 부정, 인자). 임포트 시 1회 |
| 조건 키 목록 | 알려진 키의 단일 소스. 임포터(모르는 키 오류)·실행 쪽 등록부가 함께 쓴다 |
| 키별 판정기 | 키 하나 = 판정기 하나. 새 조건 종류는 키 추가 + 판정기 등록(기획 §5.3 퀘스트·스토리 확장 자리) |
| 판정 문맥 | 판정 순간의 값 묶음: 오늘 날짜, 현재 구간(출발·도착 도시, 도로, 지역), 진행도, 이력 조회. 판정기는 저장소를 직접 보지 않는다 |

이번 키: `month`(월 범위), `date`(날짜 범위), `progress`(구간 진행도 범위), `region`, `road`, `from`, `to`, `flag`, `seen`(전체 발생 여부). 모든 키는 `!` 부정 가능. 빈 조건 = 참.

### 5.2 후보 추첨 (대화·이벤트 공용)

1. 판정 종류(이벤트 랜덤·확정 / 대화 랜덤·계기 X·수동·반복)에 맞는 행만.
2. 횟수 제한: 1회성이면 전체 기록, 상행당 1회 대상(이벤트 전부, 랜덤·수동 대화)이면 이번 상행 기록으로 제외. 확정 대화·반복 대화는 제한 없음.
3. 화자 전원 고용 상태(외부 인물 제외).
4. 조건 전부 참.
5. 랜덤 = 가중치 추첨(난수 주입). 후보 가중치가 전부 0이면 균등 추첨(사용자 결정, 2026-10-13). 양수 가중치가 있으면 가중치 0 행은 뽑히지 않는다. 계기 대화 = 테이블 순서 첫 행. 확정 이벤트 = §5.4 대기열.

### 5.3 화자 고용 판정

`IHiredCharacterRoster.IsHired` 조회(기획 B6: 고용 상태이기만 하면 됨, 정비창 배치 무관).

### 5.4 확정 이벤트 대기열

| 규칙 | 내용 |
|---|---|
| 진입 | 이벤트 판정 신호마다 확정 이벤트 후보(§5.2 1~4 통과, 이미 대기 중이 아닌 것)를 대기열에 넣는다 |
| 정렬 | ① 중요도 `Scenario` > `Core` > `Side` > `Normal` ② 같은 중요도 안에서 먼저 성립한 것(FIFO) ③ 같은 판정 회차에 함께 성립 → 테이블 순서 |
| 실행 | 앞에서 하나 꺼내 **실행 직전 재검사**. 깨졌으면 빼고 다음 것. 빠진 이벤트는 다시 성립하면 새로 진입(그 중요도 안에서 맨 뒤) |
| 비움 | 상행 시작·종료 신호 |
| 랜덤과의 관계 | 같은 판정 시점에 확정이 실행되면 랜덤 판정은 하지 않는다(기획 §3.2 "확정 > 랜덤") |

## 6. FieldManager

### 6.1 구조

전역 매니저(`IManagedComponent`, `ManagerHierarchyInstaller`의 `managedComponents` 등록). 아래 하위 컴포넌트는 같은 GameObject에 부착하고 전역 DI 대상이 아니다. FieldManager가 `GetComponent`로 조회해 계약별로 대신 등록한다(`GameManager` → `SessionStateTracker`와 같은 구조). 없으면 `InvalidOperationException`으로 조기 실패.

| 하위 컴포넌트 | 등록 계약 |
|---|---|
| 상행 정지 조율자 | 정지 걸기/풀기, 정지 상태·원인 조회 |
| 판정 시계 | 신호 수신(전투 판정·대화 점검·이벤트 판정) |
| 상행 계기 신호 | 발신 계약 / 수신 계약 분리 |

대화·이벤트 진행자(88·89)도 같은 자리에 추가할 수 있다.

### 6.2 상행 정지 조율자

**문제**: 상행 시계(`SessionStateTracker`)는 정지가 켜짐/꺼짐 하나, 배치 활동(`IFieldFormationActivityRepository`)도 전부 정지/전부 재개뿐이다. 이벤트 전투에서 전투 마무리가 상행·활동을 재개하면 전투 후 대화(기획 §3.8) 중에 상행이 움직인다.

| 정지 원인 | 거는 곳 → 푸는 곳 |
|---|---|
| 전투 | 전투 판정 성공 → 전투 마무리의 재개 지점(승리·도주) |
| 이벤트 | 이벤트 시작 → 이벤트 종료(89) |
| 이벤트 대기 | 이벤트 발생 시 정비창·방향성 지시가 열려 있음 → 이벤트 시작(89, 기획 B9) |

- 원인 집합이 비어 있지 않으면 상행 시계·배치 활동 정지. **마지막 원인이 풀릴 때만** 둘 다 재개.
- 전투 중 배치 활동만 재개하는 기존 예외(전투 시뮬레이션 재개 시)는 전투 쪽이 그대로 처리한다. 전투 원인이 풀릴 때 다른 원인이 남아 있으면 조율자가 활동을 다시 전부 정지한다.
- 이전 대상(기존 직접 호출 3곳): 전투 판정의 상행 정지(`EncounterManager`), 인카운터 흐름 시작의 활동 정지(`FieldEncounterFlowCoordinator`), 전투 마무리의 활동·상행 재개(`FinishStep`). 이후 상행 시계 정지·재개는 조율자만 호출한다.
- 패배 처리(궤주·사망·포로)의 즉시 완료(`ForceCompleteAll`)는 상행을 재개하지 않는 경로라 그대로 둔다. 상행 종료 시 원인 집합을 비운다.
- 대화는 상행을 멈추지 않으므로 쓰지 않는다.

### 6.3 판정 시계

상행 진행 이벤트(`ISessionState.OnProgressChanged`)에 얹은 단일 누적 시간.

| 신호 | 시점 |
|---|---|
| 전투 판정 | 5초 축의 0초(5, 10, 15 …) |
| 대화 점검 | +1.25초, 20초마다(1.25, 21.25, 41.25 …) |
| 이벤트 판정 | +2.5초, 5초마다(2.5, 7.5 …) |

- 상행 시계를 따르므로 정지 중엔 함께 멈춘다(전투 중 판정 정지, 기획 B10).
- 상행 시작 신호에 0으로 되돌림. 구간이 바뀌어도 이어서 센다(기존 전투 판정과 같음).
- 도착 틱(진행도 ≥ 1)엔 판정하지 않는다 — 기존 `EncounterManager`의 예외를 시계로 옮긴다.
- 한 프레임에 여러 신호 경계를 넘으면 시점 순서대로 각각 한 번씩 발생.
- `EncounterManager`는 자체 누적을 없애고 전투 판정 신호를 받는다. 확률 계산(구간 난이도의 5분 평균)은 그대로. 판정 간격 상수는 시계로 옮긴다.

### 6.4 상행 계기 신호

| 신호 | 발신 위치 |
|---|---|
| 상행 시작 | Field 공개 후 첫 구간 시작(`FieldUIController`의 기존 만피 리셋 지점) |
| 중간 도시 도착 | `FieldTripLegCoordinator`의 중간 도시 처리 |
| 전투 종료 | 랜덤 전투: 전투 마무리에서 상행을 이어갈 때(승리·도주)만. **이벤트 전투: 이벤트가 끝나 상행이 재개될 때**(이벤트 흐름 안에서는 상행이 재개되지 않으므로, 89) |
| 이벤트 종료 | 이벤트 흐름 종료 후 상행 재개 시(89) |
| 상행 종료 | 상행 종료 처리(`FinishTrip`) |

수신: 이력 저장소(상행 시작 → 이번 상행 기록 비움), 확정 이벤트 대기열(시작·종료 → 비움), 판정 시계(시작 → 0), 정지 조율자(종료 → 원인 비움), 대화(88: 계기 대기).

## 7. 대사 실행기

### 7.1 계층

| 계층 | 형태 | 역할 |
|---|---|---|
| 대사 진행 상태기 | 순수 C#, 경과 시간을 받아 진행 | 타자기·대기·2단계 클릭·일시정지·선택지 제한시간. Yarn을 모른다 |
| Yarn 연결 표시기 | Yarn 3 표시 컴포넌트 구현 | Yarn 줄·선택지 → (화자 Id, 문장, 잠김 여부, 잠김 문구, 무응답 여부). 상태기 완료 시 Yarn을 다음으로 진행 |
| 표시 화면 | 88·89 구현 | 기반은 화면 계약만: 화자 표시, 보이는 글자 수 갱신, 선택지 표시·숨김, 클릭 전달 |

Yarn 의존 코드는 Yarn 연결 표시기와 변수 저장소(§4.2) 두 곳에만 둔다.

**실행 순서 조율(검진 후 보완)**: Yarn은 중단 뒤 완료 신호를 늦게 보낼 수 있고, 완료 신호 뒤에도 내부 정리를 이어 간다. 그래서 대본 실행기는 엔진 완료 신호부터 다음 프레임까지 들어온 시작 요청을 보류했다가 그 뒤에 시작한다. 보류된 시작도 성공(true)으로 응답하며, 중단된 대본의 완료 콜백은 false로 한 번만 부른다. 규칙은 순수 C# 조율 객체(`DialogueRunSequencer`)에 두고 EditMode로 검증한다. 88의 "이벤트가 뜨면 대화를 끝내고 이벤트 시작"이 이 경로를 쓴다.

### 7.2 진행 규칙

| 항목 | 규칙 |
|---|---|
| 출력 | 초당 12자. 공백은 시간을 쓰지 않음, 문장부호 포함 |
| 대기 | clamp(1 + 0.05 × 글자 수, 2.5, 5)초 (글자 수 = 공백 제외) |
| 자동 넘김 | 실행 옵션 — 대화 켬, 이벤트 끔 |
| 클릭 | 출력 중 = 전체 표시(대기 시작), 출력 후 = 다음 줄 |
| 선택지 | 질문 줄 출력 완료 즉시 표시(대기 없음). 제한시간은 실행 옵션(대화 10초, 이벤트 없음). 만료 = `#timeout` 선택지 선택. 제한시간이 없는 실행(이벤트)에선 `#timeout`을 없는 것으로 본다 — 보이는 선택지가 전부 잠겼으면 선택 없음(검진 후 보완) |
| 일시정지 | 원인 집합. 하나라도 있으면 출력·대기·제한시간 정지. 어떤 화면을 원인으로 볼지는 88에서 연결 |
| 중단 | **즉시 종료**(사용자 결정): 화면 닫고 Yarn 실행 정지. 무응답 분기 미적용, 발생 기록 없음 |
| 수치 | 출력 속도·대기 공식·제한시간은 상수 한 곳(플레이테스트 후 조정) |

### 7.3 명령·함수 등록

기반은 Yarn 명령(`<<x>>`)·함수(`gold()` 등)를 등록하는 구조만 제공한다. 실제 효과 명령·잠김 조건 함수는 89(이벤트)에서 정의한다(기획 §8-2 잠김 조건 종류 포함).

## 10. 제작 순서 (제작 계획에서 세분화)

1. Yarn 도입 → 컴파일·전체 EditMode. (완료: OpenUPM dev.yarnspinner.unity 3.2.8, DLL은 System.Runtime.CompilerServices.Unsafe 중복 경고뿐 - Unity가 한쪽 선택, 동작 정상)
2. 이력·조건·추첨·대기열(순수 로직 + 테스트).
3. FieldManager·정지 조율자·판정 시계·계기 신호, 기존 전투 경로 이전 → 전투 회귀 확인(Play).
4. Encounter 임포터, Yarn 연결(변수 저장소·표시기).
5. 대사 상태기.
6. 디버그 도구.

기반만으로 Play에서 확인 가능한 것은 전투 회귀와 디버그 표시뿐이다. 대사 흐름의 실제 확인은 88 제작 이후.
