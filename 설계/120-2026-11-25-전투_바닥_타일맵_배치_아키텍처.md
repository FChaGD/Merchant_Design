## 1. 목적

전투 바닥을 그림 1장의 반복에서 30종 타일의 노이즈 배치로 바꾼다. 배치 맵은 Field 로딩에서 미리 계산하고, 전투 시작 시 잘라낸 범위를 Tilemap에 채운다. 기존 전투·배틀 테스트·카메라·로딩 동작은 회귀 없이 유지한다(사용자 지시).

## 2. 접근안

| 안 | 내용 | 판단 |
|---|---|---|
| A | 기존 SpriteRenderer 풀을 칸당 2개(밑층·덮개)로 확장 | 수정 범위 최소. 최대 약 4,000 오브젝트, 30장 그림이라 배칭이 깨져 아틀라스 필수 |
| **B (채택)** | Tilemap 2층(밑층·흙 덮개)으로 교체 | 대량 칸 일괄 렌더, 층 = 기획의 고정 순서표와 1:1, 새 재질은 층 추가 |
| C | 로딩에서 맵을 큰 텍스처 1장으로 굽기 | 45칸 × 256px ≈ 11,500px로 텍스처 한도·메모리 초과 - 제외 |

사용자 결정(2026-11-25): B안, 기존 기능 회귀 주의.

- 타일 에셋은 파일로 만들지 않는다 - 뷰가 그림에서 `Tile` 인스턴스를 실행 중 1회 만들어 재사용한다(파일 30개 관리 회피, 결정: 설계자 판단).

## 4. 맵 생성 규칙

### 4.1 크기
- 맵 크기 = 대열 최대(정비창 50 × 50, `FormationExtent.FromGrid`) 기준 스폰 반경을 감싸는 정사각형 칸 수. 현재 값 45 × 45칸, 꼭짓점 46 × 46. 상수로 박지 않고 기존 전장 반경 공식으로 산출한다(공식이 바뀌면 함께 따라감).

### 4.2 흙(덮개 층)
- 꼭짓점마다 흙 노이즈 값을 판정해 흙 꼭짓점을 정한다. 흙 비율(기본 15%)은 꼭짓점 기준.
- 칸의 네 꼭짓점(TL·TR·BL·BR, 1 = 흙) 조합:
  - 1111 → 흙 3종 중 균등 랜덤
  - 0001~1110 → 같은 조합 이름의 흙 경계 타일(`DirtEdge_{TL}{TR}{BL}{BR}`)
  - 0000 → 덮개 없음
- 꼭짓점 순서와 그림 방향(위=TL·TR)은 `ArtSource/BattleFloor/2026-11-24/tools/build_final.py`의 생성 규칙과 일치해야 한다 - 테스트로 고정한다.

### 4.3 잔디 계열(밑층)
- 칸 중심에서 잔디 계열 노이즈를 판정해 잔디·잡초·꽃을 정한다. 비율은 흙을 뺀 나머지 안의 비율(기본 65 : 23 : 12). 모든 칸에 깐다(흙 아래 칸 포함).
- 분류 안의 변형은 칸마다 균등 랜덤.
- 흙과 잔디 계열은 서로 다른 노이즈 필드를 쓴다(설계자 판단) - 같은 노이즈의 누적 구간이면 흙 옆 구간 분류가 항상 흙 둘레에만 생긴다.

### 4.4 노이즈·비율
- 노이즈 = 큰 노이즈(군집 지름 기본 6칸) + 작은 노이즈(크기·섞는 세기 조정 값). 맵마다 노이즈 시작 위치를 무작위로 바꾼다.
- 비율 경계는 노이즈 값을 직접 자르지 않고 맵 안 표본의 분위수로 정한다(설계자 판단) - 펄린 값 분포가 고르지 않아 직접 자르면 비율이 어긋난다.
- 난수는 `System.Random`(시드 주입 가능) - 테스트에서 결정적으로 재현.

### 4.5 맵 데이터
- 칸마다: 밑층 그림 번호(잔디 계열 13종 중), 덮개 종류(없음 / 흙 변형 / 흙 경계 조합). 생성 후 꼭짓점 배열은 보관하지 않는다.

## 5. 로딩과 전투 연결

### 5.1 로딩
- Field 진입 로딩 작업 "전투 바닥 준비 중" 1개를 Bootstrap 초기화 때 등록한다(설계 67 §4.3 - 전환 시작 시 작업 수 확정).
- 장 수 = ⌊상행 계획 총 소요시간(초) / 30⌋ + 3. 상행 계획이 없으면(디버그 진입 등) 3장(설계자 판단).
- Field 진입마다 기존 맵을 버리고 새로 만든다. 사용 기록도 초기화.

### 5.2 전투
- 바닥 뷰가 전장 크기 설정 시점(기존과 동일: 전투 표시 시작, 배틀 테스트 세팅)에 필요한 칸 수 n을 기존 공식(스폰 반경 정사각형, ⌈2 × 스폰 반경 / 2m⌉)으로 구한다.
- 매니저에게 n × n 배치를 요청한다: 미사용 맵 우선(소진 시 랜덤), 잘라낼 왼쪽 아래 칸은 x·y 각각 [0, 45 − n] 랜덤. n이 맵보다 크면 맵 전체를 쓰고 경고 로그(현 공식상 발생하지 않음).
- 화면 위치는 기존과 동일하게 원점 중심 [−n, n]m(칸 2m).

### 5.3 Tilemap
- 바닥 뷰 아래 `Grid`(칸 2m) + Tilemap 2개(밑층, 흙 덮개). 레이어 = 기존 전투 레이어. 정렬값: 밑층 −30000, 덮개 −29999(기존 타일 정렬값 유지 - 유닛 최저 약 −4,500보다 항상 아래).
- 그림마다 칸 2m에 맞는 배율을 타일 변환 행렬로 준다 - 픽셀 밀도가 다른 그림(FormationSlot 등)도 그대로 쓴다.
- 채우기는 영역 일괄 설정으로 한 번에 한다. 이전 전투보다 작으면 남은 칸은 비운다.

## 6. 배틀 테스트 씬

- 노이즈 배치 없이 FormationSlot 그림으로 전체를 채운다(기획 6-1). 바닥 뷰의 단일 그림 모드 - 배틀 테스트 인스톨러가 그림을 연결한다.
- 전투 시작 전(세팅 단계)에도 바닥이 보이는 기존 동작 유지.
- 틴트 여부는 적용 후 판단(기획 6-1).

## 7. 회귀 방지

| 대상 | 대책 |
|---|---|
| 바닥 뷰 호출자(전투 표시, 배틀 테스트 컨트롤러) | 전장 크기 설정 진입점의 모양·호출 시점 불변 |
| 유닛 그리기 순서 | 바닥 정렬값 −30000/−29999 유지 |
| 카메라 | 수정 없음. 컬링 레이어 = 기존 전투 레이어 |
| 매니저·맵·바닥 세트 없음 | 단일 그림(없으면 기존 흰 사각형 + 녹색 틴트)으로 깔고 경고 로그. 전투는 막지 않음 |
| 로딩바 | Field 작업 수 +1. 기존 로딩 테스트는 자체 구성이라 무영향 |
| 기존 바닥 그림 연결 | Field 인스톨러의 BattleFloorTile 연결을 바닥 세트 연결로 대체. `BattleFloorTile.png` 파일은 남기고 참조만 끊음 |

## 8. 검증

- 전체 EditMode 테스트 통과(기존 회귀).
- 신규 테스트: 비율 허용 오차, 덮개 조합 ↔ 꼭짓점 일치, 1111/0000 처리, 잘라내기 범위, 장 수 공식(계획 없음 포함), 맵 사용 순서(미사용 우선 → 소진 후 랜덤), 맵 크기 산출.
- CLI 런타임: Field 실제 전투 화면 캡처(바닥 배치·유닛 위 그리기), 배틀 테스트 씬 세팅 단계 캡처, 최대 줌 아웃에서 칸 사이 선 확인, 로딩바 작업 수.
