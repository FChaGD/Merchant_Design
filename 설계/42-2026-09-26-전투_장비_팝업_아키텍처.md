## 1. 범위

- 상단 물류품 팝업 구조를 **회전/임시 보관을 켜고 끌 수 있는 형태**로 일반화하고, 전투 장비 팝업을 그 위에 추가한다.
- 장비 저장소에 정리 조작 계약 추가, Placeholder 장비 4종(테이블 행 + 초기 배치).
- 범위 밖: 용병 장착 화면, 대장간 진입점, 소모품/개인 물품 팝업(같은 방식으로 스펙만 추가하면 되도록 구조만 준비).

## 2. 현재 구조의 결합 지점

| 위치 | 현재 | 장비 팝업에서 문제 |
|---|---|---|
| `InventoryPopupElements` | 임시 보관 요소(StagingArea/StagingContent)가 필수 | 임시 보관 없는 팝업은 바인딩 실패 |
| `InventoryPopupPanel` | 임시 보관 뷰를 항상 생성·렌더 | 요소가 없으면 NRE |
| `InventoryItemDragController` | Q 입력 액션 항상 활성(드래그 중), 임시 보관 드롭 판정 항상 수행 | 장비에서 Q가 동작하면 안 됨(1×1이라 표시 변화는 없지만 회전 상태 값이 바뀜) |
| `InventoryPopupUIBuilder` | 임시 보관 영역을 항상 생성, 창 위치 상수 1개 | 팝업별 크기·위치·구성이 다름 |
| `HubUIWiring` | 상단 물류품 1개만 하드코딩 등록 | 팝업 추가 시 코드 중복 |

## 3. 팝업 스펙 — 단일 정의 (`Core/UI/Inventory/InventoryPopupSpec`)

에디터 인스톨러(화면 구성)와 런타임 배선(기능 동작)이 **같은 정의**를 읽도록 팝업별 스펙을 Core에 둔다. 두 곳에 따로 적으면 "인스톨러는 임시 보관을 만들었는데 런타임은 끔" 같은 불일치가 생긴다.

```csharp
public sealed class InventoryPopupSpec
{
    public string PopupId { get; }
    public string Title { get; }
    public bool AllowsRotation { get; }   // Q 회전
    public bool HasStaging { get; }       // 임시 보관 영역(+ 닫기 차단, 상행 시작 조건)
    public Vector2 DefaultAnchorMin { get; }
    public Vector2 DefaultAnchorMax { get; }
}

public static class InventoryPopupSpecs
{
    public static readonly InventoryPopupSpec TradeGoods = new(InventoryPopupIds.TradeGoods, "상단 물류품", allowsRotation: true,  hasStaging: true,  (0.02, 0.16), (0.55, 0.80));
    public static readonly InventoryPopupSpec Equipment  = new(InventoryPopupIds.Equipment,  "전투 장비",   allowsRotation: false, hasStaging: false, (0.06, 0.10), (0.42, 0.72));
}
```

- 전투 장비 위치: 상단 물류품보다 오른쪽·아래로 어긋나게, 폭은 작게(기획 41번 §4.1). 6×4 그리드 비율(3:2)에 맞춰 그리드 영역이 창 폭 대부분을 쓴다.
- 회전 가능 여부를 "모든 품목이 정사각형인지"로 자동 판별하지 않는다 — 카탈로그 내용에 따라 조작 규칙이 바뀌면 예측하기 어렵다. 기획이 정한 값을 스펙에 명시한다.

## 4. 일반화 변경

### 4.1 화면 요소 (`InventoryPopupElements.TryBind(sceneUIRoot, spec, out elements)`)
- `spec.HasStaging`일 때만 StagingArea/StagingContent를 필수로 찾는다. 아니면 null로 둔다.

### 4.2 패널 (`InventoryPopupPanel`)
- 생성자에 `spec`을 받는다. `HasStaging`이면 임시 보관 뷰를 만들고, 아니면 null — 렌더·선택 표시에서 건너뛴다.
- `IPanelCloseGuard`는 그대로 구현한다. 임시 보관이 없으면 저장소의 `StagedItems`가 항상 비어 있어 `TryPrepareClose`가 즉시 true — 분기 추가 없이 "닫기 차단 없음"(기획 41번 §3.3)이 성립한다.
- 자동 정렬은 그대로 쓴다. 1×1이면 회전 후보가 없어(정사각형 생략) 좌상단부터 채우기만 한다.

### 4.3 드래그 컨트롤러 (`InventoryItemDragController`)
- `allowsRotation == false`면 Q 입력 액션을 **만들지 않는다**(Enable/Disable/Dispose는 null 안전 처리).
- `stagingView == null`이면 드롭 대상 판정에서 임시 보관을 건너뛴다 → 그리드 밖 드롭은 원위치.

### 4.4 인스톨러 (`InventoryPopupUIBuilder.Build(parent, spec)`)
- 창 위치·제목을 스펙에서 읽는다.
- `HasStaging`이면 기존 레이아웃(그리드 0.02~0.72 + 임시 보관 0.74~0.98). 아니면 그리드 영역을 0.02~0.98로 넓히고, **이전 실행에서 만들어진 임시 보관 요소가 있으면 제거**한다(`EditorUIBuilder.DestroyChildIfExists` — 재실행 안전성).
- `HubSceneInstaller`: `InventoryPopupUIBuilder.Build(layers.ModelessPopups, InventoryPopupSpecs.TradeGoods)`, `...Equipment)` 두 줄.

### 4.5 배선 (`HubUIWiring`)
- 스펙과 저장소 쌍의 목록을 순회해 등록한다(상단 물류품 전용 하드코딩 제거):

```csharp
TryRegisterInventoryPopup(InventoryPopupSpecs.TradeGoods, tradeGoodsInventory, tradeGoodsInventory);
TryRegisterInventoryPopup(InventoryPopupSpecs.Equipment,  equipmentInventory,  equipmentInventory);
```

- "상행 시작" 조건 목록에는 `HasStaging`인 팝업의 저장소만 넣는다(장비 제외 — 기획 41번 §3.3). 스펙이 조건을 결정하므로 나중에 장비에 임시 보관을 켜도 배선 수정이 필요 없다.

## 5. 데이터 계층

### 5.1 장비 저장소
- `IEquipmentInventoryRepository : IInventoryRepository, IItemCatalogReader, IInventoryArrangement`(설계 40번 §10 예고분).
- `PlaceholderEquipmentInventoryRepository`: `StagedItems`/`TryApplyPlacements`/`CanApplyPlacements`를 `InventoryGrid`에 위임, 성공 시 `OnChanged`. 지갑 연동 없음(장비는 골드 상자 같은 특수 품목이 없다).

### 5.2 Placeholder 장비
- `Equipment.xlsx`: `placeholder-equipment-1`~`4` 4행(IconPath 비움), 표시명 "Placeholder 장비 1"~"4". 크기 컬럼은 없다 — 임포터가 1×1로 고정(설계 35번).
- 초기 배치(6×4): (0,0), (3,1), (5,3), (1,3) — 흩어 두어 자동 정렬 결과를 눈으로 확인할 수 있게 한다.
- 초기 배치 로직은 상단 물류품 저장소와 같은 형태(테이블에 행이 없으면 건너뜀). 두 Placeholder 저장소의 중복은 실제 시스템으로 대체될 때 함께 제거되므로 공용화하지 않는다.

## 6. 영향 범위

| 파일 | 변경 |
|---|---|
| `InventoryPopupSpec`/`InventoryPopupSpecs`(신규) | 팝업별 정의 |
| `InventoryPopupElements`, `InventoryPopupPanel`, `InventoryItemDragController` | 스펙에 따른 임시 보관·회전 선택 |
| `InventoryPopupUIBuilder`, `HubSceneInstaller` | 스펙 기반 조립, 장비 팝업 생성, 임시 보관 요소 정리 |
| `HubUIWiring` | 팝업 등록 일반화, 상행 시작 조건을 스펙 기준으로 |
| `IEquipmentInventoryRepository`, `PlaceholderEquipmentInventoryRepository` | 정리 조작, 초기 배치 |
| `Equipment.xlsx` | Placeholder 4행 |
| 상단 물류품 팝업 | 동작 변화 없음(스펙 값이 기존 동작과 동일) — 회귀 확인 대상 |

## 7. 검증

- EditMode: 장비 저장소 재배치 후 `OnChanged`, 초기 배치(행 있을 때 4개·없을 때 0개), 1×1 교환 항상 Swap, 1×1 자동 정렬 결과(회전 0).
- Unity 실전: 전투 장비 버튼으로 열기·닫기, 드래그 이동·교환, Q를 눌러도 변화 없음, 자동 정렬, 이름 표시, 창 드래그, 두 팝업 동시 열기(겹침 배치 확인), 장비 팝업만 열린 상태에서 "상행 시작" 정상 활성. 상단 물류품 팝업 회귀(임시 보관·회전·닫기 차단).

## 8. 사용자 확인 필요

1. **전투 장비 창 위치·크기 수치(§3)** — (0.06, 0.10)~(0.42, 0.72) 잠정. 실전 확인 후 조정하는 것을 추천.
2. **초기 배치 위치(§5.2)** — (0,0), (3,1), (5,3), (1,3) 흩어 두기 추천.
