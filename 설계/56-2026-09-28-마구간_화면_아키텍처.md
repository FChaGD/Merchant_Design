## 5. 교역품 그리드 분리

- `PlaceholderTradeGoodsInventoryRepository`의 그리드 크기 계산에서 로스터 조회를 제거하고 `PlaceholderGridCells = 40`(기존 5대 × 8칸)으로 고정. 가로 10칸 접기 규칙은 유지 → 10×4.
- 로스터 의존성(`ICaravanRosterProvider`) 제거. 요약 주석에 "기획 55번 §3 — 마차 구매와 무관, 마차 적재 연동(31번 §3.3) 시 교체"를 명시.
- 기존 테스트 `ResolveDependencies_ComputesGridSizeFromWagonCount` → 고정 크기 검증으로 이름·내용 수정. 테스트 셋업의 로스터 생성은 제거.

## 7. 화면

### 7.1 목록형 구매 화면 UI 공유 (§10 확인 사항)

용병단 접촉 화면과 마구간 화면은 요소 구성이 같다 — 좌측 보유 텍스트 블록, 우측 후보 목록(아이콘·이름·종류·가격), 정보 패널(이름·종류·상세·가격·사유·버튼), 나가기. 차이는 제목·버튼 문구·상세(용병: 스탯, 마구간: 없음)뿐이다.

| 요소 | 공유 형태 |
|---|---|
| 요소 ID | `RosterShopUIElementIds` — 접두사 + 요소 이름으로 조립(인벤토리 편집 본문 `InventoryPopupUIElementIds` + 접두사 선례) |
| 요소 묶음 | `RosterShopElements.TryBind(sceneUIRoot, prefix)` |
| 후보 한 줄 | `RosterShopCandidateRowView`(아이콘·이름·종류·가격) — 기존 `MercenaryCandidateRowView`를 이름만 바꿔 옮김(스크립트 GUID 유지) |
| 인스톨러 | `RosterShopUIBuilder.Build(modalPopups, objectName, prefix, 제목들, 버튼 문구)` |
| 패널 로직 | 공유하지 않음 — `MercenaryContactPanel`, `StablePanel`이 각자 자기 서비스·문구를 가진다 |

- 용병 화면은 요소 ID 접두사 `MercenaryContact`를 그대로 쓴다. 제작 시 요소 이름 일부를 종류 공용으로 바꿨다(`InfoClass`→`InfoKind`, `InfoStats`→`InfoDetail`, `InfoCost`→`InfoPrice`, `HireButton`→`ActionButton`) — Build Hub Scene 재실행이 마커를 다시 쓰고, 옛 이름의 오브젝트는 빌더가 정리한다. 후보 목록 렌더링(줄 재사용·줄 높이·빈 목록 문구)도 `RosterShopCandidateList`로 공유했다. `MercenaryContactUIElementIds`/`MercenaryContactElements`/`MercenaryContactUIBuilder`는 공유 요소로 대체되어 삭제.

### 7.2 `StablePanel`

- `IUIPanel` + `IDisposable`, `PanelId = UIPanelIds.Facility(TownFacilityIds.Stable)`, 모달 팝업 채널 등록.
- 좌측: "마차 1/5" + 보유 이름, 빈 줄, "시설 1/5" + 보유 이름.
- 정보 패널 상세 칸은 비워 둔다. 가격 "가격 1,000". 사유: "재화가 부족합니다." / "더 보유할 수 없습니다.(최대 5개)".
- 갱신: 재화 변경 → 정보 패널, 로스터 변경 → 전체 재조회·선택 해제(용병 화면과 같은 규칙).
- `HubUIWiring.RegisterStable(...)`, `HubSceneInstaller` 빌더 한 줄.

## 11. 검증 절차 (제작 후)

1. Play 1회(자동 임포트로 마차·시설 자산 생성) → 종료 → Bootstrap.unity `Build Bootstrap Scene` → Hub.unity `Build Hub Scene` → 각 Ctrl+S.
2. EditMode 테스트 전체 통과.
3. 용병단 접촉 화면 재확인(공유 UI 이전): 표시·고용·사유·나가기.
4. 공업 지구 → 마구간: 좌측 "마차 1/5 / 마차이름1", "시설 1/5 / 시설이름1", 후보 8개.
5. 구매: 재화 1,000 감소, 좌측 추가, 후보 제거. 재화 부족 시 비활성+사유. 한 종류 5/5 → 해당 후보 소진.
6. 정비창: 마차·시설 보유 수가 구매 수만큼 증가, 배치 가능.
7. 상단 물류품 팝업·무역품 구매 화면: 그리드 10×4 유지(마차 구매 전후 동일).
8. 상행 → 전투 정상.
