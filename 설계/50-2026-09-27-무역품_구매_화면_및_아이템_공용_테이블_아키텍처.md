## 2. 현재 구조 (코드 확인 결과)

### 2.1 테이블·임포트

| 요소 | 현재 |
|---|---|
| 워크북 | `Table/Item/` 카테고리 4개(TradeGoods/Equipment/Consumable/PersonalItem), 각각 `ItemData`·`ItemStrings` 시트 |
| 임포터 | `ItemTableImporter` — 카테고리마다 독립 임포트(메뉴 4개). 카테고리 간 조인 없음 |
| 자산 | 카테고리마다 `ItemDefinitionTableAsset`(Id, 크기, 아이콘) + `ItemStringTableAsset`(Id, Ko) |
| 런타임 | 저장소가 두 자산으로 `TableItemCatalog`를 만들어 `IInventoryItemDefinition`(Id, 이름, 아이콘, 크기)을 노출 |
| 골드 상자 | 교역품 테이블의 한 행. 교역품 저장소가 Id 문자열로 식별해 지갑 연동 |
| 셀 규칙 | enum 열은 정수 Id(설계 18번 v2), 문자열 식별자는 슬러그(`ParseSlug`) |

### 2.2 인벤토리 UI

| 요소 | 현재 |
|---|---|
| `InventoryPopupPanel` | 그리드·임시 보관·드래그·정렬·선택·안내 문구 + 창 드래그·닫기 버튼·창 위치 기억을 한 클래스가 모두 가짐 |
| `InventoryPopupElements` | 위 요소 전체를 한 묶음으로 바인딩(창 제목 줄·닫기 버튼 필수) |
| `InventoryPopupUIBuilder` | 팝업 한 개 전체를 조립하는 공용 유틸리티 |
| 임시 보관 상태 | 저장소 내부 `InventoryGrid`에 있음 — **팝업과 고정 패널이 같은 저장소를 보면 임시 보관도 자동으로 공유된다** |
| 배치 계약 | `IInventoryRepository.TryPlaceItem(정의, 위치)` — 회전을 지정할 수 없음 |

### 2.3 UI 관리

| 요소 | 현재 |
|---|---|
| 모달 팝업 채널 | 열리면 `PopupLayerGate`가 `DepthLayer`·`PersistentLayer`를 숨기고 `PopupExemptLayer`(재화 패널)는 유지. depth 채널은 그대로 활성 |
| depth 채널 | 카테고리 depth가 활성인 동안 모달 팝업을 열고 닫아도 카테고리 depth가 유지됨 |
| 닫기 차단 | `IPanelCloseGuard`는 인벤토리 팝업 코디네이터만 확인. `PanelChannel.Close`는 확인하지 않음 |
| 시설 버튼 | `TownCategoryPanel`이 클릭 시 "아직 구현되지 않았다" 경고만 출력 |

**결론**: 기획 48번 §3.1(재화 패널만 남기고 전부 숨김) + §4.5(나가면 시장 지구 depth로 복귀)는 **기존 모달 팝업 채널의 동작과 정확히 같다.** 무역품 구매 화면을 모달 팝업으로 등록하면 가시성·복귀 처리를 새로 만들 필요가 없다.

## 3. 테이블 구조

### 3.1 워크북·시트

```
Assets/Table/Item/
  Item.xlsx          ItemData / ItemTownPrice / ItemStrings
  TradeGoods.xlsx    ItemData / ItemDetail / ItemStrings
  Misc.xlsx          ItemData / ItemDetail / ItemStrings   ← 신설
  Equipment.xlsx     ItemData / ItemDetail / ItemStrings
  Consumable.xlsx    ItemData / ItemDetail / ItemStrings
  PersonalItem.xlsx  ItemData / ItemDetail / ItemStrings
```

| 워크북 | 시트 | 열 | 행 |
|---|---|---|---|
| Item | ItemData | Id, Category, IconPath, Price | 전체 아이템 |
| Item | ItemTownPrice | ItemId, CityId, Price | 머리글만 |
| Item | ItemStrings | Id, Ko, DescKo | 전체 아이템 |
| TradeGoods | ItemData | Id, FootprintWidth, FootprintHeight, TradeKind | 교역품 |
| Misc | ItemData | Id, FootprintWidth, FootprintHeight | 골드 상자 |
| Equipment·Consumable·PersonalItem | ItemData | Id | 해당 카테고리 아이템 |
| 카테고리 워크북 전부 | ItemDetail | ItemId | 머리글만 |
| 카테고리 워크북 전부 | ItemStrings | Id | 머리글만 |

- 카테고리 워크북의 `ItemData`에 Id 행을 두는 이유: 기획 49번 §6 "공용 데이터 Id에 대응하는 카테고리 데이터 행이 없으면 오류" 검사를 위해. 장비 등은 Id 열만 있다.
- 카테고리 세부 데이터 시트는 속성이 생기면 `ItemDetail` 대신 속성 이름으로 시트를 추가한다(세부 데이터는 속성마다 시트 하나, 기획 49번 §3.1). 지금의 `ItemDetail`은 자리 표시용 머리글 시트다.

## 4. 임포트

### 4.1 임포터 구조

`ItemTableImporter`를 **아이템 전체를 한 번에 임포트**하는 구조로 바꾼다. 카테고리 워크북을 공용 워크북과 Id로 조인해야 하므로 카테고리별 독립 임포트가 성립하지 않는다.

```
Import()
  1. Item.xlsx 읽기 → 공용 행(Id, Category, IconPath, Price, Ko, DescKo) 목록, 검사
  2. 카테고리마다 워크북 읽기 → 카테고리 행과 공용 행을 Id로 조인, 검사
  3. 카테고리마다 기존 자산 형태로 기록
       ItemDefinitionTableAsset (Id, 크기, 아이콘, Price)
       ItemStringTableAsset     (Id, Ko, DescKo)
  4. 교역품 구분을 TradeGoodsKindTableAsset에 기록
  5. 세부 데이터 시트는 읽어서 머리글 존재만 확인(행이 있으면 경고 — 로직 미사용)
```

- **런타임 자산은 카테고리별 형태를 유지한다.** 저장소 4종의 배선·조회 코드를 바꾸지 않기 위해서다. 공용/카테고리 분리는 편집(엑셀) 쪽 구조이고, 조인은 임포트 시점에 끝낸다.
- 메뉴: 카테고리별 4개 → `Tools/Game/Table/Import Items` 1개. `TableImportAll`·`TableAutoImportOnPlay`의 호출 4줄도 1줄로 바꾼다.
- 신규 자산 경로(`TableAssetPaths`): `MiscItemTable`, `MiscItemStrings`, `TradeGoodsKindTable`.

### 4.2 검사 (하나라도 실패하면 예외로 임포트 중단)

| 검사 | 구현 |
|---|---|
| 필수 열 빈칸(IconPath 제외) | `EditorTableReader`에 `ParseRequiredString` 추가. 숫자·enum·슬러그는 기존 파서가 이미 빈칸을 예외로 처리 |
| 전체 Id 중복 | 공용 `ItemData`를 `ParseSlug`로 읽음(시트 하나가 전체 아이템) |
| 카테고리 행의 Id가 공용에 없음 / Category 불일치 | 조인 단계 |
| 공용 Id에 카테고리 행이 없음 | 조인 후 역검사 |
| 공용 `ItemStrings`와 `ItemData`의 Id 집합 불일치 | 조인 단계 |
| 세부 데이터 행의 CityId·ItemId 참조 | 행이 생길 때부터 적용(지금은 머리글만이라 생략, 경고만) |

## 5. 런타임 데이터 계약

### 5.1 변경

| 대상 | 변경 | 이유 |
|---|---|---|
| `ItemDefinitionEntry` | `Price` 필드 추가 | 공용 데이터 열. 카테고리 자산에 조인돼 기록됨 |
| `ItemStringTableAsset` | 항목을 `ItemStringEntry`(Id, Ko, DescKo)로 교체, 설명 조회 추가 | 설명 열 |
| `IInventoryItemDefinition` | `Description` 추가 | 이름과 같은 표시용 정보. 상품 정보 패널과 향후 인벤토리 정보 표시가 같이 씀 |
| `TableItemDefinition` / `TableItemCatalog` | 설명 전달 | — |
| `IInventoryRepository.TryPlaceItem` | 회전 매개변수(`quarterTurns`, 기본값 0) 추가 | 구매 자동 배치가 회전한 자리를 쓸 수 있어야 함(기획 48번 §4.1 "안 들어가면 회전") |
| `InventoryGrid.TryPlace` | 같은 회전 매개변수 추가 | 위와 같음 |
| `InventoryAutoSorter` | `TryFindSlot(그리드 크기, 배치된 아이템, 정의, 회전 허용, out 위치, out 회전)` 공개 | 자동 정렬과 같은 "위→아래, 왼→오, 안 되면 회전" 규칙을 재사용 |

- 가격을 `IInventoryItemDefinition`에 넣지 않는다. 가격은 판매 맥락(나중에는 마을별)에 따라 달라지는 값이라 판매 목록 조회 계약(§5.3)으로만 노출한다(ISP).

### 5.2 골드 상자 — 기타 카테고리

| 항목 | 설계 |
|---|---|
| 데이터 위치 | `MiscItemTable`/`MiscItemStrings` 자산 |
| 교역품 저장소 | 직렬화 필드 `miscItemTable`/`miscItemStrings` 추가. 카탈로그를 `CompositeItemCatalog`(교역품 + 기타)로 구성 — 교역품 그리드에 놓일 수 있는 아이템 = 교역품 + 기타 |
| `CompositeItemCatalog` | 여러 `IItemCatalogReader`를 순서대로 조회하는 plain C# 클래스(신규) |
| 지갑 연동 | 변경 없음(Id 문자열 식별 유지) |
| 배선 | `ManagerHierarchyInstaller`가 교역품 저장소에 기타 자산 2개를 추가로 배선 |

### 5.3 판매 목록

```csharp
public readonly struct ShopStockEntry
{
    public IInventoryItemDefinition Definition { get; }
    public int Price { get; }
}

public interface ITownShopStockReader
{
    // cityId: 마을별 차별화 구현 시 사용. 지금 구현은 무시한다.
    IReadOnlyList<ShopStockEntry> GetStock(int cityId, string facilityId);
}
```

| 구현 | `PlaceholderTownShopStockProvider` (MonoBehaviour, `IManagedComponent`, Bootstrap 상주) |
|---|---|
| 데이터 | 직렬화 필드: 교역품 정의·스트링 자산, `TradeGoodsKindTableAsset` |
| 규칙 | 시설 → 판매 대상 매핑을 코드 상수로 둔다. 지금은 `TradeGoodsMarket → 교역품 중 General` 하나. 매핑에 없는 시설은 빈 목록 + 경고 |
| 순서 | 테이블 행 순서 |
| 캐시 | 시설별 목록을 첫 조회 때 한 번 만들고 재사용 |
| 대체 시점 | 마을별 차별화 구현 시 `ItemTownPrice` 등 세부 데이터를 읽는 구현으로 교체. 요약 주석에 "실제 시스템 설계 후 대체 대상" 명시(Placeholder 규칙) |

- 기타 카테고리는 매핑 대상이 아니므로 골드 상자는 목록에 나오지 않는다(기획 49번 §3.4).
- 특산물 구매·대장간·잡화 상점은 해당 시설 화면을 만들 때 매핑 한 줄씩 추가한다.

### 5.4 구매 처리

`ShopPurchaseService` (plain C#, 신규)

| 입력 | 재화 지갑(`IPlayerCurrencyWallet`), 대상 저장소(`IInventoryRepository`), 회전 허용 여부 |
|---|---|
| 판정 | `Evaluate(항목)` → `Available` / `InsufficientFunds` / `NoSpace`. 둘 다 해당하면 재화 부족을 우선 |
| 구매 | `TryPurchase(항목)`: 빈 자리 탐색 → 재화 차감 → 배치 → 배치 실패 시 재화 환급 |

- 빈 자리 탐색은 **그리드에 놓인 아이템만** 기준으로 한다. 임시 보관 아이템은 그리드 칸을 차지하지 않으므로 계산에 넣지 않는다(기획 48번 §3.6 — 임시 보관은 구매품을 받는 공간이 아님).
- 차감 → 배치 순서와 롤백은 교역품 저장소의 골드 상자 처리(차감 후 배치 실패 시 환급)와 같은 방식이다.

## 6. UI 구조

### 6.1 패널 등록과 가시성

| 항목 | 설계 | 근거 |
|---|---|---|

| 패널 Id | `UIPanelIds.Facility(facilityId)` → `"Facility.TradeGoodsMarket"` | 시설 화면 공통 규칙. 다른 시설도 같은 형식 |

### 6.2 진입 시 인벤토리 팝업 닫기

- `IUIManager`에 `CloseAllInventoryPopups()` 추가 → `InventoryPopupCoordinator.CloseAll()`로 위임.
- **닫기 차단(임시 보관 비우기)을 거치지 않고 숨긴다.** 임시 보관 상태는 저장소에 있어 고정 패널이 그대로 보여 주므로(§2.2), 진입이 막히지 않고 기획 48번 §4.5 "임시 보관 아이템이 고정 패널로 이어진다"가 추가 코드 없이 성립한다.
- 호출 위치: 시설 버튼 클릭 경로(`TownCategoryPanel`)에서 `CloseAllInventoryPopups()` → `Open(...)` 순서. 패널의 `Open()`은 표시만 한다는 규칙(CLAUDE.md)을 지키기 위해 패널 내부에서 부르지 않는다. **모든 시설 화면 진입에 적용한다**(§11-1).

### 6.3 나가기 차단

- `PanelChannel.Close`가 패널이 `IPanelCloseGuard`를 구현하면 `TryPrepareClose()`를 먼저 확인하도록 바꾼다. 실패하면 닫지 않는다.
- 무역품 구매 패널이 이를 구현한다: 임시 보관 아이템을 빈 자리에 자동 배치하고, 전부 넣지 못하면 안내 문구를 띄우고 false(기획 48번 §4.5, 39번 §3.5와 같은 규칙).
- 기존 depth 패널·모달 팝업(상행 준비 등)은 이 인터페이스를 구현하지 않아 동작이 바뀌지 않는다.
- 나가기 버튼은 `UIManager.Close(PanelId)`만 호출한다(패널이 자기 `Close()`를 직접 부르지 않음).

### 6.4 상단 물류품 편집 로직 분리

현재 `InventoryPopupPanel` 한 클래스에 있는 "그리드 편집"과 "떠 있는 창"을 나눈다.

| 클래스 | 책임 | 사용처 |
|---|---|---|
| `InventoryArrangementController` (신규, plain C#, `IDisposable`) | 그리드·임시 보관 렌더링, 드래그, 회전, 선택, 자동 정렬, 안내 문구, 임시 보관 비우기(`TryFlushStaging`) | 인벤토리 팝업, 무역품 구매 고정 패널 |
| `InventoryPopupPanel` (축소) | 위 컨트롤러 + 창 제목 줄 드래그 + 닫기 버튼 + 창 위치 기억 + 코디네이터 등록 | 인벤토리 팝업 4종 |
| `InventoryArrangementElements` (신규) | 그리드·임시 보관·정렬 버튼·안내 줄·드래그 레이어·템플릿·루트 클릭 바인딩 | 두 곳 공통 |
| `InventoryPopupElements` (축소) | 위 요소 + 창 제목 줄·닫기 버튼 | 인벤토리 팝업 |

- 요소 ID는 기존 `InventoryPopupUIElementIds`를 그대로 쓰고 접두사만 다르게 준다: 고정 패널 접두사는 `"TradeGoodsMarket.Inventory"`. 클래스 이름·요약 주석을 "접두사 = 팝업 Id 또는 고정 패널 Id"로 고친다.
- 에디터: `InventoryPopupUIBuilder`에서 본문 조립(그리드·임시 보관·하단 줄·템플릿·드래그 레이어)을 `BuildArrangementBody(root, 접두사, 임시 보관 여부, 본문 윗변)`로 뽑아 팝업 조립과 무역품 구매 조립이 함께 쓴다.
- Q 회전 입력은 드래그 중에만 켜지므로(`InventoryItemDragController`) 팝업과 고정 패널이 각자 입력 액션을 가져도 충돌하지 않는다. 진입 시 팝업은 모두 닫힌다(§6.2).

### 6.5 무역품 구매 패널

| 동작 | 처리 |
|---|---|
| `Open()` | 판매 목록 조회·렌더링, 선택 초기화, 고정 패널 새로 그림, 표시 |

## 10-1. 제작 노트 (2026-09-27)

- 교역품 저장소 계약이 조회 계약과 임시 보관 조회 계약 양쪽에서 같은 변경 이벤트를 물려받아 이름이 모호하다(CS0229). 무역품 구매 패널은 조회 계약으로 형변환해 구독한다.
- `PanelChannel`은 internal이라 닫기 차단 테스트는 같은 채널을 쓰는 공개 구현체 `BattleTestPanelHost`로 검증한다(`PanelCloseGuardTests`).
- 기존 Placeholder 장비·소모품·개인 물품은 실제로 카테고리당 4종이다(기획 49번 §5.1 표의 "1·2"는 2종만 적은 것). 전부 가격 100으로 이전했다.
- 테이블 임포트 메뉴가 `Tools/Game/Table/Import Items` 하나로 바뀌었다. 검사 실패 시 자산을 갱신하지 않고 오류 로그만 남긴다.
